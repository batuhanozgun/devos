## Test 2 — “Yapılacak iş” nasıl ortaya çıkıyor?

Mission'ın üretime başlayabilecek kadar qualify edildiğini varsayalım. Domain değerleri önemli değil; çalışma sistemini sınayıyoruz.

Naif plan:

```text
Araştır
→ Planla
→ Soruları yaz
→ Kontrol et
→ Yayınla
```

Ama daha önce şu soru var:

> **“Hedefin gerçekleşmesi için nelerin doğru hale gelmesi gerekiyor?”**

Örnek conditions:

```text
C1  İçerik doğru müfredatı kapsıyor.
C2  Sorular pedagojik olarak uygun.
C3  Matematiksel içerik doğru.
C4  Kapsam ve zorluk dağılımı yeterli.
C5  Üretim kapasitesi yeterli.
C6  Kalite kontrol sistemi çalışıyor.
C7  Yayınlama ortamı hazır.
C8  Telif / kullanım sınırları karşılanıyor.
C9  Hatalar düzeltilebiliyor.
C10 Kullanımdan sorunlar geri dönebiliyor.
```

Bunlar task değil.

# Need / Condition ≠ Work

RPD araştırmasının ayırdığı:

```text
Need
Condition
Method
Decision
Action
```

bizim modelde de yararlı.

Örneğin “müfredat kapsamı yeterli olmalı” Work değil. Yöntem seçilince authoritative curriculum bulma, yorumlama, learning objectives çıkarma, coverage model ve test gibi Work'ler doğabilir.

```text
TARGET
  ↓
NEEDS / REQUIRED CONDITIONS
  ↓
POSSIBLE METHODS
  ↓
DECISIONS
  ↓
WORK
  ↓
ACTIONS
```

Action yeni bilgi üretip yeni condition/work keşfedebilir.

# Work discovery recursive

Curriculum source ihtiyacı → source acquisition Work. Bu yapıldığında prerequisite relations keşfedilebilir → yeni Need → yeni Work. Büyük Work'ün tamamı baştan çıkarılamıyor.

```text
Work discovery
→ some Work becomes known
→ execute / investigate
→ new reality becomes visible
→ more Work discovered
↺
```

# Plan hakkında düzeltme

```text
ACTUAL WORK
≠
REPRESENTATION OF WORK
```

Plan büyük ölçüde Information'dır. `PLAN.md complete` demesi actual Work state ile çelişebilir.

> **Plan, Work değildir. Plan Work hakkındaki yaşayan representation'dır.**

# Üç farklı graph adayı

Henüz primitive ilan etmiyorum:

1. Need / Condition graph — dünyada neyin doğru olması gerektiği.
2. Work graph — bunu gerçekleştirmek için ne yapıldığı.
3. Artifact / Information graph — Work'ün kullandığı/ürettiği temsiller.

OpenSpec planning-artifact readiness ile executable Work readiness'in aynı olmadığını gösteren counterexample.

# Work proposal ≠ admitted Work

Keşfedilmiş iş otomatik yapılacak iş değildir:

```text
DISCOVERED WORK
→ PROPOSED WORK
→ QUALIFIED / SELECTED
→ ADMITTED WORK
```

500 öğretmen pilotu faydalı olabilir ama scope/budget/authority/method alternatives nedeniyle admit edilmeyebilir.

# Admitted ≠ actionable

W02 admitted ama W01 output yoksa actionable değil.

Beads `open` ile `ready frontier` farkını gösteriyor; fakat bizim readiness dış gerçeklik için daha geniş:

```text
WORK READY =
  Work prerequisites satisfied
+ required Information available
+ suitable Actor available
+ Environment capability available
+ Control permits execution
```

# “Next task” yerine actionable frontier

Aynı anda W01/W03/W04/W06/W07/W08 başlanabilir olabilir. SOUL'un sorusu “sıradaki task?” değil:

> **“Mevcut durumda hangi Work'ler başlanabilir ve hangilerini neden şimdi başlatmalıyız?”**

```text
READY
≠
HIGH PRIORITY
≠
SELECTED
≠
ASSIGNED
≠
CLAIMED
≠
EXECUTING
```

# Work lifecycle

```text
NEED / CONDITION DISCOVERED
→ WORK NEED IDENTIFIED
→ WORK PROPOSED
→ WORK ADMITTED
→ PREREQUISITES DISCOVERED
→ READY / BLOCKED standing
→ PRIORITIZED
→ SELECTED
→ ASSIGNED
→ CLAIMED
→ EXECUTING
→ RESULT REPORTED
→ VERIFIED
→ ACCEPTED / REJECTED / REOPENED
```

Her noktada new need → new Work olabilir.

# İlk actionable frontier ve Actor sorusu

Artık W01/W03/W04/W06/W07/W08 ready ise ilk kez “hangi agent'lara ihtiyacımız var?” anlamlı hale geliyor.

```text
Work demand
→ required capability
→ role
→ Actor
```

Başlangıçta agent listesi çıkarsaydık rollerimizi uyduracaktık.

Gap register:
- Work discovery gerçek Work? **Represented.**
- Need/Condition = Work? **Hayır.**
- Plan = Work? **Hayır.**
- Tek task graph? **Şüpheli.**
- Unknown future Work? **Unresolved needs + discovery Work ile represented.**
- Next task? **Actionable frontier daha doğru.**
- Ready = priority/selected/assigned/claimed? **Hayır.**
- Decision new ground? **Şimdilik hayır.**
- new Foundation primitive? **Henüz hayır.**

Başlangıç model:

```text
Mission → Work → Actors → Execute
```

yerine:

```text
Intent
→ Required conditions discovery
→ Work discovery
→ Work formation / admission
→ Readiness computation
→ Actionable frontier
→ Actor/capability formation
→ Execution
→ Reality changes
→ new conditions / new Work
↺
```

Planning bir kere yapılan başlangıç aşaması değil; Work discovery tüm yaşam döngüsüne yayılmış faaliyet.

Bir sonraki stress noktası Actors.
