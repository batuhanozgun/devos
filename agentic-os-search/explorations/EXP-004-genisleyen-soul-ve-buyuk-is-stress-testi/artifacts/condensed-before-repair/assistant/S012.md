# Verifier seçenekleri

- producer self-review: sınırlı.
- second agent: aynı model/context/assumptions/source ise independence az.
- deterministic oracle: bazı hata sınıfları için güçlü, pedagogy için değil.
- human expert: farklı uygunluk, ama otomatik truth oracle değil.

İlke:

> **Verifier seçimi Work'ün hangi hata sınıfını dışlamak istediğine göre yapılmalı.**

Farklı claim'lere farklı evidence/oracle.

# Verifier disagreement

Pedagogy A PASS, B FAIL. Majority vote yanlış olabilir. Expertise/rubric/revision/criterion/value disagreement teşhis edilmeli. Yeni Work doğabilir: resolve qualification conflict; new evidence/criterion clarification/third expert/principal decision.

# Acceptance

Math PASS, curriculum PASS, pedagogy PASS WITH 2 RESIDUAL, formatting PASS, publication not tested.

“Production'a geçebilir miyiz?” saf verification değil; acceptance/progression decision.

Authority `ACCEPT WITH KNOWN RESIDUAL RISK` diyebilir.

```text
ACCEPTED ≠ PERFECT
ACCEPTED ≠ ALL QUALIFICATIONS PASS
```

Acceptance truth üretmez; authority progression'a izin verir. Residual concern silinmez.

İki layer:
- Epistemic standing: evidence neyi destekliyor?
- Governance decision: evidence+constraints+authority altında next effect ne?

# Integration

v18 verified/accepted ama publishing Actor v17 deploy etti. Accepted artifact exists, production != accepted artifact.

Artifact acceptance ≠ integrated system correctness; deployment/integration qualification gerekir.

# Mission outcome

Live site v18 gösterse bile delivery verified ≠ Mission outcome verified. Aylar sonra user behavior/teacher ambiguity/coverage gaps gibi evidence Mission standing'i PARTIALLY ACHIEVED yapabilir ve yeni Work doğurur.
