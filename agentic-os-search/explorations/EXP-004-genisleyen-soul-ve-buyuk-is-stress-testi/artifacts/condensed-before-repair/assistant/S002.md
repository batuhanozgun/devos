# S002 — U002'ye verilen substantive cevap

---

Bu konuşmada çalışma varsayımını şöyle sabitleyelim:

> **SOUL'a büyük, uzun soluklu, çok aktörlü, parçaları baştan tamamen bilinmeyebilen, günler/haftalar/aylar boyunca ilerleyebilen ve hata/geri dönüş/değişim içeren ciddi bir iş verildiğini varsayıyoruz.**

Dolayısıyla basit kullanım için bazı parçalar gereksiz görünse bile modelden çıkarmıyoruz. Şu aşamada kapasite sınırını arıyoruz.

# SOUL'un kurduğu çalışma sistemi

```text
                         PURPOSE / TARGET

              ┌────────────────┼────────────────┐
              │                │                │
              ▼                ▼                ▼
```

Buradaki kutuları henüz yazılım modülü olarak değil, **sistemin taşımak zorunda olduğu sorumluluk alanları** olarak düşünüyorum.

## 1. Purpose / Target

Bütün sistemin yönünü belirleyen şey. Sadece “yapılacak iş” değil: ne gerçekleştirilmek isteniyor, neden, kapsam/sınırlar, başarı/başarısızlık, kabulü kim yapar, hangi constraint'ler ihlal edilemez.

Sistem sürekli yalnız “hangi task sırada?” değil, **“Hâlâ doğru sonucu mu üretmeye çalışıyoruz?”** diye bakabilmeli.

## 2. Work System

Büyük işi temsil eden yaşayan yapı: işler, alt işler, hedefler, deliverable'lar, dependencies, prerequisites, blockers, readiness, priority, schedule, milestones, unknown/discovered work, replanning, reopening, retry, revision, backtracking, completion state.

Plan başta tamamen bilinmek zorunda değil; sistem çalıştıkça Work modeli değişebilir.

## 3. Actors

İşi gerçekleştirecek katılımcılar. Bazıları agent olabilir ama hepsinin olması gerekmez. Planner, researcher, builder, reviewer, verifier, integrator, coordinator, human decision-maker veya deterministic service olabilir.

Bir Actor için role, responsibility, capability, competence, authority, assignment, ownership, availability ve current state gibi ayrımlar gerekebilir.

```text
yapabiliyor
≠
görevlendirildi
≠
yetkili
≠
sorumlu
```

## 4. Information

Memory'den daha geniş: kaynaklar, araştırmalar, spesifikasyonlar, kararlar, artefaktlar, kanıtlar, geçmiş, observations, instructions, work records, knowledge, context, actor memory ve learned information.

İçerik yanında origin, version, currentness, scope, producer, epistemic status ve exposure da önemlidir.

## 5. Environment

Actors'ın gerçek çalışma dünyası: tools, APIs, filesystem, GitHub, databases, browsers, compute, network, credentials, permissions, sandbox, runtime, budget, available models ve dış sistemlerin gerçek durumu.

Actor'ın işi bilmesi, yapabilecek ortamın mevcut olduğu anlamına gelmez.

# İlk beş alan dünyanın parçaları

```text
Purpose      → Neyi gerçekleştirmeliyiz?
Work         → Bunun için ne yapılmalı?
Actors       → Kim/ne yapacak?
Information  → Neyi bilmeleri gerekiyor?
Environment  → Gerçekte neyle/ne şartlarda çalışabiliyorlar?
```

Bunların yan yana durması çalışan sistem oluşturmaz.

# 6. Composition / Control

Parçaları bağlar: hangi Actor, hangi Work'ü, hangi Information ile, hangi Environment içinde, hangi authority altında, hangi şartta yapabilir?

Orchestration, routing, dispatch, admission, permissions, authority, sequencing, coordination, handoff, gating ve state transitions burada olabilir.

# 7. Execution

Plan/kontrolün gerçek aksiyona dönüşmesi. Actor seçilir, context hazırlanır, tools verilir, Work başlatılır, aksiyon ve artifact oluşur.

```text
work state
≠
execution/session state
```

# 8. Verification / Acceptance

Actor “bitti” dediğinde sistem bunu doğrudan gerçek kabul etmemeli.

```text
Actor tamamladığını söyledi
≠
çıktı mevcut
≠
çıktı doğru
≠
diğer parçalarla entegre
≠
hedef durumu gerçekleşti
≠
yetkili taraf kabul etti
```

# 9. Continuity / Recovery

Agent/session/model/crash/plan değişimi gibi kesintilere rağmen canonical target/work state, current standings/responsibilities ve next actionable work recover edilebilmeli.

# 10. Learning / Adaptation

Sistem uzun işte kendi çalışma biçiminden de öğrenebilmeli; fakat method/control değişiklikleri de Work/authority/verification sürecine tabi olmalı.

# Başlangıç listesiyle eşleme

| Başlangıç | Karşılığı |
|---|---|
| Agent'lar | Actors |
| Rol tanımları | role/capability/authority/responsibility |
| Ortada iş olacak | Purpose + Work |
| İş planı/workflow | Work System + Composition/Control |
| Memory | Information + Continuity/Recovery + Actor/Learning mekanizmaları |

Repository'nin eklettiği parçalar Purpose/Target, Environment, Composition/Control, Execution, Verification/Acceptance, Continuity/Recovery ve Learning/Adaptation oldu.

En kısa tanım:

> **Bir hedefi temsil eden; işi keşfedip örgütleyen; gerekli Actor'ları, bilgi ve çalışma ortamını sağlayan; bunları yetki ve kontrol ilişkileriyle birbirine bağlayan; işi gerçekten yürüten; sonuçları doğrulayan; uzun zaman boyunca durumunu koruyup hatalardan geri dönebilen ve gerektiğinde kendi çalışma biçimini kontrollü olarak geliştirebilen bir sistem.**

Bir sonraki asıl soru: **Bu on alan gerçekten aynı seviyede mi?** Muhtemelen değil.
