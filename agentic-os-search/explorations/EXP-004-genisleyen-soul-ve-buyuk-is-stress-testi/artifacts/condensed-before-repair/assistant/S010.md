# Context yeni store değil

Geçici kullanım:

> **Context = belirli bir Actor'ın, belirli bir Work için, belirli anda model-visible hale getirilen çalışma temsili.**

```text
ALL SYSTEM INFORMATION
→ selection
→ transformation / compression if needed
→ exposure
→ ACTOR WORKING CONTEXT
```

Context Information'ın consumer-relative görünümü.

# Context package

W01 için Mission slice + known Information + required output + authority boundary gibi parçalar bağlanabilir. Bu prompttan fazla; provenance/Work identity/authority/output contract birbirine bağlanır. Geçici ad `WORK CONTEXT PACKAGE`, yeni primitive değil.

# Information adequacy

Bir Work'ün Information açısından yapılabilir olması sadece “bilgi bir yerde var” değil:

```text
INFORMATION ADEQUACY FOR
(Actor A, Work W, current situation)
```

Aynı Information bir Actor'a yeterli, diğerine yetersiz olabilir. Adequacy Information alone değil:

```text
Information × Work × Actor × purpose/use
```

Composite Standing.

# Context lifecycle

```text
1. Work need
2. Information requirements
3. candidate Information
4. source/freshness/applicability
5. select subset
6. transform/compress
7. preserve provenance/qualifiers
8. expose to Actor
9. Actor executes
10. capture produced Information
11. qualify/verify
12. integrate shared Information state
```

# Memory'nin yeri

Yarın Actor yeniden yaratılınca ne saklanmalı?

- Work record,
- evidence/artifacts,
- decisions,
- Actor-local useful state,
- reusable learned knowledge.

Retention farklı olabilir. “Memory sistemi” tek database değildir; Information lifecycle içindeki persistence/retrieval/revision/forgetting mechanisms ailesi.

# “SOUL büyüyor” hipotezi güçleniyor

Baz SOUL bütün domain bilgisini içermiyor. İş geldikçe Mission representation, Work graph, Actor roles/instances, domain sources, decisions, context-assembly rules, verification records, memory, tools ekleniyor.

SOUL yalnız agent yaratmıyor; kendi/working system'ine yeni kalıcı yapısal organlar ekliyor. Teknik ihtiyatlı ifade: **SOUL'un çalışma durumu ve capability topology'si Work'e göre material olarak genişliyor.**

# Context sınırı

SOUL büyüdükçe her şey context'e konamaz:

```text
SOUL SYSTEM STATE grows
while
each Actor sees a bounded working view
```

Bu nedenle memory/persistence kadar discovery, selection, routing, exposure, progressive retrieval kritik.

# Failure scenarios

Canonical Information current olabilir ama Actor'ın context'i stale olabilir:

```text
SOURCE CURRENT
≠
DERIVED VIEW CURRENT
≠
ACTOR CONTEXT CURRENT
```

Information authoritative/current/available olup belirli Work için inadequate olabilir.

Actor doğru source'u görse bile provenance/version/scope qualifier'larını output'ta kaybedebilir: payload survives, qualifier disappears.

# Information tarafında ilk kurallar

1. Canonical Information ≠ Actor Context.
2. Memory ≠ Context; memory read context'e dönüşebilir.
3. Source authority ≠ rememberedness.
4. Retrieval success ≠ adequacy.
5. Availability consumer-relative.
6. Working context qualified kalmalı.

Gap register: Context new ground değil; Memory new ground değil; System knowledge ≠ Actor knowledge; adequacy composite; Actor all-system görmez; retrieval ≠ context; stored ≠ current/authoritative; stale context critical; new primitive yok.

```text
        ▼

```
