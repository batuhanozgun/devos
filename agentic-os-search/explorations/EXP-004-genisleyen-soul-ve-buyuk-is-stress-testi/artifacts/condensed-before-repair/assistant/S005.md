# S005 — U005'e verilen substantive cevap

---

Testin **ilk aşamasını burada, bu konuşmanın içinde ben işleteceğim**. Codex açmana gerek yok.

Şu anda gerçek sistemi implement etmiyoruz; **SOUL'un kuracağı büyük çalışma sisteminin kavramsal modelini zorluyoruz**. En doğru ortam bu konuşma: repository araştırmalarını kullanarak kontrollü simülasyon.

Ben geçici olarak **SOUL rolünü** üstleneceğim. Örnek talep:

> “Bir eğitim yılı boyunca kullanılacak kapsamlı bir 4. sınıf matematik soru bankasını üret, yayımla ve sürdürülebilir biçimde işlet.”

Gerçek SOUL gibi adım adım ilerleyeceğim; normal proje planı değil, her adımda modeli sınayacağız:

```text
Ham talep
→ Mission oluşabiliyor mu?
→ Work nasıl ortaya çıkıyor?
→ Hangi Actors gerekli?
→ Hangi Information gerekli?
→ Hangi Environment gerekli?
→ Bindings / Standing / Control nasıl oluşuyor?
→ Şimdi hangi Work gerçekten yapılabilir?
```

Örneğin “Müfredatı araştıracak Researcher Actor oluşturalım” dersem hemen neden bu Actor'a ihtiyaç var, role/instance, authority, Information, completion/acceptance ve staleness sorularını açacağız.

### Codex ne zaman?

Daha sonra.

Eğer exploration sonunda Mission/Work Graph/Actor Registry/Information/Environment/Binding/Standing/Control/Transition gibi model çıkarsa ve gerçek prototip istersek Development OS / Codex tarafına geçeriz:

- schema/file structures,
- gerçek agents,
- session close/reopen,
- Actor kill/reassign,
- real recovery tests.

Üç aşama:

```text
1. Conceptual stress test
   → burada

2. Executable simulation / prototype
   → Development OS / Codex

3. Real system trials
   → gerçek models/tools/runtime/long work
```

Codex'e erken gidersek “neyi inşa etmeliyiz?” anlamadan schema/queue/agent framework gibi implementation seçimlerine ankrajlanabiliriz. Bu nedenle testi burada yürütelim; ben SOUL'un büyük işi kurmasını simüle edeyim, kullanıcı gerektiğinde boşluklara itiraz etsin.
