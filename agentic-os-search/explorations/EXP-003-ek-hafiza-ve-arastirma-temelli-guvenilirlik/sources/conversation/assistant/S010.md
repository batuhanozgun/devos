# Hepsini birleştirince nereye varıyoruz?

Foundation + Karpathy + mevcut studies bize artık yalnız bir “memory system” fikri vermiyor.

Ortaya bir çeşit **memory design grammar** çıkıyor.

Şuna benzer:

```text id="xmb2he"
                    REAL SOURCES / EVENTS / WORK

                              ↓
                         FORMATION

                              ↓

                  PERSISTENT INFORMATION
        ┌────────────────────────────────────┐
        │ source / observation / event       │
        │ derived knowledge / synthesis      │
        │ work state / decisions             │
        │ user/person information            │
        │ procedures / skills                │
        │ history / experience               │
        └────────────────────────────────────┘

                    identity / provenance
                    scope / effective time
                    standing / authority
                    version / lineage
                    ownership / visibility
                    dependency relations

                              ↓

                 DERIVED ACCESS STRUCTURES
             index / summary / graph / FTS /
             hierarchy / cache / embeddings

                              ↓

               SELECTION + EXPOSURE + ROUTING

                              ↓

                     MODEL-VISIBLE CONTEXT

                              ↓

                       REASONING / WORK

                              ↓

                 CREATE / REVISE / FEEDBACK
```

Ve her okta artık şu soruları biliyoruz:

- Yeni information object gerçekten ne?
- Dosya mı değişti, claim mi değişti?
- Kaynak mı, türetilmiş representation mı?
- Yeni evidence mı geldi, eski evidence mı tekrar edildi?
- Historical doğru ile current doğru ayrıldı mı?
- Index source'un yerine mi geçti?
- Derived view stale olduğunu biliyor mu?
- Bilgi var ama discoverable mı?
- Discoverable ama bu consumer için accessible mı?
- Accessible ama bu use için adequate mı?
- Context'e girdi ama gerçekten kullanıldı mı?
- Agent değiştirebiliyor ama değiştirmeye yetkili mi?
- Source değişince hangi dependent representations tekrar değerlendirilmek zorunda?
- Eski bilgi silinmeli mi, tarih olarak kalıp current authority'sini mi kaybetmeli?
- Memory write başarılı ama work state gerçekten değişti mi?

Karpathy tek başına bunun bir bölümünü çok güzel kuruyor. Studies ise özellikle **bu zincirin nerelerde kırıldığını gerçek sistemlerden göstermeye** başlıyor.

# Hangi çalışmalar gerçekten yeni bir şey getirdi?

Özellikle üç concrete study beni etkiledi.

### gstack

Foundation'da teorik olarak konuştuğumuz bir şeyi gerçek kodda göstermiş:

Cache kendi state'inin `stale-fallback` olduğunu **biliyor**, fakat sonraki representation boundary'sinde stderr atıldığı için planning model bu qualification'ı görmüyor.

Yani:

```text id="krzsw4"
source memory:
  content = X
  freshness = STALE
```

↓

```text id="7shfze"
model-visible memory:
  content = X
```

Bu, Foundation'ın:

> derived view qualification kaybedebilir

probleminin gerçek implementation örneği.

Böyle örnekler yüksek marjinal değer.

### ECC

Burada da:

```text id="3iyzp5"
kind = fact
```

olması:

```text id="corf8m"
truth = true
```

demek değil.

`trust = unreviewed`, `status = active/superseded/rejected` ayrı.

Dahası structured interface eksik scan diagnostics'i taşıyor; plain CLI output bunu düşürebiliyor.

Yani tekrar:

```text id="6nxpdq"
memory store doğru qualification taşıyor
↓
consumer view qualification'ı kaybediyor
```

Bu ikinci, bağımsız concrete mechanism.

### Hermes

Diskteki memory, runtime store, prompt snapshot ve pending proposal aynı şey değil.

Bu da:

```text id="r91mgw"
persistent source
≠ live runtime state
≠ model-visible state
```

ayrımını implementation üzerinde görünür yapıyor.

Bu üç study'nin Foundation'a eklediği şey yeni ontoloji değil; **Foundation ayrımlarının gerçekten sistemlerde nerede kırıldığını gösteren mekanizma kanıtları.**

# En ilginç kalan iki study neden OpenViking ve ai-memory?

Bence araştırmaya devam edeceksek ilk iki aday bunlar.

## OpenViking

Çünkü Karpathy'deki fikirlerin çok daha ileri implementation karşılığını vaat ediyor:

```text id="wf3cq9"
L0 abstract
↓
L1 overview
↓
L2 original detail
```

Senin:

> “Batu diye bir kullanıcı olduğunu biliyorum, detay dosyalarının da varlığını biliyorum ama gerekmedikçe açmıyorum.”

örneğine çok yakın.

Üstelik:

- generated summary'nin freshness'i,
- pending child changes,
- source vs vector index,
- typed Resource/Memory/Skill,
- memory `skip/create/merge/delete`,
- `memory_diff`,
- account/user/peer,
- ACL-aware retrieval

gibi konular doğrudan şu an yaptığımız konuşmanın içine oturuyor.

Eğer source study bunları gerçekten doğrularsa, **çok yüksek bilgi kazancı** olabilir.

## ai-memory

Bunun değeri farklı.

OpenViking daha çok:

> **memory/context nasıl organize edilir ve materialize edilir?**

sorusuna yakın.

`ai-memory` ise qualification sinyallerine göre:

> **memory'nin tam lifecycle'ı ve agentlar arasındaki continuity nasıl yönetilir?**

sorusuna daha yakın:

```text id="ijiew1"
capture
→ sanitize
→ consolidate
→ retrieve
→ inject
→ handoff
→ reinforce
→ decay/forget
→ backup/restore
```

Üstelik file-first canonical wiki + derived indexes ayrımı Karpathy ile karşılaştırmak için çok iyi.

İkisini araştırırsak aynı şeyi iki kere okumuyor oluruz.

# Araştırma doyumunu nasıl anlayabiliriz?

Bence burada çok iyi bir durma kriteri oluşuyor.

Yeni bir memory study ancak aşağıdakilerden en az birinde mevcut corpusu maddi olarak değiştiriyorsa yüksek marjinal değer taşır:

1. **Yeni bir information object / state ayrımı** getiriyor.
2. **Create/read/revise lifecycle'ında daha önce görmediğimiz bir failure mode** gösteriyor.
3. **Discoverability → retrieval → exposure → use zincirinde yeni bir mechanism** getiriyor.
4. **Provenance/freshness/authority/time/dependency/retention gibi bir obligation'ı farklı biçimde çözmek zorunda bırakıyor.**
5. **Mevcut yaklaşımımızı falsify eden architecture** gösteriyor.
6. **Gerçek executable evidence / benchmark / failure experiment** getirerek yalnız kavramsal bilgiyi daha güçlü hale getiriyor.

Yeni üç çalışma arka arkaya bunlardan hiçbirini yapmıyorsa ve yalnız:

> “biz de vector search yapıyoruz”,  
> “bizde de episodic memory var”,  
> “biz de summary çıkarıyoruz”

varyasyonları geliyorsa, bence artık geniş memory research'ünü kesebiliriz.

Bu, **“literatürde başka hiçbir şey yok”** demek olmaz.

Ama:

> **Yeni bilginin beklenen karar değeri, araştırma maliyetinin altına düştü.**

demek olur.

# Şu anda doyumun neresindeyiz?

Bunu ölçüm değil, araştırma-öncelik heuristiği olarak söylersem:

**Foundation + Karpathy:** güçlü kavramsal zemin.

**+ mevcut completed/partial studies:** bence memory problem alanının büyük kısmını artık **isimlendirebiliyor ve sorgulayabiliyoruz**.

Ama henüz implementation-space konusunda doygun değiliz.

Ben şu anda bizi:

> **kavramsal olarak geç evre, mekanizma/implementation karşılaştırması açısından orta-geç evre**

görürüm.

Önceki `Karpathy = 100` ölçeğimizi sırf sezgisel devam ettirirsem:

```text id="l0fpdj"
Karpathy                         100
+ Foundation                    ~180
+ mevcut güçlü studies          ~240–270
+ OpenViking + ai-memory        belki ~280–320
+ context-mode                  belki ~300–330
+ benzer 5–10 memory repo       muhtemelen 330 → 340 → 345...
```

**Bu bilimsel skor değil.** Burada göstermek istediğim eğri.

En önemli nokta:

> Artık her araştırmanın +50 getirmesini beklemiyorum.

Foundation ilk büyük sıçramaydı.

gstack/ECC/Hermes gibi somut sistemler ikinci büyük sıçramayı sağladı.

**OpenViking ve ai-memory'de hâlâ +20/+30 sınıfı bilgi kazancı ihtimali görüyorum.**

Onlardan sonra muhtemelen +5/+10 seviyesine inmeye başlayacağız.

## Dolayısıyla şu aşamadaki araştırma yönüm

Ben olsam **genel memory araştırması açmazdım**.

Çok daha kontrollü giderdim:

**OpenViking → ai-memory → yeniden değerlendirme.**

Bu ikisinden sonra Foundation + Karpathy + mevcut studies ile karşılaştırıp:

> “Yeni hangi ayrımlar/mekanizmalar geldi?”

diye bakardım.

Eğer ikisi de ciddi yeni şeyler getirirse `context-mode`a geçeriz.

Eğer ikinci study'de bile büyük ölçüde tekrar görmeye başlarsak, memory'de geniş araştırmayı kapatıp ileride **somut mimari sorusu çıktıkça targeted research** modeline geçeriz.

Bana göre şu anda `studies/`in verdiği en önemli meta-sonuç bu:

> **Memory konusunda daha araştıracak şey var; fakat artık kaynak sayısını artırmak değil, birbirinden yapısal olarak farklı birkaç sistemi seçmek gerekiyor.**

Bu, araştırmanın olgunlaşmaya başladığının iyi bir işareti.
