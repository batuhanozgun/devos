# Finding 07 — Corrected-Ground Omission Challenge

**Status:** same-model adversarial challenge; not independent verification  
**Target under attack:** the current level-aligned hypothesis

```text
Operating World / Work Domain
Information / Representation State  -> Records as persistence branch
Work
Actors
Technical Work Environment
+ typed relations / control / transitions
```

The goal is to find a materially distinct first-order problem family that cannot be represented without forced fit or residual-bucket behavior.

---

# O1 — Goals, purposes, motives, outcomes and values

## Challenge
Perhaps `Goal/Purpose` is its own foundation rather than Work or Actor semantics.

## Mapping
- Work independently distinguishes purpose/outcome from action/task/method.
- Actors supplies preference, value judgement, intention/commitment and owner authority where these belong to a bearer/position.
- Operating World supplies the state of affairs that an outcome may seek to change or maintain.
- Information/Representation can carry goal specifications/claims without creating the underlying normative ownership.

## Result
**No new peer region forced.**

Goal/purpose is a load-bearing relation between desired state, Work and relevant Actors, not yet an independently missing substrate.

---

# O2 — Governance, policy, rules, norms and law

## Challenge
Governance may appear as a fifth/sixth peer region because it spans everything.

## Mapping
Different meanings separate naturally:
- authority/obligation/accountability → Actors;
- admissibility/acceptance/process constraints → Work;
- technical enforcement/access/isolation → Technical Work Environment;
- laws/contracts/institutional conditions as facts of the domain → Operating World where applicable;
- policy texts/decisions/evidence → Information/Representation, with persistent forms under Records;
- `applies-to`, `permits`, `requires`, `prohibits`, `authorizes`, `blocks` → relation/control fabric.

## Result
**No peer region forced.**

A generic Governance bucket would collapse distinct normative, work, technical and representational semantics.

---

# O3 — Organization, community and institution

## Challenge
Activity Theory and organizational traditions often make community/organization explicit.

## Mapping
- persistent organizations/groups and membership/roles → Actors;
- division of labour/coordination → Actors ↔ Work relations;
- institutional rules → Actors/World/Representation depending the question;
- shared facilities/infrastructure → Technical Work Environment or Operating World by support/domain role.

Actors research already separates aggregation, joint action and corporate/group agency.

## Result
**No new peer region forced.**

---

# O4 — Communication and interaction

## Challenge
Communication is ubiquitous and may seem independent.

## Mapping
A communication episode can involve:
- Actors as sender/recipient/principal;
- Work as communicative/coordination activity;
- Information/Representation as message/content;
- Technical Work Environment as channel/tool/interface;
- Operating World as real-world event/state referred to;
- typed transmission/receipt/acknowledgement/interpretation relations.

## Result
**Relational composition is more informative than a Communication peer bucket.**

---

# O5 — Strategy and planning

## Challenge
Work System Theory treats strategies as a separate contextual element.

## Mapping
- strategic purpose/options/selection → Work at higher analytical level;
- ownership/approval/value trade-offs → Actors;
- assumptions and strategic models → Information/Representation;
- market/domain constraints → Operating World.

Work research explicitly rejects one universal task atom and supports portfolio/system-level Work.

## Result
**No new peer region forced.**

---

# O6 — Products, services, outputs and customers

## Challenge
WST treats products/services and customers as important boundary elements.

## Mapping
- production/service activity and intended outcome → Work;
- customer/beneficiary/affected party → Actors;
- persistent deliverable/document/model → Information/Representation/Records;
- changed physical/social/domain state or delivered service condition → Operating World;
- enabling service/tool infrastructure → Technical Work Environment.

## Result
**No new peer region forced.**

The ambiguity of `output` is better resolved by asking what kind of thing the output actually is.

---

# O7 — Resources, money, capacity and economics

## Challenge
Scarcity/resource allocation may be its own economic ground.

## Mapping
- capacity/WIP/priority/resource allocation → Work;
- technical compute/storage/network/device resources → Technical Work Environment;
- human capability/time/authority → Actors + Work;
- money/material/inventory/market availability → Operating World;
- budgets/prices/allocations as represented facts/rules → Information/Representation.

## Result
**No universal resource peer region forced.**

`Resource` is role-relative: what is a resource for one Work can be the subject/output of another.

---

# O8 — Risk, safety, quality and assurance

## Challenge
Safety engineering gives hazards/risk/assurance large conceptual weight.

## Mapping
- hazardous/undesired possible world states → Operating World;
- risk/quality claims/models/evidence → Information/Representation;
- prevention/mitigation/verification/recovery actions → Work;
- authority/accountability/approval → Actors;
- technical safeguards/constraints → Technical Work Environment;
- `threatens`, `mitigates`, `verifies`, `satisfies`, `accepts`, `violates` → relation/control fabric.

STAMP in particular supports control relations over controller, model and controlled process rather than a standalone `Safety substance`.

## Result
**No peer region forced.**

Risk/safety is a cross-ground evaluative/control concern.

---

# O9 — Time and space

## Challenge
Every foundation is temporal/contextual; perhaps time/space need peer status.

## Mapping
Time and space qualify states, relations, Work episodes, identities, environment realizations and observations. They have no independent system purpose in this inquiry absent the things/events they qualify.

Each vertical independently found temporal semantics important.

## Result
**Treat as foundational qualifiers/dimensions, not peer problem grounds.**

---

# O10 — Learning, adaptation and evolution

## Challenge
SOUL explicitly names Evolution as a major concern.

## Mapping
Learning/evolution changes one or more grounds:
- new/changed representations/records;
- new Work policies/plans;
- changed Actor capabilities/authority;
- changed technical environment/capability;
- changed domain/world state/model;
- relation/control rules that govern permitted transitions.

## Result
**No peer ground forced; transition/control semantics are mandatory.**

Evolution is a system-level process over grounds and relations.

---

# O11 — System identity, boundary, architecture and composition

## Challenge
Perhaps `System` itself is a missing foundational category.

## Mapping
The inquiry is explicitly about grounds needed to reason about a working system. `System` is the composed analytical subject, not another peer element within itself.

Boundary is nevertheless first-order:
- which world/domain is relevant;
- which Actors participate;
- which Work belongs to the system;
- which representations are in scope;
- what technical support closure applies;
- which relations cross the selected boundary.

## Result
**System/boundary is a meta-composition concern, not a peer ground.**

---

# O12 — Nontechnical work-support environment

## Challenge
Technical Work Environment may be too technical for general-purpose SOUL. What about buildings, materials, money, organizational climate or social surroundings that enable work?

## Mapping
The challenge exposes an important boundary but does not yet force one generalized `Work Environment` bucket:
- technical devices/services/interfaces → Technical Work Environment;
- people/organizations/social support → Actors and their relations;
- material/physical resources/locations/current availability → Operating World;
- rules/permissions → Actors/World/Representation;
- Work capacity/dependency → Work.

The previous broad Environment pass demonstrated the danger of placing every surrounding condition in one residual environment category.

## Result
**Keep Technical Work Environment explicit. Do not broaden it by default into an everything-around-work bucket.**

A later synthesis may define a higher-order `support context` relation spanning technical, human and domain resources, but current evidence does not justify replacing the distinct grounds.

---

# O13 — Identity and objects/things

## Challenge
W3C PROV Entity is broader than Records; perhaps a universal `Entity/Object` ground is needed.

## Mapping
Identity questions occur differently in each ground:
- domain objects/processes → Operating World;
- information-bearing representations → Information/Records;
- bearers/organizations/systems → Actors;
- Work units/activities → Work;
- environment realizations/resources/services → Technical Work Environment.

A universal Entity ground would provide a generic representation primitive but would not replace the problem-specific identity semantics already found.

## Result
**No universal-object peer ground required at the research-decomposition level.**

A generic entity/relationship meta-model may be useful later for representation.

---

# O14 — Meaning, semantics and interpretation

## Challenge
Meaning might exceed `Information` and deserve its own ground.

## Mapping
Meaning is a relation among representation, referent/domain, context, purpose and interpreter/Actor. Records already showed interpretability depends on context and representation information.

## Result
**Keep as cross-ground representational relation, not a separate peer region.**

---

# O15 — Uncertainty, unknowns and epistemic conflict

## Challenge
Uncertainty drives action and could be a separate epistemic foundation.

## Mapping
Uncertainty is primarily a property/status of Information/Representation relative to a claim/referent, with downstream consequences for Work selection, verification and Actor decisions.

Actual world indeterminacy/variability remains in Operating World; lack of knowledge about it is not the same thing.

## Result
**Strengthens Information/Representation ground; no additional peer ground.**

# Cross-framework holdout check

## Cognitive Work Analysis
Its recurring analyses map without forced residue:
- work domain → Operating World;
- control tasks/recurring activity → Work;
- strategies → Work + Information;
- social organization/cooperation → Actors + Work relations;
- worker competencies → Actors;
- support displays/technology → Information + Technical Work Environment.

## Activity Theory
- subject/community → Actors;
- object/outcome → Operating World + Work purpose;
- activity/action/operation → Work;
- tools/signs → Technical Work Environment and Information/Representation according to role;
- rules → relation/control + Actors/World;
- division of labour → Actors ↔ Work.

## Work System Theory
- processes/activities → Work;
- participants → Actors;
- information → Information/Representation;
- technologies/infrastructure → Technical Work Environment;
- customers → Actors;
- products/services → Work output / Information / Operating World depending kind;
- environment → Operating World/contextual relations;
- strategies → Work + Actors + Information.

## FRAM
A function plus input/output/precondition/resource/control/time does not add a new peer ground:
- function → Work;
- input/output → representation/domain/work effects according to kind;
- precondition/control → typed relations/constraints;
- resources → Actor/TWE/World according to role;
- time → qualifier.

### Result
Several structurally different frameworks can be mapped to the corrected grounds without turning one ground into a residual `everything else` category.

---

# Omission-challenge verdict

No additional first-order peer problem region was exposed by this round beyond the already identified corrections:

1. add/recognize **Operating World / Work Domain / Domain Reality**;
2. lift **Information / Representation State** above Records, retaining Records as the persistent-information branch;
3. require an explicit **typed relation/control/transition fabric** without treating it as another peer ground.

This does **not** prove universal completeness. It establishes declining marginal evidence for another peer region across the problem families and holdout frameworks examined so far.

Same-model limitation remains explicit: this is adversarial self-review, not independent verification.
