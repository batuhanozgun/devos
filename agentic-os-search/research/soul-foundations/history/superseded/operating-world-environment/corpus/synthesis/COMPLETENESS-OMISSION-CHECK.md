# Environment — Completeness / Omission Check

**Status:** same-model adversarial self-review; bounded-completion support, **not independent verification**  
**Vertical revision:** `environment-foundation-2026-09-01-r1`  
**Date:** 2026-09-01

## Purpose

Challenge the emerging Environment result after the main findings were formed. The goal is not to confirm a preferred fourth-leg model, but to ask whether materially different frames or late domain probes expose a missing first-order family, dissolve the region, or force a split.

A low finding count in this check is not by itself evidence of completeness. The check is useful only insofar as its probes are different enough to expose a new distinction.

## Frames seriously tested

### A — External-world / system-boundary frame

Environment is what lies outside a selected system-of-interest and affects/interacts with it.

Result:
- partly survives;
- corrected because boundary is analytical/operational rather than intrinsic and can shift with coupling/purpose.

### B — Context / situation frame

Environment is context surrounding Actor/Work.

Result:
- rejected as a collapse;
- context is selective/relevance-bearing and sometimes interactionally constituted, while live world state can exist/change regardless of current relevance or representation.

### C — Actor capability / affordance frame

Everything Environment-like can be represented as what an Actor can do.

Result:
- rejected;
- stable Actor capability does not determine situated feasibility when external resources/interfaces/conditions vary;
- actionability is relational.

### D — Runtime / infrastructure frame

Technical execution substrate is the core Environment family.

Result:
- too narrow;
- runtime is a strong instance of operating conditions/resources/interfaces but does not exhaust physical, social, institutional or shared-world conditions.

### E — Records-only reduction

Environment is whatever the system knows/records about current context.

Result:
- rejected;
- actual state can be hidden, noisy, delayed or change without a new Record; observation/belief/persistence are separable from world state.

### F — Work-only reduction

Environment can be represented as readiness, dependencies, constraints and effects of Work.

Result:
- rejected as complete reduction;
- those are Work projections/consequences, while one external condition can exist independently and affect several Work units.

### G — Relation-only / null hypothesis

No fourth object class is needed; typed relations among existing dimensions suffice.

Result:
- **partially succeeds**: evidence does not require a fourth mutually exclusive object class or architecture module.
- **fails as full dissolution** if relations have no representation of external/world states, conditions, interfaces/resources or dynamics. If those become relation relata, the foundation problem region is represented relationally rather than removed.

### H — Boundary-shift / extended-system frame

Tools, infrastructure or other entities may become constitutive system elements rather than external surroundings.

Result:
- retained as an important correction;
- strengthens boundary-relativity and rejects intrinsic `tool = Environment` classification.

## Late omission probes

### Probe 1 — Physical/off-nominal conditions and hazards

NASA physical-environment material includes temperature, pressure, radiation, winds and other operating conditions, including degraded-operation/survival concerns.

Mapped to:
- boundary-relative world state/conditions;
- actionability/feasibility;
- external dynamics/disturbance.

New first-order family opened: **no**.

### Probe 2 — Social, market, institutional and regulatory environment

OECD/Eurostat external-environment guidance covers customers, competitors, suppliers, labour markets, legal/regulatory/economic conditions, public infrastructure, social and natural environment.

Mapped to:
- boundary-relative external states/processes;
- other Actors/systems whose state/actions contribute to operating conditions;
- constraints/opportunities whose relevance is Work/Actor relational.

New first-order family opened: **no**. Normative authority/obligation remains an Actors/relation boundary rather than an Environment-local ontology result.

### Probe 3 — Hidden/noisy/delayed state

POMDP and control evidence separates actual world/process state from observation, belief and measurement noise.

Mapped to:
- world state/dynamics;
- sensing/observation boundary;
- Records/belief separation.

New first-order family opened: **no**; it materially strengthened F4.

### Probe 4 — Non-stationary environment dynamics

Recent and established RL/control work treats transition/dynamics shifts and external disturbances as changes that can alter outcomes/policy performance.

Mapped to:
- exogenous/current environment dynamics rather than static metadata.

New first-order family opened: **no**; it strengthens the time/dynamics dimension.

### Probe 5 — Multi-agent/adversarial/shared-world cases

POSG/stochastic-game models preserve multiple explicit agents plus a shared environment state, joint actions, transitions and observations.

Mapped to:
- boundary/world state plus Actors;
- same entity can retain Actor semantics while contributing to another system's operating environment.

New first-order family opened: **no**; it rejects mutually exclusive object-class decomposition.

### Probe 6 — Scarce/shared resources and infrastructure

Work research, runtime systems and external-environment sources all expose resource availability/capacity as potentially shared, changeable and not item-local.

Mapped to:
- operating-world state/resource relation;
- Work flow/capacity boundary;
- allocation/authority deferred.

New first-order family opened: **no**.

### Probe 7 — Tools as internal/external/constitutive elements

Infrastructure/extended-system frames challenge stable classification.

Mapped to:
- boundary selection;
- relation-dependent roles over concrete entities;
- operating-world access/conditions when external.

New first-order family opened: **no**.

### Probe 8 — Current research / software execution environment

ChatGPT Project, GitHub connection, tool availability, permissions and runtime constraints provide a practical but non-probative example: the same research Work/Actor intent can become feasible/infeasible when capabilities or external service state changes.

Mapped to:
- boundary-relative operating conditions/interfaces;
- actionability relation.

New first-order family opened: **no**. This is an operational example, not independent evidence of generality.

## Saturation judgment

Later probes increasingly map to the same small set of distinctions rather than opening new first-order families:

1. selected system-of-interest / boundary;
2. current external/world states, conditions and processes;
3. environment dynamics / exogenous change;
4. interfaces/resources through which interaction is possible;
5. observation/sensing versus actual state;
6. Actor/Work-relative actionability/relevance;
7. boundary-dependent roles for tools/infrastructure/external systems.

These are analytical distinctions, not proposed fields or components.

## Strongest falsification result

The initial fourth-leg hypothesis was **materially revised**.

The research does **not** support:

> `Records | Work | Actors | Environment` as four mutually exclusive object categories.

It also does **not** support complete dissolution:

> `Environment contributes no independent foundation problem once Records, Work and Actors exist.`

The stronger bounded result is:

> **A boundary-relative operating-world problem remains first-order: external/current state and dynamics can vary independently of the controlled system's current Records/Work/Actor facts, affect feasible actions and outcomes, be only partially observable, and interact through interfaces/resources. How that region is represented architecturally remains open.**

## What remains uncertain

Remaining uncertainty is mainly:
- representation/granularity thresholds;
- boundary governance;
- domain-specific state/process vocabularies;
- resource semantics;
- environment-model uncertainty/freshness;
- cross-level recurrence strength;
- cross-vertical relation/control ownership.

These do not currently justify continuing independent Environment expansion absent a new falsifier.

## Verification status

This completeness/omission pass is:
- same-model adversarial self-review;
- informed by materially different external traditions/domains;
- source-recoverable for load-bearing claims;
- **not an independent verifier, holdout, or proof of completeness**.

The strongest confidence justified is **bounded sufficiency for user evaluation**, not universal completeness.

## Stop rationale

Continuing broad source accumulation now has declining information value: new probes have predominantly mapped to established distinctions, while unresolved questions increasingly require Records/Work/Actors/relation composition rather than more isolated Environment research.

Therefore the independent Environment pass can stop at a bounded result and return to the user for evaluation.

## Reopen condition

Reopen Environment substantive research on:
- explicit user direction;
- a material later falsifier;
- or an authorised later synthesis exposing a decision-critical Environment distinction the current corpus cannot support.
