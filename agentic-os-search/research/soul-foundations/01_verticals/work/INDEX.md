## Role

Progressive retrieval router for the independent Work foundations vertical. It is not evidence and does not define a SOUL ontology.

## Status/currentness first

- `STATE.md` — current vertical status, scope, bounded-completion judgment and reopen condition.
- `CURRENT-REVISION.md` — exact blob binding for preferred current reading surfaces.
- `DOCUMENT-STATUS.md` — role/currentness classification when a file is found directly.
- `README.md` — stable human-oriented overview.

These are not substantive evidence layers.

## Content-depth route

### L0 — Key
`KEY.md`

Shortest bounded orientation. Use when a later task only needs the current meaning of the Work research and its major cautions.

### L1 — Findings map
`FINDINGS-MAP.md`

Choose the specific Work problem area and deeper route without reading the whole vertical.

### L2 — Integrated vertical synthesis
`synthesis/WORK-VERTICAL-SYNTHESIS.md`

Use when several Work dimensions interact, when the integrated current result matters, or when evaluating what the vertical established as a whole.

### L3 — Current topic findings
Use the relevant file under `findings/`:

- `WORK-FRAMES-AND-UNITS.md`
- `INTAKE-SELECTION-COMMITMENT-AND-PRIORITY.md`
- `COORDINATION-FLOW-AND-SITUATEDNESS.md`
- `CONTROL-STATE-CLOSURE-AND-RECOVERY.md`

These are current topic-detail surfaces. The L2 synthesis controls integrated/current interpretation if wording from an earlier finding conflicts with the consolidated result.

### L4A — Adversarial / completeness audit
Use when asking `why did Work stop expanding, what omission probes were run, and what could reopen it?`:

- `synthesis/COMPLETENESS-OMISSION-CHECK.md`

L4A is same-model adversarial self-review, **not independent verification**.

### L4B — Evidence trace
Use when asking `where did this Work claim come from and what source view was actually inspected?`:

- `evidence/SOURCE-LEDGER.md`

The ledger is a derived retrieval aid, not a primary source.

### L5 — Primary source
Read the exact standard/specification/paper/guidance named by the source ledger when a claim is load-bearing, contested, exact terminology matters, or source scope could change the decision.

## Layer rule

Higher layers are intentionally lossy. Descend when:

- an omitted caveat could change the decision;
- the question targets one Work dimension rather than the whole vertical;
- a claim is load-bearing or contested;
- two views appear inconsistent;
- exact terminology/source scope matters;
- a falsifier/counterexample or the bounded-completion judgment must be checked.

Do not descend merely to maximize file/source count when the bounded question is already safely answered.

## Cross-foundation retrieval rule

For a later explicitly authorised cross-foundation question:

1. begin with `DEFERRED-RELATIONS.md` if the question is explicitly relational;
2. recover only the Work-local distinction needed from L0–L3;
3. descend to L4B/L5 only when the Work claim itself is decision-critical;
4. independently recover the other vertical's current evidence rather than treating the Work-side relation note as cross-foundation truth.

## Direct-search rule

Search rank does not establish currentness. If retrieval lands on an unfamiliar Work file, inspect its role/status header or `DOCUMENT-STATUS.md` before using it.

## Currentness rule

`STATE.md` and the L2 synthesis carry the current overall Work conclusion. L3 findings carry current topic detail. `orientation/RESEARCH-ORIENTATION.md` is historical framing; L4A is adversarial self-review; L4B is evidence trace.

Exact current-surface binding is maintained in `CURRENT-REVISION.md`.
