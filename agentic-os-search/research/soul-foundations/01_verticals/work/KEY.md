# Work — KEY

**Document role:** CURRENT_L0

**Status:** intentionally lossy orientation surface; not evidence.

## What this vertical studied

The provisional problem area around how possible pursuits toward purposes or outcomes become selected or rejected, structured, committed, enacted, coordinated, monitored/evaluated, adapted, concluded or recovered over time under dependencies, constraints and scarce capacity.

`Work` remains a research label, not an accepted SOUL primitive.

## Main result

`Work = task/work item + scalar lifecycle` is too narrow as a foundation account.

Depending on the question, later reasoning may need to keep distinct:

- purpose/outcome, action/task and method/refinement;
- task/item, network/process/case, durable activity and system flow;
- candidate/eligible work, commitment/admission and actual execution;
- planned/prescribed work and actual situated/adaptive work;
- imperative, constraint-based and event/situation-driven control;
- dependencies, coordination, concurrency, capacity and flow;
- applicability/requiredness/readiness/execution/suspension/failure/closure;
- effort/work quantity, processing duration, waiting and elapsed time;
- execution completion, verification, validation and acceptance;
- termination, rollback/compensation, repair/retry and failure-generated work;
- bounded work and continuing/recurring/supporting work.

These are preserved analytical distinctions, not a proposed field list or ontology.

## Shortcuts rejected as universal rules

- `work = task`;
- every request is committed work;
- backlog = WIP;
- one fixed workflow is the neutral default;
- deviation from plan = failure;
- priority is an intrinsic timeless number;
- readiness/blockage/progress are always item-local;
- `todo → doing → done` is a sufficient state model;
- effort = duration = elapsed time;
- child completion proves parent outcome;
- execution complete = verified/validated/accepted;
- failure/cancellation simply closes or erases work;
- all meaningful work has one terminal completion event.

## Strongest working principle

> Treat Work as a plural, relational and temporally evolving problem space. Choose the analytical projection needed by the question instead of assuming one universal task atom, lifecycle or control grammar.
