## S1 — ISO 6385:2016 terminology (secondary accessible rendering)

Source:
- ISO 6385:2016, *Ergonomics principles in the design of work systems*.
- Accessible rendering used in orientation: https://standards.iteh.ai/catalog/standards/iso/def32553-89c1-498d-8433-bff4ecbc7839/iso-6385-2016

Orientation use:
- `work system` distinguishes worker(s), work equipment, workspace, work environment and task conditions;
- `work environment` is defined broadly through physical, chemical, biological, organizational, social and cultural factors surrounding a worker;
- `workspace` is separately defined.

Caveat:
- accessible rendering is not the canonical ISO publication surface; exact wording should be recovered from ISO when a later decision depends on precision.

## S2 — NIST Platform glossary

Source:
- NIST Computer Security Resource Center glossary, `Platform`.
- https://csrc.nist.gov/glossary/term/Platform

Orientation use:
- platform = hardware/device and/or associated OS or virtual environment on which software can be installed/run;
- supports distinguishing substrate/platform semantics from a broader work-support environment.

## S3 — NIST Sandbox glossary

Source:
- NIST CSRC glossary, `Sandbox`.
- https://csrc.nist.gov/glossary/term/sandbox

Orientation use:
- a sandbox is a restricted/controlled execution environment with limited resource access and permissions;
- useful for isolation, capability/restriction and environment-boundary leads.

## S4 — FDA reproduction of IEEE software terminology

Source:
- U.S. FDA, *Glossary of Computer System Software Development Terminology (8/95)*.
- https://www.fda.gov/inspections-compliance-enforcement-and-criminal-investigations/inspection-guides/glossary-computer-system-software-development-terminology-895

Orientation use:
- reproduces an IEEE definition of `software engineering environment` as hardware, software and firmware used to perform a software engineering effort, with examples such as compilers, OSes, debuggers, simulators, test/documentation tools and DBMSs.

Caveat:
- old terminology; useful historically and conceptually, not assumed current comprehensive software-engineering doctrine.

## S5 — CMU SEI Software Development Environment integration report

Source:
- Brown, Feiler & Wallnau, *Understanding Integration in a Software Development Environment*, CMU/SEI-91-TR-031 (1992).
- https://www.sei.cmu.edu/library/understanding-integration-in-a-software-development-environment/

Orientation use:
- SDE treated as a unifying framework of services supporting development and maintenance;
- integration appears at mechanism/interoperability, end-user service/tool-paradigm and process/working-practice levels.

Caveat:
- historical SDE literature; later passes should test which distinctions remain general and current.

## S6 — Development environment as code research

Source:
- *Using development environment as code for enhancing developer experience: An action design research study* (Information and Software Technology, 2026).
- Search/abstract surface: https://www.sciencedirect.com/science/article/abs/pii/S0164121226000373

Orientation use:
- reports a contemporary development-environment framing spanning local tools and remote servers;
- names version control, issue trackers, CI servers, artifact repositories and collaboration servers among environment/infrastructure components;
- raises reproducibility/consistency and transition-friction questions.

Caveat:
- software-development-specific; cannot establish a domain-general Work Environment definition.

## S7 — IEEE Technology Navigator runtime environment

Source:
- IEEE Technology Navigator, `Runtime environment`.
- https://technav.ieee.org/topic/runtime-environment/

Orientation use:
- runtime environment as software layer/services/resources needed for program execution;
- supports treating runtime/execution environment as a narrower rival frame.

Caveat:
- technology navigator summary is a derived surface; use primary IEEE standards if exact formal terminology becomes load-bearing.

## S8 — Digital workplace integrative review

Source:
- Marsh et al./review surface: *The digital workplace and its dark side: An integrative review*, Computers in Human Behavior (2022), DOI surface https://doi.org/10.1016/j.chb.2021.107118

Orientation use:
- digital workplace can mean a broad connected technology set but stronger literature extends it to technologies + practices + human-technology configurations and organizational/cultural elements;
- useful rival because it is broader than a tool bundle but may exceed the intended technical phenomenon.

## S9 — Technological work environment measurement study

Source:
- *Technological work environment: instrument development and measurement*, Behaviour & Information Technology 42(1), DOI: 10.1080/0144929X.2021.2013536
- https://www.tandfonline.com/doi/abs/10.1080/0144929X.2021.2013536

Orientation use:
- explicitly distinguishes physical, psychosocial and technological work-environment dimensions;
- operationalizes technological environment through connectivity/network and availability of appropriate devices/software.

Caveat:
- employee-perception/measurement focus may omit deeper environment identity, state, integration and execution semantics.

## S10 — CSCW shared workspace characterization

Source:
- *A unified characterisation for shared multimedia CSCW workspace designs*, Information and Software Technology 41(1), 1999.
- https://www.sciencedirect.com/science/article/abs/pii/S0950584998000792

Orientation use:
- shared workspace framed as a shared, dynamically updated multimedia channel with input/control centres;

## S11 — Digital/physical/social work environment study

Source:
- *The relationship of physical, digital and social work environment changes with the development of organizational performance in the activity-based work environment*, Facilities (2021/2022), DOI 10.1108/F-07-2021-0061.
- https://www.sciencedirect.com/org/science/article/pii/S0263277222000022
