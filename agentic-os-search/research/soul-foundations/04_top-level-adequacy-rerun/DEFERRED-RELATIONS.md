# Top-Level Adequacy Rerun — Deferred Relation / Composition Pressures

**Status:** post-rerun relation ledger  
**Date:** 2026-09-05  
**Role:** preserve next-phase pressure; NOT an authorized relation taxonomy or execution queue

## Current rule

The adequacy rerun retains four top-level grounds and finds that systematic typed relation/control/transition composition is the next major unresolved Foundation problem if separately authorized.

The relation families below are **orientation candidates only**.

Do not infer that:

- each bullet is a final relation type;
- pairwise relations are sufficient;
- every relation belongs to exactly one pair;
- this file authorizes relation/control research;
- relation names imply ontology or architecture decisions.

## 1. Environment ↔ Information

Pressure includes:

- referent / representation;
- observes / measures / senses;
- measurement/observation formation;
- as-of / freshness / temporal reference;
- model / forecast / estimate versus realized state;
- evidence of past/current Environment state;
- uncertainty/conflict versus actual condition;
- source eligibility and acquisition paths.

Protected rule:

```text
actual Environment state != representation about it
```

## 2. Environment ↔ Work

Pressure includes:

- Work targets Environment condition;
- Work attempts/causes/changes Environment dynamics/state;
- Work depends on realized Work Conditions;
- Environment condition enables/blocks/degrades Work;
- support provisioning/repair Work;
- one Work stream produces another Work's Environment condition;
- actual outcome versus Work completion.

Protected rule:

```text
Work completion != realized Environment outcome
```

## 3. Environment ↔ Actors

Pressure includes:

- Actor capability/competence versus actual affordance/access;
- location/situation/boundary-relative participation;
- credential/tool/network/resource access;
- situated actionability;
- technical effect reach;
- institutional/physical constraints;
- Actor-created conditions that remain Environment reality.

Protected rules:

```text
Actor capability != Environment actionability
technical effect power != legitimate authority
```

## 4. Information ↔ Work

Pressure includes:

- Work definition/specification/plan;
- Work status/evidence/trace;
- Work consumes/produces/transforms/selects Information;
- context formation relative to Work;
- handoff/continuity state;
- exact-target/version binding;
- verification/validation evidence;
- persistent Work history/Records.

Protected rule:

```text
representation of Work state != actual Work state
```

## 5. Information ↔ Actors

Pressure includes:

- identity/role/authority/delegation representations;
- source / holder / asserter / transmitter / principal;
- expertise/certification/mandate versus source reliability;
- belief/shared/system-level informational states;
- action/decision/accountability evidence;
- authority over a statement versus factual truth;
- representation of Actor standing versus actual standing.

Protected rule:

```text
representation says Actor standing = X
!= actual Actor standing = X
```

## 6. Work ↔ Actors

Pressure includes:

- participant / performer;
- requester / initiator;
- assignment;
- decision / authorization;
- obligation / commitment;
- delegation / reassignment;
- verifier / reviewer / integrator;
- authority to accept;
- accountability / ownership / stewardship;
- continuing responsibility versus continuing Work.

Protected rules:

```text
Work admission != Actor obligation / authorization
Work acceptance state != authority to accept
```

## 7. Goal / outcome / criteria composition

Likely multi-anchor structure:

- sought/desired condition → direction relation from Work;
- actual realized target condition → Environment;
- specification/criteria/evidence → Information;
- preference/value/mandate/acceptance authority → Actors.

Open question:

> What exact typed structure preserves intended outcome, criterion, actual attainment, evidence and authorized judgment without inventing a fifth Goal ground?

## 8. Verification / validation / acceptance composition

Likely anchors:

```text
verification/validation activity   → Work
evidence/result/claim              → Information
actual target condition            → Environment where applicable
verifier/accepter/authority/forum  → Actors
```

Required non-collapse:

```text
execution complete
!= verified
!= valid / fit for intended use
!= authorized acceptance
```

## 9. Capability / actionability / effective power

Likely ingredients:

- Actor intrinsic/standing capability/competence;
- Actor permission/authority;
- Environment resource/interface/network/tool availability;
- Work method/path/requirement;
- Information about credentials/policy/current state;
- reachable actor/tool/channel topology.

Open derived standings may include:

- technically possible;
- currently actionable;
- institutionally authorized;
- safely permitted;
- reachable indirect effect power.

Critical rule:

```text
reachable effect power != legitimate authority
```

## 10. Dependency / coordination / support composition

Pressure includes:

- Work dependency/order/concurrency;
- Environment capacity/resource contention/common-mode conditions;
- Actor assignment/authority/handoff;
- Information shared-state/provenance/versioning;
- merge/integration and conflict handling.

Do not import a fixed sequential/parallel/hierarchical taxonomy as Foundation truth.

## 11. Provenance / attribution / responsibility / accountability

Possible layers:

- Information provenance/source/derivation;
- Work performer/contribution;
- Actor causal/institutional/legal attribution;
- Environment actual effect/causal trajectory;
- responsibility/obligation/accountability relation to standards/forums.

Required non-collapse:

```text
causal contribution
!= provenance attribution
!= institutional/legal attribution
!= responsibility
!= accountability
```

## 12. Target / effect / causation

Pressure includes:

- Work intended effect;
- actual Environment dynamics/outcome;
- Information evidence/model/counterfactual;
- Actor attribution/responsibility;
- causal sufficiency and uncertainty.

Do not infer causation merely from Work occurrence followed by Environment change.

## 13. Access / enforcement / governance

Pressure includes:

- Actor authority/permission/obligation;
- Information policy/configuration/credential representation;
- Environment runtime/sandbox/network/tool enforcement;
- Work approval/gate/review paths;
- actual allowed/blocked/effective transition.

Important distinction:

```text
policy text != authority != enforcement != observed compliance
```

## 14. Feedback / learning / evolution

Candidate recurrent pattern:

```text
Environment event / outcome / failure
→ Information observation / evidence / incident record
→ Work diagnosis / adaptation / new pursuit
→ Actor decision / authority
→ changed Environment / Information / Work / Actor standing
```

Persistent learning may become Records; repeated failures may later become deterministic controls.

This is a multi-ground transition/composition pattern, not a fifth Evolution ground under current evidence.

## 15. Risk / value / priority

Pressure includes:

- Actor/stakeholder values, preferences, tolerances and authority;
- Information estimates, uncertainty and evidence;
- Environment consequences and constraints;
- Work candidates, priority and opportunity cost;
- capacity/resources.

Do not model risk/value/priority as one timeless intrinsic scalar on Work or Actors by default.

## 16. Time / continuity

Time qualifies all four grounds differently:

- Environment state/dynamics/path dependence;
- Information freshness/version/persistence;
- Work lifecycle/recurrence/continuation;
- Actor identity/role/delegation/authority continuity.

Later composition must support cross-ground temporal binding without introducing a generic Time ground merely to hold timestamps.

## 17. Suggested future research-design question

If/when the user authorizes relation/control work, the first task should likely be **research-program design**, not immediate enumeration of relation types.

That design should decide:

- relation discovery method;
- pairwise vs multi-ground research order;
- derived standing versus primitive relation criteria;
- control/transition versus descriptive relation boundary;
- how to falsify a candidate relation family;
- how to avoid importing architecture/ontology choices;
- how to reuse these deferred ledgers without treating them as accepted taxonomy.

## Guardrail

This ledger records the frontier exposed by the adequacy rerun. It does not activate that frontier.
