# Relation / Control / Composition — Parent Research Plan

**Status:** active parent-pass plan  
**Date:** 2026-09-05

## Objective

Research the cross-ground composition fabric implied by the accepted Foundation frame:

```text
Environment / Operating Reality
Information / Representation
Work
Actors / Agency–Participation–Authority
```

The aim is **not** to produce an ontology relation list. The aim is to discover the strongest current Foundation-level problem decomposition for how these grounds bind, qualify, govern and change one another.

## Core methodological constraints

### 1. Ground semantics remain controlling

A composition finding may connect grounds but must not redefine a ground merely for convenience.

### 2. Relation name != semantic kind

Words such as `supports`, `controls`, `authorizes`, `causes`, `verifies`, `accepts`, `depends on`, `represents` or `uses` may hide very different structures.

Each candidate must be tested for:
- endpoints/anchors;
- reference frame and scope;
- time/currentness;
- directionality and cardinality;
- descriptive vs normative vs causal vs evidential meaning;
- whether it is primitive or derived;
- whether a transition/event is required;
- whether authority/control is represented or actually realized;
- whether it is Foundation semantic or implementation mechanism.

### 3. Pairwise probes are necessary but insufficient

Use all six ground pairs to expose boundary semantics, but do not assume every meaningful relation can be owned by one pair.

### 4. Multi-ground composites are explicit research objects

At minimum attack:
- goal / outcome / criteria;
- verification / validation / acceptance;
- capability / access / actionability / effective power;
- governance / policy / authority / enforcement;
- provenance / attribution / responsibility / accountability;
- target / effect / causation;
- dependency / coordination / support;
- feedback / learning / evolution;
- risk / value / priority;
- temporal continuity / freshness / standing changes.

### 5. No architecture leakage

Do not infer:
- graph database schema;
- entity/relation tables;
- runtime services;
- policy engines;
- orchestration architecture;
- workflow engine design;
- component boundaries.

These may later implement Foundation semantics but cannot define them here.

## C0 — Canonical / evidence recovery

Recover exact accepted inputs:
- post-deepening adequacy rerun and its relation ledger;
- Environment/Information/Work/Actors current manifests and deferred relation/open-question surfaces;
- original adequacy relation/control evidence when needed;
- candidate-study catalog and only selected META surfaces.

Output:
- exact evidence inventory;
- stale/currentness issues;
- initial candidate composition families;
- explicit falsifiers.

## C1 — Composition-object / semantic-kind discrimination

Ask what fundamentally different research objects are being mixed under `relations / control / transitions`.

Candidate discriminators to attack:
- descriptive/binding relation;
- participation/role relation;
- derived standing/qualification;
- control/constraint/authorization;
- transition/effect/feedback;
- evidence/provenance relation;
- causal relation;
- mechanism/implementation.

Do not promote these candidates merely because they sound neat.

## C2 — Six pairwise probes

### Environment ↔ Information
Observation, measurement, referent/representation, freshness, evidence of condition.

### Environment ↔ Work
Target, effect, support/readiness, outcome, dependency on realized conditions.

### Environment ↔ Actors
Capability vs affordance/access, situated actionability, effect reach, physical/institutional constraints.

### Information ↔ Work
Definition/plan/status/evidence, consumes/produces/transforms/selects, exact-target binding, handoff/continuity.

### Information ↔ Actors
Source/holder/asserter, identity/authority/delegation representation, expertise/source reliability, attribution evidence.

### Work ↔ Actors
Participation, assignment, decision, authorization, obligation, delegation, verification/review, acceptance authority, accountability.

For each pair identify:
- stable protected distinctions;
- candidate relation families;
- cases where the pair cannot explain the semantic result without another ground.

## C3 — Multi-ground composite-pattern discovery

Use canonical hard cases rather than enumerating all combinations.

Required cases:
1. **Goal/outcome/criteria** — sought condition, specification, realized condition, preference/authority.
2. **Verification/validation/acceptance** — activity, evidence, exact target, actual condition/use, verifier/accepter authority.
3. **Actionability/effective power** — capability, permission/authority, environment access, work path, policy/enforcement, reachable topology.
4. **Governance/control** — policy representation, normative standing, control work, technical enforcement, observed compliance.
5. **Provenance/attribution/accountability** — information lineage, work contribution, actual effect, actor attribution, forum/standard.
6. **Feedback/evolution** — outcome/event → observation/evidence → diagnosis/new Work → authorized change → new state.

Optional only when materially distinct:
- risk/value/priority;
- dependency/coordination/support;
- temporal continuity;
- causation/counterfactual effect.

## C4 — Rival organizing frames / candidate immediate regions

Attempt serious alternatives, including:
- pairwise-relation matrix as the whole answer;
- graph of typed relations only;
- state + relation + transition;
- descriptive relations vs normative controls;
- binding / qualification / control / transition;
- provenance / authority / dependency / causation families;
- control-loop-centered frame;
- commitment/goal-centered frame.

Compare on:
- semantic loss;
- false disjointness;
- multi-ground coverage;
- domain stability;
- ability to preserve ground boundaries;
- architecture neutrality;
- whether it creates residual buckets.

## C5 — Selective external / candidate-study holdouts

Use materially different traditions only to challenge live hypotheses.

Likely authoritative/strong holdouts:
- W3C PROV — entity/activity/agent relations, generation/use/association/delegation/derivation;
- NIST ABAC — subject/object/operation/environment/policy composition for authorization;
- NASA systems engineering — verification vs validation, requirements/stakeholder expectation/intended environment composition;
- metrology/VIM — measurand, measurement procedure/result, uncertainty and referent/result separation;
- systems/control or governance sources when a live control hypothesis requires them.

Candidate studies:
- Anthropic AI-native SDLC for layered control, transitive authority and feedback/evolution;
- multi-agent patterns for delegation/coordination/verification topology;
- context-memory-harness when context/persistence/runtime-control boundaries are load-bearing.

Holdouts may falsify/pressure the parent model; they do not define its taxonomy.

## C6 — Parent synthesis / immediate-child discovery

Determine:
- whether a coherent parent-level composition object exists;
- what stable immediate research regions, if any, deserve separate child passes;
- which pressures are merely dimensions or cross-cutting relations;
- which cases remain deferred to architecture or domain-specific work.

A child is promoted only if it has a protected question and distinct failure modes that cannot be handled as an internal dimension of another child.

## C7 — Adversarial closure

Attack the proposed parent result by trying to show:
- relation/control composition is too broad/residual;
- relation types are already fully owned by individual grounds;
- one fifth ground is actually required;
- pairwise relations are sufficient and multi-ground composition is unnecessary;
- the proposed children are false partitions;
- a materially stronger rival frame exists;
- the research is smuggling architecture/ontology decisions into Foundation.

Verification status must explicitly distinguish same-model adversarial review from independent replication.

## Closure outcomes

### A — coherent parent + stable children
Return parent result and discovered immediate research regions for user evaluation. Do not auto-activate a child.

### B — coherent parent, no stable child split
Retain a bounded relational/composition problem map and return for evaluation.

### C — upstream falsifier
Reopen only the minimum affected Foundation ground/adequacy question.

### D — composition frame inadequate
Revise the research method before deeper work; do not manufacture a taxonomy.

## Stage boundary

Even a successful parent closure does not authorize SOUL/Development OS architecture, ontology/data model or implementation.
