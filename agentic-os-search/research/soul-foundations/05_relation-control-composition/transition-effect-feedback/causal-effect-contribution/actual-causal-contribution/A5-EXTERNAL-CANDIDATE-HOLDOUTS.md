## 2. NASA mishap investigation pressure

Parent E5 recovered NASA mishap practice as an actual-episode tradition centered on:
- realized mishap/close-call;
- event/condition reconstruction;
- causal factors and cause-effect relationships;
- barriers/controls;
- proximate/contributing/root-level inquiry;
- corrective action and recurrence relevance;
- the possibility that an investigation does not yield one root cause.

### Pressure on child structure

This supports:

```text
exact episode
+ multiple causal factors
+ depth relative to corrective value
```

It does not force separate children for proximate, barrier or systemic factors. Those coexist in one investigation around one explanandum.

## 3. NTSB investigation pressure

Parent E5 recovered NTSB practice as separating:
- fact gathering;
- sequence reconstruction;
- causal analysis;
- probable-cause determination;
- contributing factors.

It also permits multiple causal/contributing factors rather than one mandatory root.

### Pressure

```text
factual sequence
!= causal analysis

one accident
→ multiple actionable contributors possible
```

This supports the shared actual-episode grammar and rejects chronology reduction.

No NTSB pressure requires one child for each causal role.

## 4. FAA causal/root-cause pressure

Parent E5 recovered FAA guidance warning that fixing only a proximate cause can leave recurrence risk and that unsupported candidate causes should be eliminated.

### Pressure

- deeper causation matters when it changes corrective action;
- causal candidates must be discriminated, not merely narrated;
- proximate/systemic depth is intervention-relative.

This directly supports the R06 stop rule rather than a fixed depth hierarchy.

## 5. WHO patient-safety systems pressure

Parent E5 recovered WHO pressure that patient harm commonly involves multiple interrelated human, technological, process, organizational and external factors and should not be reduced to blame of one individual.

### Pressure

```text
human action causally contributed
!= individual blame is complete explanation
```

This supports:
- multi-factor configurations;
- systemic contributors inside the same episode analysis;
- Actors responsibility/accountability boundary.

It does not justify a separate `Systemic Causation` child because system-level factors still answer the same episode question and can interact with proximate factors.

## 6. MIT CAST/STPA systems-safety pressure

Parent E5 recovered CAST/STPA tradition as rejecting oversimplified single-root/blame framing and analyzing control/system interactions.

CAST is especially useful as retrospective accident analysis pressure.

### Pressure

- causal structure can be networked/systemic;
- unsafe interactions can matter even when individual components behave locally as designed;
- control/barrier structure can be causal to an episode without becoming identical to Control semantics;
- causal analysis is not limited to component failure chains.

This strengthens configuration/path semantics but does not create a separate child.

## 7. Multiple causation holdout

Across NASA/NTSB/WHO/MIT pressure, actual episode causation repeatedly needs:
- several contributors;
- interaction;
- barriers/control failures;
- human/system/environment conditions;
- varying depths.

No tradition requires:

```text
root_cause = exactly one
```

The child therefore must remain configuration-sensitive.

## 8. Omission/failure-to-prevent holdout

Safety/incident traditions repeatedly treat missing/failed barriers as investigation-relevant.

But their relevance is tied to system function/trajectory, not arbitrary absence.

This supports A2's guarded rule:

```text
absent barrier/control
+ relevant path/function/contrast
+ evidence it would have changed trajectory
→ may be actual causal contributor
```

while preserving:

```text
causal omission != duty/blame by identity
```

No separate omission child is forced.

## 9. Agentic-software candidate pressure — Anthropic

The bounded Anthropic AI-native SDLC study provides a concrete episode class:
- a restricted agent may lack direct production authority;
- another reachable agent/tool may provide a stronger action path;
- human review can interrupt the path;
- model/provider changes can expose previously unseen authority paths;
- observability can record activity without proving correctness or causal completeness.

### Actual-causation pressure

For one such incident the questions are:

```text
Which exact actor/tool/message/action path actually produced or nearly produced the protected effect?
Which controls/barriers actually stopped or failed to stop that path?
Which environmental/authority conditions enabled it?
```

This requires exact episode/path/configuration analysis.

But:

```text
local permission weakness exists
!= it caused this exact effect

new guardrail introduced after incident
!= guardrail generally effective
```

The latter belongs to Contrastive / Interventional Causal Effect.

## 10. Candidate study also reinforces frame-blindness

The Anthropic adversarial package explicitly warns:

```text
observability present
!= assurance
```

and alternate-path analysis warns that one visible tool path may omit another materially equivalent route.

Actual-cause translation:

```text
all logged/known paths explained
!= all material causal paths observed
!= causal explanation complete
```

This strengthens A3's frame-coverage guardrail.

## 11. Does `Systemic Causation` emerge as child?

No.

External pressure shows systemic factors are essential, but:
- they are episode-bound;
- they interact with proximate factors;
- their depth changes with inquiry boundary;
- they use the same evidence/alternative/depth grammar;
- they do not answer a separate protected question.

Verdict: **systemic/framing remains profile/depth dimension.**

## 12. Does `Barrier / Control Failure Causation` emerge as child?

No.

A failed barrier is causally relevant only if it mattered to the exact path/effect.

Control semantics remains separate from actual causal contribution.

Verdict: **barrier/prevention/detection failure remains role/profile.**

## 13. Does `Human / Organizational / Technical` split emerge?

No.

These identify ground/domain anchors, not causal-problem kinds. One causal configuration can contain all three.

Verdict: **do not turn ground identity into causal children.**
