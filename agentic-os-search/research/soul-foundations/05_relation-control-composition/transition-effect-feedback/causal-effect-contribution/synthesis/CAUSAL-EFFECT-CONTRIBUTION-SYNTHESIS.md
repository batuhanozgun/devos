## 2. Why causal analysis belongs here at all

Accepted Transition / Propagation answers:

> What actually changed, where/when, and how did it propagate?

That does **not** answer:

> Why did the realized effect happen or what would changing a candidate cause do to outcomes?

Therefore:

```text
transition / propagation
!= causal explanation
```

At the same time, causal analysis depends on a defined effect/outcome/change target, so no fifth top-level composition sibling is justified.

## 3. Shared Foundation causal grammar

Across both promoted children, preserve as needed:

```text
Causal claim
├─ exact effect / outcome / explanandum
├─ candidate cause / contributor / action / exposure
├─ relevant context / scope / time
├─ causal contrast / reference semantics where material
├─ typed causal role/depth where decision-critical
├─ domain-appropriate evidence
├─ competing explanations/confounding where material
├─ calibrated confidence / unresolved alternatives
└─ stopping depth tied to intervention/recurrence/decision value
```

This grammar is deliberately less specific than one statistical/engineering causal formalism and more specific than a generic `causedBy` link.

## 4. Child A — Actual Causal Contribution / Episode Causation

Protected question:

> In this exact realized cross-ground episode/effect, which actual events, conditions, omissions, controls, actions or interactions causally contributed to what occurred?

Typical use cases:
- accident/mishap investigation;
- production incident analysis;
- safety-event reconstruction;
- component/software failure analysis;
- causal analysis of one harmful or successful episode;
- whether one control prevented/mitigated one exact effect.

Key causal roles, retained as overlapping profiles:
- proximate/direct mechanism;
- enabling/contributing condition;
- prevention failure;
- detection/containment failure;
- systemic/framing condition;
- mitigating/preventive contribution.

Strong non-collapse:

```text
chronology != actual cause
trigger != complete causal explanation
proximate cause != complete causal explanation
one cause identified != complete causal model
but-for necessity != universal causal criterion
causal contribution != responsibility/accountability
```

Multiple/joint/redundant causes must be representable.

## 5. Child B — Contrastive / Interventional Causal Effect

Protected question:

> How would outcome/effect Y differ under a defined alternative state/action/exposure/intervention X versus X', for the relevant unit/population/context?

Typical use cases:
- treatment/exposure effect;
- whether a safety/control mechanism reduces risk;
- whether a guardrail reduces failures across runs;
- whether changing process/configuration improves outcomes;
- policy/intervention effect;
- controlled or observational causal evaluation.

Strong non-collapse:

```text
association != causal effect
statistical significance != causal proof
before/after difference != intervention effectiveness
general/contrastive effect != actual cause of one episode
actual episode cause != general effect magnitude
```

Typical decision-critical concerns:
- causal contrast/baseline;
- confounding;
- selection/information bias;
- intervention realization/fidelity;
- effect heterogeneity;
- interference/spillover;
- transport/context limits.

No one method is universal.

## 6. Why the two children cannot be safely merged

The two propositions can diverge.

### General effect without actual cause

A treatment/control can reduce risk on average while not being the cause of one observed outcome.

### Actual cause without identified general effect

A factor can causally contribute to one incident without providing a valid estimate of its population-wide effect or of the benefit of eliminating it everywhere.

Therefore:

```text
What would X do to Y?
!=
Did X cause this observed Y?
```

The difference is not merely evidence quality; it is a different causal query.

## 7. Causal role/depth result

The pass rejected a child hierarchy such as:

```text
Proximate Cause
Contributing Condition
Prevention Failure
Detection Failure
Systemic Cause
```

because roles:
- overlap;
- change with exact explanandum;
- depend on boundary/scale;
- can coexist on the same contributor;
- are cut across by necessary/sufficient/probabilistic properties.

They remain a causal-depth checklist/profile set.

## 8. Depth stopping rule

The project's R06 causal-depth protocol is retained as a reusable stopping rule:

> Continue deeper while another causal layer materially changes intervention choice, recurrence risk, control design, responsibility boundary or decision outcome. Stop when additional depth no longer changes those materially.

Thus Foundation avoids both:
- stopping at a correct but shallow proximate cause;
- infinite metaphysical `why?` chains.

## 9. Causal evidence result

No universal evidence hierarchy survives.

Useful modes include:
- physical/mechanistic evidence;
- randomized intervention;
- controlled comparison/fault injection;
- natural/quasi experiment;
- observational causal inference;
- counterfactual reasoning;
- incident reconstruction/elimination;
- barrier/control analysis;
- repeated evidence across contexts;
- domain theory.

The fit between claim and method matters more than a global ranking.

Key discipline:

```text
causal relation
!= evidence for causal relation
!= evidence sufficient to conclude causal relation
!= authorized decision based on conclusion
```

## 10. Alternatives/confounding result

A plausible causal story is insufficient where serious alternatives remain.

Observational association may reflect:
- chance;
- selection bias;
- information/measurement bias;
- confounding;
- analysis error;
- or actual causal effect.

Incident chronology may also fit several mechanisms.

Therefore preserve:
- competing causal explanations;
- disconfirming evidence;
- unresolved alternatives;
- tests that would discriminate among them.

Causal confidence should track evidence's discriminating power.

## 11. Multiple causation / overdetermination

Foundation must permit:
- joint causation;
- multiple sufficient sets;
- redundant/overdetermining causes;
- enabling contributors;
- severity-amplifying contributors;
- mitigating/preventive contributors.

Naive `but for X, would E occur?` is useful but not universal because independent sufficient causes can defeat simple necessity tests.

Therefore never require:

```text
root_cause = exactly one value
```

## 12. Omission / failure-to-prevent

Absence alone is not enough for causal attribution.

A useful omission/failure-to-prevent claim generally requires causal relevance through:
- expected preventive function;
- feasible alternative;
- mechanism;
- causal contrast;
- or evidence that the missing barrier would have changed the trajectory.

Keep separate:

```text
absence causally relevant
!= Actor had duty
!= Actor is blameworthy
```

## 13. Control-effectiveness composition

Accepted Control owns:

> What governing semantics apply?

Causal Effect owns:

> Did the Control change outcome/risk?

Standing owns:

> Is evidence sufficient to qualify it as effective under criterion C?

Two profiles:

```text
Actual:
Did Control C prevent/mitigate this exact effect?

Contrastive:
Does Control C reduce incident probability/severity across its governed context?
```

Therefore Control Effectiveness does not become a third child.

## 14. Actor responsibility/accountability boundary

Actual causation may establish:

```text
Actor action A causally contributed to E
```

Actors still separately owns:
- authorization;
- obligation/duty;
- representation/delegation;
- responsibility;
- accountability/forum.

Thus:

```text
causal contribution
!= responsibility
!= accountability
```

This is critical for avoiding blame-driven causal models.
