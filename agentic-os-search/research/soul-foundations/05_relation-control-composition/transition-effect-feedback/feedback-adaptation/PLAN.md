## Objective

Bound cross-ground feedback/adaptation semantics without collapsing the child into:
- observation/telemetry;
- generic Work continuation;
- Control response;
- ground-local Domain Dynamics;
- one-off corrective action;
- recorded lessons;
- generic organizational learning;
- causal-effectiveness claims;
- or architecture/schema design.

## Passes

### F0 — Canonical/current evidence recovery
Recover accepted Transition/Causal prerequisites, parent residuals, Information/Work/Control boundaries, candidate-study pressure and authoritative feedback/learning/adaptive-control traditions. Freeze falsifiers before synthesis.

### F1 — Minimum feedback/adaptation signature
Test what must be preserved: prior outcome/observation source, returned signal/representation, target consumer/controller/decision process, relevant reference/objective where material, timing/delay/currentness, causal influence on later action/state, recurrence/loop semantics, persistent adaptation locus/state where material, evidence and uncertainty.

### F2 — Feedback-use / persistence / adaptation discrimination
Distinguish signal availability, exposure/consumption, actual influence, one-off response, repeated response under fixed rule, persistent rule/state/capability change and future-response change. Test whether `Feedback` and `Adaptation` are stable immediate children or one leaf with layers.

### F3 — Delay / staleness / stability / frame audit
Test delayed or stale signals, noisy/misleading feedback, oscillation, overshoot, positive-feedback amplification, hidden/unobserved outcomes, proxy gaming and local improvement that worsens broader system outcomes. Preserve stability/safety semantics without importing full control theory.

### F4 — Rival internal decompositions
Test candidate splits:
- Feedback Loop / Persistent Adaptation;
- Observation / Evaluation / Adaptation;
- Reactive / Adaptive / Evolutionary;
- Parameter / Policy / Structural Adaptation;
- Local / System / Organizational Learning;
- Corrective / Preventive / Learning Feedback;
- Human / Automated / Hybrid;
- Beneficial / Harmful adaptation.

Promote none without distinct protected questions, failure families, evidence requirements and cross-domain recurrence.

### F5 — Authoritative external + candidate holdouts
Use independent traditions as hostile pressure, not taxonomy authority. Candidate targets:
- WHO patient-safety incident reporting and learning systems;

### F6 — Synthesis / immediate-child decision
Decide whether Feedback/Adaptation is a bounded leaf, needs immediate children, splits differently, or forces Transition/composition/four-ground reopen.

### F7 — Adversarial closure
Attack the strongest provisional result, especially:
- observation/feedback collapse;
- response/adaptation collapse;
- feedback-loop/adaptation under-splitting;
- Work/Control/Information boundary theft;
- ground-local dynamics duplication;
- stability/oscillation under-modeling;
- causal-effectiveness leakage;
- `learning` as unearned label;
- frame blindness / proxy feedback;
- recursive self-change;
- architecture/control-theory leakage.

## Required non-collapse probes

```text
observation != feedback
feedback available != feedback consumed
feedback consumed != feedback influenced later behavior
one-off corrective response != persistent adaptation
repeated response under fixed rule != adaptation by identity
stored lesson != future behavior change
feedback loop exists != system learned
adaptation occurred != adaptation was beneficial/effective
before/after improvement != adaptation caused improvement
local objective improvement != global/system objective improvement
```

## Closure criteria

Close only when:
- ground-local dynamics boundary remains stable;
- minimum feedback/adaptation grammar survives cross-domain pressure;
- signal→consumption→influence→persistence distinctions are bounded;
- delay/staleness/stability/frame risks remain decision-visible;
- causal-effectiveness and Standing boundaries remain stable;
- rival decompositions fail or justified children survive;
- residuals are reopen triggers rather than hidden execution debt;
- no architecture/control implementation commitment is required.
