# Transition / Effect / Feedback — T0 Evidence Recovery

**Status:** COMPLETE  
**Date:** 2026-09-05

## 1. Canonical starting state

Accepted composition prerequisites:

```text
Relational Binding                  ← accepted bounded leaf
Composite Standing / Qualification ← accepted bounded leaf
Control / Constraint                ← accepted bounded leaf
Transition / Effect / Feedback      ← active child under test
```

The child is not permitted to steal ground-local dynamics.

Environment already owns accepted `Domain Dynamics`:

> what actually unfolds, persists, interacts or changes through time in materially relevant Domain Reality.

Information already owns `Informational Dynamics / Formation–Transition` for how informational states are formed, derived/changed and exposed.

Work owns pursuit/execution/coordination/recovery evolution; Actors owns participation/authority/delegation/attribution standing.

Therefore a mere statement that something changed, an event occurred, Work executed or Information transformed is insufficient to route to this child.

## 2. Protected cross-ground pressure

The unresolved cross-ground questions after Binding + Standing + Control concentrate on:

- an action/decision/control update in one ground causing or failing to cause changes in another;
- realized effect versus intended/represented/accepted outcome;
- propagation across multiple targets, agents, services, controls or representations;
- delayed/partial/failed update propagation;
- when a prior standing/control becomes stale, invalid, superseded or requires re-evaluation;
- causal attribution beyond temporal ordering;
- monitoring/observation returning into Work/Control/Environment/Actor changes;
- one-off response versus persistent adaptation/evolution.

## 3. Existing boundaries recovered

### Environment Domain Dynamics

Already preserves:

```text
actual temporal change != causal effect attribution
actual Dynamics != log/model/simulation/forecast
Domain Dynamics != focal Work lifecycle
Actor action in Dynamics != Actor identity/authority semantics
```

This is load-bearing: Transition must not become `Domain Dynamics again, but bigger`.

### Composite Standing

Already preserves:

```text
dependency changed
→ prior standing may require re-evaluation
!= standing necessarily changed

standing currentness != transition/history
```

Transition therefore owns change/propagation mechanics, not the current qualification itself.

### Control

Already preserves:

```text
control currentness != transition/change history
enforcement-point success != end-to-end control-objective success
```

Transition must explain actual propagation/effect paths without turning them into Control semantics.

## 4. External hostile pressure recovered

### W3C PROV

PROV distinguishes:
- entities and activities;
- instantaneous events such as generation, usage and invalidation;
- ordering constraints;
- influence/derivation relations.

Useful pressure:

```text
event occurrence / ordering
!= generic influence
!= one universal causal interpretation
```

### Lamport distributed-event ordering

Distributed systems may have only a partial order of events; a total timestamp order can be imposed while still being different from causal order.

Useful pressure:

```text
timestamp / total order != causal order
```

### OpenTelemetry event semantics

Event timestamp and observed timestamp are distinct: occurrence time can differ from receipt/observation time.

Useful pressure:

```text
occurrence time != observation time
```

### NASA/FAA/CDC causal analysis

NASA event-and-causal-factor analysis explicitly separates reconstructing event sequence from developing causal factors/root causes. FAA root-cause guidance emphasizes causal factors and recurrence prevention. CDC cautions that association/statistical significance/temporal sequence alone does not establish causation.

Useful pressure:

```text
sequence != sufficient causal explanation
proximate trigger != complete causal model
```

### NIST / FAA / WHO feedback-learning pressure

Continuous monitoring and incident response only become improvement loops when observations/results are analyzed and actually change risk management, controls, Work, procedures or system behavior. Reporting/monitoring alone does not establish learning.

Useful pressure:

```text
observation/report != feedback closure
feedback signal != persistent adaptation
```

## 5. Candidate-study pressure

Anthropic AI-native SDLC study:

```text
production incident
→ diagnosis
→ new intent / fix Work
→ configuration/code/control change
→ permanent eval case
```

This is useful as a software-domain feedback/evolution holdout, but it is not Foundation taxonomy authority.

Context/memory/harness research adds pressure around retries, stop conditions, runtime changes and persistence, while multi-agent research adds delegation/coordination propagation paths.

## 6. Frozen falsifier set

### F1 — Ground-local collapse
If all meaningful cases can be routed to Environment/Information/Work/Actors local dynamics plus Binding, this child fails.

### F2 — Generic history bucket
If the child only means `events over time`, it fails.

### F3 — Sequence/causation collapse
If temporal order is treated as causal explanation, the semantics fail.

### F4 — Intended/realized collapse
If planned/commanded/intended effect is treated as realized effect, the semantics fail.

### F5 — Record/event collapse
If event/log/trace record is treated as occurrence by identity, the semantics fail.

### F6 — Observation/feedback collapse
If monitoring or returned Information is sufficient for feedback, the semantics fail.

### F7 — Feedback/adaptation collapse
If one corrective response is sufficient to claim learning/evolution, the semantics fail.

### F8 — Distributed simultaneity assumption
If issued update/revocation/control change is assumed effective everywhere immediately, the semantics fail.

### F9 — Cause singularity
If every effect is forced into one root cause rather than allowing contributing/enabling/prevention/detection causes, the semantics fail.

### F10 — Residual-bucket parent failure
If `Transition / Effect / Feedback` cannot be organized by stable protected questions and merely collects what Binding/Standing/Control did not own, reopen the composition parent.
