# Transition / Effect / Feedback — T4 Rival Internal Decompositions

**Status:** COMPLETE  
**Date:** 2026-09-05

## 1. Promotion standard

An immediate child must:
- carry a stable protected question;
- expose a distinct decision-critical failure family;
- remain meaningful across materially different domains;
- avoid mainly duplicating accepted ground-local dynamics or siblings;
- not require mutually exclusive event populations.

The parent composition children are diagnostic problem regions, so overlap within one episode is allowed.

## 2. Critical boundary correction — cross-ground only

Environment `Domain Dynamics` already includes ground-local:
- realized occurrence/interaction;
- change/trajectory;
- feedback;
- temporal dependence;
- dynamic regimes.

Therefore this child must not claim all transition, causation or feedback.

Canonical routing test entering T4:

> Does the protected question require linking changes/effects/return paths across accepted Foundation grounds or their accepted composition bindings/standings/controls such that keeping the analysis within one ground would lose decision-critical semantics?

If no, route ground-local.

## 3. Rival A — one bounded leaf

```text
Transition / Effect / Feedback
    ← one shared grammar
```

### Strength
Simple and avoids hierarchy proliferation.

### Failure
T1–T3 show three questions can vary independently:
- transition known while cause unknown;
- cause investigated without any feedback loop;
- feedback loop exists while control law remains unchanged;
- adaptation claimed even though only one response occurred.

Distinct recovery actions follow:
- transition uncertainty → observe/reconstruct propagation;
- causal uncertainty → investigate mechanisms/alternatives;
- feedback failure → repair return path/consumption;
- adaptation failure → change persistent response-generating structure.

### Result
**Rejected.** One leaf obscures distinct failure families.

## 4. Rival B — direct label split `Transition / Effect / Feedback`

```text
Transition
Effect
Feedback
```

### Strength
Matches parent label.

### Failure
`Effect` is ambiguous:
- realized consequence;
- causal effect;
- control effect;
- desired outcome.

`Transition` without `Propagation` risks stealing all ground-local dynamics.

### Result
**Rejected as under-specified naming**, not as underlying three-region intuition.

## 5. Rival C — three diagnostic children

```text
Cross-Ground Transition / Propagation
Cross-Ground Causal Effect / Contribution
Cross-Ground Feedback / Adaptation
```

### Protected questions

#### Transition / Propagation
What actually changed across ground boundaries, where/when did it become effective, and how fully did it propagate?

#### Causal Effect / Contribution
Which action/event/condition/control/Work/Actor contribution caused, enabled, amplified, prevented or failed to prevent/detect a cross-ground realized effect, with what causal depth/confidence?

#### Feedback / Adaptation
Did observations/results/effects return across ground boundaries to alter later behavior/control/work/configuration, and was the change one-off or persistent?

### Failure-family separation

```text
propagation failure
!= causal-attribution failure
!= feedback-return failure
!= adaptation-persistence failure
```

### Cross-domain viability
- distributed policy rollout;
- incident response;
- safety systems;
- scientific intervention/observation;
- agentic software evolution;
- organizational learning.

### Result
**SURVIVES; strongest candidate.**

## 6. Rival D — Forward Change / Return Feedback

```text
Forward Transition / Effect
Return Feedback / Adaptation
```

### Strength
Elegant closed-loop framing.

### Failure
Causal attribution disappears inside `Forward` even though:

```text
what changed?
!= why did it change?
```

This matters for recurrence prevention, control effectiveness and accountability.

### Result
**Rejected.**

## 7. Rival E — Event / Causation / Adaptation

### Failure
`Event` excludes continuous/gradual/interval dynamics and propagation; `Adaptation` omits non-adaptive feedback loops.

### Result
**Rejected.**

## 8. Rival F — State Transition / Propagation / Feedback

### Failure
Separating state transition from propagation creates false disjointness: propagation is a chain/network of realized transitions, often the exact cross-ground object of interest.

Causation again disappears.

### Result
**Rejected.**

## 9. Rival G — Intended / Realized / Observed

### Strength
Important anti-collapse dimensions.

### Failure
They are epistemic/result dimensions, not stable protected problem regions. A single transition may instantiate all three; causal/feedback questions remain unresolved.

### Result
**Rejected as child split; retained as dimensions.**

## 10. Rival H — Local / Cross-Ground / Systemic

### Failure
The current parent is already cross-ground. `Local` belongs accepted grounds; `systemic` is scope/depth, not a separate semantic kind.

### Result
**Rejected.**

## 11. Rival I — Process / Event / Trajectory

Already tested under Environment Domain Dynamics and rejected as universal child structure due continuous/discrete/scale overlap.

Importing it here would duplicate ground-local dynamics.

### Result
**Rejected.**

## 12. Rival J — Causation as fifth composition sibling, not Transition child

### Attack
Causal Effect might be peer to Binding/Standing/Control/Transition.

### Test
Causal questions arise specifically over realized changes/effects and temporal propagation. They consume transition identity/time/result semantics and then add explanatory attribution/depth.

Moving causation to parent level would leave Transition semantically thin and create broad overlap with every sibling.

### Result
**Rejected provisionally.** Keep as Transition child unless T5/T7 expose independent parent-level scope.

## 13. Rival K — Feedback as Control, not Transition

### Attack
Feedback is how controls use outputs to change inputs; therefore Control owns it.

### Test
Control owns the governing relation/rule. Feedback asks whether observations/effects actually returned and influenced later behavior, including loops with no governing policy and learning/evolution that changes the control itself.

```text
control law exists != feedback path closed
feedback occurred != control law changed
```

### Result
**Rejected.** High interaction, distinct protected question.

## 14. Rival L — Adaptation as Work only

### Attack
Any adaptation is just new Work.

### Test
Work owns the adaptation activity. The Transition child asks whether the activity actually changed persistent system response/configuration/control/capability and whether later episodes behave differently.

```text
adaptation Work completed != system adapted
```

### Result
**Rejected.**

## 15. Candidate child labels after T4

Strongest wording:

```text
Transition / Effect / Feedback
├─ Cross-Ground Transition / Propagation
├─ Cross-Ground Causal Effect / Contribution
└─ Cross-Ground Feedback / Adaptation
```

The `Cross-Ground` qualifier is load-bearing routing guidance, not merely stylistic.

## 16. Promotion status

All three candidates now clear internal protected-question/failure-family tests provisionally.

T5 must challenge them with independent external traditions and candidate studies before promotion.
