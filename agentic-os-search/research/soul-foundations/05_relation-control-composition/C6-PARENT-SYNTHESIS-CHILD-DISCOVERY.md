## 1. Executive synthesis

The parent composition problem is coherent and distinct from the four accepted grounds.

It does not add a fifth semantic ground. It studies how accepted-ground anchors are bound, jointly qualified, governed and changed.

The strongest current parent formulation is:

> **Cross-Ground Composition concerns the typed semantic fabric by which Environment, Information, Work and Actors are connected, jointly acquire criterion-relative standings, constrain/authorize possible transitions, and produce/propagate effects over time without collapsing local ground semantics.**

This is a Foundation research formulation, not an ontology or architecture component.

## 2. Immediate research regions discovered

C1–C5 support four stable immediate problem regions.

### Child 1 — Relational Binding

Protected question:

> Which accepted-ground anchors are connected, in what typed role, direction, scope, reference frame and time, and what semantic difference would be lost by replacing that relation with a generic link?

Examples:
- representation ↔ referent;
- Actor ↔ Work participation/authorization/delegation;
- Work ↔ Environment target/support/dependency;
- Information ↔ Work specification/evidence/context;
- source/holder/asserter relations;
- provenance/dependency/participation specializations.

Distinct failure family:
- wrong endpoint/role/direction;
- scope/time/reference loss;
- relation inferred from co-occurrence;
- generic `related-to` or `influence` hiding load-bearing semantics;
- represented relation mistaken for actual standing.

Current status:

**PROMOTE AS IMMEDIATE RESEARCH REGION, pending parent user evaluation.**

---

### Child 2 — Composite Standing / Qualification

Protected question:

> What criterion-, target-, use-, authority- or time-relative standing holds only when several accepted-ground facts/relations are jointly evaluated, and what anchors make that standing valid/current?

Examples:
- actionable now;
- authorized for a particular operation/context;
- verified against requirement/target/version;
- validated / fit for intended use;
- accepted by authorized party;
- goal/outcome attained;
- evidence sufficient for decision;
- compliant/current/relevant/ready under explicit criteria.

Distinct failure family:
- composite standing localized as an intrinsic one-ground attribute;
- omitted criterion/use/reference;
- stale target/evidence;
- missing authority;
- represented status mistaken for actual standing;
- one prerequisite silently treated as sufficient.

Current status:

**PROMOTE AS IMMEDIATE RESEARCH REGION, pending parent user evaluation.**

### Child 3 — Control / Constraint

Protected question:

> What normative, institutional, procedural or realized technical structures make a transition/action permitted, required, blocked, gated, escalated or conditioned, and how are authority, decision, policy representation, enforcement and compliance kept distinct?

Examples:
- authorization/permission/obligation;
- policy/rule/gate;
- separation of duty;
- human approval/escalation;
- technical enforcement/sandbox/network/tool constraints;
- required verification before transition;
- delegation scope and path closure.

Distinct failure family:
- policy text mistaken for authority;
- authority mistaken for technical effect power;
- decision mistaken for enforcement;
- enforcement mistaken for legitimate authority;
- bypass/alternate path left open;
- permission/obligation collapsed;
- human involvement mistaken for authorization.

Current status:

**PROMOTE AS IMMEDIATE RESEARCH REGION, pending parent user evaluation.**

### Child 4 — Transition / Effect / Feedback

Protected question:

> How do changes, actions, observations, decisions and effects propagate across ground states over time, with what trigger/precondition/causal/temporal semantics and feedback consequences?

Examples:
- Work attempt → Environment effect;
- Environment event → Information observation;
- Actor decision/delegation → Work/Actor standing change;
- verification evidence → composite standing change;
- provisioning Work → Work Conditions change;
- incident → evidence → diagnosis Work → authorized adaptation;
- repeated feedback → changed control/Work/Information state.

Distinct failure family:
- sequence mistaken for causation;
- intended effect mistaken for actual effect;
- information update mistaken for world/work change;
- missing trigger/precondition;
- stale propagation/feedback;
- derived-standing change conflated with local state change;
- loop described without exact transition ownership/evidence.

Current status:

**PROMOTE AS IMMEDIATE RESEARCH REGION, pending parent user evaluation.**

## 3. Structural result

Recommended bounded parent structure:

```text
Cross-Ground Composition
├─ Relational Binding
├─ Composite Standing / Qualification
├─ Control / Constraint
└─ Transition / Effect / Feedback
```

Important interpretation:

> These are **diagnostic research problem regions**, not mutually exclusive relation/event classes.

A real verification episode can involve all four:
- bindings among target/criterion/evidence/verifier;
- a derived `verified` standing;
- a gate/control rule;
- a verification activity and standing transition.

Overlap is therefore expected when the protected questions differ.

## 6. Suggested sequencing after parent acceptance

Current dependency-oriented recommendation:

```text
1. Relational Binding
2. Composite Standing / Qualification
3. Control / Constraint
4. Transition / Effect / Feedback
```

Rationale:
- Binding establishes the typed anchors/roles later standings and controls refer to;
- Composite Standing tests how multiple bindings/states become qualified outcomes;
- Control then studies permission/obligation/gating over known anchors/standings;
- Transition/Effect/Feedback studies propagation and dynamic composition across the established semantics.

This order is a research-routing hypothesis, not a claim that runtime systems operate sequentially in that order.

C7 must attack both the four-region structure and this sequencing recommendation.

## 7. Parent boundary

Cross-Ground Composition must not become:
- a generic `relations` residual bucket;
- an architecture module;
- a universal graph schema;
- a workflow/control engine model;
- a fifth ground that owns relations already local to Environment/Information/Work/Actors.

The parent exists only for semantic questions whose correctness depends on preserving multiple ground anchors or the way state/standing/control changes across them.
