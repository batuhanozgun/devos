# Relational Binding — B2 Six-Pair Binding-Family Discovery

**Status:** COMPLETE  
**Date:** 2026-09-05

## 1. Purpose

Use all six accepted-ground pairs to discover recurrent **binding semantic families** without assuming:

- pairwise ground combinations are children;
- repeated verbs are universal relation types;
- every binding family is disjoint;
- every observed connection belongs wholly inside Binding rather than Standing/Control/Transition.

The B1 signature remains controlling:

```text
binding meaning
+ exact anchors in typed semantic positions
+ applicability frame
+ conditional time / n-ary qualification / version constraints
```

## 2. Environment ↔ Information

### Recovered bindings

- representation / description / model / forecast **about** Environment referent;
- observation / measurement result **of** Environment condition/phenomenon;
- evidence / record **concerning** past/current Environment state;
- Informational state **temporally indexed to** Environment state/event;
- context view **selected from / scoped against** a larger Environment/source situation.

### Protected semantic question

> What actual referent, condition, event, scope and time is this informational state about or grounded in?

### Family pressure

Strong **Reference / Representation** family.

### Boundary pressure

`evidence for claim` is not purely Binding when sufficiency/reliability is at issue. Binding can preserve:
- evidence item ↔ target claim/referent;
- source/result ↔ procedure/referent;

but whether evidence is sufficient belongs Composite Standing.

### Relation-name collision

`observes`, `measures`, `represents`, `models`, `describes`, `records`, `evidence-of` are not interchangeable. A generic `about` relation can erase formation/procedure/source distinctions; however those differences may partly belong Information Dynamics/Work rather than Binding children.

### B2 result

**Reference/Representation is a stable binding family candidate.**

## 3. Environment ↔ Work

### Recovered bindings

- Work **targets** / is directed at Environment condition/system;
- Work **depends on** realized Environment condition/resource/interface;
- Environment **supports/enables/constrains** Work execution;
- Work **uses** Environment resource/interface;
- Work **maintains/accommodates** Environment condition;
- one Work product/effect can become another Work's Environment condition.

### Protected semantic questions

Two distinct questions appear:

1. **Target/Subject** — what reality is the Work trying to understand/change/maintain/accommodate?
2. **Dependency/Support** — what realized conditions/resources/interfaces does the Work rely on?

### Family pressure

Strong candidates:
- **Reference / Targeting**;
- **Dependency / Support**.

### Boundary pressure

`Work caused Environment change` is not a static Binding result by default. Binding can preserve:
- Work ↔ intended target;
- Work ↔ alleged/attributed effect;

but actual transition/effect/causal sufficiency belongs Transition/Effect plus evidential qualification.

### Relation-name collision

`uses`, `depends-on`, `supported-by`, `enabled-by` are not synonyms:
- dependency may exist without active use;
- use does not imply critical dependency;
- support may be optional or substitutable;
- enabled-by may be descriptive feasibility or a derived standing.

### B2 result

**Target/Reference and Dependency/Support both survive as distinct family pressures.**

---

## 4. Environment ↔ Actors

### Recovered bindings

- Actor **situated in / exposed to / located relative to** Environment condition;
- Actor **accesses / can reach** resource/interface/network/tool;
- Actor capability **encounters** actual affordance/constraint;
- Actor **uses / operates through** Environment resource/interface;
- Actor **contributes to / affects** Environment condition.

### Protected semantic questions

- What Environment resource/condition is this Actor physically/technically/institutionally situated relative to?
- What interface/resource/path is actually reachable by this Actor?

### Family pressure

Possible **Situation / Access / Interface** family, but it overlaps strongly with Dependency/Support and Participation.

### Boundary pressure

`Actor can act now` is Composite Standing, not Binding. It requires:
- capability;
- Environment access/affordance;
- relevant Work/action path;
- sometimes authority/control.

Similarly `Actor caused outcome` invokes Transition/Effect and attribution evidence.

### B2 result

**Situation/Access is a useful relation family but not yet a stable child candidate distinct from Dependency/Support/Participation.**

---

## 5. Information ↔ Work

### Recovered bindings

- Information **specifies / defines / plans** Work;
- Work **uses / consumes / selects** Information;
- Work **produces / transforms / records** Information;
- Information **represents** Work status/history;
- Information **is evidence/result for** verification/validation Work;
- context/handoff state **supports** Work continuity;
- evidence/specification **binds to exact Work/artifact/target version**.

### Protected semantic questions

At least three pressures appear:

1. **Reference / Specification** — what Work/item/target does this Information describe or constrain?
2. **Dependency / Support** — what Information is required/used for this Work?
3. **Provenance / Production** — what Work activity produced/transformed this Information?

### Boundary pressure

`Work produces Information` has two aspects:
- resulting lineage/binding can be described statically;
- actual generation event belongs Transition/Effect/Information Dynamics.

`Information is sufficient context/evidence` belongs Composite Standing.

`policy/configuration controls Work` belongs Control when permission/gating is central.

### B2 result

This pair strongly demonstrates that relation families **cross ground pairs** and cannot be defined by pair identity.

---

## 6. Information ↔ Actors

### Recovered bindings

- Actor **source / holder / asserter / author / transmitter / recipient** of Information;
- Information **represents / identifies / describes** Actor;
- Information **is attributed to** Actor;
- Actor **believes / accepts / disputes** Information;
- Information records **authority / role / delegation** involving Actor.

### Protected semantic questions

Two strong pressures:

1. **Participation / Epistemic-Communicative Position** — in what capacity is Actor related to the informational state?
2. **Provenance / Attribution** — to whom/what is origin, authorship, assertion, custody or derivation attributed?

### Family pressure

- **Participation / Position**;
- **Provenance / Attribution**;
- Reference/Representation where Information is about the Actor.

### Overlap test

`source` is simultaneously:
- an Actor position relative to Information;
- a provenance relation.

Therefore source/provenance and participation are not cleanly disjoint families.

### Boundary pressure

`source authoritative for question Q` is Composite Standing.

`Actor authorized to disclose/approve` is Control/Actor standing.

### B2 result

Strong evidence against a simple partition where every relation instance belongs to exactly one semantic family.

---

## 7. Work ↔ Actors

### Recovered bindings

- Actor **participates in / performs / requests / initiates** Work;
- Actor is **assigned to** Work;
- Actor **decides / authorizes / reviews / verifies / integrates / accepts** Work;
- Actor obligation/commitment **concerns** Work;
- delegation/reassignment changes Actor↔Work relation while Work identity persists;
- Actor **owns / stewards / is accountable for** Work or continuing responsibility.

### Protected semantic question

> In what capacity/position is this bearer related to this Work, under what scope/time/reference frame?

### Family pressure

Very strong **Participation / Position** family.

### Role collision

A single `assigned-to` or `member-of` relation is insufficient because:

```text
performer
!= requester
!= decider
!= authorizer
!= verifier
!= accepter
!= beneficiary
!= accountable party
```

The same Actor can occupy several positions for the same Work, sometimes at different times/scopes.

### Boundary pressure

- obligation/permission → Control/Actor standing;
- `Work can legitimately close` → Composite Standing;
- reassignment event → Transition;
- actual contribution/causal effect → Transition/Provenance.

### B2 result

**Participation / Position is the strongest recurring non-referential binding family candidate.**

# 8. Cross-pair family synthesis

## Candidate A — Reference / Representation / Targeting

Core question:

> What is this anchor about, directed toward, specified against, targeted at or otherwise semantically referring to?

Appears in:
- Environment ↔ Information;
- Environment ↔ Work;
- Information ↔ Work;
- Information ↔ Actors.

Examples:
- representation → referent;
- Work → target Environment condition;
- specification → Work/target;
- evidence → exact target/version;
- Information → represented Actor.

### Strength

Stable protected question around **semantic target/reference**.

### Weakness

`Work targets Environment` is intentional/directional while `Information represents Environment` is representational/aboutness. Whether these belong under one child remains unresolved.

---

## Candidate B — Participation / Position

Core question:

> In what capacity does an Actor/anchor participate in, stand relative to, hold, source, request, perform, review or otherwise occupy a typed position in relation to another anchor?

Appears strongly in:
- Work ↔ Actors;
- Information ↔ Actors;
- Environment ↔ Actors.

### Strength

Distinct failure family: role confusion.

### Weakness

Some positions such as `source`, `principal`, `beneficiary`, `accountable party` overlap provenance, standing and control semantics.

---

## Candidate C — Dependency / Support

Core question:

> What does this Work/Actor/operation rely on, use, require, receive support from or become feasible through?

Appears strongly in:
- Environment ↔ Work;
- Information ↔ Work;
- Environment ↔ Actors;
- multi-agent/coordination cases indirectly.

### Strength

Distinct failure family:
- dependency omitted;
- support mistaken for availability;
- optional resource mistaken for critical prerequisite;
- dependency scope/method lost.

### Weakness

`enabled-by` can become Composite Standing; technical reach/access can become actionability; dependency order can become Work-local or Transition semantics.

---

## Candidate D — Provenance / Attribution

Core question:

> From whom/what/which activity/which source path does this informational state, contribution or result derive, and to whom/what is it attributed?

Appears strongly in:
- Information ↔ Actors;
- Information ↔ Work;
- Information ↔ Environment;
- Work/Actor contribution cases.

### Strength

Strong external tradition and distinct wrong-source/wrong-derivation/wrong-attribution failures.

### Weakness

Provenance contains:
- participation/association;
- reference/source;
- transition/generation/derivation;
- evidential standing.

It may therefore be a cross-cutting family rather than a clean Binding child.

---

## Candidate E — Situation / Access / Interface

Core question:

> What resource/interface/place/channel is an Actor or Work situated relative to or technically able to reach/use?

### Strength

Important for SOUL/Development OS actionability and transitive power.

### Weakness

Mostly overlaps Dependency/Support plus Environment-local structure. Authority and actionability explicitly belong outside Binding.

Current pressure: **likely specialization/family, not child.**

---

## Candidate F — Specification / Evidence / Traceability

Core question:

> What specification/claim/evidence/result is linked to which exact Work/target/version/criterion?

### Strength

Decision-critical for verification and source/target fidelity.

### Weakness

Mixes Reference/Targeting, Provenance and later Composite Standing. `Evidence sufficient` is not Binding.

Current pressure: **cross-cutting hard-case family, not clean child.**

---

# 9. Verb vocabulary is not a stable taxonomy

Across pairs the same verbs hide different semantics:

### `uses`

Can mean:
- Work consumes Information;
- Work invokes Environment resource;
- Actor operates Environment tool;
- an Activity uses an Entity in provenance.

### `supports`

Can mean:
- resource supports Work feasibility;
- evidence supports claim;
- Actor supports Work organizationally;
- environment supports method execution.

### `targets`

Can mean:
- Work intended target;
- Information annotation/representation target;
- control action target;
- verification target/version.

### `source`

Can mean:
- origin of Information;
- Actor role;
- data source resource;
- causal origin.

Therefore relation names require protected semantics/positions/frame; lexical similarity does not justify merging.

# 10. Pairwise grounding remains useful but is not a child structure

Each pair offers coverage and boundary tests. But relation families cut across pairs, and one binding instance may include anchors from three grounds when qualification is load-bearing.

Reject:

```text
Relational Binding
├─ Environment–Information
├─ Environment–Work
├─ Environment–Actors
├─ Information–Work
├─ Information–Actors
└─ Work–Actors
```

as the preferred child hypothesis.

Ground pairs remain a **discovery matrix**.

# 11. Current family status after B2

```text
Reference / Representation / Targeting  ← strong candidate family
Participation / Position                ← strong candidate family
Dependency / Support                    ← strong candidate family
Provenance / Attribution                ← strong candidate family, overlap risk high
Situation / Access / Interface          ← likely specialization/cross-cutting
Specification / Evidence / Traceability ← composite cross-cutting hard-case family
```

No family is promoted yet.

# 12. B2 judgment

The evidence supports a stable Binding grammar more strongly than a clean relation-family partition.

Four families deserve serious B4 child tests:

1. Reference / Targeting;
2. Participation / Position;
3. Dependency / Support;
4. Provenance / Attribution.

But overlap is already material:
- source = participation + provenance;
- evidence/traceability = reference + provenance + standing;
- target = reference + Work intention;
- access = dependency + situation;
- attribution can depend on participation and transition.

Therefore B3 must next test whether qualification/arity/scope/time are merely dimensions or whether **Qualified/N-ary Binding** is itself the more stable internal split.

Proceed to B3.
