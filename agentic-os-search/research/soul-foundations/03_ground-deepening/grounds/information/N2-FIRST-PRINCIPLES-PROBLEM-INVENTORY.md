# Information / Representation State — N2 First-Principles Problem Inventory

**Status:** N2 bounded first inventory COMPLETE; not a child hierarchy  
**Date:** 2026-09-04  
**Dependency:** `N1-NODE-COHERENCE-ATTACK.md`

## 1. Method

N2 asks:

> If a system/actor cannot operate directly on all relevant reality and instead relies on signals, observations, representations, claims, models, derived views and persistent resources, what distinct failure/semantic questions must be answerable?

The inventory is derived from problem/failure questions rather than from imported taxonomies.

Every region below is classified only as a **problem family**. N3 must later determine whether it is:

- an immediate child;
- a cross-cutting dimension;
- a relation/role;
- a lifecycle condition;
- a neighbouring-ground issue;
- or merely a domain-specific specialization.

## 2. P1 — Referent / subject / scope binding

Core problem:

> What is this informational state about, at what granularity and under what scope?

Failure cases:

- representation silently refers to the wrong object/version/period;
- one label conflates entity, property, event or aggregate;
- intended referent is ambiguous;
- a proxy/sample is treated as the whole target;
- a claim's quantifier/scope is lost;
- representation persists while its referent identity changes.

Questions:

- What is the subject/referent?
- What property/aspect is represented?
- At what spatial/temporal/organizational granularity?
- Is the represented subject direct, sampled, proxied or inferred?

Likely structural role: foundational and recurrent; child status unresolved.

## 3. P2 — Informational access / acquisition / observation formation

Core problem:

> How did information become available from a subject or source?

Failure cases:

- actual state is only partially observable;
- signal is noisy/selective/delayed;
- observation procedure changes or samples the phenomenon;
- procedure/result/source binding is missing;
- missing observation is interpreted as negative evidence;
- observation and underlying state are collapsed.

Questions:

- What procedure/sensor/query/test/interaction produced the result?
- What could the procedure detect or miss?
- What was sampled rather than directly observed?
- What selection/filtering occurred before a representation existed?

Important N1 correction:

`Observation` may be a process/relation producing an informational result, not a stable object subtype.

## 4. P3 — Representational content / form / assertion semantics

Core problem:

> What content is expressed or encoded, and what kind of representational commitment does it make?

Failure cases:

- same content encoded in multiple forms is mistaken for multiple facts;
- form is preserved while meaning/interpretation is lost;
- assertion is confused with reality;
- syntactic/statistical information is treated as semantic content;
- a representation cannot express required distinctions;
- ambiguous vocabulary changes interpretation.

Questions:

- What proposition/description/value/model does the representation express?
- What interpretation maps form to content?
- Is it descriptive, predictive, hypothetical, normative, interrogative or another mode?
- Does it assert, merely encode, simulate or propose?

Likely structural role: central, but mode/attitude may be a relation/status rather than content subtype.

## 5. P4 — Informational identity / granularity / equivalence

Core problem:

> When are two informational instances the same content/resource/view, and when are they materially distinct?

Failure cases:

- copy/equivalent encoding/new assertion/new derivation are conflated;
- identity depends on content in one use and provenance in another;
- aggregation hides constituent distinctions;
- two representations conflict because their scope differs rather than content.

Questions:

- same content vs same informational resource?
- same assertion by different sources?
- same model under different parameters/version?
- equivalent representation vs materially new derived state?

Records already deepens the persistent form of this problem, but identity exists before persistence.

## 6. P5 — Source / holder / perspective / attribution

Core problem:

> From whose/which perspective or source does the informational state exist, and who/what holds or asserts it?

Failure cases:

- one Actor's belief is treated as shared/system belief;
- source is lost in aggregation;
- anonymous assertion gains implicit authority;
- delegated/quoted information is attributed to the wrong origin;
- external source, system estimate and user assertion are collapsed.

Questions:

- who/what originated, observed, asserted, inferred or currently holds it?
- is it actor-local, group-shared, system-level or externally sourced?
- are source, current holder, transmitter and authorizer different?

Boundary rule:

Actor identity/authority itself remains Actors territory. Information owns the representational perspective/attribution problem only insofar as it changes interpretation/standing of informational states.

## 7. P6 — Derivation / transformation / lineage

Core problem:

> How did one informational state arise from others, and what semantic effect did the transformation have?

Failure cases:

- summary silently strengthens/weakens source claims;
- computation loses source binding;
- derived result is mistaken for a primary observation;
- translation/normalization changes meaning;
- inference chain cannot be reconstructed;
- circular derivation is mistaken for independent support.

Questions:

- copied, transformed, aggregated, inferred, simulated, summarized, translated or revised?
- which inputs and procedure contributed?
- what information was lost, added or changed?
- is derivation deterministic/reproducible?

Likely structural role: process/relation plus lineage dimension; child status unresolved.

## 8. P7 — Epistemic / evidential / reliability standing

Core problem:

> What should be believed, relied upon or inferred from this informational state, and relative to what target question/claim?

Failure cases:

- assertion is treated as fact because it exists;
- authoritative source role is treated as guaranteed truth;
- evidence for one hypothesis is treated as universal evidence;
- confidence is attached without a model/basis;
- contradictory evidence is hidden by aggregation;
- retrieval result is mistaken for evidential sufficiency.

Questions:

- claim, assumption, hypothesis, estimate, accepted fact, disputed assertion?
- supports/challenges which target claim or decision?
- what confidence/uncertainty/reliability applies and why?
- what counterevidence or competing hypothesis exists?

Important N1 correction:

`Evidence` is strongly relational. Epistemic standing may therefore be a cross-cutting relation/status family rather than an immediate child.

## 9. P8 — Temporal applicability / freshness / change in informational standing

Core problem:

> When does this informational state apply, when was it known/produced, and is it still current for the intended use?

Failure cases:

- old observation treated as current state;
- future forecast treated as realized condition;
- correction/retraction not propagated;
- as-of semantics lost;
- knowledge-time and domain/effective-time conflated.

Questions:

- about which time is the content?
- when was it observed/asserted/derived/received?
- what is its validity/applicability interval?
- what later event corrected, superseded, retracted or invalidated it?

Records already deepens persistent history/standing; nonpersistent information still has temporal applicability/freshness problems.

Likely structural role: cross-cutting dimension/state-change concern.

## 10. P9 — Selection / view / context formation

Core problem:

> Which subset/projection of available information is exposed for the current purpose, and what does the selection omit or distort?

Failure cases:

- omitted evidence changes the decision;
- summary/view is mistaken for complete source;
- irrelevant volume hides decision-critical information;
- same information is contextually relevant for one Work/Actor and irrelevant for another;
- context is reified as an intrinsic object property.

Questions:

- selected relative to which Work, Actor, query or decision?
- what source universe was eligible?
- what filter/compression/ranking/transformation occurred?
- what coverage/fidelity/freshness contract does the view have?

Current structural hypothesis:

Context/view formation is more likely a use-relative selection/projection relation over information than a clean immediate child, but N3/N4 must test this.

## 11. P10 — Conflict / consistency / plurality

Core problem:

> What happens when multiple informational states about overlapping subjects disagree or cannot all be jointly maintained?

Failure cases:

- conflict is erased by choosing one source silently;
- differing scope/time/perspective is misdiagnosed as contradiction;
- genuine contradiction is hidden as versioning;
- consensus is mistaken for truth;
- system cannot preserve rival hypotheses.

Questions:

- same referent/scope/time?
- logical contradiction, differing estimate, differing perspective or stale state?
- can rival representations coexist?
- what process/authority may resolve standing without rewriting history?

Likely structural role: cross-cutting condition over multiple representations.

## 12. P11 — Accessibility / exposure / communication boundary

Core problem:

> Which informational states are available to which consumer/system at what point, and what does successful transmission actually establish?

Failure cases:

- source exists but is not visible/retrievable;
- transmitted bits are intact but semantically uninterpretable;
- access/permission restricts available evidence;
- message delivery is mistaken for shared understanding;
- representation exists in storage but is absent from working context.

Questions:

- available vs known vs selected vs understood?
- who/what can access it?
- what communication/encoding dependencies exist?
- did exposure preserve interpretation and binding?

Boundary rule:

Permission/authority ownership belongs mainly to Actors/policy/composition; Information cares about availability/exposure when it affects informational state and downstream interpretation.

## 13. P12 — Persistence / memory / recordhood transition

Core problem:

> What changes when an informational state must survive across time, sessions, systems or custodial transitions?

Failure cases:

- transient state disappears despite later reliance;
- arbitrary memory becomes trusted source;
- persistence loses identity/provenance/interpretability;
- every cached/context item is treated as a Record;
- retained information outlives its valid use/authority.

Questions:

- which informational state must persist, why and for how long?
- does persistence create recordhood or only storage?
- what preservation closure becomes necessary?
- what retention/disposition obligations arise?

Existing Records research already deeply covers the specialised persistent-information problem. N3 must determine its structural relation to the broader ground rather than restart it.

## 14. Candidate cross-cutting dimensions after N2

The inventory repeatedly uses dimensions that do **not** currently look like clean child branches:

- referent/scope;
- source/provenance;
- holder/perspective;
- temporal applicability/freshness;
- uncertainty/confidence;
- authority/standing;
- accessibility/visibility;
- representation medium/form;
- persistence horizon;
- derivation lineage.

Their recurrence across many problem families is evidence **against** promoting them mechanically as sibling children.

## 15. Candidate process/result distinction

A recurring structural separation is:

```text
formation / acquisition / transformation process
        ↓
informational result / representation / state
        ↓
relations / standing / use / context / evidence
        ↓
optional persistence / lifecycle obligations
```

This is a useful N3 clustering hypothesis, **not an accepted hierarchy**.

It avoids comparing unlike kinds such as `observation process`, `belief state`, `evidence role`, `context view` and `record lifecycle` as if they were peer object types.

## 16. N2 verdict

The first-principles inventory is broad enough to expose the main candidate failure regions without importing one disciplinary taxonomy.

The strongest structural finding is negative:

> **The inherited adequacy-stage list is not a valid immediate-child hierarchy because it mixes processes, results/states, relations/roles, cross-cutting dimensions and lifecycle conditions.**

N3 should therefore cluster by stable **problem region / obligation family**, not by familiar nouns.
