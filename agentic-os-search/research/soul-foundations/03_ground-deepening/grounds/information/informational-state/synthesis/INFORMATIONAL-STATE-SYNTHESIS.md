# Informational State / Representational Constitution — Synthesis

**Status:** bounded synthesis prepared for user evaluation  
**Date:** 2026-09-05  
**Scope:** Informational State child only; not architecture, ontology, schema or implementation

## 0. Why this synthesis exists

The accepted Information parent identified two first-order children:

```text
Information / Representation
    ├─ Informational State / Representational Constitution
    └─ Informational Dynamics / Formation–Transformation
```

The parent pass exposed several State-side problem regions but deliberately did not decide their internal hierarchy.

This child pass therefore asked:

> Does Informational State contain stable immediate children, or is its internal structure better understood as mutually dependent constitution dimensions and relations?

The pass did not assume that `referent / content / identity` was already the answer.

---

# 1. Node coherence result

`Informational State / Representational Constitution` remains a coherent research node.

It cannot be reduced to:

- the Dynamics that generated/changed it;
- the actual Environment condition it represents;
- an Actor's belief/knowledge;
- a file/data object;
- persistent Records;
- a list of familiar nouns such as claim, belief, evidence, context and record.

The protected State problem is:

> **What represented/informational result exists, what is it about and applicable to, what does it express and how, which identity/equivalence criteria distinguish it, and which qualifications/relations materially affect its interpretation or use?**

`State` is an analytical role, not a truth or immutability claim. It can include observations, estimates, hypotheses, forecasts, models, distributions, normative representations, graph/data states, selected views and other representational results.

---

# 2. Main bounded result — no immediate child promoted

The strongest current conclusion is:

> **Informational State / Representational Constitution is a bounded leaf for the current Foundation research depth.**

No stable immediate child split survived N1–N6.

This is not because the node is simple. It is because the recurring distinctions are deeply interdependent facets/relations of the **same constituted state** rather than clean first-order territories.

---

# 3. Internal constitution map

The current map should remain explicit and retrievable:

```text
Informational State / Representational Constitution

A. Reference & applicability
   - referent / subject binding
   - scope / time / population / reference frame

B. Content & realization
   - content / semantic interpretation
   - representation form / encoding / schema binding
   - mode / stance / representational commitment

C. Individuation
   - identity / granularity / equivalence
   - version / copy / projection / fragment / aggregate when material

D. Qualification & relations
   - source / holder / perspective / attribution
   - uncertainty / confidence / reliability / epistemic standing
   - temporal standing / freshness
   - plurality / compatibility / conflict
   - availability / visibility / persistence status where State-side
```

The four headings are **orientation clusters, not child branches**. They may overlap in a domain-specific model.

---

# 4. Why `Reference / Content / Identity` did not become children

The inherited three-part candidate is attractive because each region has distinct failure cases.

However:

- changing referent/scope often changes what the content means;
- identity/equivalence depends on referent, scope, content, form, provenance and protected use;
- form/schema affects interpretation and equivalence;
- temporal/modal/perspective qualifiers can change content or identity;
- source/standing remains materially important but does not fit cleanly into the three branches.

The three remain excellent diagnostic questions, but they do not form a stable first-order hierarchy.

---

# 5. Why `Core Constitution / Qualification–Standing` did not become children

This was the strongest rival.

It would separate:

```text
what the state says/is
vs
how the state is qualified for reliance/use
```

The distinction is useful, but not structurally stable enough for promotion:

- uncertainty may be represented content or qualification;
- temporal information may be content scope, currentness standing or version identity;
- source/perspective can change interpretation itself;
- forecast/hypothesis/quotation can be content mode or assertion standing;
- evidence is target-relative;
- authority belongs partly to Actors/policy/control;
- truth relates State to Environment/model semantics;
- visibility/context depends on Dynamics and use.

The candidate `Standing` branch would therefore become a residual bucket of heterogeneous cross-boundary relations.

---

# 6. Reference and applicability

A representation is not adequately constituted by value/content alone.

Decision-critical questions can include:

- which entity/object/resource/property/event is represented;
- direct target, sample, proxy, aggregate or model target;
- spatial/population/organizational scope;
- temporal applicability;
- quantifier;
- scenario/condition;
- unit/reference frame.

Examples of separable errors:

- right value, wrong room;
- right statistic, wrong population;
- right claim, wrong period;
- historical state treated as current;
- forecast scenario treated as realised state.

Yet reference/applicability remains semantically entangled with content; it therefore stays a constitution dimension rather than a child.

---

# 7. Content, form and interpretation

Keep distinct when material:

```text
representation form / bytes / syntax
!= interpretation convention / schema / units
!= represented semantic content
```

Examples:

- different JSON/XML/RDF/text encodings can carry equivalent content;
- identical bytes under different schema can mean different things;
- an encoded value can survive while interpretive dependencies disappear;
- a view can hide source distinctions even when syntactically valid.

This is central State constitution, but the form/content boundary itself changes by domain and does not justify universal siblings.

---

# 8. Mode / stance / representational commitment

The same apparent content can have different representational force:

- observed result;
- external assertion;
- quotation;
- assumption;
- hypothesis;
- estimate;
- forecast;
- simulation result;
- model prediction;
- normative/policy representation;
- candidate alternative.

Failure to preserve mode is not merely style loss. It can turn `someone reports X` into `X is established`, or `forecast X` into `X happened`.

But mode does not create a universal State type hierarchy. RDF 1.2 supplies a strong structural holdout: a proposition may be referenced without being asserted.

---

# 9. Identity / equivalence / granularity

Identity is one of the most load-bearing State questions and one of the least reducible to a single field.

Preserve distinctions when protected use cares about them:

```text
same bytes
same representation resource
same semantic content
same assertion
same source assertion
same version
same derivation
same projection
same aggregate
same state for this protected use
```

These are not automatically equivalent.

External and internal holdouts converge:

- RDF canonicalization: different serializations can be isomorphic/equivalent;
- PROV: specialization/alternate descriptions can fix different aspects of the same underlying thing;
- Web Annotation: a SpecificResource can have its own identity while source/selector/state/scope constrain it;
- Records: resource/version/representation/copy/derivation/aggregate distinctions can all matter.

Therefore identity/equivalence is best treated as **individuation/comparison over constituted states/resources under criteria**, not an isolated child branch.

---

# 10. Source / holder / perspective / attribution

Keep distinct when material:

- originator/source;
- observer;
- asserter;
- derivation producer;
- current holder/store;
- transmitter;
- represented perspective;
- authorizer.

The same proposition may be held by A, disputed by B, stored in a shared system and currently visible to neither.

Information owns these relations insofar as they alter interpretation/provenance/standing. Actor identity, capability, role and authority remain Actors.

---

# 11. Uncertainty / confidence / reliability / epistemic standing

These are necessary but heterogeneous.

A useful system must avoid collapsing:

```text
state exists
!= state is true
!= state is reliable
!= source is authoritative
!= state supports target claim
!= evidence is sufficient for decision
```

Uncertainty can itself be content (for example a distribution) or a qualification around content. Reliability may depend on source/process history. Evidence is target-relative.

This heterogeneity is why no universal `Standing` child was promoted.

---

# 12. Temporal standing / freshness

At least the following may need separation:

- time the content is about;
- observation/effective/applicable time;
- time produced/asserted/received;
- time recorded/known;
- validity interval;
- current/superseded/retracted standing.

Records deepens the persistent-history case. Dynamics owns the events/operations that change standing. State owns the current/historical qualifications necessary to interpret the represented result.

One generic timestamp is not a foundational solution.

---

# 13. Conflict / plurality

Two states should not be called contradictory until comparison conditions are aligned.

Check, when material:

- referent/property;
- time/scope;
- unit/reference frame;
- mode/stance;
- granularity;
- uncertainty;
- provenance/independence.

Conflict is therefore a **relation over multiple constituted states**, not a State subtype.

Conflict detection/merge/revision belongs to Dynamics; adjudication may additionally involve Work/Actors/authority.

---

# 14. Availability / visibility / persistence

Keep separate:

```text
source exists
!= state persists
!= state is retrievable
!= state is selected into current context
!= consumer sees/understands it
```

The Context/Memory/Harness study supplies a practical engineering holdout:

```text
persistence → survives
memory      → managed for later recall/update/forget
context     → model-visible now
```

This is not imported as Foundation taxonomy. It demonstrates independent failure surfaces around one State.

---

# 15. Truth, verification and authority

One of the strongest later-SOUL safeguards emerging from this node is to keep these relations separate:

```text
representation exists
!= authentic source/artifact
!= representation is current
!= claim is true
!= claim is evidence for this target
!= evidence is sufficient
!= source has authority for this role
!= decision is authorised/committed
```

W3C Verifiable Credentials 2.0 is a particularly strong holdout: verification/authenticity/currentness of a credential does not establish truth of the credential's claims; claim validation remains separate and use-specific.

---

# 16. Boundary with Informational Dynamics

The accepted sibling boundary remains strong:

```text
State
    what represented result exists and how it is constituted/qualified

Dynamics
    how states become available, are acquired, derived, selected, revised,
    communicated, invalidated or otherwise changed
```

The same transformation may produce a well-defined but wrong State. A State can be ambiguous/mis-scoped despite a correctly executed process.

State being a leaf does not weaken its separation from Dynamics.

---

# 17. Boundary with Environment

Environment owns actual realised conditions. State may represent observations, estimates, forecasts, models or claims about them.

```text
actual condition
!= representation of condition
```

Good State constitution is necessary for correct interpretation but insufficient for factual truth.

---

# 18. Boundary with Work

A State may represent:

- goal;
- plan;
- status;
- completion assertion;
- verification evidence;
- decision rationale.

But actual Work selection/commitment/execution/verification/acceptance is not created merely by changing the representation.

---

# 19. Boundary with Actors

A State may contain claims about Actor identity/authority and may be sourced/held by Actors.

But Actor identity, capability, role, authority, obligation and accountability are not State properties merely because they can be represented.

---

# 20. Boundary with Records

Persistence does not create State semantics; it adds future-use/horizon obligations around already constituted informational states and their histories.

Records remains the deep specialization for:

- exact identity/version/representation binding;
- preservation closure;
- survivable provenance/context/standing;
- retrieval/reconstruction;
- retention/disposition.

Correct persistence can preserve a false, ambiguous or stale State perfectly.

---

# 21. External falsifier result

N5 deliberately used materially different traditions:

- JCGM/BIPM metrology;
- RDF 1.2 representation;
- RDF Dataset Canonicalization;
- Web Annotation;
- W3C PROV;
- Verifiable Credentials 2.0;
- DCAT 3.

They do not share one vocabulary or data model, but they repeatedly need combinations of:

- referent/target;
- content/form;
- scope/applicability;
- identity/equivalence/version;
- source/perspective;
- validity/status/uncertainty.

They factor these differently. None forces a clean universal immediate-child partition inside State.

---

# 22. Adversarial completion result

N6 explicitly attempted to promote:

- Reference/Scope;
- Content/Interpretation;
- Representation Resource/Form;
- Identity/Equivalence;
- Mode/Assertion;
- Qualification/Standing;
- Perspective/Holder;
- Temporal State;
- Conflict/Plurality;
- Schema/Ontology;
- multimodal/non-propositional State;
- Intrinsic vs Extrinsic State.

It also attempted to merge State into the parent and split it into separate top-level grounds.

No rival produced a cleaner first-order hierarchy without greater overlap, residual buckets or cross-ground leakage.

N6 is same-model adversarial review, not independent verification.

---

# 23. Practical diagnostic value for later SOUL / Development OS

Without making architecture decisions, later failure diagnosis can distinguish at least:

### Wrong reference / applicability

The content may be accurate but attached to the wrong target/version/time/scope.

### Wrong content / interpretation

The state points to the right target but expresses/encodes/interprets the wrong thing.

### Wrong identity / equivalence

The system conflates or separates versions, copies, projections, aggregates or corroborating sources incorrectly.

### Wrong mode / standing

A forecast becomes fact, quotation becomes endorsement, old state becomes current, confidence/uncertainty is lost.

### Wrong attribution / perspective

Source, holder, origin, derivation or viewpoint is misbound.

### False conflict / missed conflict

States are compared without aligned scope/time/mode/granularity, or genuine contradiction is overwritten.

These remain diagnostic dimensions, not architecture modules.

---

# 24. What is not concluded

This research does **not** establish:

- one universal Information object schema;
- mandatory fields every informational state must have;
- a Knowledge Graph ontology;
- RDF as SOUL's representation model;
- a truth/evidence calculus;
- a trust framework;
- database tables or document formats;
- context/memory architecture;
- SOUL primitives/modules;
- Development OS implementation requirements.

The map says what kinds of distinctions can be decision-critical. Later design must decide which are explicit for a given task-specific system.
