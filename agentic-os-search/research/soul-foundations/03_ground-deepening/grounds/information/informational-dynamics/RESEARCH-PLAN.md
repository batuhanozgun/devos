# Informational Dynamics / Formation–Transformation — Research Plan

**Status:** active node plan  
**Date:** 2026-09-05

## Objective

Research Informational Dynamics as a first-principles Foundation node without importing a ready-made ETL, data lifecycle, cognition, provenance, retrieval or software-pipeline taxonomy as the answer.

The pass must determine whether informational formation/change has stable immediate first-order children and preserve distinctions that later SOUL / Development OS reasoning may need for diagnosis, composition and control.

## Starting hypotheses to attack

The Information parent pass exposed several dynamic regions:

1. acquisition / observation formation;
2. derivation / transformation / lineage;
3. selection / view / context formation;
4. revision / correction / retraction / supersession;
5. communication / exposure / receipt;
6. persistence lifecycle transitions when materially informational.

These are **not pre-accepted children**. The pass must test merge, split, lifecycle-stage, relation and mechanism alternatives.

## Decision-critical questions

### Formation / acquisition

- What makes an informational state newly available rather than merely newly visible?
- Which distinction among sensing, observation, querying, extraction, ingestion and assertion is foundational?
- When does a source-to-representation step create new informational content versus copy/expose existing content?

### Transformation / derivation

- What distinguishes copying, normalization, translation, projection, aggregation, summarization, inference and simulation when their semantic effects differ?
- Which transformations preserve content, which lose information, and which create derived claims?
- Is lineage a dynamic branch, a relation across states/processes, or both depending on focal question?

### Selection / context formation

- Is retrieval/ranking/filtering/context assembly a first-order Dynamics branch or a specialization of transformation/exposure?
- When does selecting a subset create a materially new informational state/view?
- How should omission, compression and ranking effects be represented without turning use-relative relevance into intrinsic Information taxonomy?

### Revision / invalidation / conflict

- Are correction, retraction, supersession, invalidation, reconciliation and merge merely transformation types, or do they form a distinct state-change region because standing/history semantics differ?
- What changes: content, applicability, identity, standing, visibility, or all of these?

### Communication / exposure

- Is communication fundamentally state transfer/exposure, or does semantic receipt/interpretation require a distinct dynamic problem region?
- What does successful transmission establish, and what does it not establish?

### Persistence lifecycle

- Which write/update/recall/forget/disposition dynamics are generic Information changes and which belong only to Records/persistence specialization?
- Can persistence transitions remain an overlay without forcing a peer Dynamics child?

## N0 — Canonical / internal evidence recovery

Recover:

- parent Information N2/N3/N4/N5/N6/N7 evidence relevant to Dynamics;
- accepted Informational State sibling result for boundary and output-state semantics;
- completed Records evidence where change/time/standing/retrieval/disposition exposes Dynamics requirements;
- relevant candidate studies through `research/studies/CATALOG.md` and selected `META.md`/findings;
- historical evidence only when current canonical surfaces point to it or it materially tests a boundary.

## N1 — Node coherence attack

Test whether:

- Informational Dynamics is genuinely distinct from Informational State;
- it is too broad and residual;
- `Formation–Transformation` is an adequate protected description;
- communication/exposure belongs inside Dynamics or should remain relational;
- revision/standing change forces a stronger parent framing;
- lifecycle process categories are domain-specific rather than Foundation-level.

## N2 — First-principles problem inventory

Derive problem families from failure cases and independent questions, not familiar pipeline nouns.

Expected probes include:

- wrong/biased acquisition despite well-defined result format;
- incomplete observation treated as complete evidence;
- transformation silently changes claim strength or scope;
- derived result loses lineage/source binding;
- retrieval/context assembly omits decisive information;
- correction exists but stale states remain exposed;
- retraction changes standing but not historical existence;
- merge hides genuine disagreement;
- transmission succeeds but semantic interpretation fails;
- stored state is correct but wrong version is retrieved;
- deletion/forgetting changes future availability without erasing historical fact that the state once existed.

## N3 — Immediate-child discovery

Compare at least these rival frames:

- acquisition / transformation / selection-exposure / revision;
- formation / state-to-state transformation / distribution-access;
- source-to-state / state-to-state / state-to-consumer transitions;
- lifecycle-stage decomposition;
- no stable split: one Dynamics node with cross-cutting transition dimensions.

Promote only distinctions that survive the project child-promotion test.

## N4 — Boundary / anti-collapse

Stress against:

- Informational State: current result/constitution vs process/change;
- Environment: physical/runtime causal process vs informational mediation;
- Work: deliberate reasoning/review/decision activity vs the informational transformation it produces;
- Actors: communicator/source/receiver identity and authority vs information-change process;
- Records: persistent lifecycle obligations vs generic formation/change.

## N5 — External / cross-domain falsifiers

Use materially different traditions rather than many examples from one vocabulary. Candidate domains:

- metrology / observation processes;
- W3C PROV generation/use/invalidation/derivation;
- database query/view/provenance and change propagation;
- information retrieval and context/view construction;
- belief revision / knowledge-base change;
- scientific correction/retraction/versioning;
- communication / encoding / message transfer;
- event sourcing / versioned state / temporal data as technical holdouts;
- records lifecycle and disposition;
- transformation pipelines where semantic-preserving vs semantic-changing operations differ.

Primary/authoritative sources are preferred where available. External taxonomies are falsifiers and mechanism evidence, not imported Foundation ontology.

## N6 — Omission / reduction / rival audit

Attempt to find:

- a stable missing first-order child;
- a case forced unnaturally into the proposed split;
- a supposed Dynamics region that actually belongs to State or a neighboring ground;
- a simpler decomposition preserving all decision-critical distinctions;
- an external framing that exposes hidden lifecycle/pipeline assumptions.

Same-model audit must remain labeled non-independent.

## N7 — Closure

Close for user evaluation only if:

- the node boundary remains coherent and non-residual;
- immediate-child structure or justified no-split result is boundedly supported;
- broad external probes have declining structural information gain;
- cross-cutting transition dimensions/relations are explicit;
- State, Records and neighboring-ground boundaries remain recoverable;
- residual/reopen questions are explicit;
- verification strength is accurately labeled.

Finding an immediate child does not authorize researching it in this pass.
