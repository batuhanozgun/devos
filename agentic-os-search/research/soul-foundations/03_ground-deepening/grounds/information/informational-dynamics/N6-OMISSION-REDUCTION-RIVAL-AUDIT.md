# Informational Dynamics / Formation–Transformation — N6 Omission, Reduction and Rival-Decomposition Audit

## 1. Leading result under attack

```text
Informational Dynamics
    ├─ Informational Formation / Acquisition
    ├─ Informational Derivation / Transformation
    └─ Informational Selection / Exposure
```

The audit attempts to force a missing child, merge existing children, or show that one child is only a cross-cutting dimension.

## 2. Missing child probe — Revision / Standing Change

Why plausible:

- correction, retraction, supersession, invalidation and belief revision have distinctive semantics;
- content can remain unchanged while standing/currentness changes;
- Records research shows generic `update` is inadequate.

Attack:

Revision is defined by transition effect, not by a disjoint source/output topology. It can be triggered by new acquisition, derived inference, direct transformation, conflict reconciliation or an authorized standing designation. Propagation of the result then crosses Selection/Exposure.

A fourth peer would duplicate C2 and partly C3.

**Verdict:** retain as a load-bearing C2 specialization / cross-cutting transition mode; no fourth child.

## 3. Missing child probe — Communication / Distribution

Why plausible:

Communication has sender, receiver, message, channel and delivery semantics distinct from local computation.

Attack:

- message content → State;
- sender/receiver identity/authority → Actors;
- channel/runtime → Environment;
- re-encoding/translation → C2;
- publication/delivery/exposure → C3;
- receiver-side newly instantiated copy → C1 relative to receiver/system boundary.

Communication is therefore a composite pattern spanning children and neighboring grounds rather than a clean peer branch.

**Verdict:** no fourth child.

## 4. Missing child probe — Propagation / Synchronization

Why plausible:

Corrections can fail to propagate even when local transformation is correct; stale caches/views are a major failure mode.

Attack:

Propagation usually combines:

- dependency detection/recompute/invalidation → C2;
- delivery/retrieval/visibility of new state → C3;
- persistence-specific cache/history obligations → Records when applicable.

The protected question is important but crosses two existing branches rather than partitioning the parent.

**Verdict:** cross-branch dynamic relation/pattern; no new child.

## 5. Missing child probe — Persistence / Memory Lifecycle

Why plausible:

Write, update, read, forget, retain and dispose have deep, independent failure surfaces.

Attack:

Persistence is already a demonstrated specialization/profile crossing Information:

- capture/write can instantiate persistent state → C1/C2 depending origin;
- migration/revision → C2;
- retrieval/recall → C3;
- disposition adds Records-specific preservation/retention/custody outcomes.

Promoting persistence inside Dynamics would duplicate a specialization already known to cross State and all Dynamics branches.

**Verdict:** remain deep persistence specialization/profile.

## 6. Missing child probe — Encoding / Interpretation

Why plausible:

Parsing, transcription, schema mapping and semantic interpretation can fail before or during transformation.

Attack:

The same concern changes role by transition:

- signal/source → first representation → C1;
- representation → another representation → C2;
- selecting correct variant/format for consumer → C3.

Output meaning/constitution itself belongs State.

**Verdict:** cross-cutting mechanism/semantic dimension, not peer child.

## 7. Missing child probe — Conflict / Reconciliation

Why plausible:

Contradiction, plurality and merging have distinctive information-system semantics.

Attack:

- conflict/plurality condition → State relation;
- detecting conflict → C2/C3 depending comparison path;
- reconciliation/merge → C2;
- selecting/designating accepted/current state → C3 + standing relation;
- authority/decision → Work/Actors/control.

**Verdict:** important specialization/composite, not peer child.

## 8. Missing child probe — Validation / Verification

Why plausible:

Information is often checked, corroborated or tested before use.

Attack:

Verification has a Work/control dimension because it is relative to a claim and success criterion. Informationally it may:

- acquire new test/observation evidence → C1;
- derive assessment results → C2;
- select relevant evidence → C3;
- change standing of claims → C2/relations.

A peer `Verification` child would mix Work semantics with Dynamics mechanisms.

**Verdict:** no new child.

## 9. Merge attack — C1 Formation into C2 Transformation

Rival:

> All formation is transformation of some prior signal/source, so C1 is redundant.

Counterexample:

This formulation is formally possible only by enlarging `informational state` to include any pre-semantic phenomenon/signal/source. That would steal Environment/source-boundary semantics and erase acquisition-specific questions about observability, sampling, detectability and procedure-result binding.

Metrology is a strong holdout: the process of measurement and the result are distinct, and intended target/procedure/system relations matter before a result exists.

**Verdict:** C1 retained.

## 10. Merge attack — C3 Selection into C2 Transformation

Rival:

> Selecting/ranking/filtering is just a transformation from a set to a subset/list.

Counterexample:

Treating every selection as transformation is mathematically possible but diagnostically lossy. It collapses two protected questions:

- did the transformation from selected inputs to output preserve/derive meaning correctly?
- were the right existing inputs made visible in the first place?

A faithful summary of an incomplete retrieved set and a distorted summary of a complete set require different fixes. TREC/Web Annotation independently expose selection relative to an information need/source segment without requiring source mutation.

**Verdict:** C3 retained.

## 11. Merge attack — C1 Formation into C3 Selection

Rival:

> Acquisition is selecting information from the world/source.

Counterexample:

Correctly choosing a source does not guarantee correct sensing/fetching/parsing/capture. Conversely, a correctly formed state can later be omitted by selection.

External fetch illustrates the reference-frame caveat but preserves separate failure questions.

**Verdict:** C1/C3 retained.

## 12. Split attack — make Selection and Exposure separate children

Rival:

```text
Selection / Retrieval
Distribution / Exposure
```

Why plausible:

Selection chooses what; exposure/communication makes it available to whom.

Attack:

Both share a protected first-order question:

> Which already-existing informational state becomes available/visible to a use/consumer, under what eligibility/ordering/coverage conditions?

Retrieval, ranking, publication and delivery differ operationally, but their common failure family is source-available information not becoming correctly visible. Receiver-side formation or semantic transformation can be routed to C1/C2 when material.

No external tradition examined requires splitting them universally at this level.

**Verdict:** keep combined C3 for current Foundation depth.

## 13. Split attack — make Derivation and Revision separate children

Rival:

```text
Derivation / Computation
Revision / Standing Change
```

Attack:

Both are state-to-state informational transitions whose protected question is what new/changed state or standing follows from existing states/processes and what semantic effect occurred. Revision is especially important, but its boundaries depend on domain standing/authority semantics and frequently use derivation/reconciliation operations.

**Verdict:** keep revision as deep specialization/mode inside C2 for now.

## 14. No-split attack — one Dynamics leaf

Rival:

> The branches overlap by reference frame, so represent all dynamics with transition dimensions only.

Counterexamples:

Three independent failure questions repeatedly survive:

1. **Formation validity:** was an informational state appropriately formed from source/phenomenon/assertion?
2. **Transformation validity/fidelity:** did existing informational inputs produce/change output soundly and with understood semantic effect?
3. **Selection/exposure sufficiency:** did the right already-existing information become visible/available for the use?

Distinct interventions follow:

- change sampling/acquisition procedure;
- fix derivation/transformation logic;
- fix retrieval/eligibility/ranking/exposure.

The distinctions materially alter diagnosis and later system reasoning.

**Verdict:** no-split rejected.

## 15. Parent-label attack

Current accepted label:

`Informational Dynamics / Formation–Transformation`

Problem:

The qualifier `Formation–Transformation` under-signals Selection/Exposure.

Candidates:

1. `Informational Dynamics / Formation–Transition`
2. `Informational Dynamics / Formation–Transformation–Exposure`
3. `Informational Dynamics` alone
4. retain current label with explicit scope

Assessment:

- option 2 is accurate but enumerative/brittle;
- option 3 is clean but loses explanatory orientation;
- option 4 preserves continuity but leaves a known semantic under-signal;
- option 1 uses `transition` as the broad umbrella for changes in existence, content, identity, standing, visibility or availability and naturally covers all three children.

**N6 recommendation:** refine descriptive label at closure to **`Informational Dynamics / Formation–Transition`**, subject to user evaluation. This is a research naming refinement, not an ontology-class decision.
