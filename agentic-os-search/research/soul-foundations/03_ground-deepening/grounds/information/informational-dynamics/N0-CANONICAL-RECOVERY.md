## 1. Purpose

Recover what is already known before generating a Dynamics-specific decomposition.

This pass does not adopt parent/candidate taxonomies. It extracts only the load-bearing constraints that the active Dynamics node must survive.

## 2. Canonical starting point

Accepted parent structure:

```text
Information / Representation
    ├─ Informational State / Representational Constitution   ← bounded leaf / user-evaluated
    └─ Informational Dynamics / Formation–Transformation     ← ACTIVE
```

Accepted sibling constraint:

> Dynamics must explain how informational states are formed or changed without absorbing the State-side constitution questions that determine what the resulting informational state means/is.

## 3. Dynamic regions inherited from parent research

The parent exposed at least these process/change surfaces:

- acquisition / observation formation;
- derivation / transformation / lineage;
- selection / retrieval / view / context formation;
- revision / correction / retraction / supersession / invalidation;
- communication / exposure / receipt;
- persistence-related lifecycle transitions;
- conflict resolution / reconciliation where a state or standing changes.

No one of these is accepted as an immediate child.

## 4. First anti-collapse rule

The same State output can be reached through different processes, and the same process family can produce different State outputs.

Examples:

- identical measurement format can result from sound or biased acquisition;
- identical summary format can be faithful or scope-distorting;
- two retrieval paths can return the same text with different coverage/provenance implications;
- the same claim content can remain stored while its standing changes from current to superseded/retracted.

Therefore process semantics cannot be reduced to output-state attributes alone.

## 5. Second anti-collapse rule — not every dynamic is content transformation

Recovered evidence shows at least four materially different effects:

1. **formation:** a state/result becomes informationally available through observation/assertion/ingestion/generation;
2. **derivation/transformation:** existing informational states contribute to a new or modified state;
3. **selection/exposure:** the source universe may remain unchanged while a consumer-visible/working set changes;
4. **standing/availability transition:** content may remain unchanged while currentness, validity, reliance, visibility or persistence status changes.

This is evidence that `Dynamics = content transformation` is too narrow.

It is not yet evidence that the four effects are immediate children.

## 6. Third anti-collapse rule — process vs Work / Actor / Environment

A dynamic informational process may be embedded in Work, performed by an Actor, or implemented through Environment capabilities without collapsing into those neighboring grounds.

Examples:

- reasoning may be deliberate Work while the resulting inference is an informational derivation;
- a person may communicate a statement while sender identity/authority remains Actors semantics;
- a sensor/network/query engine may be Environment capability while the observation/retrieval process is focal Dynamics when the question is how a representation was formed/exposed.

The active pass must preserve this focal-question boundary.

## 7. Records constraint

Records research proves that one generic `update` loses distinctions among revision, migration, derivation, supersession, correction, retraction, access removal, custody transfer and disposition.

But Records also warns against universalising its persistence-specific lifecycle labels.

Dynamics must therefore recover the underlying semantic effects without copying the Records change vocabulary as a universal child taxonomy.

## 8. Context / retrieval constraint

Candidate and Records research jointly support:

```text
source state exists
≠ source is eligible
≠ source is retrieved
≠ source is selected into current context
≠ consumer interprets/uses it correctly
```

Retrieval/context formation therefore creates Dynamics-specific failure surfaces even when no source content changes.

This is a major challenge to decompositions based only on `create / update / delete` or `acquire / transform`.

## 9. Artifact-chain constraint

The Anthropic SDLC study provides a software-domain holdout where one informational state is repeatedly transformed into another:

```text
signal → intent → spec → plan → implementation evidence → review → production evidence → incident → new intent
```

The important reusable property is not the six SDLC stages. It is that successive artifacts can:

- preserve some content;
- add commitments/interpretation;
- lose qualifiers;
- change standing;
- become inputs to later transitions.

The Dynamics pass must therefore distinguish semantic transition effect from domain-specific stage labels.

## 10. Initial rival framings retained for attack

### Rival A — pipeline stages

```text
acquire → transform → select/distribute → revise
```

Risk: stage order may be domain-specific and recursive systems can loop.

### Rival B — transition topology

```text
external/source → informational state
informational state(s) → informational state(s)
informational state(s) → consumer-visible/available state
```

Risk: topology alone may hide distinct semantic effects such as invalidation or standing change.

### Rival C — semantic effect

```text
formation
content/representation derivation
selection/exposure
standing/availability change
```

Risk: categories may overlap for one operation.

### Rival D — no stable split

Treat Dynamics as one bounded leaf with explicit transition dimensions such as origin, inputs, outputs, semantic effect, lineage, time, visibility and identity effect.

Risk: may be too coarse if acquisition, derivation and selection repeatedly require different protected questions/failure analysis.
