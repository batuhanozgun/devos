# Derivation — Cross-Node and Cross-Ground Interfaces

**Date:** 2026-09-12  
**Role:** retrieval/boundary ledger, not an execution queue

| Interface | Retained division |
|---|---|
| Formation / Acquisition | source capture and origin/result relation versus transfer/warrant/revision; model-mediated formation may involve Derivation without becoming identical to it |
| Selection / Exposure | which existing material reaches a use versus what transformations do to supplied inputs; still separately unresearched |
| Informational State | constitution, identity, mode and plurality of results versus change relations |
| Records / persistence | horizon-specific preservation/history/custody versus generic maintained-information change; revision need not be durably stored |
| Work | purpose, investigation and decision activity versus the informational product and transition |
| Actors / Control | who can assert, revise, designate or govern versus the meaning and realization of information change |
| Binding | exact premise/source/output roles, scopes, time and n-ary associations; generic links are insufficient |
| Standing | actual qualification, evidential assessment and recognition versus the production/revision that changes their represented basis |
| Propagation | local revised result versus incorporation across targets; downstream exposure is not presumed |
| Actual Causation | actual contribution of a particular input/configuration versus logical support of a conclusion |
| Contrastive Effect | outcome under different transformation/revision regimes versus validity of the present informational bridge |
| Returned Influence / Adaptation | operative feedback and retained future-response change versus storing a derived lesson or revised statement |

No child is a runtime module or replacement for these accepted questions. A deduction can be logically valid yet unauthorized to act upon; a revision can be legitimate yet based on false evidence; a source can influence an output without justifying it.
