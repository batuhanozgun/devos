# Work Conditions — OPEN QUESTIONS

**Status:** bounded residual uncertainty after current immediate-child pass

These are residual questions, not demonstrated missing immediate children.

## Q1 — final label

Current preferred label:
- **Work Conditions**.

Open:
- whether ordinary employment-language associations with `working conditions` create enough ambiguity to justify a future alternative;
- whether a later composition vocabulary should use a more explicitly relational phrase while retaining this research label.

## Q2 — load-bearing materiality threshold

Current rule:
- include a realized circumstance when plausible variation could materially change protected Work feasibility, method, safety, pace, reliability, resource sufficiency or achievable quality/precision.

Open:
- how a later SOUL/Development OS representation operationalizes `materially` without pulling in the whole world;
- how thresholds vary by risk, purpose and protected outcome.

## Q3 — support-closure boundary

Open:
- how far indirect dependencies should be included;
- when a remote/shared service belongs inside one Work-Conditions view versus remains an external dependency linked by relation;
- how common-mode/shared-failure dependencies should be bounded.

## Q4 — availability / readiness / sufficiency

These remain explicit dimensions, not children.

Open:
- which purpose-relative condition judgments later composition needs;
- how to distinguish objective support condition from evidence/confidence about that condition;
- how partial capability-specific degradation should be represented.

## Q5 — Actor-provided support

Open:
- how staffing/support coverage is represented as a Work Condition while identity, competence, authority, obligation and accountability remain Actor semantics;
- how collective/team capability interacts with current support availability.

## Q6 — institutional / regulatory conditions

Open:
- how to represent realized applicability, prohibition, permission effect and procedural access without confusing them with rule text or authority source;
- which parts belong to later typed relations among Information, Actors, Work and Environment.

## Q7 — time windows and Work control

Open:
- how external realized windows (site/service/weather/filing availability) bind to Work deadlines/schedules/ordering;
- how changing windows affect Work readiness without duplicating Work state.

## Q8 — role switching / boundary lifecycle

Open:
- how one concrete system/facility/resource can be Domain Reality for one Work and Work Condition for another while preserving identity;
- how role assignment changes as focal Work or system boundary changes.

## Q9 — condition identity / equivalence

TWE has deep technical environment identity/equivalence semantics.

Open:
- whether broader Work Conditions need a general equivalence notion for support substitution;
- when two different facilities/resources/support configurations are equivalent for a protected Work purpose;
- whether this remains entirely purpose-relative.

## Q10 — causal attribution

A Work Condition may coincide with or contribute to failure/success.

Open:
- what evidence is required before saying a condition caused blockage, delay, hazard or outcome;
- how to distinguish actual condition from causal attribution and counterfactual dependence.

## Q11 — specialization profiles

Current result rejects technical/physical/social/institutional/logistical branches as universal children.

Open:
- when later domain-specific use justifies a specialization profile;
- how Technical Work Environment should be linked as retained deep evidence without forcing symmetrical siblings.
