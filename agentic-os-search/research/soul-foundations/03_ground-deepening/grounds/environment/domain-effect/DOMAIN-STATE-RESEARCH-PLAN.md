## Decision-critical framing questions

The pass must explicitly test rather than assume:

1. Is `Domain State / Configuration` one coherent node, or should `State` and `Configuration/Structure` split?
2. Are `constituents/identity`, `properties/condition`, and `relations/topology` genuine child regions or merely aspects of one realized state description?
3. Does a universal `Structure / Composition` child become necessary at this deeper level even though it was not required under Domain Reality?
4. Which constraints/invariants are part of realized State, which constrain possible State/Dynamics, and which are only represented rules in Information?
5. What makes the selected domain constituent/system/situation the **same** across state change, replacement, aggregation or boundary change; is identity/continuity a child, a cross-cutting dimension or domain-specific specialization?
6. What state granularity is sufficient for a protected reasoning purpose, and when does omitted history make a current-state description insufficient?
7. How must actual realized state remain separate from observed, inferred, specified, desired, forecast, simulated or recorded state without assuming that every social/institutional fact is metaphysically representation-independent?
8. Can physical, digital, social, institutional and hybrid states share one problem hierarchy without a type-based taxonomy becoming the project tree?
9. Is `state` itself too model-centric, such that `realized condition`, `situation`, `configuration` or another framing better preserves the problem?

## Research sequence

### S0 — Evidence / inherited-assumption inventory

Output:
- established parent findings;
- inherited but unverified State assumptions;
- open State-local questions;
- frozen falsifiers above;
- known source/view limitations.

Do not treat the current node label or the prior State-vs-Dynamics split as privileged because this project produced them.

### S1 — Node coherence / split–merge–rename challenge

Test rivals such as:

```text
A. Domain State / Configuration                  [one node]
B. Domain State + Domain Structure/Configuration [split]
C. Constituents/Identity + Properties/Condition + Relations/Topology
D. Realized Situation / Condition                [rename/reframe]
E. Fact/relation-only reduction                   [no dedicated State node]
F. Bounded leaf                                   [no stable immediate children]
```

A rival wins only if it preserves the parent boundary and materially improves failure analysis or later SOUL/Development-OS reasoning with less forced fit.

### S2 — First-principles State problem inventory

Derive problems before importing any external ontology/taxonomy.

Probe, without pre-promoting:
- domain participation/scope;
- constituent presence and identity;
- composition/part-whole;
- properties/qualities/status;
- realized relations/topology/configuration;
- spatial arrangement where load-bearing;
- institutional/social standing where load-bearing;
- identity/continuity across replacement/change;
- granularity and sufficient state;
- current actuality versus possible/allowed/desired state;
- actual versus observed/inferred/specified/recorded state;
- constraints/invariants and admissibility;
- absence/null/non-applicability;
- conflicting simultaneous scopes or reference frames.

### S3 — Immediate-child discovery

Cluster only stable first-order problem regions.

For every candidate child apply the existing child-promotion test:
- distinct first-order question or protected outcome;
- distinct failure modes;
- repeated cross-domain usefulness;
- distinct boundary/reduction behavior;
- materially different downstream reasoning if collapsed.

Do not promote a child merely because a formal ontology, modeling language or data model has a corresponding category.

### S4 — Cross-cutting-dimension and boundary tests

Explicitly test whether the following are children or cross-cutting dimensions:
- reference frame / scope;
- time index;
- spatial extent;
- identity / continuity;
- granularity / abstraction;
- observability / uncertainty;
- provenance/currentness of representations;
- constraints / invariants;
- validity/applicability;
- actual-versus-represented distinction.

Stress-test against the Dynamics sibling so temporal process semantics do not leak into State.

### S5 — Cross-lineage external falsification

Use materially different traditions; no source taxonomy defines the project tree by authority.

Candidate source families:
- control/state-space and dynamical-systems notions of state;
- MDP / situation-calculus / transition-system notions of world or situation state;
- systems engineering and system-context/configuration disciplines;
- configuration-management and as-built/as-operated system-state traditions;
- formal ontology / persistence / identity counterframes;
- temporal/database/snapshot traditions as representation counterframes, not reality authority;
- digital-twin actual-system versus model/state synchronization literature;
- institutional/social ontology for realized standing and rule-dependent facts;
- additional traditions discovered during search if they expose a distinct first-order State problem.

### S6 — Cross-domain holdouts

At minimum challenge the candidate child map with:
- SOUL / KEEL / Development OS operating against a live repository and deployed system;
- distributed/software production topology and configuration drift;
- physical asset/repair state;
- scientific specimen/experimental system state;
- market/business condition;
- legal/institutional standing;
- social/organizational realized condition without transferring Actor semantics;
- hybrid physical/digital system;
- a domain where identity persists despite substantial component replacement;
- a domain where current snapshot is insufficient unless history is retained.

Holdouts test the hierarchy; they are not illustrations.

### S7 — Omission / reduction / adversarial audit

Try to find:
- a recurrent State-local family outside all immediate children;
- a child that is really a cross-cutting dimension;
- forced fit caused by putting structure inside configuration;
- a case where identity/continuity deserves co-equal status;
- a case where constraints/invariants deserve co-equal status;
- a case where a represented state is being silently substituted for actual state;
- a case where Dynamics semantics have leaked into State;
- a domain where the chosen State framing changes materially with boundary/reference choice;
- a reason the node should remain a leaf.

Same-model completion review must be labeled non-independent.

### S8 — Node-level closure

Close the **Domain State / Configuration** pass when:
- the node is coherent or a stronger replacement is established;
- immediate-child map or justified leaf result is explicit;
- Structure, Identity, Constraints and Granularity rivals have been directly challenged;
- cross-cutting dimensions are separated from children;
- materially different holdouts stop producing new first-order State regions;
- load-bearing claims have source/view recovery;
- residuals and deferred relations are explicit;
- additional broad research shows declining structural information gain.

Then return to user evaluation before activating any discovered child or the Dynamics sibling.

- candidate splits are representation/modeling views rather than distinct problem regions;
- decomposition does not change failure analysis, boundary reasoning, relation structure or later design reasoning materially;
- further search mainly refines vocabulary/domain examples.
