# Domain Dynamics Finding 05 — Cross-Domain Holdouts

**Status:** active-pass adversarial finding  
**Stage:** D6  
**Verification class:** same-model holdout challenge informed by independent external traditions; not independent verification

## Candidate under attack

```text
Domain Reality
    ├─ Domain State
    └─ Domain Dynamics     ← candidate bounded leaf
```

The candidate says Dynamics needs explicit internal problem regions/modes but no universal immediate children at this foundation level.

## H1 — live software / distributed system

Dynamics:
- asynchronous requests and interactions;
- reconciliation loops;
- failures, retries and recovery;
- deployment/runtime evolution;
- external service/network disturbances.

Challenge:
- continuous controller operation and discrete failures/events coexist;
- focal development/operations Work may influence but does not exhaust runtime change.

Verdict: one Dynamics node holds; process/event distinction is useful but not a stable child boundary.

## H2 — physical asset

Dynamics:
- operation, heating, vibration and wear;
- degradation accumulation;
- shocks/failures;
- repair-caused change and independent drift.

Challenge:
- gradual process and abrupt transition interleave;
- current Condition can be identical at a coarse view while hidden accumulated damage/history changes future behavior.

Verdict: Dynamics required; history is load-bearing but not a separate universal child.

## H3 — ecological system

Dynamics:
- population/community interaction;
- resource flows;
- feedback;
- gradual pressure;
- tipping/regime shifts and recovery trajectories.

Challenge:
- feedback/process and abrupt shift form one coupled dynamic system;
- alternative regimes and hysteresis can make recovery path differ from degradation path.

Verdict: stability/regime/history are Dynamics properties/patterns, not independent children.

## H4 — market/business domain

Dynamics:
- transactions/flows;
- demand/supply adaptation;
- network effects;
- expectation/institution-mediated change;
- exogenous shocks.

Challenge:
- endogenous/exogenous status depends on selected market/system boundary;
- observations/feeds/forecasts remain representations.

Verdict: source-of-change does not survive as a universal child split.

## H5 — scientific/experimental system

Dynamics:
- natural evolution;
- intervention-coupled response;
- measurement interaction where material;
- delayed effects and unobserved processes.

Challenge:
- Work may be observational, experimental or mixed;
- actual sequence does not establish causal attribution to intervention.

Verdict: Dynamics remains independent of Work lifecycle and causality relation.

## H6 — institutional/social domain

Dynamics:
- rule/practice-maintained continuation;
- performative or legal status transitions;
- gradual institutional change;
- enforcement/noncompliance dynamics.

Challenge:
- some real changes are constituted through collective/rule-mediated practices;
- Actor authority and particular textual records must remain separate semantics.

Verdict: `actual` cannot mean independent of all social representation, but actual institutional Dynamics remains distinguishable from any particular Record/model and from Actor authority.

## H7 — hybrid physical/digital system

Dynamics:
- continuous physical evolution;
- discrete controller/event changes;
- synchronization and communication delays;
- model/counterpart divergence.

Challenge:
- the same system crosses continuous/discrete modes;
- virtual representation may track but not equal actual evolution.

Verdict: formalism-based child split rejected.

## H8 — same observed current State, different history

Construct two systems with the same selected current visible Condition but different accumulated stress/history.

Possible result:
- future response differs because the selected State omitted relevant internal state, or because the system is genuinely hysteretic/path dependent.

Challenge:
- the project must distinguish representation insufficiency from reality-side memory.

Verdict: history/path dependence is an explicit Dynamics sufficiency question, not a universal child.

## H9 — identity across replacement

A system retains operational identity while components are progressively replaced, or loses relevant identity after a structural transition.

Challenge:
- identity criteria vary by domain and protected purpose;
- both State and Dynamics need them.

Verdict: identity/continuity remains cross-cutting, not Dynamics-local child.

## H10 — Work partly causes a transition

A focal Work intervention changes one variable while autonomous/exogenous processes continue to shape the trajectory.

Challenge:
- Work action, actual transition and causal contribution are different claims.

Verdict: Work-coupled Dynamics is relational, not a child.

## H11 — no focal Work

A disease progresses, ecosystem shifts, market changes or software runtime fails before any focal Work begins.

Verdict: Dynamics cannot be defined as Work-induced change.

## H12 — Work Conditions role switching

A cloud service's evolving availability is:
- Domain Dynamics when the focal Work diagnoses/changes that service;
- Work-Condition dynamics when another Work merely depends on it.

Verdict: target/support distinction is reference-relative role composition, not object-type or Dynamics child taxonomy.

## Holdout verdict

No holdout forces a stable first-order child outside the explicit Dynamics problem map. The strongest recurring distinctions—occurrence/change, history, regime, source-of-change, formalism—change role with scale, boundary, representation or system type.

The candidate **`Domain Dynamics` as a bounded leaf** survives the current holdout set.
