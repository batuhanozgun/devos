Domain Dynamics     ← leaf at current foundation-research depth

## Why this audit can add only limited confidence

The same model that produced the synthesis performs this audit, so maker/verifier errors can be correlated. Confidence comes only from:
- frozen falsifiers established before external search;
- materially different external source lineages;
- holdouts chosen to break rather than illustrate the candidate;
- explicit rival decompositions;
- source/view recovery;
- the audit's willingness to reopen or reject the leaf.

The audit is not labeled independent.

## A2 — Strongest rival split attack

Rival:

```text
Domain Dynamics
    ├─ Occurrence / Interaction / Process
    └─ Change / Transition / Trajectory
```

Why it could be right:
- 'what is happening?' and 'what changed?' can lead to different evidence and failure questions;
- process failure can be investigated differently from wrong resulting transition.

Counterexamples:
- continuous process is itself a trajectory/change;
- a transition may be a coarse temporal projection of an underlying process;
- hybrid robotics and hybrid-system formalisms combine continuous evolution and discrete events in one Dynamics;
- ecological gradual feedback and abrupt regime shift are coupled rather than independent branches;
- scale/reference can reclassify an event as process or a process as disturbance.

Child-promotion test:
- distinct question: **partly yes**;
- distinct failure modes: **partly yes**;
- cross-domain recurrence: **yes**;
- stable boundary/reduction behavior: **no**;
- independent recursive research value when collapsed: **not demonstrated**.

**Verdict:** strongest rival, but insufficient for promotion. Keep explicit non-hierarchical distinction and reopen trigger.

## A3 — Process/Event split attack

External process ontologies disagree about occurrence categories. Hybrid systems intentionally unify flow and jump modes.

If the project promoted process/event children now, the split would depend too heavily on ontology/formalism and temporal granularity.

**Verdict:** reject as universal child split.

## A4 — Endogenous/Exogenous split attack

Change the system boundary:
- an external weather shock for one system becomes internal atmospheric Dynamics for a larger domain;
- a support-system process can become target-domain process when focal Work changes.

A universal child should not flip merely because the analyst redraws an otherwise legitimate reference boundary unless the branch itself is explicitly relational.

**Verdict:** boundary/source dimension, not child.

## A5 — History / Path Dependence split attack

Two failure pathways exist:
1. chosen State is insufficient and omitted a load-bearing current variable;
2. genuine hysteresis/path dependence keeps history materially relevant.

Because the first can disappear under a better State representation while the second can cut across any occurrence/change type, one History child would mix representation insufficiency with reality-side memory.

**Verdict:** retain as explicit Dynamics sufficiency/dependency problem, not child.

## A6 — Stability / Regime split attack

Limit cycles, equilibrium, attractor basins, instability, synchronization and regime shifts can materially change later reasoning.

But they characterize patterns/properties of trajectories/dynamics rather than a separate co-equal region that exists alongside the dynamics producing/exhibiting them.

**Verdict:** high-value property/pattern dimension, not child.

## A7 — Constraints / Laws / Possibility attack

Transition laws, invariants and reachable-state structures can constrain possible evolution. Represented laws/rules may be Information; realized physical/institutional constraint conditions may also appear in Domain State.

A possible transition is not an actual realized transition.

**Verdict:** keep explicit realized-versus-possible boundary; no Dynamics child.

## A8 — Causality / Mechanism attack

Could Dynamics require a `Mechanism` child?

Risk:
- mechanics/interaction may be reality-side processes;
- but saying a factor/mechanism caused an outcome generally requires a relation/evidence standard beyond mere temporal occurrence.

Promoting `Mechanism` would encourage actual process description and causal attribution to collapse.

**Verdict:** realized interaction belongs Dynamics; causal mechanism/effect claims remain relational/evidential. No child.

## A9 — Work collapse attack

Holdouts:
- disease progression without intervention;
- ecosystem/market change without focal Work;
- runtime failures/recovery outside one development task;
- domain evolution after Work completion.

These preserve meaningful Dynamics without focal Work.

**Verdict:** Dynamics ≠ Work lifecycle survives.

## A10 — Work Conditions leakage attack

The same evolving system can be target domain for one Work and support condition for another.

If the hierarchy duplicated it as two kinds of reality, relation/reference semantics would be lost.

**Verdict:** role switching is cross-boundary composition obligation, not Dynamics child.

## A11 — Information / representation substitution attack

Counterexamples:
- digital twin synchronized with physical counterpart;
- Kubernetes API-reported state versus changing runtime;
- event log missing an unobserved process;
- forecast predicting a trajectory that does not occur.

**Verdict:** actual Dynamics remains distinct from representation/model/observation.

## A12 — Institutional/social holdout attack

If actuality were defined as representation-independent physical occurrence, institutional changes would fail the branch.

The corrected criterion is weaker and more useful:
- institutional reality can be constituted through collective rules/practice;
- a realized institutional change is still not identical to any one Record/assertion/model;
- Actor authority and collective attitudes retain their own semantics.

**Verdict:** social holdout survives after boundary qualification; no separate social-Dynamics child.

## A13 — Type-taxonomy attack

Physical, software, ecological, market, institutional and hybrid systems exhibit different mechanisms, but each re-exposes occurrence/change/history/regime/boundary questions.

**Verdict:** domain types are specializations/holdouts, not universal immediate children.

## A14 — Search saturation / information-gain check

Late external probes and holdouts mostly:
- strengthened the rename from `/ Processes` to `Domain Dynamics`;
- reclassified candidates as modes/properties/relations;
- refined actual-versus-possible/represented boundaries;
- produced stronger reopen conditions.

They did not produce a new recurrent first-order region.

The strongest unresolved structural rival remains Occurrence versus Change, already preserved explicitly.

**Verdict:** additional broad search has declining structural information gain at this level.

## A15 — Verification sensitivity check

Question:

> If the leaf result were wrong in a way represented by the frozen falsifiers, would the pass have had a route to detect it?

Yes, boundedly:
- F2/F3/F5/F7 could have promoted process/event, trajectory/history, feedback/mechanism or history if stable cross-domain boundaries emerged;

But the verifier remains same-model and sources do not independently validate the project decomposition.

**Verdict:** falsification-sensitive enough for bounded closure, not for universal/independent validation.
