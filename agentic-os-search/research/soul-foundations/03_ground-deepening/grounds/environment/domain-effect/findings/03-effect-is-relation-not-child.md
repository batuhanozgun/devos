# Domain Reality Finding 03 — Effect Is Not a Separate Reality Child

**Status:** current active-node finding  
**Question:** is `Effect Reality` an immediate child alongside Domain Reality?

## Current finding

**No separate `Effect Reality` child is supported.**

Three concepts must be separated:

1. **actual resulting domain condition/trajectory** — what really happened in the domain;
2. **desired/accepted outcome** — what Work intended or what success criteria require;
3. **causal effect / attribution** — what difference is due to a particular action/intervention/cause.

Only the first is straightforwardly Domain Reality.

## State-transition evidence

Situation-calculus, MDP and control traditions describe actions/events as producing transitions in a world/process state.

A realized effect therefore appears as:

```text
prior domain state/trajectory
    + action/event/disturbance
        → later domain state/trajectory
```

The later condition is not a different kind of reality merely because it followed Work.

## Causal-inference discriminator

Potential-outcomes traditions define causal effect as a contrast such as `Y(1) - Y(0)` between outcomes under alternative intervention conditions.

For a single unit, both potential outcomes are not jointly observed. Thus causal effect is not simply the observed post-condition and is not established by a pre/post change alone.

Project implication:

> **actual change ≠ causal effect attribution**

A later SOUL/Development OS account may need strong causal relations/evidence, but Domain Reality should not absorb the counterfactual/evidential machinery required to validate them.

## Observational-Work falsifier

Clinical diagnosis, astronomy, epidemiological observation and other non-interventionist inquiry demonstrate that focal Work can have a genuine domain while intentionally causing no change in it.

Therefore a domain node cannot require a co-equal effect region for its existence.

## Outcome grounding

The Environment parent result remains correct that Work completion is not equivalent to real-world outcome.

But the cleaner decomposition is:
- actual resulting condition → Domain State/trajectory;
- intended/accepted outcome → primarily Work/Information/relations as later composition requires;
- causal attribution → relation/evidence problem;
- side effects → actual domain changes plus causal relation when attribution is claimed.

## Result

Drop `Effect` from the node label.

Do not create:

```text
Domain Reality
Effect Reality
```

or:

```text
Domain Reality
└─ Effect Reality
```

as the current immediate hierarchy.

Preserve effects as a **cross-cutting transition/outcome/causality relation** over Domain Reality and Work rather than a separate reality bucket.
