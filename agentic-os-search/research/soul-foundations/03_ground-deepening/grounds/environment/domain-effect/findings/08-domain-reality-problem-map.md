# Domain Reality Finding 08 — Problem Map and Failure Surfaces

**Status:** current integrative node finding  
**Purpose:** make the immediate-child result productive without turning it into architecture/schema

## Current immediate hierarchy

```text
Domain Reality
    ├─ Domain State / Configuration
    └─ Domain Dynamics / Processes
```

The two branches are analytical problem regions, not mutually exclusive object classes.

---

# A. Domain State / Configuration

Primary question:

> What realized domain condition obtains at the relevant scope and time?

## S1 — Scope / reference / domain participation

- What realized reality is materially in scope for this focal Work?
- Which constituents/relations/configuration facts are load-bearing?
- What can be omitted without changing the protected reasoning?

Failure:
- wrong domain scope;
- semantic leakage from Information/Actors/Work;
- irrelevant world facts included or critical facts omitted.

## S2 — Constituents and realized relations

- What is present?
- Which actual relations/topology/configuration hold?
- Which composition facts matter now?

Failure:
- treating a represented/design structure as the realized structure;
- stale topology/configuration;
- wrong identity/continuity assumption.

## S3 — Properties / qualities / status

- What current properties/conditions hold?
- Which values/statuses materially affect Work or outcome grounding?

Failure:
- stale/wrong current condition;
- chosen granularity hides a load-bearing state difference.

## S4 — Actual versus represented condition boundary

- Which current condition is actual?
- What is only observed, inferred, specified, forecast or recorded?

Failure:
- model/measurement/Record substituted for realized state.

---

# B. Domain Dynamics / Processes

Primary question:

> What processes/interactions/events make Domain Reality change or persist through time?

## D1 — Endogenous processes

- What domain processes unfold from the domain's current organization/state?
- What feedback, flows, interactions or internal transitions matter?

Failure:
- static snapshot used where trajectory matters;
- wrong process/feedback assumptions.

## D2 — Exogenous events / disturbances

- What can change the domain independently of focal Work?
- Which external events/shocks/disturbances alter the trajectory?

Failure:
- Work action assumed to be the only source of change;
- omitted disturbance produces false effect attribution or prediction.

## D3 — Work-coupled transitions

- Through what interaction can focal Work alter the domain?
- What actual transition occurred after/interacting with Work?

Failure:
- intended action mistaken for actual transition;
- Work closure mistaken for resulting domain change.

Causal attribution remains relational/evidential; this branch supplies the realized trajectory side.

## D4 — Temporal behavior / path dependence

- Which rates, delays, sequences, persistence or hysteresis matter?
- Can the same current state have different futures because histories differ?

Failure:
- delayed/indirect effects missed;
- path dependence compressed into current scalar state;
- wrong temporal ordering.

# Cross-cutting dimensions — explicit but not immediate children

## C1 — Boundary / reference frame

Applies to both state and dynamics. Domain membership/role is reference-relative.

## C2 — Spatial / temporal scope

Indexes what state/process is relevant; no separate universal spatial or temporal child is currently justified.

## C3 — Constraints / invariants / laws / possibility space

Can constrain admissible states and/or transitions. Depending on domain, represented rules may belong partly to Information while realized institutional/physical constraints participate in Domain Reality.

No third universal constraints child is currently required.

## C4 — Observability / uncertainty

Actual state/process can be hidden or only partially observed. Observation, inference, confidence and uncertainty representation belong primarily to Information/composition.

## C5 — Causality / attribution

The domain contains realized states/trajectories. `X caused Y` requires a causal relation/evidential standard not supplied by the mere existence of two states.

## C6 — Outcome / success relation

Actual resulting domain condition is Domain Reality. Desired/accepted outcome and judgment of success connect Work/Information/relations to Domain Reality.

## C7 — Identity / continuity

Which constituent/system/domain scope is treated as the same across change can matter in both branches. No universal identity rule is established here.

## C8 — Controllability / actionability

Whether a domain process/state can be influenced by a particular Actor/Work under Work Conditions is relational, not a Domain Reality child.

---

# Strong non-collapse distinctions

```text
Domain Reality ≠ every target of Work
actual state/configuration ≠ observation/model/specification/Record
domain dynamics ≠ Work lifecycle
after-state/change ≠ causal effect attribution
intended outcome ≠ actual resulting condition
structure/model view ≠ automatically a separate Domain Reality child
domain type (physical/social/digital/...) ≠ universal immediate branch
```

## Productive-decomposition result

The two-child map changes research behavior:
- State/Configuration asks whether the actual condition has been correctly scoped and characterized.
- Dynamics/Processes asks whether evolution, disturbance, interaction and trajectory have been correctly understood.

A later child pass can deepen either question independently without researching the other in parallel.
