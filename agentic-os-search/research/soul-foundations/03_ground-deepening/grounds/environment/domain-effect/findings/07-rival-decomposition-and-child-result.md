# Domain Reality Finding 07 — Rival Decomposition and Immediate-Child Result

**Status:** current active-node adversarial finding

## Candidate under attack

```text
Domain Reality
    ├─ Domain State / Configuration
    └─ Domain Dynamics / Processes
```

## Criteria

Prefer the smallest decomposition that:
- preserves distinct first-order questions/failure modes;
- generalizes across materially different domains;
- does not steal Work/Information/Actors semantics;
- survives boundary/reference changes;
- improves later SOUL/Development OS reasoning;
- does not merely import a modeling or ontology taxonomy.

## Rival A — keep `Domain / Effect Reality` undifferentiated

**Strength:** minimal hierarchy.

**Failure:** `effect` conflates actual resulting condition, desired outcome and causal attribution. Observation-only Work also has a domain without intended effect.

**Verdict:** reject label/frame.

## Rival B — `Domain Reality` as a leaf with state/dynamics only as dimensions

**Strength:** avoids over-hierarchization.

**Failure:** state/configuration and dynamics/processes repeatedly expose distinct research questions and distinct failure modes across clinical, technical, scientific, market and institutional cases. Omitting either materially changes diagnosis, prediction and effect reasoning.

**Verdict:** weaker than promoting two problem branches.

## Rival C — `Domain Reality → State/Configuration + Dynamics/Processes`

**Strengths:**
- smallest split that survived child-promotion;
- cross-lineage recurrence;
- distinct error surfaces;
- handles static, changing, observational and intervention cases;
- keeps effect/causality relational;
- does not require type-based children.

**Risk:** may be mistaken for an ontology claim that all reality consists of two object types.

**Guardrail:** branches are research questions/lenses, non-exclusive and potentially implemented relationally.

**Verdict:** strongest current immediate-child structure.

## Rival D — `Domain Reality + Effect Reality` siblings

**Failure:** causal effect is not simply an actual observed region; it is defined relationally/contrastively in causal traditions. Actual outcomes are domain conditions/trajectories.

**Verdict:** reject.

## Rival E — `Structure + State + Dynamics`

**Strength:** systems modeling often distinguishes structure and behavior; structure can be highly load-bearing.

**Failure at this level:**
- current constituents/relations/topology can fit State/Configuration;
- invariant structural constraints cut across state/dynamics;
- universal structure taxonomies vary by domain;
- separate structure child increases cross-ground leakage for social/institutional/digital cases;
- no tested holdout required it as a third first-order problem branch.

**Verdict:** do not promote now; reopen if later evidence shows forced fit.

## Rival F — `Entities + Processes + Qualities` / upper-ontology partitions

**Strength:** formal ontologies such as BFO/DOLCE offer disciplined reality partitions.

**Failure:** upper ontologies disagree in their primitives and solve an ontology-engineering problem different from the project research-routing question. Importing one would give external taxonomy authority over project child selection.

**Verdict:** useful counterframe, not current hierarchy.

## Rival G — type-based children

```text
Physical
Digital
Social
Institutional
Economic
...
```

**Failure:** hybrid cases cross these categories; state/dynamics questions recur in each; type taxonomy would multiply branches without changing first-order research logic.

**Verdict:** reject as universal immediate children; may be later specialization profiles.

## Rival H — `Controlled Process / Target System` only

**Strength:** powerful for intervention/control and engineering cases.

**Failure:** too narrow for observational science, diagnosis, broad social/institutional domains and Work where no single controlled system exists.

**Verdict:** specialization/frame, not universal node.

## Rival I — relation-only / no Domain Reality node

**Strength:** later graph/ontology could represent state/process facts through typed relations.

**Failure as research routing:** relation-only framing does not by itself force explicit investigation of actual realized condition, hidden state, evolution, disturbance, trajectory and world/model mismatch.

**Verdict:** viable representation strategy, insufficient reduction of the research problem.

## Immediate-child result

Current strongest bounded map:

```text
Environment / Operating Reality
    ├─ Domain Reality
    │    ├─ Domain State / Configuration
    │    └─ Domain Dynamics / Processes
    │
    └─ Work Conditions / Enabling–Constraining Environment
         └─ Technical Work Environment
```

`Effect/Outcome` remains a cross-cutting Work↔Domain transition/result/causality question, not a third child.

## Epistemic limit

This is cross-source synthesis plus same-model adversarial comparison. It is not independent verification or universal ontology completeness.
