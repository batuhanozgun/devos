# Domain Reality Finding 04 — Immediate Children: State / Configuration and Dynamics / Processes

**Status:** current active-node finding  
**Question:** do any candidate distinctions under Domain Reality deserve promotion to immediate child problem regions?

## Bounded current result

The strongest immediate-child candidate is:

```text
Domain Reality
    ├─ Domain State / Configuration
    └─ Domain Dynamics / Processes
```

These are **problem branches**, not mutually exclusive entity classes.

## Child A — Domain State / Configuration

Primary question:

> **What realized domain condition/configuration obtains at the relevant time and scope?**

This can include, when material:
- which domain constituents are present;
- current properties/qualities;
- current relations/topology/configuration;
- current status/condition;
- current spatial arrangement;
- current resource/domain values;
- current institutional/social standing in its domain-reality role.

`State` here is not a claim that every domain must be represented as one formal state vector. It is a research question about realized condition.

### Distinct failures

- wrong/omitted current condition;
- stale configuration;
- wrong constituent/relation/topology assumption;
- selected state granularity omits a load-bearing fact;
- represented/observed state mistaken for realized state.

## Child B — Domain Dynamics / Processes

Primary question:

> **What realized processes, interactions, transitions and disturbances make the domain evolve through time?**

This can include, when material:
- endogenous processes;
- exogenous events/disturbances;
- interactions among domain constituents;
- rates/flows/feedback;
- path dependence and delayed consequences;
- transitions caused partly by Work actions;
- transitions caused independently of focal Work.

### Distinct failures

- static-snapshot reasoning where trajectory matters;
- wrong transition/process assumptions;
- omitted disturbance;
- ignored feedback/nonlinearity/path dependence;
- wrong temporal ordering/rate;
- assuming Work action is the only source of change.

## Why the split passes child-promotion

### Distinct first-order questions

`What is true/realized at the relevant time?` and `How does it change/unfold?` are not interchangeable.

### Distinct failure modes

A system can have a correctly observed current condition but a wrong dynamics model, or the reverse. A correct current patient state does not establish disease trajectory; correct current service topology does not establish future failure/recovery behavior.

### Cross-lineage recurrence

Independent traditions repeatedly distinguish:
- system state from behavior/dynamics;
- world/situation state from action/event transitions;
- state variables from system dynamics;
- continuant/entity views from process/occurrent views;
- system structure from behavior views.

The exact taxonomies differ, but the condition-versus-change distinction recurs.

### Downstream reasoning value

Later SOUL/Development OS reasoning must separately answer:
- what condition is actually present now/at the relevant time;
- what trajectories/processes are possible or occurring;
- what future/side effects may emerge under continued dynamics;
- whether a Work action changes the domain or merely coincides with a change.

Collapsing both into one undifferentiated `domain state` repeatedly loses these failure distinctions.

## Why `Structure` is not promoted as a third immediate child

Systems modeling and WDA provide strong structure/decomposition views, and formal ontologies distinguish entities from processes.

However, at this project level, a universal `Domain Structure` child is not yet necessary:
- realized constituents/relations/topology can be captured as part of Domain State/Configuration;
- stable/invariant structural constraints can be recorded as cross-cutting conditions on state/dynamics;
- type-based structural taxonomies vary strongly by domain;
- a separate structure child creates leakage risk in social/institutional and digital cases where identity/meaning/authority may belong partly to Actors or Information.

Reopen if later child research shows structure has distinct first-order semantics that cannot be represented without forced fit.

## Why these are not merely incidental dimensions

The hierarchical method warns against promoting `state` and `dynamics` automatically.

They are promoted here only after the child test because:
- each defines a stable independent research question;
- each exposes distinct omissions/failures;
- materially different domains require both;
- later reasoning changes if one is missing;
- external traditions repeatedly preserve the distinction even though their exact ontologies differ.

They remain non-exclusive analytical problem branches, not object buckets.
