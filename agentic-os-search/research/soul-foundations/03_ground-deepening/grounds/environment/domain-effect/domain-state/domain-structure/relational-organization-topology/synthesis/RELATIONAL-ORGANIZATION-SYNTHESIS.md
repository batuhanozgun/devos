## Protected question

> **How are the materially relevant constituents actually structurally organized relative to one another and, where necessary, to the selected reference frame at the selected time?**

The node protects realized organization facts after constituency has been established.

Examples include, when materially structural:
- connection / adjacency / reachability organization;
- dependency / support relations;
- interfaces and cross-boundary links;
- relative placement/orientation;
- containment, contact, overlap and separation;
- hierarchy, layering and ordering;
- supply, market and institutional relation structure;
- higher-order/non-pairwise relations.

## Why it remains distinct from Constituent Composition

The accepted sibling asks:

> which constituents actually make up or participate in the selected whole?

Relational Organization asks:

> how are those constituents structurally organized?

Independent failure surface:

```text
correct constituent set
+
wrong relation/arrangement structure
=
Relational Organization failure
```

This repeatedly survives software dependencies, physical assemblies, system-of-systems, ecology, spatial systems, supply networks and institutions.

## Why `Topology` is not retained

The word does not maintain one reliable semantic boundary:
- Cisco uses topology for physical/logical node placement/interconnection and may include logical data flow;
- OGC uses topology for spatial relation families;
- network science uses topology across graphs, higher-order networks, hypergraphs and related formal structures.

Those are useful external vocabularies, but none should define the project node.

`Relational Organization` preserves the common analytical problem without committing to graph, network-only or pairwise semantics.

## Immediate-child audit

### Connectivity / Dependency

Not promoted.

Connection and dependency differ semantically, but no stable universal recovery branch emerges. Both remain typed structural relations inside the same higher-order question.

### Spatial / Geometric Organization

Not promoted.

Spatial relation can be structurally critical, but mechanical assembly, networking and GIS show it as a relation family/domain profile rather than a universal project child.

### Interfaces / Boundaries / Couplings

Not promoted.

An extant interface is a structural relation. Interaction through it is Dynamics; strength/health/capacity may be Condition; interface requirements/models are representation/specification surfaces.

### Hierarchy / Layering / Order

Not promoted.

Hierarchy is one organizational form. NIST explicitly notes that some systems are non-hierarchical.

### Pairwise versus Higher-Order Relations

Not promoted.

Higher-order network research proves that graph edges are not a universal relation primitive. This creates an arity/representation guardrail rather than a new child branch.

### Local Relations versus Global Patterns

Not promoted.

Reachability, bottlenecks, redundancy, clustering and hierarchy can summarize/derive global organization. Numeric metrics may become Condition characteristics when the value itself is the protected question.

## Boundary details

### Condition

A structural relation can have realized characteristics:
- latency;
- distance;
- strength;
- capacity;
- centrality/density/redundancy metric;
- health/quality standing.

If the current value or criterion-relative standing is the protected question, the case may belong to Domain Condition rather than becoming a Relational Organization child.

If the actual relation pattern/organization itself is the protected question, it remains here.

### Dynamics

Current organization is a snapshot/state-side fact.

Flow, interaction, exchange, communication, shipment or causal process through a relation can be Dynamics. Rewiring is change; the resulting relation structure is current Relational Organization.

### Actors

Reporting/hierarchy can be structurally relevant, but authority, permission, obligation, competence and delegation require Actor-side semantic testing. Org-chart edge appearance does not decide ownership.

### Information / representation

Architecture diagrams, topology maps, dependency graphs, routing/configuration tables, GIS assertions and digital twins are not actual organization by identity. They may be evidence/models of it.

Potential or required links are also distinct from realized links.
