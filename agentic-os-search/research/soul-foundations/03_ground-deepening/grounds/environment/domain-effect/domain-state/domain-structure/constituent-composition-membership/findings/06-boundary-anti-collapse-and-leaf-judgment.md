## Result

No stable immediate-child split survives strongly enough to justify recursive promotion.

## Strong boundaries

### Versus Relational Organization / Topology

```text
which constituents make up / participate in the selected whole
≠
how those included constituents are structurally connected / arranged / interfaced
```

Membership may be evidenced by relations in some network definitions, but this does not erase the different protected question.

### Versus Domain Condition

```text
constituent absent / not included
≠
constituent included but unhealthy / unavailable / inactive / degraded
```

Structural cardinality can be composition when it is the number of actual constituent instances. Quantitative properties such as concentration/load/fraction may instead be Condition when the value itself is the protected question.

### Versus Domain Dynamics

```text
current constituent composition at t
≠
join / leave / add / remove / replacement event or trajectory
```

A before/after membership snapshot belongs here; the transition belongs to Dynamics.

### Versus Information / representation

```text
actual constituent composition
≠
BOM / SBOM / inventory / registry / architecture model / configuration baseline / observation by identity
```

A representation may be excellent evidence and may be controlled to match reality, but does not become the realized composition merely by being authoritative.

### Versus Actors

```text
person / organization is a current structural constituent/member
≠
its authority / obligation / competence / accountability / representational role
```

Membership can carry a role relation, but Actor semantics are not owned by Composition.

### Versus normative criteria

```text
actual included constituents
≠
required / allowed / intended constituents
```

Specification can be compared with reality later; do not silently turn the specification into actual membership.

### Versus spatial containment

```text
inside / located within
≠
part of / member of / constituent of by default
```

Containment can support constituent status only when the domain-valid constituent relation says so.

## Candidate children rejected

Not promoted:
- Constitutive Parthood / Composition;
- Participation / Membership;
- Nesting / Hierarchy / Aggregation;
- Temporary / Fuzzy / Peripheral Participation;
- Boundary / Scope;
- Identity / Continuity;
- Multiplicity / Cardinality / Amount;
- Type versus token composition;
- physical / software / biological / social constituent types.

Why:
- some are constituent-relation forms;
- some are recursive scope/granularity forms;
- some are cross-cutting dimensions;
- some leak into Condition/Dynamics/Information/Actors depending protected question;
- type-based taxonomies do not generalize.

## Internal problem map retained inside the leaf

A later SOUL reasoning system still needs to handle:
1. selected whole/reference scope;
2. constituent identity/type resolution at the needed granularity;
3. constituent-relation semantics (`part`, `member`, `participant`, `ingredient/material constituent`, etc.);
4. actual inclusion/exclusion;
5. recursive nesting/decomposition;
6. structural multiplicity/cardinality where load-bearing;
7. temporal validity at the selected snapshot;
8. multi-whole participation;
9. identity/replacement boundary;
10. actual-versus-represented evidence separation.

These are not schema fields or ontology primitives implied by this finding.
