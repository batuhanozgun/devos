# Domain State Finding 08 — Rival Decomposition and Immediate-Child Result

**Status:** active-node integrative finding; pending final omission audit  
**Date:** 2026-09-02

## Question

Which decomposition best preserves the Domain-State problem without turning the research tree into an ontology/data-model taxonomy?

## Rivals tested

### A — State is a leaf

```text
Domain State
```

Strength:
- maximally simple;
- philosophical `state of affairs/fact` accounts can treat objects, properties and relations together.

Failure:
- repeatedly loses the distinction between wrong **domain organization/composition** and wrong **condition/status**;
- these failures require different recovery questions and recur across software, manufacturing, institutional, ecological and market cases.

**Judgment:** too compressed.

---

### B — Structure / Composition + Condition / Status

```text
Domain State
    ├─ Domain Structure / Composition
    └─ Domain Condition / Status
```

Strengths:
- smallest split that preserves the recurring failure distinction;
- structure combines constituents with organizing relationships/topology rather than mirroring graph primitives;
- condition combines current properties/qualities/values/status without creating domain-type taxonomies;
- both can remain explicitly reality-side and non-identical to their representations;
- works across physical, digital, social/institutional and hybrid domains;
- leaves Dynamics cleanly outside current State.

**Judgment:** strongest current result.

---

### C — Constituents + Relations/Topology + Properties/Status

```text
Domain State
    ├─ Constituents / Membership
    ├─ Relations / Topology
    └─ Properties / Status
```

Strength:
- maps closely to graph/fact/ontology formalisms.

Failure:
- constituent set and structural relations jointly answer the same first-order question: what is actually there and how is it structurally organized;
- external systems definitions usually bind elements + relationships into `structure`;
- separate promotion mainly follows data-model primitives and creates unnecessary hierarchy.

**Judgment:** over-decomposed for current purpose.

---

### D — Structure + Condition + Identity

Identity is decision-critical but spans both children and the Dynamics sibling; it has no universal Domain-State-only criterion.

**Judgment:** Identity remains cross-cutting.

---

### E — Structure + Condition + Constraints

Constraints/invariants govern possible/admissible states and often transitions. Their represented formulations can live in Information; a currently binding realized condition can already be expressed in Condition/Status.

**Judgment:** cross-cutting possibility/admissibility dimension, not third State child.

---

### F — Structure + Condition + Space/Time

Space/time index the state and structural relations but do not define an independent first-order State problem across all domains.

**Judgment:** cross-cutting reference dimensions.

---

### G — physical / digital / social / institutional State children

These are domain specializations, not universal problem regions. Each domain again requires structure/composition and condition/status questions.

**Judgment:** rejected as universal hierarchy.

---

### H — `Situation` or `State of Affairs` as replacement

These frames can unify objects/properties/relations and are useful counterframes.

However:
- `situation` risks collision with contextual relevance and activity framing;
- `state of affairs` imports a philosophical/formal ontology problem;
- neither improves the project-level failure distinction enough to displace the simpler `Domain State` label.

**Judgment:** useful counterframes, not stronger current project label.

---

## Strongest current immediate hierarchy

```text
Domain State
    ├─ Domain Structure / Composition
    └─ Domain Condition / Status
```

Branches are analytical problem regions, not exclusive kinds of entities.

## Cross-cutting dimensions retained explicitly

- scope / reference frame;
- identity / continuity;
- granularity / state sufficiency;
- constraints / invariants;
- spatial/temporal index;
- actual-versus-represented boundary;
- observability/currentness/provenance of representations.

## Final challenge still required

Before closure, the completion audit must still try to find:
- a recurrent third State-local problem outside both children;
- a forced-fit case caused by grouping constituents + relations;
- a reason identity or constraints deserve promotion after all;
- evidence that structure/condition is merely a modeling convention with no distinct SOUL/Development-OS reasoning consequence.
