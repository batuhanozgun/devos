# Realized Characteristics Finding 01 — Node Coherence and Label

**Status:** bounded finding  
**Date:** 2026-09-04

## Question

Does the promoted `Realized Characteristics / Values` region remain coherent at its own depth, and is the paired label still the strongest wording?

## Result

**The node remains coherent, but the preferred semantic label simplifies to `Realized Characteristics`.**

Protected question:

> **What materially relevant non-structural characteristics actually obtain for the selected bearer, relation or whole at the selected time, before asking whether they satisfy a separate criterion?**

This includes, when material:
- quantitative magnitudes;
- qualitative/categorical characteristics;
- current mode/regime descriptors;
- relation-valued characteristics;
- whole/aggregate/emergent characteristics;
provided the protected question is what currently obtains rather than structure, transition/history or criterion-relative standing.

## Why retain `Realized`

`Characteristic` alone can name a characteristic kind, specification, schema field, desired attribute or observable property. `Realized` keeps the research node on the actual-condition side:

```text
specified / possible / observable characteristic
≠ characteristic that actually obtains
```

## Why drop `/ Values`

`value` is useful explanatory vocabulary but too ambiguous as a co-primary node label:
- VIM uses quantity value for a number + reference expressing magnitude;
- nominal properties also have values expressed through words/codes;
- measured values and observation results are attributed/estimated information surfaces;
- W3C SSN explicitly treats observation results as information items with many data forms.

The reality-side node must not silently become a value-record/data-type bucket.

Dropping `Values` does **not** deny that an actual characteristic can have a true/current magnitude or category. It only keeps representation and expression from defining the node.

## Why not `Realized Properties`

`property` is workable, but source traditions use it for:
- property kinds;
- observable/actuatable property definitions;
- intrinsic/extrinsic metaphysical properties;
- database/model attributes.

`Realized Characteristics` is less committed to any one ontology or formalism and aligns with the project’s problem-oriented naming style.

## Coherence test

The region has one stable recovery question across domains:

> reconstruct what current non-structural characteristic actually obtains for the relevant bearer/scope.

Changing the value form, measurement method, domain or bearer level does not change that first-order recovery task.

## Falsifier judgment

- F1 inherited paired label optimal: **rejected**.
- F2 `Values` should be dropped/demoted: **supported**.
- F3 `Characteristics` necessarily absorbs Structure/Standing/Dynamics: **rejected under protected-question boundaries**.

Domain Condition
