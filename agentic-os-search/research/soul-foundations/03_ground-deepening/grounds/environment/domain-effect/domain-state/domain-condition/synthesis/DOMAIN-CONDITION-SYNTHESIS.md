# Domain Condition — Integrated Synthesis

**Status:** BOUNDEDLY SUFFICIENT FOR CURRENT IMMEDIATE-CHILD PURPOSE; AWAITING USER EVALUATION  
**Date:** 2026-09-03  
**Scope:** Environment → Domain Reality → Domain State → node inherited as `Domain Condition / Status`; immediate-child discovery only

## Executive result

The inherited node survives deeper research, but its label and internal map refine.

Starting label:

```text
Domain Condition / Status
```

Strongest current bounded result:

```text
Domain Condition
    ├─ Realized Characteristics / Values
    └─ Criterion-Relative Standing / Status
```

The children are analytical problem regions, not object classes, database field types or architecture modules.

The core distinction is:

> **What current characteristics/values/modes actually obtain?**  
> versus  
> **Given a relevant criterion, what standing currently obtains?**

This distinction repeatedly changes failure analysis and recovery across technical, physical, ecological, market and institutional domains.

---

# 1. Why the node is renamed to Domain Condition

`Status` is too overloaded to remain a co-primary parent synonym.

Depending on context, `status` can be:
- a real categorical standing;
- an operating/lifecycle mode;
- an API or registry field;
- a report/cache;
- a derived health/quality classification.

The broader surviving reality node is therefore:

> **Domain Condition**

with the working definition:

> **Domain Condition is the materially relevant non-structural condition that actually obtains for selected domain constituents or a selected domain whole at a selected scope and time, including realized characteristics/values and materially relevant criterion-relative standings.**

This does not imply full observability or a single state vector.

---

# 2. Child A — Realized Characteristics / Values

Primary question:

> **What materially relevant characteristics, quantities, qualitative values, modes or relational conditions actually obtain at the selected scope and time, before asking whether they satisfy a separate criterion?**

Includes when material:
- temperature, pressure, concentration, load, price, spread, depth;
- current wear/damage or other physical/biological condition;
- operating mode/regime such as Manual/Test/Running/Paused when it simply states which regime obtains;
- current qualitative characteristics;
- current relational condition/value when the protected question is the condition itself.

This is not a scalar/attribute database bucket. Values can be categorical, qualitative, quantitative or relational.

## Failure surface

Examples:
- wrong current temperature/load/price;
- wrong current mode;
- missing load-bearing current property;
- wrong condition value despite correct structure;
- correct status classification with incomplete/wrong non-load-bearing characteristic detail.

---

# 3. Child B — Criterion-Relative Standing / Status

Primary question:

> **Relative to a materially relevant functional, normative, regulatory or domain criterion, what standing currently obtains for the selected constituent or whole?**

Includes when material:
- healthy / degraded / failed;
- ready / not ready;
- acceptable / unacceptable;
- compliant / non-compliant;
- valid / invalid;
- in good standing / not in good standing;
- severity/quality standing relative to a defined criterion.

The criterion itself is not automatically a Condition fact. It may be a requirement, rule, threshold, function definition or other later Information/control relation. The Condition-side fact is the **realized standing relative to that criterion**.

## Failure surface

Examples:
- underlying condition facts are correct but the wrong threshold/rule is applied;
- the relevant criterion is stale or inapplicable;
- a status/health report is correct syntactically but wrong about the actual standing;
- the true standing is known while some underlying non-load-bearing characteristic remains uncertain.

These failures require different recovery from simply reconstructing current characteristics.

---

# 4. Why the split qualifies as immediate children

## Distinct first-order questions

```text
what obtains?
vs
how does what obtains stand relative to the relevant criterion?
```

## Distinct dependency structure

The second question requires a criterion/relation in addition to the current condition facts. The first does not necessarily require a normative/functional criterion.

## Distinct recovery paths

A reasoner can correctly recover current values yet misclassify health/compliance because it selected the wrong criterion. Conversely, a current standing can sometimes be authoritatively established without reconstructing every underlying detail.

## Cross-lineage convergence

Materially different traditions repeatedly expose the distinction:
- SEBoK state vocabulary separates property/value state from health/potential usage;
- NASA separately requires system state/mode and system health information;
- ISO monitoring standards separate measurement from assessment criteria/interpretation;
- ISO quality is explicitly requirement-relative;
- NIST health/condition management derives/assesses health using condition information;
- software readiness is distinct from mere running mode;
- institutional good standing is a rule-relative status rather than a bare physical property.

This convergence challenges rivals; it does not independently prove the project hierarchy.

---

# 5. Health is not a primitive child

`Health` can appear in two semantic roles.

### Underlying realized condition

Wear, damage or degradation level may be a realized characteristic/value.

### Criterion-relative health standing

Healthy/degraded/failed may express standing relative to expected function, thresholds or health criteria.

Therefore a universal `Health` child would collapse underlying condition and evaluation.

---

# 6. Mode / lifecycle status is not a third child

Current mode can be a realized characteristic:

```text
mode = Manual
phase = Running
regime = Test
```

A mode transition is Dynamics.

A criterion-relative readiness status can instead belong to the second child.

The word `status` alone therefore does not determine semantic ownership.

---

# 7. Capability, availability and reliability

No dedicated universal Condition child survives.

- current capacity/load may be a realized characteristic/value;
- current readiness/operability can be criterion-relative standing;
- capability is generally ability under specified conditions;
- availability can be probabilistic and time-averaged/asymptotic;
- reliability explicitly concerns functioning without failure over a period.

Thus these notions can cross Condition, Dynamics, Work Conditions and representation/model semantics depending on the protected question.

---

# 8. Constraints, requirements and compliance

Keep:

```text
rule / threshold / requirement
≠ current condition by identity
```

but:

```text
current fact that the condition satisfies/violates the criterion
→ possible Criterion-Relative Standing / Status
```

This preserves constraints/invariants as cross-cutting while giving current compliance/validity a clear Condition route.

---

# 9. Whole versus constituent condition

Not promoted as children.

A component and a whole can each have:
- realized characteristics/values;
- criterion-relative standing/status.

Aggregation is domain/purpose dependent. Whole health may be dominated by a critical part, protected by redundancy, or emergent from interactions. Therefore whole/constituent is a **scope/aggregation dimension**, not a universal child split.

---

# 10. Intrinsic / relational and datatype rivals

Not promoted.

Intrinsic/extrinsic and relational/non-relational property distinctions do not provide one stable universal partition. Likewise scalar/categorical/qualitative/Boolean distinctions are value/representation forms.

The project split is semantic/problem-role based rather than property-metaphysics or data-model based.

---

# 11. Actual Condition versus representation

The deeper pass strengthens the existing boundary:

```text
actual realized characteristic/value
≠ measurement / sensor reading / estimate / model value / database field

actual criterion-relative standing
≠ health score / API status / dashboard / certificate / assertion by identity

criterion / rule / threshold
≠ reported evaluation by identity
```

This does not mean socially or institutionally constituted standing is unreal. A legal standing can genuinely obtain under institutional rules while any particular registry record/certificate can still represent it incorrectly or stale-ly.

---

# 12. Boundaries to siblings and other grounds

## Structure

```text
what participates / how organized
≠ current characteristics or criterion-relative standing
```

## Dynamics

```text
current value/mode/standing
≠ transition/trend/history/degradation trajectory/future projection
```

## Information

Observation, measurement, inference, health models, status fields, certificates and rule representations are not actual Condition by identity.

## Actors

Institutional standing can be Domain Condition; actor identity, authority, responsibility and who grants/revokes standing remain Actors semantics.

## Work Conditions

The same realized fact can play Domain Condition or Work Condition depending on the focal Work role. Role switching does not create a new child.

## Causality

Current abnormal/degraded condition does not establish why it occurred.

# 13. Cross-domain holdout result

The two-child candidate survived materially different cases:
- deployed software/service systems;
- physical machine/manufacturing assets;
- infrastructure/process systems;
- ecological systems;
- financial/market conditions;
- institutional/legal standing;
- scientific specimen/experimental targets;
- hybrid cyber-physical/digital-twin targets;
- whole-versus-constituent aggregation;
- Domain Condition ↔ Work Condition role switching.

No recurrent third Condition-local first-order region was forced.

---

# 14. Parent impact

The Domain State parent remains:

```text
Domain State
    ├─ Domain Structure
    │    ├─ Constituent Composition / Membership
    │    └─ Relational Organization / Topology
    └─ Domain Condition
         ├─ Realized Characteristics / Values
         └─ Criterion-Relative Standing / Status
```

Deeper Condition research does **not** currently force a third co-equal Domain State child or reopen the Structure-versus-Condition split.

The previous parent-level label `Domain Condition / Status` should be treated as a historical/inherited label; current-facing surfaces should use `Domain Condition`.

---

# 15. What this hierarchy does not mean

It does **not** imply:
- two database sections or field types;
- every domain materially exercises both children;
- standing is always explicitly stored or measured;
- characteristics are directly observable;
- health is always a standing rather than an underlying condition;
- categorical mode automatically belongs to Status;
- a criterion/rule belongs inside Environment by identity;
- all condition facts classify exclusively without contextual role overlap;
- Structure/Condition/children are architecture modules.

The branches protect different reasoning failures, not a clean object partition.

---

# 16. Verification and closure

The frozen F1–F16 falsifiers were explicitly audited.

Strongest material changes from the inherited hypothesis:
- parent label refines from `Domain Condition / Status` to `Domain Condition`;
- leaf hypothesis F16 is rejected;
- F2 survives with stronger semantic framing as current characteristics versus criterion-relative standing;
- health, mode, availability, whole/constituent, intrinsic/relational and type-based rivals do not survive as third children.

Late cross-domain and counterframe searches mostly refined role/boundary rules rather than exposing another first-order region. Broad Condition search therefore reached bounded sufficiency for the current immediate-child purpose.

The completion/omission audit is same-model adversarial self-review, **not independent verification**. External sources discriminate rival hypotheses but do not independently validate the exact hierarchy.

## Bounded answer

> **The Domain State child previously labeled `Domain Condition / Status` is better framed as `Domain Condition`. At this deeper resolution, two immediate research regions survive: `Realized Characteristics / Values` asks what current condition facts/modes actually obtain; `Criterion-Relative Standing / Status` asks what current standing obtains relative to a materially relevant criterion. Health, mode, capability, whole/constituent level, property form and observed/reported status do not justify additional universal children.**
