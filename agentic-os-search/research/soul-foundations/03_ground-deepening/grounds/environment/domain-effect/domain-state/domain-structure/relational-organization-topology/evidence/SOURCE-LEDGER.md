## External challenge sources

### Systems engineering / general structure

**SEBoK — Structure, Identity, and Function in Systems**  
https://sebokwiki.org/wiki/Structure%2C_Identity%2C_and_Function_in_Systems
- Current SEBoK v2.14 framing treats structure as arrangement of components and relationships among them across physical, living, social and conceptual systems.
- Useful against reduction of Structure to membership only.
- Also supports keeping identity distinct from current organization.

**SEBoK — Structure glossary**  
https://sebokwiki.org/wiki/Structure_%28glossary%29
- Structure includes physical/logical layout and internal/external connections; also summarizes static existence as elements plus relationships.
- Challenge value: confirms organization/connectivity as a distinct structural problem while not dictating child taxonomy.

**SEBoK — Product as a System Fundamentals**  
https://sebokwiki.org/wiki/Product_as_a_System_Fundamentals
- Connections encompass interactions and relationships; listed relationship forms include spatial, motion-related, temporal and social.
- Challenge value: materially weakens a universal `connectivity vs spatial` child split because a systems tradition treats multiple relation semantics inside a common connections/relationships family.
- Caution: the page is broader than the project Structure/Dynamics boundary; the project must not import its temporal/interaction categories wholesale.

**NIST SP 800-160 Vol. 1 Rev. 1 — Engineering Trustworthy Secure Systems**  
https://nvlpubs.nist.gov/nistpubs/SpecialPublications/NIST.SP.800-160v1r1.pdf
- Notes that not all systems are hierarchical; non-hierarchical system models should reflect relationships among constituent elements.
- Treats interfacing systems and one-way/bidirectional resource-exchange interfaces explicitly.
- Challenge value: hierarchy is a structural form, not a universal branch; interfaces are relation forms across system boundaries.

**NASA — Product Integration**  
https://www.nasa.gov/reference/5-2-product-integration/
- Defines interfaces as pathways of system interactions and lists mechanical, fluids, thermal, electrical, data, logical and human interface types.
- Challenge value: interface semantics are plural but converge on a common interface/relationship problem; interaction through an interface must remain distinct from the extant interface relation.

**NASA — System Design Processes**  
https://www.nasa.gov/reference/4-0-system-design-processes/
- System architecture work defines underlying structure and relationships; interfaces and relationships among partitioned subsystems/elements are explicit.
- Challenge value: organization/relationship is structurally material but architecture is a representation/design surface, not automatically actual structure.

### Network/topology terminology

**Cisco — What Is Network Topology?**  
https://www.cisco.com/site/us/en/learn/topics/networking/what-is-network-topology.html
- Uses topology for physical/logical structure, node placement and interconnection; logical topology may also describe data flow.
- Challenge value: `Topology` is too overloaded as a project companion label because it may include constituent placement, interconnections and even flow/dynamics.

**SIAM Review — What Are Higher-Order Networks?**  
https://epubs.siam.org/doi/10.1137/21M1414024
- Graphs encode pairwise relations; higher-order networks generalize beyond dyads.
- Challenge value: the project node must not silently mean graph edges or pairwise connectivity. Relation arity is a form/dimension, not evidence by itself for a new child.

**Nature Physics — The physics of higher-order interactions in complex systems**  
https://www.nature.com/articles/s41567-021-01371-4
- Highlights real systems with group interactions not reducible to pairwise links.
- Challenge value: protects the semantic node from graph-schema collapse.

### Spatial/geographic organization

**OGC GeoSPARQL 1.1**  
https://docs.ogc.org/is/22-047r1/22-047r1.html
- Standardizes a spatial topological relation family including equals, disjoint, intersects, touches, crosses, within, contains and overlaps.
- Challenge value: spatial/topological relations can be structurally rich, but this is a domain relation family rather than evidence for a universal project child.

### Physical/mechanical assembly

**Autodesk Fusion — Assembly relationships**  
https://help.autodesk.com/view/fusion360/ENU/?contextId=ASM-JOINTS
- Treats constraints and joints as component relationships defining relative position, degrees of freedom and motion allowances.
- Challenge value: spatial placement and mechanical connection/constraint semantics coexist inside a common assembly-relationship problem rather than requiring a universal split.

**Autodesk Inventor 2026 — Assembly Constraints**  
https://help.autodesk.com/cloudhelp/2026/ENU/Inventor-Help/files/GUID-CF4462AF-CEC6-4B8B-8F86-72D9AC9A3574.htm
- Constraints establish orientation and mechanical relationships among components.
- Challenge value: physical arrangement is naturally relation-relative and can be contained by Relational Organization when actual organization is the protected question.

**NIST — Representations and Methodologies for Assembly Modeling**  
https://www.nist.gov/publications/representations-and-methodologies-assembly-modeling
- Assembly design includes constraints, relative motion, fit and joint-strength requirements.
- Challenge value: reinforces relation-semantic plurality; also reminds that design representations/requirements are not actual organization by identity.

https://docs.aws.amazon.com/applicationsignals/latest/APIReference/API_DependencyGraph.html

## Evidence-status summary

The external challenge set supports all of the following simultaneously:
- realized structural relations are a recurrent independent problem beyond Constituent Composition;
- relation semantics are heterogeneous and can include spatial, dependency, interface, hierarchical, higher-order and institutional forms;
- no external tradition establishes a universal `connectivity vs spatial` or `dependency vs connection` project split;
- topology terminology is materially overloaded across networking, GIS and higher-order mathematics;
- actual organization must remain distinct from representations, potential/intended relations, current condition metrics and process/change dynamics.

No source independently validates the exact SOUL hierarchy or the bounded-leaf judgment.
