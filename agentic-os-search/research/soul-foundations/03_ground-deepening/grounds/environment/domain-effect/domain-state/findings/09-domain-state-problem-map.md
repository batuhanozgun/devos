# Domain State Finding 09 — Problem Map and Failure Surfaces

**Status:** active-node integrative problem map  
**Date:** 2026-09-02

## Current strongest hierarchy

```text
Domain State
    ├─ Domain Structure / Composition
    └─ Domain Condition / Status
```

These are analytical problem branches, not mutually exclusive fact/entity classes.

---

# A. Domain Structure / Composition

Primary question:

> What materially relevant constituents are actually present, and how are they actually composed/organized/connected at the selected scope/time?

## A1 — Participation / membership / presence

- Which constituents are actually present/in scope?
- Is a required/expected constituent absent?
- Is an unexpected constituent present?

Failure:
- missing/extra/wrong constituent;
- wrong domain scope;
- representation/inventory mistaken for actual membership.

## A2 — Part–whole composition / nesting

- What is part of what?
- Which nested/subsystem/grouping relationships currently obtain?
- Which level of composition is load-bearing for the protected reasoning?

Failure:
- wrong decomposition/aggregation;
- wrong whole/part assumption;
- cross-level facts mixed without reference.

## A3 — Structural relations / topology / arrangement

- Which current connections/dependencies/containment/placement/organizational relations matter?
- What realized topology/arrangement obtains?

Failure:
- stale/wrong topology;
- a correct constituent set arranged incorrectly;
- an inferred/design connection mistaken for actual connection.

## A4 — Structural integrity of the selected whole

- Does the current arrangement still constitute the relevant whole/system/situation for this analysis?

Failure:
- identity/continuity silently changes because a structural change crosses a domain-specific identity threshold.

Identity criterion itself remains cross-cutting, not a child.

---

# B. Domain Condition / Status

Primary question:

> What materially relevant properties, qualities, values, health, mode, status or standing actually hold at the selected scope/time?

## B1 — Constituent condition

- What current condition/property values hold for a constituent?
- Is it healthy/degraded/available/valid/active/etc. in the Domain role?

Failure:
- stale/wrong value/status;
- reported status substituted for actual condition.

## B2 — Whole/domain condition

- What condition or quality holds for the selected whole/domain rather than only one part?
- Are emergent/aggregate current properties material?

Failure:
- part-level values assumed sufficient for whole-state judgment;
- aggregation hides a load-bearing local condition.

## B3 — Current mode / standing / validity

- What current mode, phase-independent status or institutional/social standing obtains?
- Is a current institutional/relational status valid/operative?

Failure:
- represented entitlement/status mistaken for actual standing;
- Actor/Information semantics swallowed by Environment instead of retaining only the Domain role.

## B4 — Current quantitative/qualitative values

- Which current values/qualities materially matter for Work/outcome grounding?

Failure:
- wrong granularity or stale measurement/report;
- selected value omits a load-bearing condition.

# Cross-cutting dimensions — explicit but not immediate children

## C1 — Reference / scope / boundary

Determines which Domain State and which whole/constituents are at issue.

## C2 — Time index / currentness

A State claim must be anchored to relevant time; `current` is not synonymous with `most recently recorded`.

## C3 — Actual versus represented

Applies to both branches:
- actual structure vs architecture/inventory/model;
- actual condition vs measurement/status/report.

## C4 — Identity / continuity

Needed to decide whether a structural/condition difference is change in the same thing, replacement, split/merge or boundary change. Crosses State and Dynamics.

## C5 — Granularity / state sufficiency

Which facts must be included is purpose/reference-relative. This is not one intrinsic universal state vector.

## C6 — Constraints / invariants / admissibility

Constrains possible/valid structures, conditions and transitions; is not generally identical to the current State that satisfies/violates it.

## C7 — Observability / evidence / uncertainty

Actual State may be hidden. Observation, inference, confidence, provenance and conflict belong primarily to Information/composition.

## C8 — Causal explanation

A current degraded/wrong condition may be caused by Structure, Dynamics, Work, Actors or Work Conditions. State classification describes **what obtains**, not by itself the root cause.

Therefore:

```text
current condition/status ≠ causal explanation of that condition
```

## C9 — Role switching

The same concrete fact may participate as Domain State for one Work and Work Condition for another. Semantic ownership remains role-relative.

# Important non-collapse distinctions

```text
Domain State ≠ one formal/model state vector
actual Structure ≠ design/baseline/inventory by identity
actual Condition ≠ measured/reported status by identity
Structure ≠ Dynamics
Condition ≠ Dynamics
Identity/continuity ≠ constituent child
constraint/invariant ≠ current state by identity
current State difference ≠ causal root cause
```

## Productive-decomposition result

The two-child split changes research/recovery behavior:
- Structure/Composition asks whether we have the right realized **things and organization**;
- Condition/Status asks whether those things/the whole have the right realized **current condition/standing**.

A later child pass can deepen either independently. This pass does not authorize that descent.
