## Research sequence

### D0 — Evidence and inherited-assumption inventory

Output:
- what is already strongly supported;
- what is only inherited from parent synthesis;
- unresolved Domain/Effect-local questions;
- explicit starting falsifiers.

Do not search broadly until this inventory is frozen.

### D1 — Node coherence / split-merge challenge

Test rivals such as:

```text
A. Domain / Effect Reality             [one node]
B. Domain Reality + Effect Reality     [two sibling nodes]
C. Work Domain only                    [effect is relational, not a node]
D. Controlled Process / Target System  [system/control-centric framing]
E. World / Situation                   [broader reality framing]
F. Relation-only reduction             [no dedicated node]
```

A rival wins only if it handles boundary, effects, nested targets and cross-domain cases with less forced fit.

### D2 — First-principles Domain/Effect problem inventory

Derive problems before importing external taxonomies.

Candidate questions to probe, not predetermined children:
- target/domain scope and reference frame;
- entities, processes and actual state;
- dynamics, disturbances and path dependence;
- state that Work must accommodate versus state it intends to change;
- actual effects, side effects and partial/delayed effects;
- outcome grounding and success against reality;
- coupling/action surfaces relevant to producing effects;
- controllability/influence versus merely observed domain state;
- nested target systems and role switching;
- spatial/temporal extent where load-bearing;
- causal attribution boundary;
- unknown/hidden state versus represented uncertainty.

### D3 — Immediate-child discovery

Cluster the problem inventory into the smallest stable set of first-order children.

For every candidate child ask:
- distinct first-order question?
- distinct failure mode?
- distinct reduction/boundary behavior?
- repeated cross-domain usefulness?
- materially different later SOUL/Development OS reasoning if collapsed?

Do not promote `state`, `dynamics`, `observability`, `time`, `boundary` or similar dimensions automatically; first test whether they cut across multiple children.

### D4 — Boundary / reduction tests

Attack the child map with cases where:
- target system is internal under a wider boundary;
- the same system is target in one Work and execution condition in another;
- actual state differs from observation/model/Record;
- one Work ends but effects are absent, delayed, partial or reversed;
- another Actor or Work stream changes domain state;
- domain state is social/institutional rather than physical;
- focal Work is purely analytical/diagnostic and intentionally causes no effect.

### D5 — Cross-lineage research

Use materially different traditions for falsification rather than one taxonomy source. Candidate source families:
- systems engineering / operational environment / system-of-interest;
- Cognitive Work Analysis / Work Domain Analysis;
- control theory / controlled process / disturbances;
- ecological/affordance traditions where action possibilities are relevant;
- causal intervention/effect traditions where outcome grounding is relevant;
- domain traditions with explicit world-vs-model separation;
- additional traditions discovered during search if they expose a distinct first-order problem.

No source is allowed to define the project hierarchy by authority alone.

### D6 — Cross-domain holdouts

Use deliberately different cases. At minimum include:
- software / Development OS / SOUL or KEEL product work;
- clinical treatment/diagnosis;
- physical repair/maintenance;
- scientific experiment/observation;
- market/business decision or intervention;
- robotics/autonomous operation;
- legal/institutional work;
- a case with no intended world change, only understanding/assessment;
- a case with delayed/indirect effects.

Holdouts should test the candidate child split, not merely illustrate it.

### D7 — Omission / causal-depth / rival audit

Explicitly try to find:
- a recurrent Domain/Effect-local family outside all immediate children;
- a child that is only a dimension;
- a forced split between `domain` and `effect`;
- a case where effect semantics belong mainly to Work/relation rather than Environment;
- a hidden causal assumption that converts correlation/observation into actual effect;
- a boundary choice that changes the hierarchy materially.

Same-model completion review must be labeled non-independent.

### D8 — Branch-level closure

Close the **Domain / Effect Reality node pass** when:
- node boundary is coherent or a stronger replacement is identified;
- immediate child map is explicit and adversarially tested;
- cross-cutting dimensions are separated from child branches;
- materially different later holdouts stop producing new first-order children;
- load-bearing claims have source/view recovery;
- residuals and deferred relations are explicit;
- additional broad research has declining structural information value.

Then return to user evaluation.
