# Environment Finding 02 — Parent Boundary and Reference Frame

**Status:** current Environment-ground finding  
**Question:** can a broad Environment parent remain coherent without becoming `everything relevant`?

## Current finding

Yes, but only with an explicit reference frame and exclusion rule.

The strongest current parent is not a collection of intrinsically environmental objects. It is a **boundary- and purpose-relative problem ground about realized conditions around focal Work / a working system whose state can matter independently of current Work, Actor and representation facts.**

A usable analysis must identify at least:
- the focal Work or working-system function;
- the selected system-of-interest / analysis boundary when one is material;
- which realized conditions are load-bearing to target/effect or execution feasibility;
- the interaction/coupling by which those conditions matter.

## Why a reference frame is mandatory

Systems engineering repeatedly makes system/context classification observer- and boundary-dependent. One observer's system can be another observer's system element; enabling systems and other systems are defined relative to a system-of-interest; system context is resolved around a selected SoI.

Therefore:

> `is Environment` is not a permanent intrinsic identity claim.

A CI cluster may be:
- support condition for application-development Work;
- target/domain reality for CI-maintenance Work;
- internal element of a wider controlled platform under another boundary.

The same concrete thing may change analytical role without changing physical identity.

## External convergence

### SEBoK / systems engineering

SEBoK's current Environment glossary includes surroundings in which a system-of-interest is used and supported, and also surroundings in which it is developed, produced or retired. This is unusually close to the project's need for a higher parent spanning operating and lifecycle/support conditions.

SEBoK system-context material also emphasizes selected system boundaries, wider systems and surrounding natural/social/engineered systems.

### NIST / ISO 15288

NIST distinguishes:
- system-of-interest;
- enabling systems supporting lifecycle activities;
- other systems interacting in the operational environment.

An enabling system need not be in the product's operational environment. This rejects physical containment as the parent rule while supporting a wider reference-frame analysis.

### NASA ConOps

NASA separately describes physical environment and support environment, and also requires explicit system scope, external interfaces and enabling systems. The distinction supports lower branches without requiring separate top-level project grounds.

## Exclusion rule

Reject:
- Environment = everything outside a boundary;
- Environment = everything influencing Work;
- Environment = all constraints/resources;
- Environment = all context;
- Environment = all tools/technologies.

These formulations swallow other grounds or include irrelevant facts.

A concrete thing can participate environmentally while retaining first-order semantics elsewhere:
- person/organization → Actor semantics remain;
- policy text/model → Information semantics remain;
- another activity → Work semantics remain;
- technical tool/service → may participate in a support role without becoming an intrinsic Environment class.

## Relevance threshold

Mere existence, proximity or network reachability is insufficient.

A condition belongs in the relevant Environment analysis when there is a defensible coupling by which its realized state materially affects one or more of:
- the domain/effect space of focal Work;
- feasible/safe/permitted/performant execution;
- availability of a necessary interaction/resource/interface;
- actual consequences/outcomes.

This is not yet a formal membership algorithm; it is the strongest bounded semantic rule.

## Result

The parent survives the residual-bucket challenge.

Its coherence comes from **realized, load-bearing situated conditions relative to a focal reference**, not from object taxonomy or a simple inside/outside partition.
