# Environment Finding 10 — Problem Map and Failure Surfaces

**Status:** current Environment-ground integrative finding  
**Purpose:** identify productive internal problem families without turning them into architecture/schema fields

## Current Environment problem map

The research supports a reusable set of problem families across both Environment roles.

### E1 — Reference frame / system-of-interest / focal Work

Questions:
- relative to what Work/function/system is Environment being analyzed?
- what is inside/outside/controlled versus merely coupled?
- which wider system or lifecycle phase matters?

Failure:
- hidden or stale reference frame makes all later membership claims unstable.

### E2 — Boundary / relevance / environmental participation

Questions:
- which realized conditions are load-bearing?
- through what interaction/dependence do they matter?
- what can be omitted safely?

Failure:
- `everything relevant` residual bucket or omission of a critical condition.

### E3 — Role decomposition

Questions:
- does the condition matter as Domain/Effect Reality?
- as Work Condition / enabling–constraining circumstance?
- both?

Failure:
- target and execution failures collapse; role treated as permanent entity type.

### E4 — Realized state / condition

Questions:
- what is actually true now?
- which state/condition dimensions matter to the protected analysis?

Failure:
- specified/declared/observed state mistaken for realized state.

### E5 — Dynamics / disturbance / history

Questions:
- what changes independently?
- what changes due to Work?
- which transitions, disturbances, rates or path-dependent effects matter?

Failure:
- static-context assumption; unmodelled drift/shock; delayed effect missed.

### E6 — Coupling / interfaces / resources / capacity

Questions:
- through what surfaces can Work sense, act, exchange or depend?
- what resources/capacities are necessary?
- which dependencies are shared/hidden?

Failure:
- resource exists but cannot actually support use; hidden coupling; capacity shortfall; interface mismatch.

### E7 — Constraints / hazards / permissions as realized conditions

Questions:
- what current conditions limit, prohibit, degrade or make unsafe an action?
- which are environmental facts versus represented/normative claims?

Failure:
- constraint ignored or semantic ownership collapsed into Environment.

### E8 — Observability / discoverability / model mismatch boundary

Questions:
- what is observable/inferable and with what latency/noise/coverage?
- what remains hidden?
- how can believed/specified condition diverge from actual condition?

Failure:
- confidence in a measurement/model treated as direct Environment truth.

This family defines the Environment side of the distinction; representation semantics belong to Information.

### E9 — Situated actionability / feasibility / performance relation

Questions:
- given Environment condition, what action possibilities or performance envelopes become available/unavailable relative to Actor/Work?

Failure:
- intrinsic capability claim used where situational feasibility is required.

Actionability is cross-ground/relational; Environment supplies load-bearing condition-side facts.

### E10 — Effects / outcome grounding

Questions:
- what actual environmental state changes did Work cause?
- what side effects/partial effects occurred?
- what state defines real-world success/failure?

Failure:
- Work completion/acceptance substituted for actual domain effect.

### E11 — Nesting / role switching / boundary lifecycle

Questions:
- does the same system/resource change role across Work?
- do system boundaries change with coupling/control/lifecycle?
- are nested environments/support contexts being confused?

Failure:
- permanent object classification; double identity; stale boundary.

### E12 — Specialized environment branches

Question:
- does a domain require deep semantics below Domain/Effect or Work Conditions?

Known deep specialization:
- Technical Work Environment under Work Conditions.

Potential future specializations may be physical/laboratory/field/institutional profiles, but none is currently justified as a universal separate top-level branch merely by domain vocabulary.

## Cross-cutting distinctions to preserve

```text
actual condition ≠ specification ≠ observation ≠ model ≠ Record
Work closure ≠ environmental effect
Actor capability ≠ situated actionability
tool/resource identity ≠ environmental role
externality ≠ relevance
support ≠ positive-only; constraints/degradation are constitutive conditions
same concrete thing ≠ same analytical role across Work
```

## Productive decomposition result

Environment is not just a broad label. It opens coherent research questions and failure modes at multiple depths.

This satisfies the `productive decomposition` requirement for a top-level research ground without establishing one ontology, graph model, database schema or architecture module.
