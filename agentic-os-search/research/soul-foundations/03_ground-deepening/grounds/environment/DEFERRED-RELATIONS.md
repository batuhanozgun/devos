# Environment / Operating Reality — DEFERRED RELATIONS

**Status:** cross-ground observations captured during Environment research; not solved here  
**Rule:** these are not evidence for another ground and do not authorize parallel research

## Environment ↔ Information / Representation

- How should actual Environment state be related to observation, signal, model, assumption, forecast, specified operating envelope and persistent Record?
- Which uncertainty/freshness/conflict semantics belong to representation rather than Environment?
- How should evidence support claims that a realized condition existed at a relevant time?
- How should selected context be derived from a much larger Environment without treating context as the Environment itself?

Environment-local rule already established:

> actual condition ≠ specification/observation/model/Record

The representation side remains for the later Information pass/composition work.

## Environment ↔ Work

- How should Work target/effect relations distinguish intended outcome, performed action and actual Environment effect?
- How should execution conditions/resources make Work ready/blocked/degraded without duplicating Work lifecycle state?
- How should Work that provisions/repairs/changes an environment be represented when the support environment becomes the Work target?
- How should one Work's produced effects become another Work's Environment condition?

Environment-local rule already established:

> Work closure/status ≠ actual Environment state/effect

## Environment ↔ Actors

- How should Actor capability/competence combine with Environment condition to derive situated actionability?
- How should access/permission/authority interact with physical/technical/institutional feasibility?
- How should persons/organizations that create realized Environment conditions remain Actors simultaneously?
- How should support personnel be represented without turning Actor identity into an Environment object class?

Environment-local rule already established:

> Actor capability ≠ situated actionability
