# Work Ground — Coverage / Gap Audit Synthesis

**Status:** bounded audit synthesis / awaiting user evaluation  
**Date:** 2026-09-05  
**Scope:** Work as one of the accepted four Foundation grounds after Environment and Information deepening

## 1. Executive conclusion

The independent Work vertical remains sufficient for the current Foundation purpose after being re-tested against:

- the now-accepted Environment / Operating Reality boundary;
- the now-accepted Information / Representation boundary;
- the existing Actors authority/capability distinctions;
- newer agentic-system candidate studies;
- new omission/reduction/rival tests.

The audit did **not** find a material Work-local first-order gap requiring new substantive Work research.

The strongest current Foundation-level formulation remains:

> **Work concerns the organization and evolution of pursuits over time: how possible pursuits toward purposes/outcomes are selected or rejected, structured, admitted, enacted, coordinated, monitored/evaluated, adapted, concluded or recovered under dependencies and constraints.**

This is a research-ground formulation, not an ontology primitive or architecture module.

## 2. What the audit changed

The main effect is not a new Work taxonomy. It is a sharper boundary around what the prior Work distinctions mean under the four-ground frame.

### 2.1 Actual Work state vs informational Work state

A plan, ticket, status report, test result, acceptance note or handoff is an informational representation.

Therefore:

```text
representation says Work is X
!= actual Work is X
```

The prior Work corpus already distinguished plan from actual Work and completion from verification/acceptance. The accepted Information ground makes this anti-collapse explicit and general.

### 2.2 Work readiness vs Environment Work Conditions

Actual capability/resource/availability/sufficiency belongs Environment-side.

Work readiness/blockage/admission can depend on those conditions plus Work dependencies/policies, but should not silently own the underlying realized condition.

### 2.3 Work admission vs Actor commitment/authority

The prior Work term `commitment` has a dual-use risk.

For Work, the useful distinction is candidate/eligible/selected-or-admitted/executing.

Actor obligation, promise, permission or authorization remains a distinct Actors/relation problem.

### 2.4 Work completion vs outcome reality

Work execution may close while:

- the intended Environment condition is not achieved;
- evidence is incomplete or stale;
- verification fails;
- validation fails;
- an authorized acceptance gate remains open.

This strengthens the prior completion/verification/validation/acceptance separation.

## 3. Why Work remains a distinct ground

A serious rival was tested: perhaps Work is only a composite of Environment + Information + Actors.

That reduction fails because Work semantics can vary while neighboring facts remain largely fixed.

With the same actors, repository and runtime:

- multiple possible pursuits can exist but only some are admitted;
- the same plan can correspond to unstarted, active, suspended or abandoned Work;
- one pursuit can be decomposed/ordered differently;
- dependency and flow state can change;
- Work can be reassigned without ceasing to be the same pursuit;
- closure/recovery semantics can change independently of source representations.

The irreducible protected question is the **pursuit and its organization/evolution**, not the bearer, representation or world state alone.

## 4. Existing Work distinctions remain sufficient

The prior twelve families continue to cover the tested cases:

1. purpose/outcome vs action/task vs method;
2. plural units/levels;
3. candidate/eligibility/admission/execution;
4. plan vs situated execution/adaptation;
5. control-regime plurality;
6. dependency/coordination/concurrency;
7. item state vs system flow/capacity relation;
8. multidimensional Work state;
9. effort/duration/waiting/elapsed/recurrence;
10. completion vs verification/validation/acceptance;
11. termination/failure/recovery/compensation/retry;
12. bounded vs continuing/supporting Work.

No audit case required a thirteenth first-order family.

## 5. Sensemaking / decision / investigation

These remain real Work forms.

Their immediate product may be Information rather than an external Environment change, but their Work semantics still concern:

- purpose;
- admission;
- method;
- dependencies/evidence needs;
- execution;
- evaluation;
- closure/redirection.

Therefore epistemic output does not require a separate Work ground/branch.

## 6. Discovery-driven and meta-work

Discovery-driven Work can modify the plan, scope, candidate set or decomposition as information improves.

This is covered by progressive elaboration, adaptive replanning, event/situation-driven control, feedback and candidate selection.

Meta-work—Work that changes workflow, agent configuration, verifier, tooling or the working system—is ordinary Work at another target level. The target may belong to Information, Environment or later control/composition structure; the Work semantics remain familiar.

## 7. Agentic-system holdouts

Three newer candidate-study lines were used to challenge the prior Work corpus.

### Anthropic AI-native SDLC

Its artifact chain, plan-before-mutation, stage/dependency mismatch, parallel sessions, verifier distinction, production gates and incident loops all mapped onto existing Work distinctions.

Strong lesson:

> artifact/state chain != universal Work ontology.

### Multi-agent coordination patterns

Sequential/parallel/hierarchical/generator–critic/composite patterns are better understood as dependency/concurrency/delegation/evaluation/routing relations over Work, not peer Work kinds.

Hidden human orchestration is real coordination/articulation Work.

### Context / Memory / Harness Engineering

Context formation and memory lifecycle sharpen Information boundaries; harness/runtime sharpens Environment/control boundaries. Orchestration/retry/verification loops still instantiate existing Work semantics.

Strong lesson:

> mechanism/topology/runtime layer != Work taxonomy.

## 8. Risk, uncertainty and value

The audit specifically attacked two plausible omissions.

### Risk / uncertainty

Uncertainty can attach to outcome, scope, duration, dependencies, failure, capacity and recurrence. It crosses Work, Information and Environment rather than forming a stable disjoint Work family.

It remains a legitimate residual for later formalization if design requires it.

### Value / benefit

Value affects purpose, selection, priority and stopping/acceptance. But it depends on Actor/stakeholder criteria, expected Environment consequences and Information/estimates.

No separate Work family or fifth ground is currently forced.

## 9. Immediate-child judgment

Several plausible child decompositions were tested:

- Plan / Execute / Evaluate;
- Candidate / Active / Closed;
- Bounded / Continuing;
- Item / Network / System;
- Purpose / Coordination / Execution / Evaluation / Recovery.

All are useful projections but fail as a stable universal sibling hierarchy because they mix:

- temporal stages;
- analysis levels;
- control relations;
- closure regimes;
- overlapping dimensions.

Current structural judgment:

```text
Work   ← coherent Foundation ground
        ← boundedly sufficient at current depth
        ← deep multidimensional internal problem map
        ← NO stable universal immediate-child split promoted
```

This is a bounded-leaf judgment at the current Foundation depth, not a claim that Work lacks deeper concepts.

## 10. Why broad new external search was not opened

The audit plan made new external research conditional on a live first-order gap hypothesis.

A1–A3 eliminated the live gaps; A5 did not revive one. The prior Work corpus already spans materially different source traditions.

Additional broad search at this point would have low expected structural information gain and high risk of accumulating mechanism/domain taxonomies without changing the Foundation result.

A4 remains reopenable if a future falsifier creates a decision-critical question.

## 11. Current anti-collapse rules

```text
Work != task/work item
Work != Actor/agency
Work != Environment process/state
Work != information about Work
Work != one workflow/lifecycle

Work admission != Actor obligation/authorization
Work readiness != Environment resource/capability state
Work completion != target condition achieved
Work completion != verification/validation/acceptance
Work representation current != Work actually current
```
