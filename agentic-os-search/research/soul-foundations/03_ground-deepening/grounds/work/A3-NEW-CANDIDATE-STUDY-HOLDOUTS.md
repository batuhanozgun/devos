## 1. Purpose

Try to falsify the A2 no-gap result using candidate studies created after the independent Work vertical closed.

These studies are not Foundation authority. Their value here is that they contain contemporary agentic-system cases that the original Work corpus did not explicitly organize around.

Primary holdouts:

- Anthropic AI-Native SDLC Playbook;
- Multi-Agent Coordination Patterns;
- Context / Memory / Harness Engineering.

## 2. Holdout A — Anthropic AI-Native SDLC

### 2.1 Artifact chain vs actual Work

Observed pattern:

```text
intent → spec → plan → implementation → review → deployment → incident/new intent
```

Potential falsifier:

Could Work be fundamentally an artifact-state machine that the prior corpus missed?

### Test

The chain is better explained by several already-preserved distinctions:

- informational artifacts represent Work intent/plan/evidence;
- Work admission/commitment is distinct from artifact existence;
- plan vs actual execution is distinct;
- verification/acceptance are distinct from execution completion;
- incident/failure can generate new Work;
- maintenance is continuing/recurring Work.

The artifact chain is therefore a **domain-specific information-carrying workflow**, not a new universal Work family.

### Result

No gap. It reinforces A1's rule that Work representations are not actual Work.

---

### 2.2 Six stages vs dependency graph

The playbook uses familiar stage labels but its actual operational prerequisites/dependencies do not reduce to stage order.

Potential falsifier:

Could the prior Work corpus over-emphasize lifecycle stages?

### Test

The prior Work research explicitly rejects one universal lifecycle/imperative sequence and preserves:

- partial order;
- dependency networks;
- alternative control regimes;
- coordination/concurrency;
- system-level flow.

### Result

No gap. The holdout strongly supports the existing anti-lifecycle reduction.

---

### 2.3 Plan-before-mutation and adaptive revision

Potential falsifier:

Agentic software work may require a distinct `pre-action reasoning` family.

### Test

Plan-before-mutation is one control policy over:

- planning/prescription;
- admission/gate;
- execution;
- later deviation/adaptation.

The Work corpus already distinguishes ex-ante plan from actual/adaptive Work.

### Result

No new family.

---

### 2.4 Parallel sessions / subagents

Potential falsifier:

Parallel agent execution may create a distinct agentic Work regime.

### Test

It maps cleanly to:

- decomposition / multiple Work units;
- concurrency / partial ordering;
- dependency/coordination;
- Environment isolation/capacity;
- Actors capability/authority;
- merge/integration Work.

### Result

No new Work-local family. The holdout makes coordination and integration costs more concrete.

---

### 2.5 Producer feedback vs independent verification

Potential falsifier:

Could verifier topology require a distinct Work family beyond evaluation?

### Test

The prior Work corpus already separates execution completion from verification, validation and acceptance. The candidate study adds a stronger **verification-validity/independence** concern, but that concerns evidence/oracle/Actor/control relations, not a missing Work form.

Verification itself can be a separate Work unit; its epistemic validity is not solved merely by classifying it as Work.

### Result

No missing Work family; stronger cross-ground/control relation.

---

### 2.6 Production incidents and configuration evolution

Potential falsifier:

Could incident-generated work or changing agent configuration require a new Work regime?

### Test

- incident → failure-generated diagnosis/remediation/revalidation;
- production maintenance → continuing/recurring Work;
- configuration change → meta-work whose object is the working system;
- regression evals → verification/evaluation Work;
- rollback → recovery/compensation family.

### Result

No gap.

# 3. Holdout B — Multi-Agent Coordination Patterns

## 3.1 Sequential / parallel / hierarchical patterns

Potential falsifier:

Could these be missing top-level Work modes?

### Test

They are better interpreted as relations/topologies over existing Work:

- sequential → dependency ordering;
- parallel → concurrency/independent branches;
- hierarchical → decomposition/coordination across levels plus Actors delegation;
- routing/composite → selection/control policy.

### Result

Not new first-order Work families.

---

## 3.2 Hidden orchestration

The side study identifies the human engineer/orchestrator as a possible hidden coordination bottleneck.

Potential falsifier:

Could orchestration be outside the prior Work model?

### Test

The prior Work corpus explicitly treats coordination/articulation as real Work, including sequencing, handoff preparation, synchronization, clarification and resource-contention management.

### Result

No gap. This holdout is a strong contemporary example of `coordination invisibility`.

---

## 3.3 Merge / integration work

Parallel branches create integration questions:

- conflict detection;
- target/version compatibility;
- merge authority;
- disagreement preservation;
- integration verification.

Potential falsifier:

Could `integration` be a missing Work family?

### Test

Integration composes:

- coordination/dependency management;
- transformation/assembly of outputs;
- parent-level outcome criteria;
- evaluation/verification;
- recovery/rework after conflict.

The content/provenance of outputs is Information; merge authority is Actors; actual runtime merge capability is Environment.

### Result

No new Work-local family.

---

## 3.4 Generator / reviewer / verifier / integrator separation

These are meaningful **Work-role relations** and separate Work units, but role identity/authority belongs Actors and verification validity belongs evidence/control reasoning.

### Result

The pattern strengthens the need to represent multiple Work units and dependencies; it does not create a new first-order Work axis.

# 4. Holdout C — Context / Memory / Harness Engineering

## 4.1 Context formation

Potential falsifier:

Agent context construction may look like a new Work-specific substrate.

### Test

- selecting/retrieving/injecting information → Information Dynamics;
- deciding/requiring that context assembly occur as part of a pursuit → Work/control relation;
- runtime ability to perform it → Environment;
- authority/access → Actors.

### Result

No missing Work family. This holdout strengthens the four-ground boundary rather than breaking Work.

---

## 4.2 Memory / continuity lifecycle

Potential falsifier:

Fresh-session continuation may require a new `continuity Work` category.

### Test

- persistent state/handoff → Information/Records;
- reading/recovering state → Information dynamics + actual Work action;
- suspension/resumption/migration → already covered Work state/coordination;
- new performer/capability → Actors/Environment.

### Result

No new Work family.

---

## 4.3 Harness loops / retries / verification / recovery

Potential falsifier:

Harness-managed agent loops may be distinct from ordinary Work.

### Test

The mechanism can automatically instantiate/control Work, but the Work semantics still map to:

- event/situation-driven control;
- retries/recovery;
- verification/evaluation;
- stop/escalation;
- recurring/continuing operation.

Harness/runtime is a control/environment substrate; automation does not create a new Work kind.

### Result

No gap.

---

# 5. Strongest new lesson from A3

The newer agentic studies do not expose a missing first-order Work family. They expose a recurring **composition mistake**:

> mechanism/topology/runtime layer is easy to mistake for Work taxonomy.

Examples:

- `parallel agents` is not a Work ontology branch;
- `RAG/context assembly` is not a Work branch;
- `generator–critic` is not a universal Work lifecycle;
- `intent/spec/plan` artifacts are not actual Work stages by themselves;
- `harness loop` is not a new Work ground.

These mechanisms instantiate or control Work while also relying on Information, Environment and Actors.

## 6. A3 falsification result

No post-vertical candidate study forced a stable new Work-local first-order problem family.

Instead they independently reinforced current Work distinctions:

- plural units and decomposition;
- dependency/coordination/concurrency;
- plan vs actual execution;
- system flow/bottleneck;
- verification/validation/acceptance separation;
- failure-generated recovery Work;
- continuing/recurring Work;
- meta-work as ordinary Work at another target level.
