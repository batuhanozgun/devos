## Joined findings, controls and limits

1. C-WRITER emits cumulative transcript totals on repeated Stop calls and deduplicates repeated message.id lines by keeping the last usage for each ID. C-BRIDGE correctly chooses the last matching cumulative row, scans beyond the former tail window and tests that SUM would be wrong. C-STORE instead sums all matching rows. Under matched IDs/paths, cumulative costs 3 then 7 become 10 in Rust but 7 in the bridge. A configured limit10, zero other costs and an eligible active session can therefore select the Rust stopping path despite the latest represented estimate7. One-row input or a genuinely delta-producing external writer are countercases. No live overcharge/stop was observed.
2. Rust totals include every stored session, while pausing selects Pending/Running/Idle. A global allowance is not automatically a per-day or current-active-run budget. Cache-token columns in C-WRITER are not deserialized into tokens_used, which uses input+output only. Profile USD remains a separate native-host/text concern from Note24, not a check newly added by C-ENFORCER.
3. Missing/unreadable/no-usage transcript with no accepted harness cache can append a new all-zero estimate without an explicit availability flag. C-BRIDGE uses that last row; malformed JSON rows are skipped with useful aggregated warning breadcrumbs. C-STORE skips type-invalid rows, updates only represented matching sessions and does not zero every absent session as the tool-activity importer does. Missing/empty/all-skipped cost files leave old values; unknown session UPDATE affects zero rows without being rejected. Conditions must not be pooled across the two importers.
4. Cost writer/bridge/monitor prioritize sanitized JSON session_id before ECC_SESSION_ID; the tool-activity writer prefers the environment ID. If those labels differ, the streams separate. The built-in Claude command uses --name, while the explicit --session-id in the wrapper addresses ECC's run-session. No native-to-ECC remapping is performed in C-STORE. Equality or another adapter is a working countercase; no installed mismatch was measured.
5. Transcript totals discard per-message model association and are priced with the last known model. Mixed-model arithmetic can therefore differ from summing each message at its corresponding rate. An optional finite/nonnegative/fresh ≤300s harness cache overrides cost but not token totals; the row does not record which source won. C-STATUS does not implement that cache writer or consume native cost for its metric display. No global absence of custom writers is asserted; a configured external writer is required for that optional route.
6. Statusline writes native context percentage only into an existing bridge and does not refresh its own observation timestamp or clear a previous percentage when the new input is null. Metrics bridge refreshes last_timestamp on every tool, retaining the context field. Monitor's60s staleness condition consequently ages bridge activity rather than context observation. An old percentage can pass as fresh after another tool; a fresh statusline value can be considered stale if bridge updates are disabled. Stable dedup may suppress a repeated warning, so continued classification is not guaranteed repeated display.
7. Unique temporary filenames and rename retries protect replacement against shared-temp collisions. They do not isolate the read-modify-write sequence: statusline and metrics writers can overwrite each other's newer fields after both read an older snapshot. This is a conditional interleaving, not a run concurrency test or whole-OS durability guarantee.
8. Monitor gives additionalContext advice, with explicit informational cost text, null-context handling, selected top-two conditions, tier dedup and escalation. It neither reserves budget nor stops a process. Warning state is written before the result is delivered; a later delivery failure can leave the same tier suppressed. Dispatcher output exists, but host uptake/obedience is unmeasured. Scope and loop signals are bounded heuristics, not objective task drift or nonprogress proofs.
9. C-STATUS's bar subtracts a fixed16.5-point buffer and renders adjusted used percentage; monitor evaluates raw remaining percentage. They are different denominators, not independent observations of one identical percentage. Native remaining16.5 can render100% adjusted use without proving the real window has zero capacity. The source's constant is not a validated current auto-compaction policy.
