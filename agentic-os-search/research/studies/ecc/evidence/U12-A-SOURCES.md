## Joined producer/consumer explanation

**Selection/storage:** explicit/inherited/default profile resolution and list/scalar composition precede record creation. Effective profile.agent is stored as the session's harness choice; its absence from the retrieved profile object is not loss of the already-recorded harness. Actual worker startup reads the session profile, not only the named config entry. Program/adapter selection remains in the loaded Config. Marker detection and a runner entry are not executable/version/capability validation.

**Native translation:** Claude receives native model/tool-permission/mode/directory/dollar-cap/append-prompt arguments, but not a token-budget argument. Codex receives fixed workspace-write sandbox plus native model/directories; its remaining profile fields become task text. OpenCode receives model natively and other fields as text. Gemini receives model/directories natively and other fields as text. A textual System instructions heading is still part of that task argument. No emitted argv is asserted to have been accepted by an installed host.

**Configured replacement:** a runner entry is selected before built-in handling, even for the same known harness key. It replaces rather than extends the built-in command recipe. Optional flag presence marks projection support; it does not interrogate the binary. An absent flag preserves the setting as text; an incorrect present flag can suppress that fallback while producing invalid or differently interpreted argv. The append-system-prompt flag and default inline=true can deliver the same text in both places. No malicious-runner premise or universal uselessness of textual guidance is assumed.

**Native semantics:** current Claude documentation distinguishes allowed-tools preapproval from exclusive tool availability; its tools option is a different mechanism not emitted here. Current Codex documentation distinguishes read-only/workspace-write and says add-dir extends writable roots. Therefore the inspected Codex profile permission_mode=plan becomes a textual directive without changing the fixed sandbox option. OpenCode and Gemini have native permission mechanisms of their own; omission from this adapter is not proof the hosts lack controls.

**Budgets:** enforce_budget_hard_limits checks aggregate cfg token/USD limits and each active stored profile's token budget, not profile.max_budget_usd. It uses recorded usage, then pauses selected Pending/Running/Idle sessions with worktree-preserving stop. The TUI's real tick→sync_from_store→metric import→enforcer path is present; the selected CLI metric refresh also calls it. Native output capture alone is not that loop. Invocation, current metrics, selected states and termination are load-bearing conditions. Profile dollar text on other hosts is not converted to an independent per-profile cap by this global check.

**Failure/correspondence:** normal profile writers serialize valid JSON, but readers turn invalid allow/deny/directory JSON into empty vectors. With a malformed stored deny list and otherwise readable row, subsequent construction can omit its deny argument/directive. This is conditional on malformed stored data, not a normal serialized round trip or observed exploit. Configured env values are applied after shared env and can change correlation labels while runtime writes still use their separate explicit session id. Locating two plugin-root marker files and exporting paths does not demonstrate plugin activation or exact distribution identity.
