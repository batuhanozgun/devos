## Primary interface comparisons — viewed 2026-09-21

**D-CLAUDE:** [official hooks reference](https://code.claude.com/docs/en/hooks), selected PostToolUse/PostToolUseFailure and input schema. The current documented successful-tool payload uses tool_response, session_id, tool_use_id and optional duration_ms. The pinned tracker reads tool_output, takes identity from env, creates a fresh local ID and sets duration0. The actual followed dispatcher forwards raw JSON without bridging those fields. Normal Rust shared environment explicitly provides ECC_SESSION_ID/CLAUDE_SESSION_ID, an important positive path. These are dated contract comparisons, not an installed-version fingerprint or observed host rejection. Other adapters may bridge different inputs; no claim that all ECC telemetry is absent.

**D-SQLITE:** [ON CONFLICT](https://www.sqlite.org/lang_conflict.html), selected IGNORE and ABORT semantics. INSERT OR IGNORE does not suppress foreign-key errors. Combined with R-STORE's enabled foreign keys, deletion and full-file replay, a retained event for a successfully deleted session can abort import. Prior successful statements are not rolled back by a missing whole-import transaction. This supports a conditional source path, not a performed Rust/SQLite incident test.

## Joined findings and important contrasts

1. A real connected source path exists: PostToolUse sync dispatcher/profile → tracker → local JSONL → StateStore import → tool_log → TUI timeline. R-MANAGER supplies normal session environment IDs. The importer is in StateStore; earlier handoff wording about manager ingestion was navigation shorthand, not its exact implementation owner.
2. Capture is selective and best-effort. Disabled/minimal/dry-run, missing env identity, malformed/truncated input and caught write failures differ from no tool activity. Documented tool_response can be omitted from output_summary because tool_output is consumed; duration0 is not measured execution time. Local random row identity is not native-call replay identity.
3. T-HOME resolves the writer's data root independently of R-CFG's DB-parent metrics path. Overrides or a different DB directory can separate writer and reader. Neither common filename nor session label proves they observe the same file; the direct shared-env function does not transmit the DB-derived metrics path.
4. The importer rereads all lines; valid unique current-file IDs drive counters, while tool_log keeps first stored records under a unique hook_event_id. Missing file leaves counters unchanged; existing empty/all-invalid file can zero them without deleting history. files_changed counts unique file_paths including reads. Ignored duplicate insertion does not suppress later aggregate/graph projection of that row.
5. An unknown session's fresh event ID can fail FK insertion. A normal successful session deletion removes its tool_log rows but not the JSONL; replay can therefore hit the absent session, stop before later events and leave prior partial writes. The TUI records its new file signature before import and catches errors, so an unchanged signature can prevent retry after a transient failure or DB-only repair. TUI continues separate enforcers; the CLI helper propagates import failure instead.
6. Risk scoring reads the sanitized/truncated input_summary, not full params/output or verified effects. Reasons/action are calculated but the importer retains only score. No per-tool pre-action gate follows in the observed path. A separate file-overlap control can stop a chosen session, record an incident/decision and notify peers; it uses file events and configured conflict strategy, not SuggestedAction::Block.
7. Input summaries/params and input-derived previews have real redaction/truncation. Git enrichment supplies raw selected diff lines without reapplying those sanitizers before persistence. A tracked diff containing sensitive text within retained lines can therefore preserve it despite sanitized input fields. It is a working-tree difference, not an isolated per-tool delta. No real secrets or malicious payload were acquired.
8. TUI timeline reads the latest128 tool entries per session and omits unparseable timestamps; query failures become empty entries there. Import accepts nonempty timestamp strings, and direct logger uses its own current time. The logger/page query and actual display are genuine consumers, not completeness or authenticated execution evidence.
