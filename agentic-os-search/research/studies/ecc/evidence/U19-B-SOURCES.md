## 4. Claim-to-chain bindings

1. **Real selected host input:** PACKAGE→H-MANIFEST/H-PACKAGES→H-RESOURCES→H-LOADER registration/factory→H-SESSION binding/runner→PI callbacks. Actual host types agree on selected event names. Installed availability/permission/effectiveness remain distinct.
2. **Producer and effects:** PI→RUNNER/FLAGS→START legacy process→OBSERVER leases/pruning and original learning selection→JSON context. END uses the real cleanup helper, not session-end.js. Context-off does not disable all START effects; hook disable/dry-run is a different predicate.
3. **Final consumer and lifetime:** PI clears pending before returning; H-RUNNER can chain/replace prompts; H-SESSION sets agent.state.systemPrompt and calls agent.prompt, rebuilding from base on another ordinary prompt. Internal tool/retry/queued continuation is not another identical callback boundary. H-SDK separately restores messages; no claim of absent native session persistence.
4. **Ordered replacement:** a later handler can omit an earlier ECC contribution after pending was cleared. This is an admitted source composition, not observed hostile input or proof that every later handler drops it. Model/key checks precede the callback and are not a valid consumed-context countercase here.
5. **Cache lifetime:** PI's module rules versus factory-local pending state; H-LOADER may reuse the same cached factory; H-RESOURCES initial loaded=false versus subsequent reload clear; H-SERVICES creates a fresh loader. Conditional same-cwd cached construction can retain old rules. H-SESSION explicit reload and changed-cwd invalidation are positive alternatives. H-RUNTIME's replace factory is caller-supplied; no universal CLI/custom-runtime claim is made.
6. **Failure projection:** RUNNER missing named script logs stderr, returns original payload/exit0. PI callback ignores stderr and extractor returns undefined without warning. Missing common runner/nonzero/override errors instead produce warning. START's own caught errors and exported-run exceptions must retain their separate exit semantics.
7. **Test validity:** T-PI mixes source assertions, real runtime-selector/runner calls, replicated EPIPE pattern and copied helper mirrors. Rule mirror excludes memoization; pending tests inspect ordering; profile fixture uses an allowed minimal profile and checks exit success. These do not exercise original TS factory under Pi or final prompt composition. No passing receipt is inferred.
