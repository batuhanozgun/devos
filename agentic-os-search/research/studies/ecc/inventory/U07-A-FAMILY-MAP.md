## 3. Concrete distinctions established or revived in U07-A

### 3.1 Review feedback is a different producer from a governance event

Plan Canvas does more than expose a field named approval: its CLI opens a specific artifact, calls an await endpoint and handles returned feedback/ended states. It gives different next-step instructions when the user ends the session. Its pending command consults a separate session store, including when the server is absent. These are S163 source behaviors, not a model demonstration.

The body calls real server/store functions, but their contents have not yet been read. In particular, text claiming queued feedback is never lost is not established by a client error message. The next unit must determine durable queue semantics, exact artifact/revision binding, who may issue a verdict, and how it is consumed. This route does not retroactively establish that governance-capture events enter SQLite or solicit approval.

### 3.2 ECC2's evaluation registry must not inherit the Node helper's verdict

S10 already existed in the U01-A reading record; this is a revived priority, not a newly discovered or newly added ECC feature. It describes content-addressed candidate configuration, unique paired seeds, sample/delta/win-rate thresholds, transactionally updated active registry and audit/rollback behavior. It also expressly limits its CLI to deterministic supplied measurements and says the active pointer does not change running sessions.

These are the author's documented contracts until harness_eval.rs and its store/callers are read. They are sufficient to show that a broad claim such as 'ECC evaluates every change using the U05-B helper' would be unjustified. The older bounded helper findings remain valid for their own source path.

### 3.3 A deliberately unavailable executor is different from an unsafe active executor

S164 calls S165's gate module, which reaches S166's unconditional requireSupportedIsolation exception. Both runGate and runVariant are also disabled at their public entry. The selected CLI gate path refuses before reading the candidate configuration or creating/opening its capsule.

Static variant checks, unique task IDs, result-envelope and complete-baseline helpers coexist with this refusal. Their presence is not a implemented OS isolation backend or a live improvement experiment. Conversely, lack of an executor is not silently treated as permission to run with a copied directory or a trusted-local label. This is a concrete source-level boundary, not only roadmap wording. Capsule/receipt/replay internals remain open, and no path was executed here.

### 3.4 The native review pilot preserves several forms of uncertainty

S167 validates its input, selects review dimensions, gathers findings, deduplicates them and sends high/critical findings to a verifier. Null/error review results contribute to failedDimensions; verifier null/error is retained as an unverified blocker. An explicit false verdict with confidence below 0.8 also remains blocking; only a sufficiently confident refutation demotes that finding. The final verdict is CHANGES_REQUESTED when blockers or failed dimensions remain.

The README's introductory phrase about defaulting to refuted on uncertainty is not the stronger source of truth for this predicate; the pinned code and its detailed prompt do the opposite. That is a documentation/body distinction, not a claim of a measured runtime regression. A numeric confidence and a field named proof do not establish epistemic independence or true impact. Schema validation is delegated to the native host. The script's special args/agent/parallel/log environment was not run or conformance-verified.

Outer interactive plan/commit gates and installation/pipeline wiring remain separate obligations in S23. This pilot is therefore neither a completed end-to-end autonomous factory nor merely inert prose.

### 3.5 Distribution and integration are not one shared catalog

S169 builds .opencode/dist using the TypeScript compiler and fails when that dependency is missing. Generated runtime output must be traced to its source, not discarded as a duplicate directory. S170 explicitly describes an initial gitagent export and leaves native agents/commands/hooks authoritative within the target repository; it is not a complete runtime map. S172 separately declares a Python package and CLI entry into src/llm.

S168 describes AURA as an explicit caller-owned trust check, not a global ECC hook, and does not itself claim to execute payment or delegation. Its adapter implementation and external reputation service have not been evaluated. Likewise AgentShield code is separately maintained according to S150. These boundaries prevent incidental external links from turning into an unbounded new research campaign while keeping actual dependencies visible.
