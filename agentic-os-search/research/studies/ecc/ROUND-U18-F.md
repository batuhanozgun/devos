## Result and native-system contribution

NanoClaw is a human-driven, file-backed transcript REPL with an npm/script/skill entry, not an ecc subcommand or a new external target. It reads prior history before appending the current input, passes history/selected skill text/current input to claude -p over stdin, waits, records the returned string and asks for another line. Named persistence, local utilities, current-input nonduplication and single-REPL sequencing are useful implemented mechanisms.

The result distinguishes transcript recovery from environment recovery: model and skill selections are in memory/environment, cwd selects skill files and the home-scoped session name is not project-bound. Read failures can appear as empty history or omitted skills. Plain text section labels do not invoke native system-prompt or resume interfaces. Host permission/configuration remains external; the Windows model argument is not validated merely because the command name is fixed.

The main representational counterpart is an unescaped Markdown separator inside an Assistant response. Raw replay can preserve text which parsed export/compaction drops. The parser's first5,000,000-string-unit cap creates another consequence: compaction can preserve an older parsed prefix's tail while discarding newer records beyond the cap. Default compaction deliberately retains twenty message records without a semantic summary or automatic archive; its parser cap and metrics are not input-budget enforcement.

Process outcomes become transcript strings. A nonzero exit with empty stderr can lose its failure qualifier; errors can be stored as Assistant replies. Separate User/Assistant writes do not represent an atomic attempt or acknowledged external effect. Branching copies a transcript, not project files/host state, and an existing target can be overwritten. Raw MD and parsed exports have different fidelity and target controls.

These are conditional source deductions, not observed loss, attacks, failed model calls or efficacy measurements. They do not dismiss the lightweight design or demand a universal memory engine; they explain what this particular mechanism preserves and where a stronger continuity claim needs more evidence.
