## 1. Judgment

**Retain the mechanism/consumer-oriented research discipline and proportional counter-tests. Do not carry the publication workflow forward unchanged.** The record supports particular explanatory gains and useful recovery controls; it also contains repeated transfer/transcription failures and substantial unmeasured bookkeeping burden. It does not establish a best, efficient, independently validated or universally reusable research method.

The distinction matters: successfully producing a qualified CORE is an output; correcting an earlier interpretation is an observed contribution; proving that this method causes better results than an alternative would require a different comparison. These are not interchangeable judgments. A negative or inconclusive method assessment can complete the second deliverable without declaring the method successful. [WHY] [METHOD] [MR-BASE] [CORE]

The strongest positive chain is U15-A → U15-B: a provisional synthesis identified a missing delivery relationship; the next unit actually traced merge/rebase into downstream retention and changed the system explanation. The strongest negative chain is E06 → E10 plus later catalogue repairs: integrity and publication risks were recognized, but similar failure classes recurred. Detection and recovery improved the admissible evidence; they did not demonstrate prevention. [MR34] [MR35] [REC06] [REC10] [PUB19B] [PUB19D]

METHOD §12 asks for both a real subsequent-unit effect check and a repository-only re-entry record before a general method-usefulness claim. The former is recoverable. The reviewed takeover records retain same-conversation context, so they do not establish the latter in the intended conversation-independent sense. No such test is manufactured here. This is a limit of the evidence recovered for this assessment, not a repository-wide proof that no other record could exist. General method validation remains unestablished. ## 3. Case A — Follow the actual producer and next consumer

**Trigger and prior risk.** A facade, filename or record can make the mechanism appear understood too early. Note02's initial checkpoint description was migration-specific; the next unit opened the producer rather than treating its name as the boundary. The non-Claude branch also produced bridge state. It also distinguished the ordinary ownership guard from guided Kimi's operation-identity/current-digest preflight. [N02] [N03] [MR-BASE, MR02–MR03]

**Observed consequence.** The explanation was corrected rather than simply expanded. A managed pathname, an identical unowned file and a partially written recovery operation no longer inherited one ownership or completion meaning. This is recoverable in the later note and method history; no new installer execution is claimed by U20-B.

The stronger later example is MR34's explicit decision to leave adjacent metrics work and investigate the missing delivery edge. MR35 and Note34 then followed actual integration into the daemon's next cleanup step. A rebase path can preserve unresolved work while a subsequent controller uses different retention predicates. The discovered issue is in the composition, not merely in an isolated function's local behavior. The earlier MR34 said the later benefit was not yet observed; MR35 supplies the subsequent result. [MR34] [MR35] [N34]

**Assessment: retain.** Trace a consequential output to the actual next consumer and ask whether identity, meaning and conditions survive. Prefer a caller/consumer contrast when labels suggest equivalence. This has specific demonstrated explanatory value in this case history.

**Limits and transfer.** These are purposively selected, same-assistant corrections, not a blinded comparison or a measurement of omission reduction. A sufficiently careful alternative source review could also have found them. Do not require every dependency to be exhausted: continue only while the next relation changes the question being answered. Do not turn every absent global guarantee into a defect in a deliberately narrower component.

## 4. Case B — Small discriminating probes, with honest substitution boundaries

E03 is a useful representative because its original plan, full results and interpretation are all recoverable without rerunning the target. It held the wrapper and collector identities fixed and replaced the external provider with an explicitly fake executable. The cases varied process exit, output format and task-file availability. The result record preserves actual commands, raw status/handoff text, parsed fields and whether the fake was invoked. [E03-README] [E03-PLAN] [E03-RESULT]

The discriminator is concrete. A zero-exit response reporting incomplete work still produced completed process status; changing the output format could leave the raw report present while parsed arrays became empty. Nonzero exit and missing task supplied negative controls. These observations separated process completion, reported task evidence and representation fidelity. They did not evaluate a model's reasoning, real Codex permissions, tmux launch or accepted software output. Matching five expectations is not a five-case product-safety pass rate. [N05] [E03-RESULT]

The plan says its criteria were fixed after source inspection and before execution; the results record the same plan digest and unchanged status. That is a preserved source-informed experimental record, not an independent temporal attestation or blind replication. Designing cases after seeing source is useful for mechanism discrimination, but it cannot support a representative incident-frequency estimate.

E10 adds a different limited cross-check: the recovered record says an independent YAML parser accepted the input and rejected one transformed output. Parser agreement tests syntax, not Gemini loading or model obedience. E06 supplies the contrary boundary: incomplete or invalid surviving evidence cannot be rehabilitated merely because the predicted result is plausible. [REC10] [CHECK10] [REC06] [CHECK06]

**Assessment: retain selectively.** Use a local probe when it distinguishes a live uncertainty at an affordable, authorized boundary. Preserve original bytes, input, output and negative controls. Label substituted dependencies and adapted logic. Do not run a test just to increase the experiment count, and do not combine heterogeneous probes into one efficacy score. This assessment reread records; it executed no old or new target probe.

## 5. Case C — Evidence transfer and interruption: recovery is not prevention

E06 exposed three separate failures: current work state was stale, created objects were not attached to a published evidence tree, and one exact stored object failed decompression. Its recovery checks distinguish text-reader incompatibility from actually invalid compressed content. The second object was preserved but not fully verified. Partial forensic recovery did not supply verified run outcomes. Excluding E06 from findings was therefore necessary, even though it reduced the apparent evidence base. [REC06] [CHECK06]

The diagnosis also corrected an earlier understatement that only final readback was missing. That correction is a research-quality gain, not proof the preceding process was reliable. The exact cause of the original byte corruption and the platform interruption was not established. Do not attribute either to context length, an outage, branch count or a particular tool without evidence.

E10 later had a surviving original attachment whose archive checks passed, while its repository encoding was defective. The recovery record binds a guarded transformation to the exact bad input and exact original output, with changed-input rejection. This supports a materially different disposition from E06: the original E10 bytes were recovered, not new outcomes invented under an old identifier. No target rerun was counted as recovery. [REC10] [CHECK10]

**Assessment: mixed.** Preserve small durable source findings, explicit active state and evidence admissibility. Retain exact-object checks, quarantine and a recoverable source route. Reject free-form regeneration of opaque binary encodings as a dependable transfer method. The recurrence of transfer failure after the earlier corrective warning means the record does not support a claim that recurrence was prevented. It does not prove that both corruptions had the same low-level cause.

**Transfer condition.** A future publication route should establish source bytes → transfer → destination bytes → readable members → reachable repository files before execution evidence is admitted. Checksums establish correspondence, not scientific truth. Recovery should have a decision-value boundary: E06's documented speculative repairs found no valid complete archive and were stopped. Such salvage is not automatically more valuable than preserving the failed evidence and completing a source-only answer.

## 6. Case D — Durable state helped recovery, but blind re-entry remains untested

The U19-B interruption is a positive, limited continuity case. Its recovery input already held Note50, the ledger and updated plan/entries; STATE still showed activation, CATALOG showed the earlier selection and the receipt was absent. The recovery identified that distinction and finished the publication rather than repeating the Pi investigation. A subsequent non-force update was rejected because another workstream advanced main; rebuilding on the fresh parent preserved that other work. [PUB19B]

This supports the practical value of publishing a bounded result before its final outward response and keeping source completion distinct from publication completion. It also shows why a single status field can be insufficient during a multi-file interruption: existing artifacts and their identities supplied the missing evidence.

It does **not** demonstrate that a fresh agent with no conversation context selected the correct task from the repository alone. The record explicitly retains same-conversation readings. The current U20-B likewise has prior conversation and CORE material visible. A self-written statement that a new session could recover the work is a design/readback judgment, not the missing re-entry test. [METHOD] [PUB19B] [PUB20A]

**Assessment: retain scoped continuity, withhold general validation.** Preserve purpose, current versus completed work, authorization, evidence standing and the exact next responsibility. Use a staged checkpoint when necessary, then reconcile the affected entries. Do not keep duplicating the whole history into every current file. A future conversation-independent check should recover a small predefined set of facts without being supplied the expected answers; it would validate that one recovery condition, not all future sessions. No such test or new background work is claimed here.

## 7. Case E — Publication correctness had useful detection but a fragile producer

The early method history already names the burden of replacing growing logs through a whole-file API. U19-B's catalogue repair then needed rejected candidates for unrelated row changes. U19-D records another candidate fixing one unrelated row while introducing a change in another. These are not ECC defects: they are assistant-produced errors in the research repository's publication workflow. [MR-BASE] [PUB19B] [PUB19D]

Complete candidate diffs prevented the identified drafts from becoming main. Known blob reuse and non-force updates preserved already checked material and concurrent work. These are genuine controls. They operate after candidate generation, however; a successful correction does not demonstrate a producer that will stop making the error.

U19-D also introduced a bounded structural improvement: the existing question history was preserved as the exact Git object under QUESTIONS-THROUGH-U19-C, with explicit one-level current changes and inheritance. This avoids paraphrasing that old body. It protects that particular baseline, not every separately regenerated catalogue or index, and does not itself prove a future reader will apply the inheritance correctly. [PUB19D]

Counterevidence is retained: U19-F and U20-A report a selected catalogue candidate requiring no unrelated-row correction. Those successes refute an assertion that every publication failed; they do not establish a new low error rate or demonstrate a preventive change. We lack a complete attempt denominator and controlled comparison. [PUB19F] [PUB20A]

**Assessment: change the production path; keep pre-publication detection.** Prefer exact-source transformations with narrow accepted changes and assertions that untouched content stayed identical. Reuse immutable objects instead of regenerating them. Review the intended semantic change separately from byte preservation, then check the final main result. Under a whole-content-only interface, use an unreferenced candidate and actual diff before advancing main; acknowledge that this is a mitigation, not an implemented patch-only writer.

Do not respond by creating more duplicated logs or another architecture project. The minimum durable roles are current state, original evidence, an interpretation/change record, retrieval pointers and a publication check. They need not each be independently recopied for every small observation. This is a recommendation drawn from the case, not a retroactive rewrite of historical records or an agent-control change.

## 8. Case F — Scope return and synthesis, without pretending unread sources vanished

The original inventory objective was not fully achieved by the first shallow map. Early rounds carried that debt rather than treating a mechanism slice as complete coverage. The later provisional assembly named concrete missing connections. The omission review subsequently found material host and document relationships, which led to dedicated source returns. This is a justified reason for some of the research's length; it is not proof the order or granularity was optimal. [MR-BASE] [MR34] [N56]

The historical Kiro comparison is a useful rival discriminator: the record supported older copies remaining while the primary prompt developed, not a demonstrated converter deleting newer requirements. The Cursor return distinguished an actual old planner from the ordinary public entry's selected path. These cases show that an apparent defect explanation can itself be corrected by lineage or caller evidence. They also caution against treating all counterexamples as evidence for one negative narrative. [N51] [N53]

Note56 then gave finite dispositions rather than continuing indefinitely into every service, translation or image. It explicitly excluded image-derived conclusions because visual access failed, and retained selected/clipped roadmap coverage. That exclusion is acceptable only while the synthesis's claims do not depend on the unseen content. It is not evidence that the unseen material is empty, irrelevant or equivalent. [N56]

CORE followed the admitted question and supplied a joined explanation rather than reopening every named product. Its claim map preserves prior evidence classes and actor-mediated transitions. This is a completed source-synthesis step, not independent confirmation of the original research. [CORE] [MAP20A] [MR58]

**Assessment: retain explicit relationship-frontier reviews and claim-relative stopping.** Use the whole-system account to select the next consequential question. Reopen a necessary unresolved relation; qualify stronger or unused scope. Reject file-count completeness and the opposite rule that every unrun live test must block a bounded source conclusion. The present history gives no evidence for a universal optimal review interval or exact unit size.

## 9. What can transfer, and what remains a proposal

| Disposition | Practice | Evidence and transfer limit |
|---|---|---|
| RETAIN / specific contribution observed | Source identity and producer→representation→actual consumer tracing | MR02→MR03 and MR34→MR35 corrected the model; not a controlled superiority claim |
| RETAIN / bounded evidence value | Small discriminating probes with explicit doubles, raw outcomes and negative controls | E03 records useful distinctions; does not measure live-agent quality or prevalence |
| RETAIN / recovery value observed | Durable source checkpoints, preserved failed evidence, non-force publication | U19-B recovered an existing result; E06/E10 received different warranted dispositions |
| CHANGE / recurrent failure not prevented | Whole-file and opaque-evidence generation/publication path | Repeated rejected catalogue candidates and binary transfer defects; exact patch/byte pipeline is a proposed stronger production route, not already generally deployed |
| RETAIN WITH LIMITS | One-level historical question inheritance and progressive retrieval | Exact baseline preservation is established; conversation-independent interpretation is not |
| RETAIN / source-scope return achieved | Provisional synthesis and finite omission disposition | Note56→CORE is traceable; unread media/variants and stronger claims remain excluded |
| WITHHOLD | General efficiency, independent continuity, best-method or cross-study efficacy verdict | No appropriate comparison, complete cost/error denominator or qualifying blind re-entry record recovered |

For a future study, the transferable core is a question and return criterion, exact source/claim/evidence distinctions, actual consumer tracing, a discriminating countercase where useful, and recoverable current state. ECC-specific host, installation and runtime matrices should not become compulsory categories for every target. A method for a small conceptual paper need not reproduce this repository study's file structure or number of rounds.

A genuinely improved publication path and a conversation-independent re-entry exercise would address known weaknesses, but are not prerequisites to honestly reporting this retrospective. They become further validation work only when a later decision relies on those stronger guarantees. Do not silently turn this assessment into implementation of a research operating system.
