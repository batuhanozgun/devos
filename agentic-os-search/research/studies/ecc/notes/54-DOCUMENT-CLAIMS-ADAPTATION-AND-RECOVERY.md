## 4. A documented recovery action is not made safe by calling it an archive

TROUBLESHOOTING recommends archiving large observation logs rather than deleting them. Inside its actual sh -c loop, the gzip-to-archive command is followed unconditionally by a colon command redirecting into the source file. It contains no success-dependent branch or archive verification between them.

For the conditional case, take an existing selected observation file, an ordinary shell with errexit and noclobber off, and an archive write or compression failure while the source remains writable. The sequential next command can still execute; redirecting the colon command truncates that source. The intended replacement archive is then not established as usable before the original is emptied. POSIX shell list/redirection/null-command semantics and GNU gzip's separate error status support this deduction. The command was not run; no user log or real archive was touched. [TROUBLE, D-SH, D-GZIP]

The failure can be visible on stderr, so this is not a claim that all errors are hidden. If compression succeeds and its output is usable, the ordinary flow can archive the selected bytes before truncation. A separately configured fail-fast shell also changes the selected failure case. Neither alternative inserts a checked archive-to-source relationship into the published recipe itself. Its same-day destination naming and live-writer concurrency need further qualification for stronger retention claims; no crash-durability guarantee is inferred from successful compression.

This is not an automatically executed ECC cleanup path. It is an actionable maintenance procedure supplied to a human or tool-capable actor, with real effects if copied and executed. That role matters to the system explanation: a maintenance recommendation can bypass the ownership/validation/recovery behavior of the managed installer, so findings from the managed path cannot be transferred to it. The needed causal distinction is attempted preservation versus established replacement, not merely the presence of the word backup.

Other troubleshooting sections combine old default paths and manual cache/permission operations with the newer doctor/repair route. Such a path must be bound to the actual selected installation/data root before use; a historical path is not by itself proof that data is absent.
