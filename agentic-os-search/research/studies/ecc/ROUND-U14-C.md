Following the context writer and consumer revealed a per-field time problem. The statusline writes context into an existing bridge without its own sample clock, while tool updates refresh the shared timestamp. An old percentage can consequently pass the freshness check; the reverse is possible when only the statusline updates. Unique temporary files protect replacement against shared-temp collisions, but do not serialize competing read-modify-write operations. These are source-derived interleavings, not observed concurrent failures.

The actual output contract remains useful and limited: warnings are selected, tier-deduplicated, optionally cost-suppressed and emitted as additionalContext. Cost warnings explicitly do not command a stop. The distinct Rust controller really calls stopping logic. Treating both as one budget service would either overclaim the warning or understate the controller. Persistence before output delivery is not an acknowledgment, and neither occupancy nor repeated calls alone proves work quality.
