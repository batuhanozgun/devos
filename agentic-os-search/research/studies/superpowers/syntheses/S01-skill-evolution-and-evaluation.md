## 1. Native explanation

Superpowers treats a reusable skill as an intervention in how a future agent discovers guidance, interprets a task and acts. It does not equate every failure with a need for more prose. Its writing method distinguishes reusable guidance, project conventions, executable validation and separate domain-specific plugins. It then selects a form of guidance appropriate to the observed failure: prohibition for bypassed discipline, a positive output recipe for poor shape, a required field for omission, or a conditional tied to an observable state. These are source-defined method choices, not an adopted SOUL ontology. [U06-A F43–F45]

The intended development loop is evidence-directed: observe a baseline, change the relevant guidance, test application under realistic conditions, inspect mistakes and revise. No-guidance controls test whether an intervention adds something; old/new comparisons test whether a revision improves on the existing method. These are different experiments. Repeated tuning on known cases is development evidence, not independent generalization. [U06-A F46–F47]

The external lab provides a more explicit measurement system than the authoring prose alone. In the selected conversation review case, the desired outcome is useful, grounded findings delivered to the user—not a mandated skill invocation. The stock/treatment definitions name the same agent settings and the primary Superpowers SHA versus explicit none. This permits outcome-oriented comparison in principle without granting any particular comparison causal validity in advance. [U06-B1 F50–F51]

## 2. Three linked processes, not one automatic pipeline

| Process | Main transformation | Necessary qualification |
|---|---|---|
| Procedure development | Observed problem → intervention → skill revision | The problem is real, the intervention is appropriate, and a relevant comparison distinguishes its effect. |
| Evaluation | Prepared subject and scenario → interaction → retained evidence → assessor report → composed verdict | Correct target, usable observations, valid measurement, sound judgment and appropriately bounded inference. |
| Admission and distribution | Candidate change and evidence → human/maintainer decision → released material | Actual review/authority and actual delivery of the accepted revision; a checklist or result file is not the effect. |

The repository's authoring and contributor contracts connect these processes, but they are not a universally enforced transaction. Personal skill creation, contributor admission, lab execution and released behavior have different owners, artifacts and failure conditions. A development-only evaluator is not automatically a production dependency. Actual packaging and update realization remain U07. [U06-A F48–F49; U06-B2 F64]

## 3. The assessor has a concrete interface, with a semantic boundary

The selected conversation path allocates a user-like interlocutor and a later assessor with different inputs. Quorum splits the brief from the private rubric. Gauntlet's inspected assessment function starts an empty history and exposes only indexed evidence reading and report submission. Those two evaluator roles may use the same configured model; separation of role, process and input is not automatic epistemic independence. [U06-B1 F52; U06-B2 F59]

The producer requires one row per parsed criterion, attaches canonical criterion text by position and derives overall status from the submitted row verdicts. Observation, basis, limitations and references are required. Referenced files must have been successfully returned in a previous model request; a same-response read does not qualify the report. The scoped reader checks the index and path boundaries. These are meaningful code-level constraints, not merely emphatic wording. [U06-B2 F59]

Their guarantee stops at a specific point. A row can exist while answering the wrong obligation. A nonempty basis can be unsound. A source can have been read without supporting the claim. Repeated rows are explicitly accepted by a parser test because different obligations can legitimately share evidence. Neither accepting nor banning repetition would itself decide whether the judgments are correct. Semantic coverage therefore remains a property to evaluate, not a by-product of schema validation. [U06-B2 F59/G08]

## 4. Qualification is multidimensional

The study's evidence supports keeping at least the following distinctions:

| Dimension | Examples of actual mechanisms | Stronger claim not established by that mechanism alone |
|---|---|---|
| Subject identity | Explicit none/root/ambient handling; full-SHA worktree creation; registered-versus-observed snapshot comparison | Model-visible treatment and comparable actual runtime behavior |
| Observation | Native logs, visible captures, normalized trajectory and selected copied output | Every decision-critical fact is represented without loss |
| Report representation | Required fields, criterion count, read-before-cite and limited markup recovery | True, relevant and complete criterion judgments |
| Publication | Run identity, result digest, finalization and no-replace completion marker | Correctness of the underlying result or retention of all original evidence |
| Execution/accounting | Logical/physical request links, settlements, known/unknown usage | Fully observed total spend merely because a subtotal is priced |
| Inference | Outcome rubric and configured comparison arms | General causal improvement or release readiness |

These are analytical distinctions grounded in the inspected mechanisms, not a proposed mandatory six-layer architecture. [U06-B1 F50–F57; U06-B2 F59–F64]

Quorum retains pass, fail and indeterminate outcomes. A delivered answer can coexist with an instrument failure. A failed assertion can coexist with successfully functioning measurement. Some post-check errors can still be followed by an assessment attempt, while the final composed verdict remains indeterminate. Attempting assessment, accepting its representation and authorizing a final inference are separate events. [U06-B1 F53–F56]

## 5. Two changes can improve the same score for different reasons

One can change the subject procedure or change the measuring instrument. The resulting number must retain that distinction.

The public code-review smoke record reports improved report acceptance after a parser repair, while malformed criteria placement still occurred. The repair recovered model-authored rows under the existing validators and marked the recovery. This is a reported instrument improvement, not evidence that the coding agent or Superpowers learned to produce better work. Its retained-case development check and later fresh run have different evidential status. [U06-B2 F60/D30]

The subsequent public diagnostic reports semantic grounding misses even when evidence was read and native reports were accepted. Two full-review errors reportedly recurred; isolated unsupported claims and supported rewrites were correctly distinguished. This challenges a stronger semantic-reliability inference, but does not isolate context length or yield a general error rate. The private original bundles were not independently inspected by this study. [U06-B2 F62/D31]

A later focused release-path report still distinguishes successful execution and transfer from uncalibrated grading, preserving disputed outcomes and simulator deviations. This is why neither an earlier clean smoke nor an all-green executable-check total can substitute for the relevant inference. [U06-B2 F64/D37]

## 6. Positive contributions and remaining limits

The source family contributes more than cautionary counterexamples. It contains controlled-intervention intentions, failure-specific guidance design, an outcome-oriented rubric, explicit no-treatment handling, canonical criterion attachment, temporal source exposure, selected evidence retention, result publication contracts and separate accounting completeness. Public reports also retain failures and qualify their conclusions. These features provide concrete mechanisms for comparison and reuse.

Nevertheless, this study has not established general Superpowers effectiveness, grader calibration, all-harness isolation, actual compliance in each run or automatically enforced release admission. Public author reports and code-level controls support a bounded explanation; they are not independent replication. A future efficacy/adoption question would require re-entering exact run provenance, task distributions, controlled comparisons, actual grading evidence and current runtime versions.
