## Primary question / purpose

Build a source-grounded model of what gstack actually is and how it works as a software-development operating system / software factory, rather than reducing it to a collection of prompt files.

The completed study answers:

1. What does gstack do in **Information / Representation**?
2. What does gstack do in **Work**?
3. What does gstack do in **Actors / Agency–Participation–Authority**?
4. What does gstack do in **Environment / Operating Reality**?
5. Which important mechanisms are irreducibly cross-ground, and how does gstack make the four areas work together as one operational system?

The four accepted Foundation grounds are an upper-layer projection/comparison frame, **not a source-bucketing scheme**.

## Bounded result

The compact current study model is in `CORE.md`.

Shortest form:

> **gstack is an artifact-mediated, qualification-driven software-development operating system that repeatedly binds the current situation, forms evidence, computes standing, resolves authority/control, performs a bounded effect, reads back what actually became true, invalidates stale representations, and continues/recover/adapts from the new state.**

Core operating loop:

```text
SITUATE
→ KNOW
→ QUALIFY
→ GOVERN
→ ACT
→ VERIFY REALITY
→ REFRESH / RECOVER / LEARN
```

This result is candidate external research, not Foundation canon or SOUL / Development OS architecture.
