## 3. Material v1.80 changes

### 3.1 `/freeze` state-root and failure polarity were hardened

At the pinned revision, the study treated `/freeze` as a real Claude-host Edit/Write interposition boundary but also recorded that host/runtime enforcement semantics can fail or weaken at seams.

v1.80 fixes a concrete fail-open defect: the freeze writer and hook reader could resolve different state roots under `GSTACK_HOME`. The current `freeze/bin/check-freeze.sh` now uses the shared hook state-root resolver and adds fail-closed behavior for missing/stale helpers, unparseable payloads and unexpected non-zero hook death.

**Current-main correction:** do not reuse the specific claim “freeze silently allows everything under `GSTACK_HOME`” as a current v1.80 bug. That defect is repaired by this release.

The broader control finding remains valid. `freeze/SKILL.md.tmpl` still hooks **Edit** and **Write** specifically; Bash remains an allowed tool. Therefore:

```text
Edit/Write boundary enforced
!= every possible filesystem mutation path controlled
```

The Foundation-facing/control-scope lesson survives even though one enforcement defect was fixed.

### 3.2 Setup now preserves skill registration when Chromium is unavailable

v1.80 changes the Playwright/Chromium bootstrap from a setup-fatal step into a bounded, reason-coded, best-effort capability acquisition step.

Examples of explicit degraded reasons include:

- `skipped`;
- `chromium-install`;
- `chromium-install-timeout`;
- `chromium-install-locked`;
- `windows-no-node`;
- `windows-node-modules`;
- `post-install-launch`.

Skills continue to register even when browser capability is unavailable.

This **strengthens**, rather than weakens, the core study model:

```text
setup completed
!= every runtime capability available

skill registered
!= browser-dependent skill currently actionable
```

Environment/capability standing therefore remains a separate operational input to Work.

### 3.3 Installer mutation authority now depends on provenance/ownership proof

v1.80 adds explicit ownership semantics across `setup` and `bin/gstack-relink` so a same-name skill is not treated as gstack-owned merely by name.

The release distinguishes stronger and weaker provenance evidence, preserves foreign entries, and backs up a customized weakly-proven generated `SKILL.md` before replacement.

This supplies new support for the study's authority/binding/control model:

```text
technical ability to mutate path
!= authority to mutate that installed artifact

same name
!= ownership/provenance
```

It is a concrete example of exact binding + provenance being required before a destructive effect is authorized.

### 3.4 Telemetry fixed another standing-flattening error

Setup's one-shot telemetry events could sweep another live session's pending marker and finalize it as `outcome: unknown`.

v1.80 adds `--no-sweep` for events that own no session.

This is another instance of the study's broader seam pattern:

```text
artifact/status belongs to session A
+ consumer from session B
→ incorrect status transition
```

The fix reinforces the value of exact identity/binding before aggregation or state transition.

### 3.5 Test validity remains Environment-sensitive

The PR's final Windows fix moves assembled setup harnesses from large `bash -c` argv payloads to temp-file execution after MSYS2 truncated a ~15.7 KB argument through an 8192-byte glob buffer.

This is additional evidence for the study's existing conclusion:

```text
test logic exists
!= intended test bytes reached the runtime intact
```

Execution environment is part of verification standing.
