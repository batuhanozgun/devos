## Cases
Each case plants its own two basis decisions, a criterion decision and a passing verdict on use one, makes its change, then calls `accept`. [Revised under ledger rule 3 (N-293 (1), 2026-10-19): and its own target, a Finding at its revision 1; the verdict's Review is the audit environment's (`reviewer_role_class` `devos_denetim`). Each refused case (N25-a to N25-d) first makes, in an inner block that is rolled back, the same `accept` for use one with no change (its control); if that control is not accepted, the case is the test's own `could_not_check`, since its refusal would not be the staleness rule's. Each refused case so asks more than before: refused, no Acceptance row, and the same call without its change accepted.]
- **N25-a** (the original): the first basis decision gets a newer revision. Refused; no Acceptance row.
- **N25-b**: the criterion gets a newer revision. Refused.
- **N25-c**: accepted for use two, while the review was for use one. Refused.
- **N25-d**: only the second basis decision gets a newer revision. Refused: every basis is checked, not only the first.
- **N25-pos**: nothing changed. Accepted; one Acceptance row more.
- **N25-pre**: `could_not_check` when an object is absent.
