## Cases
Input 1, the sample share (for `need` and for `finding`, `<f>`):
- `6ST-share-<f>-clean`: a complete record → accepted. `6ST-share-<f>-fail`: its gated field empty → refused naming the field (the gate's fail answer).
- `6ST-share-<f>-missing` (the stream's row deleted), `-unreadable` (the table renamed), `-partial` (the stream's `block_size` null, constraints dropped) → a complete record is refused as "could not check"; no row added.
Input 2, the hidden position (stream `finding`, with a block open):
- `6ST-pos-missing` (`block_position` null mid-block), `6ST-pos-unreadable` (the column renamed), `6ST-pos-partial` (`block_position` = `block_size` + 5) → refused as "could not check"; no row. If the build keeps no `block_position`, the cases are COULD NOT CHECK until revised to its form.
Input 3, the path list's copy (a routine item W, claimed):
- `6ST-path-clean`: an artifact on `docs/…` → accepted. `6ST-path-fail`: on `supabase/migrations/…` → refused, naming the impact class.
- `6ST-path-missing` (every row deleted), `6ST-path-unreadable` (the table renamed), `6ST-path-partial` (a row whose `path` is null, constraints dropped) → an artifact on `docs/…` is refused as "could not check"; no row.
- `6ST-path-op-clean` (an operation of the reversible class on `docs/…`) → accepted; `6ST-path-op-missing` (every row deleted) → refused as "could not check".
Input 4, the stream's block state as the withholding of an open sample reads it (phase C6, CHK-C02-030 C7 (a), gap G24; EV-C02-008 5.2 (a) and (b) as merged; W-C02-10 builds it, 5.2 (d)). Fixture: the `finding` stream brought to a block boundary, then complete findings written with the working token until the database draws one while its block stays open (at most six blocks, as `T-W07-N01` part B does); the sample `s`, its target `t`, and a Verdict `v` on `s` planted at owner level with the Verdict table's user triggers off for that insert only (README 5.1 (a): the rule under test is the withholding; DM-41 (a) refuses a Verdict in its target's transaction). The withheld values are `s`, `v` and the ids of every event whose `aggregate_id` is `s` or `v`. The reads judged: every read function README 8.1 ("The open sample") finds by its text, called with `t`, `s` and `v` as its uuid argument, keeping each (function, argument) whose answer to `devos_denetim`, with the state intact, holds a withheld value.
- `6ST-wh-den-clean`: with the state intact, at least one such read returns a withheld value to `devos_denetim` (its queue holds them at once, B:247).
- `6ST-wh-<c>-clean`, for `<c>` = `cal`, `sin`, `kur`, `ci`: the same reads with that class's token, the state intact: each read the class's gate admits answers clean (`ok`) and holds no withheld value. A read the gate refuses is no case for that class, named in the detail.
- `6ST-wh-<c>-missing` (the stream's row deleted), `-unreadable` (the stream table renamed), `-partial` (the row present, every column but `stream` and `block_size` null, constraints dropped), each planted at owner level inside an undone subtransaction: each admitted read answers interface v1's could not check (status `refused`, `reason_code` `could_not_check`), holds no withheld value, carries no key but `status`, `reason_code` and `reason`, and leaves every `devos_private` table but RejectedAttempt and the token tables unchanged (a digest before and after each read). Clean is `bad` (could not check folded into clean); another refusal is `bad` (folded into fail); a raised error or another form is the test's own `could_not_check`. If W-C02-10's record gives another fail-closed form (for example the read withholds while it cannot read the state), or N-264 (`plan/work/C02.md`; TABLES G23) changes the draw so that no read depends on the block state, these cases are revised before the first result (README section 8); if N-264 is decided before the merge so that no read depends on it, a record of that decision replaces them.
- `6ST-counts`: per check, the counts of clean, fail and could-not-check answers seen as wanted, with the denominator (all cases).

## Could not check
The test's own result is COULD NOT CHECK when an object is absent (`6ST-pre`), a planted state cannot be planted (the case's own `could_not_check`), a block cannot be opened, or a fixture cannot be made; for Input 4 also when no open block with a drawn record is reached in six blocks, the Verdict cannot be planted, no read returns the withheld values to `devos_denetim`, or no read is admitted to a class.

## Not covered
How a setting could go missing in a project (only migrations change it); the hidden position's randomness; `devos`. Input 4 judges the reads the text search finds, with a uuid argument; a read whose text names none of the three tables, or that the search misses, is not judged here (as in `T-W07-N01` part B). It does not judge the residuals EV-C02-008 5.2 (e) names (the builder's read-only connection, the export), nor the walks' answers to an open sample as a root, which are `T-W07-N01` part B's.
