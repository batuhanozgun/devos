# T-W07-DM19B · A burst of calls without a verified token adds no rows beyond one counted row per function, reason code and hour

Synthetic test data (plan Section 8 item 13): synthetic tokens of `devos-test` (issued, and one revoked, in part A's rolled-back transaction; in part B, issued and revoked by the migration job's step). The malformed and unknown forms are made at run time from an issued token: cut in half, and its last character replaced by another of the same class. A review and verdict are made up for `accept`. No token value is written in any file, printed or stored.

**Serves.** W-C02-09 point 3. EV-C02-002 DM-19 and section 6: "a burst of calls without a verified token adds no rows beyond one counted row per function, reason code and hour, and a revoked token is counted, not recorded one by one". EV-C02-003 §15, row "Calls with no verified token from outside": "A test W-C02-07 writes: a burst of such calls adds no rows beyond the count". EV-C02-004 X-04 and X-05.
**Command.** Staged in `tests/C02/W-C02-07/job/` (phase C5; README 5.1 (c)): W-C02-09 copies each of its files byte for byte into `supabase/migrations/tests/` once the file can pass, and the job runs that copy, under the path named below; the harness runs the staged file. Part A, in `devos-test`: the migration job's test step runs `psql -X -v ON_ERROR_STOP=1 -f supabase/migrations/tests/w07_dm19b_burst_count.sql` as `postgres`, and passes only on the notice `W07_DM19B_BURST_COUNT PASS`. Part B: the job's runner, inside its `devos-test` step, runs `python3 -I supabase/migrations/tests/w07_dm19b_burst_over_http.py`. It gets the job's one JSON object on standard input, with exactly the keys `endpoint`, `apikey` (a string, or `null` while the key is not stored), `tokens` and `revoked_token` (N-255, "The key's source, decided"); it declares no need of the database, so the job runs it under `env -i`. With `apikey` null it exits 3 with that reason. It uses, never printed: `endpoint`, `apikey`, `tokens.devos_calisma`, `tokens.devos_denetim` and `revoked_token`. It ends on `W07_DM19B_BURST_OVER_HTTP PASS|FAIL|COULD NOT CHECK (...)` with exit 0, 1 or 3. That the job runs it is an interface on W-C02-03's job (the executor's decision 3). Break (part A): `python3 -I tests/C02/W-C02-07/harness/run_breaks.py --patch tests/C02/W-C02-07/breaks/B-DM19B-1_row_per_call.sql --pg-bin <PostgreSQL 17 bin>`.
**Time added to W-C02-13's run.** None scheduled. Part B makes 251 HTTP calls (seconds to a minute). A burst across an hour's end may add a second counted row, so the bound is computed from the burst's start and end.
**Interface assumed.** README section 8.1 (the assumed interface, version 1, phase C) holds for this test; where anything here differs from it, section 8.1 holds. Group B's call convention, as T-W07-F04 states it. For this test:
- `devos_private.rejected_attempt` (`function_name`, `role_class`, `reason_code`, `counted_hour`, `count`), with the reason codes `missing`, `empty`, `malformed`, `unknown` and `revoked` (EV-C02-003 §15; as Group D's T-W07-6TK);
- `devos_api.token_role_class()` (a read) and `devos_api.accept(verdict_ref, accepted_use)`;
- `devos_private.revoke_env_token(<the env_tokens row's id>)`;
- part B: Data API calls by `POST /rest/v1/rpc/<fn>` with `Content-Profile: devos_api`, and `devos_api.read_rejected_attempts(since timestamptz)` for `devos_denetim` (EV-C02-003 §4.1, row "Reading RejectedAttempt"; the function's name is assumed).

## Cases
- **DM19B-<fn>-<form>**, for each function (`token_role_class`, `accept`) and token form (`missing`, `empty`, `malformed`, `unknown`, `revoked`): N = 20 calls (part A). All of them are refused, none raises, the counted rows for (function, form, `none`) grow by at most the hours spanned (1, or 2 across an hour's end), their total grows by exactly 20, and no per-call row appears.
- **DM19B-percall** (contrast): 3 calls of `accept` with a verified `devos_calisma` token add exactly 3 rows with that role class. A verified caller is recorded one by one.
- **DM19B-pos**: `token_role_class()` with the verified token is accepted, answers `devos_calisma`, and writes no record.
- **From 2026-10-19 (N-301, under ledger rule 3): B:270's counted row, "A counted row changes only during its hour and is exported after it", at the two functions M09-09 builds on it** (part A). The owner plants three counted rows (synthetic function names `w07_fixture_dm19b_*`, reason code `missing`, role class `none`, count 3): one of an hour that has ended (two hours ago), and two of the current hour, one of them created one second before the read's `since`.
  - **DM19B-me-hour** (k09 of EV-C02-014 section 11): `mark_exported` with the backup token, `table` `rejected_attempt`, over the range of the first two rows. Accepted; the ended hour's row is marked (the positive half, so a function that marks nothing fails), and the current hour's row is not.
  - **DM19B-rr-hour** (k15): `read_rejected_attempts(since => now())` with the audit token. Accepted, and its rows hold the current hour's counted row created before `since`. Its hour is open, so its count can hold calls made after `since` (B:270 with EV-C02-008 1.4's row R15: `devos_denetim` reads RejectedAttempt).
- **DM19B-B-<form>** (part B): N = 50 calls of `token_role_class` over the Data API per form, counted through `read_rejected_attempts` before and after, with the same bound. **DM19B-B-pos**: the verified token's call answers `devos_calisma`.
