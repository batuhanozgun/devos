## Cases
Every case's attempt is undone; the file ends in `rollback`. 59 cases.
- **FN-pre**: `could_not_check` when `issue_env_token`, a table the cases read, the role `anon`, or every one of the fourteen is absent. Before the build exists (on W-C02-08's schema) the file gives COULD NOT CHECK.
- **FN-M-cat**: each of the fourteen is `devos_api.<name>(jsonb)`, with definer rights and a fixed `search_path` (W-C02-09 point 2). One missing makes this case `bad` (and that function's FN-G cases `could_not_check`).
- **FN-G-<fn>** (fourteen): the function called with `{}` and a token of each of `devos_calisma`, `devos_denetim`, `devos_sinav`, `devos_ci`, `devos_backup`, and with no token: each refused, with `role_class_not_permitted` (with `missing` for no token); no family table changes; `rejected_attempt` gains at least five rows (one per call with a verified token, B 3.13; DM-19); and the no-token call's counted row (reason code `missing`) has its `count` increased by exactly one (CHK-C02-075 finding 2 (e); EV-C02-013 D-11). An answer outside interface v1 (a raised error), or a counted row that cannot be read, makes the case `could_not_check`.
- **FN-G-pos-<fn>** (fourteen, positive controls of the gate): the same function and input with a `devos_kurulum` token is not refused for the class or for the token (it may be refused for its input); it differs from FN-G-<fn> only in the token's class.
- **FN-C-<fn>** (the ten that close): with an open run, after a planted `ledger_handed_over` event, the recipe's call with `devos_kurulum` is refused and nothing but `rejected_attempt` changes. Its control is the same call before the hand-over, accepted; if the control is not accepted, the case is `could_not_check`. Each function's prerequisites are planted before the planted hand-over (they write through the functions, which refuse after it).
- **FN-O-transfer_review**, **FN-O-transfer_acceptance** (positive controls of the closing rule's exceptions): after the planted hand-over, with no `run_id`, a Review copy is written (+1 review row, its one `transferred` event) and its Acceptance copy is written (+1 acceptance row); the installation's Mission is made before the hand-over. **FN-O-transfer_artifact**: after the hand-over, with no `run_id`, a `git_file` Artifact whose path has a verdict file's form (`evidence/C<nn>/checks/CHK-C<nn>-<n>.md`; a synthetic stage C99) is written (+1 artifact row, its one `transferred` event). **FN-O-transfer_artifact-other**: after the hand-over, a `git_file` Artifact of another path is refused and nothing but `rejected_attempt` changes; its control is the same call with a run before the hand-over, accepted (else `could_not_check`). **FN-O-record_ledger_entry**: after the hand-over, `record_ledger_entry` on a stage's Work under the installation's Mission is accepted and writes exactly one event, a `ledger_entry` on that Work, and no `transferred` event; no other table changes but `rejected_attempt`.
- **FN-T-ev-transfer_review**, **FN-T-ev-transfer_decision** (positive controls of the transaction rule and of S1's writer rule): an accepted call adds its record (+1 review or decision row) and exactly one `transferred` event of the sent source ID, whose `aggregate_id` is the returned id, whose `transfer_source` carries the sent `source_id` and `sha256`, with `role_class` `devos_kurulum` and `origin` `call`.
- **FN-T-half-ev-transfer_review**, **FN-T-half-ev-transfer_decision**: the same call with the `transferred` event's insert made to fail (a planted trigger on `event` for that type): not accepted; no family table changes (no record without its mark); no `transferred` event of the source. **FN-T-half-rec-transfer_review**: the same with the Verdict's insert made to fail (a trigger on `verdict`): not accepted, nothing changes, no mark (no mark without its record, whichever order the build writes in).
- **FN-I-same**, **FN-I-same-decision** (positive controls of the key): an exact repeat of an accepted call (same source, same hash) is accepted, returns the same id, and changes no family table (no new record, no new event; no error).
- **FN-I-other-review**, **FN-I-other-decision**: the same source with another `sha256` is refused; no family table changes; the source still has one `transferred` event; `rejected_attempt` gains a row.
- **FN-A-pos**: `transfer_acceptance` naming an accepted Review copy of result `pass` on a planted Work is accepted: +1 acceptance row, its one `transferred` event, and the Work's `acceptance` is `accepted`. **FN-A-missing** (the copy named is an id that names no Review), **FN-A-fail** (result `fail`), **FN-A-cond** (result `conditional`, `current_evidence` naming only the copy): each refused; nothing but `rejected_attempt` changes; the Work's `acceptance` stays `proposed`. Each differs from FN-A-pos in one thing. **FN-A-cond-pos** (a conditional copy with the `ledger_entry` event that records its conditions met, accepted): the event is written by `transfer_event` (kind `ledger_entry` on the target Work) and `current_evidence` names the copy and `{"event_id": n}`; accepted, +1 acceptance row, its one `transferred` event, the Work `accepted`. In every FN-A case the installation's Mission is made first (`transfer_acceptance` takes its owner authority from it; EV-C02-013 D-8).
- **FN-R-declared**: `transfer_review` with `role_class`, `reviewer_role_class` `devos_denetim` and `origin` `owner` added to the payload: if accepted, the copy's `reviewer_role_class` is `devos_kurulum` and its events are `devos_kurulum`/`call` (B principle 8; S1). If the build refuses the unknown keys, the case is `could_not_check`.
