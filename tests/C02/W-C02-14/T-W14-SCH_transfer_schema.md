## Cases
Every case's attempt is undone; the file ends in `rollback`.
- **SCH-S1-type-<type>** for `transferred`, `transfer_run`, `ledger_entry`, `note_line`, `record_line`, `usage_reading`, `batu_step`, `ledger_state_row` (positive controls): an owner-level event of that type, with S1's payload form, is accepted. `transfer_run` is also planted with `phase` `completed` and `mode` `full` and `verdict_copies`, each accepted. If no type at all can be planted, every type case is `could_not_check` (the fixture, not a type, may be what is refused).
- **SCH-S1-type-ledger_handed_over** (positive control): the first `ledger_handed_over` event is accepted. **SCH-S1-handover-two**: a second is refused, and the count of such events is unchanged.
- **SCH-S2-dup-same**: with one `transferred` event of key (`decision`, `<tag>_D-901`) present, a second with the same kind, source ID and hash is refused; the key's events stay one. **SCH-S2-dup-other**: the same with another `sha256` (the conflict of EV-C02-005 3.1), refused; the key's events stay one. **SCH-S2-pos-kind** (positive control): the same source ID with another kind (`need`) is accepted. **SCH-S2-pos-sid** (positive control): the same kind with another source ID is accepted. **SCH-S2-cat**: the catalogue holds a valid unique index on `devos_private.event` with two key expressions naming `transfer_source`'s `kind` and `source_id` and a predicate naming `transferred`.
- **SCH-S1-nosrc**: a `transferred` event without `transfer_source` is refused. **SCH-S1-miss-<field>** for `kind`, `source_id`, `path`, `input_commit`, `last_commit`, `sha256`: a `transferred` event whose `transfer_source` lacks that field is refused. **SCH-S1-commit**: one whose `input_commit` has 7 hexadecimal characters is refused. **SCH-S1-null-kind**, **SCH-S1-null-source_id**: a `transferred` event whose `transfer_source` has that key field as JSON null, the other five fields well formed, is refused (CHK-C02-066 C2: the index's expression is then SQL NULL, so the event escapes S2's key). **SCH-S1-commit-nonhex**: one whose `input_commit` has 40 characters that are not hexadecimal is refused, in two attempts that must both be refused: none of the 40 hexadecimal, and 39 hexadecimal with the 20th not (CHK-C02-066 C3). The designer's additions, same class: **SCH-S1-commit-null**: `input_commit` JSON null, the other five well formed, is refused; **SCH-S1-src-array**: `transfer_source` an array of its six field names instead of the object is refused. These five are built from the well-formed event's own `transfer_source` (same source ID) changed in one thing. Each needs the well-formed event (same payload, every field present) accepted first in the same run, or it is `could_not_check`.
- **SCH-S3-declined**: a Decision with `status` `declined` is accepted. **SCH-S3-closed** (control that the status is a value set): `status` `w14_fixture_not_a_status` is refused. Both need the base fixture, `status` `open`, accepted.
- **SCH-S4-chg-yes**, **-chg-no**, **-chg-nr**: a Finding with `changeable` `yes`, `no`, `not_recorded` is accepted. **SCH-S4-chg-closed**: `changeable` `w14_fixture_maybe` is refused. **SCH-S4-ces-nr**: `counter_evidence_searched` `not_recorded` is accepted. All need the base fixture (`changeable` `yes`, `counter_evidence_searched` a synthetic text) accepted; each differs from it in one field.
- **SCH-S4-art-git_file**, **SCH-S4-art-git_tree**: an Artifact of that `kind` is accepted. Base: an Artifact of another kind (the first member the column's IN-list admits other than these two, else a synthetic word) accepted.
- **SCH-S4-acc-use**: an Acceptance with `accepted_use` `installation_acceptance` is accepted. Base: an Acceptance of another use, chosen the same way, accepted.
- **SCH-pre**: `could_not_check` when `devos_private.event` or one of its columns `event_type`, `payload` (`jsonb`), `aggregate_type`, `aggregate_id` is absent, or when one of the five columns S3 and S4 change has no table. Before the build exists the file gives COULD NOT CHECK.

## Could not check
The file gives COULD NOT CHECK when SCH-pre fails (before the build exists, or when an assumed table or column is absent). A group of cases gives `could_not_check`, never a pass, when its base fixture or its first event cannot be planted (the reason is named): for example where a later item adds a table rule (a format gate built as a trigger, W-C02-10) that refuses an owner-level fixture of this file; the test designer then revises the fixture under ledger rule 3, with the earlier results void. SCH-S1-type-ledger_handed_over gives `could_not_check` if a `ledger_handed_over` event is already committed in the database tested; SCH-S1-handover-two is then judged against it. Where the design is ambiguous, this test tests what the record names and states the ambiguity under "Not covered" (2) to (5); it does not guess the build's choice.
