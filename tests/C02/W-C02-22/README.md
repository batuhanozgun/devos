# W-C02-22 (SB-COR PR-A1): the tests, in Appendix C's form C0

The acceptance condition is `plan/work/W-C02-22.md`; the claims, the pinned forms and each check's two named breaks are there, point by point. This file gives the C0 fields per check family. `check.py` is the oracle; `breaks.py` builds the "filled but meaningless" head and makes the 86 breaks; both are pinned by SHA-256 in the condition. Both read every file with `git show <rev>:<path>` and write only in temporary directories.

Run: `python3 -I tests/C02/W-C02-22/check.py --repo <full clone> --base aa6d144 --head <rev>` (add `--only protected` for SB-COR 4.2); `python3 -I tests/C02/W-C02-22/breaks.py --repo <full clone> --base aa6d144 --main <rev>`.

**Filled but meaningless** (C0's format-gate example). `breaks.py` builds, on `main`, a head whose role files, `CLAUDE.md`, working order, PC-53, item file and round-notes file carry every pinned form filled with the word "x" and the anchors joined; `check.py` passes it 41 of 41. That example must land in the binding checker's product-only reading: a green script is not a sign that the text works.
