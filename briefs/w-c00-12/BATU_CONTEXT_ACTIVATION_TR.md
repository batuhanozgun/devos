## Builder's assessment (English)

**Core claim.** Knowledge being present in the model is not the same as knowledge being active while it thinks about the problem. Context selects which knowledge takes part. The aim is not maximum context but the right context for the problem.

**Builder installation (observed).**
- The builder's own discipline D9 ("use the research library") was skipped or recorded as "none relevant" while the operating model was built. The RPD study exposed a flaw in the W-C00-12 plan within minutes of being opened, and it was opened only because Batu named it.
- `CLAUDE.md` makes every session read the operating model and the state file at boot, but no relevant research. So the answer to "who decides what the model sees?" is currently a static reading list. Nobody decides per problem.
- The first message of the W-C00-12 session is exactly a context-activation act. Under principle 11, the builder writing it can carry its own framing and blind spots into the new session. Mitigation: besides the sources the builder names, the session runs its own context discovery (which problem areas the work touches; which library studies relate; which to read at what depth) and records what it consulted and what it deliberately did not.

**DevOS.**
- The plan's per-role knowledge maps (`plan/Ek_A_Rol_Sozlesmeleri.md`) are a start, but they are static (role → studies). The analogy asks for activation by problem.
- The C04 library import with similarity search may not be enough: a document can share no words with the request yet carry the critical mechanism. That calls for an index of problem → related mechanisms → studies, the library's classification method that Batu described.

**Limits.**
1. Wrong context gives a wrong frame. Source status must travel with the content: strong finding, candidate view, summary, or superseded decision.
2. The role that selects the context should not be the only judge of it. An independent "what was not looked at?" check applies principle 11 to context selection.
3. Depth must be decided per item; over-reading dilutes the signal.

**Consequence for W-C00-12.** Acceptance (h): every major design decision includes a context-discovery step and a record of what was consulted and what was deliberately left out, with the status of each source. The decision-and-basis record of input 14 carries it.
