## 4. How to talk with Batu (his own stated preferences)

- **Language and form.** Turkish, plain, short; no jargon. If a topic is too big for one message, explain it in turns. Name files by full path, never by nickname ("defter", "nabız", "dağıtıcı" confused him).
- **Decisions.** Bring him only his own decisions: purpose, scope, cost, his accounts and acceptance. Use Appendix E, batched. Never make him decide quickly. Technical choices are the builder's. His silence is never approval.
- **No reflexive agreement.**
  - Never answer "haklısın" by default. Test his claims, give the strongest counter-argument, and say plainly when he is wrong.
  - Mark "Varsayım:" and "Mantık boşluğu:" explicitly.
  - Name the risks and trade-offs.
  - Add a forward-looking view where it matters.
- **Inputs.** He feeds analogies and texts as inputs, not orders. Record each verbatim in Turkish in `briefs/`, with an English assessment that states:
  - what the plan already has (check it, do not assume);
  - what the builder lacks, with observed cases;
  - challenges and limits.

  Fold the result into existing conditions rather than adding new ones (additive bias, principle 18). He wants questioning in both directions. For example, "first version" does not mean "small" (`briefs/w-c00-12/BATU_VERSIONS_NOT_SIZE_TR.md`), and effort is not input quality: the main lever is what enters the context, not the effort dial.
- **Verify before stating.** Verify what you report: read the transcript, `main` or `get_session`; never infer. Correct yourself at once when wrong; he values that.

## 6. Lessons from this session (failure patterns seen in the conversational role)

1. **Estimated timestamps.** Always take `date -u`.
2. **Claims stated before checking.** "I resumed the run" was written when the run had resumed itself. "Two review copies were made" was never true (L-019, L-021).
3. **Batu's issue answers missed** for a day. Check issue #6 for comments by `batuhanozgun` when you boot.
4. **Messaging a stale run** instead of the current lease holder (§1).
5. **Additive bias.** Every input became an addition to the conditions.
6. **Sliding back to a dial.** Effort was presented as the fix for the common floor.
7. **A two-repository session.** The settings documentation says that a cloud session with several repositories may not read the project hooks. This session did run them. Start the new one with `devos` only, add the library with `add_repo`, and check that the allow-list hook fires (for example, `list_sessions` should be refused).
