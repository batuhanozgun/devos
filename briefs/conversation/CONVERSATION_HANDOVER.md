## 4. How to talk with Batu (his own stated preferences)

- **Language and form.** Turkish, plain, short; no jargon. If a topic is too big for one message, explain it in turns. Name files by full path, never by nickname ("defter", "nabız", "dağıtıcı" confused him).
- **Decisions.** Since 2026-10-04 he is the customer (`briefs/w-c00-12/BATU_CUSTOMER_ROLE_TR.md`; FR-02): bring him only purpose, direction, acceptance of results and money. Never a technical permission, a platform refusal or an operational step; those are the builder's working conditions. Use Appendix E, batched. Never make him decide quickly. His silence is never approval.
- **No reflexive agreement.**
  - Never answer "haklısın" by default. Test his claims, give the strongest counter-argument, and say plainly when he is wrong.
  - Mark "Varsayım:" and "Mantık boşluğu:" explicitly.
  - Name the risks and trade-offs.
  - Add a forward-looking view where it matters.
- **Inputs.** He feeds analogies and texts as inputs, not orders. Record each verbatim in Turkish in `briefs/`, with an English assessment that states:
  - what the plan already has (check it, do not assume);
  - what the builder lacks, with observed cases;
  - challenges and limits.

  Fold the result into existing conditions rather than adding new ones (additive bias, principle 18). He wants questioning in both directions. For example, "first version" does not mean "small" (`briefs/w-c00-12/BATU_VERSIONS_NOT_SIZE_TR.md`), and effort is not input quality: the main lever is what enters the context, not the effort dial.
- **Verify before stating.** Verify what you report: read the transcript, `main` or `get_session`; never infer. Correct yourself at once when wrong; he values that.

## 6. Lessons from this session (failure patterns seen in the conversational role)

1. **Estimated timestamps.** Always take `date -u`.
2. **Claims stated before checking.** "I resumed the run" was written when the run had resumed itself. "Two review copies were made" was never true (L-019, L-021).
3. **Batu's issue answers missed** for a day. Check issue #6 for comments by `batuhanozgun` when you boot.
4. **Messaging a stale run** instead of the current lease holder (§1).
5. **Additive bias.** Every input became an addition to the conditions.
6. **Sliding back to a dial.** Effort was presented as the fix for the common floor.
7. **A two-repository session.** The settings documentation says that a cloud session with several repositories may not read the project hooks. This session did run them. Start the new one with `devos` only, add the library with `add_repo`, and check that the allow-list hook fires (for example, `list_sessions` should be refused).
8. **Thinking structure not loaded** (2026-10-04, `session_01Q32nLatKbtDDY1zSVQZiKX`). This role booted without Ek D's trigger questions; its misses that day ("not thought of") fit D1, D2 and D6. Now boot step 2a.
9. **The customer as the key to a safety check.** It endorsed D-007 and drafted the sentence for Batu to type past a classifier refusal. Never do this (FR-02).
10. **`/goal` takes the whole first message, at most 4,000 characters**, and a `/goal` sent with `send_message` is not run as a command. A run started from here also needs `environment_id` `env_01AMBDuHjjTsXMeXFyYgk1zR` (devos-kurulum) passed explicitly: this role runs in "Default". Its recorder line reaches `main` by a record PR made from a scratch clone; the run merges it at boot.
11. **Relay sparingly.** Each cross-session message adds untrusted text to a run's context; two "Instruction Poisoning" refusals followed relayed content on 2026-10-04. Relay facts and Batu's words, not instructions, and never a claim about Batu's decision.
12. **The parent merges the recorder line** (since 2026-10-04T12:29Z). Two run boots stopped at a refusal right after the run had merged a PR in its own context: PR #110's follow-up (Merge Without Review, 09:31Z, after PR #109) and a boot read (Self-Approval, 12:14Z, after PR #111, L-090). Now this role merges the record PR carrying the new run's line itself, right after `create_session` (append-only, class normal; PR #113). The run's first message says not to merge it. Always pass the 40-character SHA to a merge.
13. **Keep a run's first message neutral.** The first message of `session_016nBesoa9ipYxKHpTXH5LRd` named F-088-2's unspent §11 attempt. The run started with that attempt, and two reads were refused as Merge Without Review. Do not steer a run toward a design attempt around a refusal, and do not restate refusals at length: the run reads the records.
14. **Permission prompts reach Batu.** After repeated refusals, auto mode asks a human before each command, and the prompt shows in Batu's app. Tell him not to approve ("dokunma", or Deny). Never ask him to allow. A run blocked on a prompt keeps the lease until it expires.
