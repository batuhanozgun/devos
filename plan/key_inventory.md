# Key inventory

**What this is.** The single key inventory of plan Section 12, "Key inventory" (plan line 1215): for each key and token, its owner, where it is kept, its permissions and its revocation path. C00 did not write it; CHK-C00-067 carried it to C01 as note N-105 on `plan/work/C01.md` (item W-C01-02). PC-18 (`plan/decisions/PC-18.md`, and its note under C00's Acceptance line, plan line 923) says what counts as a secret, and that the credentials the platform itself places in sessions are entered here as platform-issued. C03 reads this file: N-107 on `plan/work/C03.md` matches the keys listed here in test 3, by value, with counts only. First written at `main` 4113915 on 2026-10-06.

**Rule: no value.** This file never holds the value of a key, token or password, nor a fragment, hash, length, prefix, character class or any other derivative of one. A key is named only by an identifier: a variable name, a setting's name or a description. "Where it is kept" names a place, never a path to a value.

**Keeper.** The executor (the working session). Changes reach `main` through the installation's merge gate, like every other file.

**When an entry is added.** Every key and token plan Section 12 names is entered when it is created: its row below goes from "planned" to "exists", with the date and the record of the step that created it, in the executor's first change after that step. The C01 probe tokens come first (Batu's steps 4 and 5 under "Batu's steps" in `plan/work/C01.md`); this file is merged into `main` before Batu is asked to create the first of them (N-105). A key that has no row yet gets one when it is created, the same way.

**When an entry is removed or marked revoked.** No row is deleted. A key that is revoked gets the state "revoked"; one that no longer exists, "removed"; each with the date and the record. The C01 probe tokens stay listed, as existing, until C02's first migration removes them with the probe schema (plan C01, P3; C02's Acceptance: "The C01 probe schema and its tokens no longer exist"); deleting the probe environments at the end of C01 (W-C01-29) does not end their entries.

**States.** "exists" (with the record that shows it); "planned (created at ...)"; "revoked"; "removed". A planned row gives what the plan says now; it is checked against the real key when the key is created.

## Notes

**Platform-issued entries (rows 3 to 6), under PC-18.** These are the credential-like variables and the file that the Claude Code platform itself puts into sessions, as `evidence/C00/closure/C1_probe_output.txt` shows them in the working session. In the session's environment only, and only while they are confined to the session, they are outside C00's sixth condition; that they are confined is not shown, and N-109 checks it before C02 builds DevOS's environments (red or neither: C00's acceptance on the sixth condition is void or goes to a frame review). In a repository, a record or the chat, a value of any of them counts as a secret. Their owner and revocation path are the platform's: what is known is in the rows; how they are revoked, when they expire and whose account they act for are not known.

**Not entered from the probe's output.** `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN` and `CLAUDE_CODE_OAUTH_TOKEN`, in the guard's `CREDENTIAL_VARS`, were unset at both probes (EV-C00-022 sections 1 and 1c; criterion 25 keeps an Anthropic API key out of the environment settings); if one is ever set, it is a secret under PC-18 and gets a row. `MAX_THINKING_TOKENS` was listed by the probe's name heuristic; by its name it is a setting, not a credential (an assumption, EV-C00-022 section 1).

**Not entered from the plan.** The publishable keys of `devos` and `devos-test`: not secret information (plan 6.2, line 630).

**Limits.** Rows 1 to 9 rest on the probe's list: the guard's `CREDENTIAL_VARS` and, by a name heuristic, other credential-like names; that is no evidence that the session holds no other credential (EV-C00-022 sections 1 and 1c). The credential stores the guard lists in `CREDENTIAL_PATHS` (`.git-credentials`, the GitHub command line's `hosts.yml`) were not probed (EV-C00-022 section 1b item (viii)); whether the platform puts one into sessions is not known. The probe ran in the working session only; C01's probe sessions and DevOS's later environments are not covered by it.

**The probe tokens' format.** Plan C01 row 3's fail path (line 944) asks that tokens get a recognisable format, so that every outbound check (the public-write leak check, the guard hook) stops strings of it; plan 6.7's network row (line 733) relies on it. `plan/work/W-C01-03.md` (acceptance item 2) has the probe design fix such a format for the probe tokens, in its record under `evidence/C01/`. W-C01-03 fixes the format, and this file does not state it.
