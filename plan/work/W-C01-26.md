# W-C01-26 · N-109: do the platform's session credentials act beyond the session?

N-109 on `plan/work/C01.md` (PC-18 place 5; CHK-C00-070 condition 2; CHK-C00-073 condition 2). C00's sixth condition leaves the credentials the platform places in every session for its own channels (the messaging token; the session's token file) outside it, in the session's environment, only while they are confined to the session (PC-18; `plan/work/C00.md`). This item runs the check that W-C01-03 wrote down before it runs, with the probe environments (P1) and under the probe-only guard rule (W-C01-04). "It is a new check, not C01 #17's observation as #17 is written." It does not act on Batu's other work. Its deadline: before C02 builds DevOS's environments.

## Acceptance

<!-- acceptance -->
The check runs as W-C01-03 wrote it down, and its result is recorded either way in an evidence file under `evidence/C01/` with the common evidence envelope (plan Section 8 item 9: the source commit, the deployment configuration, the criterion version, the input, the actual observation, the raw evidence ID and the independence level), with no value of any credential. It turns red if either credential can act beyond its session: on another session in the same environment, on a session in another environment (the probe environments, P1), or on the account's settings or services. For each credential and each reach, the record holds the attempt, the platform's answer and the guard's answer, and the control: the probe's use of that credential working in its own session by the same route.

- **Green:** the result is N-107's input on `plan/work/C03.md`.

The item is accepted when the result and its route are recorded: for red, the void mark in `plan/work/C00.md` and the frame review's decision; for green, the evidence ID given to N-107 by a dated line; for neither, the frame review's decision.
