# W-C00-14 · Interim leak check in the guard for C00–C04

Added on 2026-10-05 (L-146) as work found by W-C00-10 (topic T-01 of `evidence/C00/EV-C00-013_findings_register.md`, disposition in `evidence/C00/EV-C00-014_w10_round1_dispositions.md`). Plan 0.5 item 3, K-9 item 5 and 6.7 say a code-based leak check runs inside the session before every public write; between C00 and C04 none runs, while the builder may read the private library directly (CHK-C00-022 F1, CHK-C00-023 F11). This item builds the fingerprint layer as a guard rule, before any public write drawn on the library (and so before W-C00-08 pass B). The semantic layer stays in C04 (plan C04 task 5). Background: R-W10-2 (the routes that write publicly and where a rule sits), summarized in L-146.

## Acceptance

<!-- acceptance -->
The guard (`.claude/hooks/tool_allowlist.py`) denies, under its own rule ID, any public write whose added text has a long match with fingerprints built from the private research library: a push to `devos` (the file contents, paths and commit messages of every commit in the pushed range, not only the endpoint diff) and every string field of a GitHub write tool aimed at `devos`. Fingerprints are built by a script in `tools/` from the library clone, outside the repository, in a store the guard protects from writes; the guard knows the only place a library clone may be (a clone of the library anywhere else is denied), and while that clone exists a missing or stale store makes every public write fail closed. A push that shares its Bash call with a command that can create commits or move refs is denied. Text already on `origin/main` does not count as a match. The same routes are also checked for the service names of `tools/check_service_names.sh` (OI-012, D-013), with the same rules for the log and the denial. Neither the matched text nor the fingerprints reach the decision log, the denial text or the repository. The PreToolUse and PermissionRequest hooks carry an explicit timeout no shorter than the merge gate's own limit. Tests in `tools/test_tool_allowlist.sh`, against a fixture library holding a planted fake secret: its verbatim form, and a planted fake service name, are stopped in a pushed commit's file, in a commit message, in a PR body, in a comment and in an issue (negative controls); DevOS's own synthesis that cites the fixture's source identifier passes in each of the same routes, and so does a push when no library clone exists (positive controls); a missing store with a clone present is denied; the planted text appears in neither the decision log nor any denial. All guard and merge-gate tests pass. A fresh-context checker verdict at the head (class high) judges the change against this condition and plan 6.7, and the working order section 10 states what the check does not cover (paraphrase until C04, interpreter routes, outbound URLs).
