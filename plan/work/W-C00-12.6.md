Written before the work starts, 2026-10-04. (a) Settings: `.claude/settings.json` on `main` sets `model` `claude-opus-5-5`, `effortLevel` `xhigh`, `ultracode` true and `permissions.defaultMode` `acceptEdits`; the guard denies `create_session` unless it passes `model` `claude-opus-5-5` and `permission_mode` `acceptEdits`, and denies routines that start a fresh session on each firing (their model cannot be set, BP-05). (b) A decision for every call: the guard answers every PreToolUse call with allow or deny, except `AskUserQuestion` and `ExitPlanMode`, which need the user by design, and it answers every permission prompt Claude Code still raises (PermissionRequest) with allow or deny under the same rules; it never answers "ask". Unit test: over the whole test corpus, every output is a valid decision and none is "ask". (c) Written reasons and a log: every denial states the rule ID, what was attempted (the tool and a redacted summary of its input), why the rule exists, where the rule is written, and what to do instead; every decision, allowed or denied, is appended to a per-session decision log with its time, session ID, tool-use ID, rule ID and reason; `tools/guard_report.py` prints a session's denials for its log entry. Unit-tested. (d) Explicit bans, each with a planted case that is denied and a near miss that is allowed: a push to `main`; force pushes and remote history rewriting; deleting a remote branch; a push to a branch outside `claude/` or to a remote other than `devos`; revision changes in the live working tree (checkout, switch, reset, rebase, cherry-pick, revert, am, stash, restore, clean, commit, and merge or pull other than a fast-forward to `origin/main`); writes to the live working tree's `.claude/` (except `.claude/worktrees/`), to any `.git/` directory and to Claude Code's own user configuration; uploads with curl or wget; the `gh`, `gcloud`, `gsutil`, `bq` and `claude` command lines; any use of the session's credential variables or files; GitHub file writes to `main`; enabling auto-merge; approving a pull request review. (e) Merge gate: `merge_pull_request` needs the full 40-character head SHA; when the head's diff from `main` is class high (`tools/check_records.py` impact), the merge is allowed only if a verdict in the head's own tree covers that head as `check_records.py merged` requires (PASS or PASS-WITH-CONDITIONS, bound to its review branch by an owned reviewer session that made no commit of the change). Planted cases: a class-high head without a covering verdict is denied; the same head with one is allowed; a class-normal head is allowed; a short SHA is denied. (f) Kept: every rule of the v1.7 guard that this item does not name as changed still holds, shown by the earlier test controls rewritten for the decision output; `Workflow` is allowed only when its script sets no isolation option. (g) Fail closed: a guard that cannot run blocks the call (wrapper test, as T-H4), and a permission prompt the guard cannot decide is denied, not left open. (h) Independent review: a session verdict, PASS or PASS-WITH-CONDITIONS with its conditions met, bound to the PR head before merge; besides the review prompt's criteria it answers "Does any route the new guard allows reproduce an outcome refused on 2026-10-04 (L-088, L-090) without a new design?" and "Is any rule here weaker than the v1.7 guard without D-008 requiring it?". (i) Live check after merge: a session created on `main` in acceptEdits mode with model `claude-opus-5-5` runs a fixed probe list without any permission prompt; its allowed calls run, its planted denials are denied with their written reasons, and its decision log holds every call; an evidence record states the result, and a failure reopens this item. (j) Text: operating model sections 2.1, 9 and 11 and Appendix M describe the new barrier and its residual risks; `CLAUDE.md` names the mode; the conversation brief corrects its lesson on permission prompts.
