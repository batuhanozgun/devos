# W-C01-43 · The disciplines check reads a workflow agent's task past the harness's relay of the user's request

Admitted 2026-10-11 (L-187). Found while W-C01-42's workflow (run `wf_f172f804-e71`) was being taken: every one of its six agents' reports carries the nine answers, and every task carried the whole discipline block, yet `tools/subagent_audit.py disciplines` printed `DISCIPLINES MISSING` for all six. Cause, observed in the transcripts: the workflow harness now puts a first user message of its own before the task, relaying the user's latest request ("[Workflow harness — user request] …"); the task follows as the second user message, with no assistant event between them. The tool reads the task from the first user event only (its docstring; W-C01-28). Plain `Agent` helpers are not affected (CHK-C01-031 and CHK-C01-032 passed). Until it is fixed, no workflow helper's output can be taken as a result (working order section 4 step 4), and workflows are a main way of splitting work. Serves working order sections 4 and 9 (D-016; N-110).

**State (2026-10-11, L-188).** The fix is judged by CHK-C01-033 (PASS-WITH-CONDITIONS at `0204381`) and merges with L-188; its two conditions (point 4's run from the live tree after the merge, and point 3's naming of the texts left as written) are met in the entry that closes this item.
