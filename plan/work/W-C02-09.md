# W-C02-09 · `devos_api` functions, their events, and the identity chain's functions (tasks 2 and 3)

Every state transition of C02's families as a `devos_api` function that produces its event in the same transaction (task 2; B section 4's groups for C02, R1 section 1 (c); F06), each first verifying the caller's environment token and deriving the role class from it, and, for an effect on a work item, the claim token (B:22, B:45); and the identity chain (task 3): `devos_private.issue_env_token(role_class)` and `revoke_env_token`, which only the project owner can run (B:46; 6.3, "How is the token generated?"), the claim token, and the authority epoch's use, as W-C02-05 designs them. It passes the tests W-C02-07 wrote for its parts. Owner: the executor. Deadline: before W-C02-10.

   - ✔ `devos_private.issue_env_token(role_class)`, run as the project owner in `devos-test` by the path W-C02-05 designs, shows a token once and stores only its hash (B 3.27). ✘ Looked for right after, by the token's value: it is in no table, no event payload, no rejected-attempt record, no function result or error text, and no log the item can read (B 3.27: "The token itself is kept in no table and no record").    - ✘ `issue_env_token` and `revoke_env_token`, called as every application role and with every role class's token, `devos_kurulum`'s included (B section 2, its "Cannot do" cell: "Issuing tokens"), are refused. ✘ Looked for: no file under `supabase/migrations/` calls `issue_env_token` (6.3: the builder "writes a database function that generates tokens but cannot run it"); the record names every other route that could run it (for example the migration job's role) and the layer that closes each, as W-C02-05 designs.
   - ✔ A call carrying a valid token of class X is processed as class X. At least one call per role class goes through the real path W-C02-05 chose (the Data API with the publishable key and the token in the header it names, or the Edge Function gate of row 3's first branch; Appendix B section 8's last row), not only with the header simulated in SQL; a test that simulates it says so in its record.

   - ✘ A declared role name and a declared session ID other than the caller's own, sent with the same token, change nothing in the outcome (B principle 8: "no authority decision rests on them").
   - ✔ `revoke_env_token`, run as the project owner, increments the global authority epoch (B section 2); ✘ the revoked token is then refused, and a claim taken in the earlier epoch produces no effect (B principle 9; F08 (c)).
