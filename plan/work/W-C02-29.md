# W-C02-29 · N-315: records.py refuses a foreign working directory; sync_worktree.sh refuses a foreign tree and heals a stamp-only render

**The note.** N-315 (`plan/work/C02.md`; L-431, L-432). The executor ran a scratch clone's `tools/records.py render` with the live tree as the working directory. `records.py` resolves its paths from the working directory (`ROOT = Path(".")`), so it rewrote the live tree's `plan/ledger.md` and `DURUM.md`. Guard rule B4 denies `git restore` there. `tools/sync_worktree.sh` refuses any local change except `owned_ids.txt`, so the live tree cannot reach `main`. The live tree also runs its own old copy of the sync script.

**The approach** (agreed after two triage rounds of the test designer, the producer and a checker; filed in `evidence/C02/EV-C02-024_n315_triage.md`; verbatim below):
- **Way out.** A new working session, which Batu opens. It is not an in-session route.
- **Prevention.** One class-high pull request:
  - (1) `records.py` refuses a working directory that is not its own checkout.
  - (2) `sync_worktree.sh` (i) refuses a tree that is not its own checkout, and (ii) discards `plan/ledger.md` or `DURUM.md` only when its one change against `HEAD` is the render stamp in its strict format.
  - (3) Tests written first, each with its break.

This item is (B). Point 8 below is (A)'s observation.
