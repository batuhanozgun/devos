# W-C02-19 · The merge gate covers plan 6.7's high-impact path list

Plan 6.7's high-impact path list (PC-08) is "the one list of high-impact paths, used by Section 6.1, the high-impact changes below and the impact-class rules": `CLAUDE.md`, `.claude/` (settings, hooks, protocols, agents), `methods/`, `supabase/migrations/`, `supabase/functions/`, `pipelines/`, `.github/workflows/`, `.github/CODEOWNERS`, and the decision channel's code once C06 writes it. The installation's merge gate (`tools/merge_gate.py`, `HIGH_PREFIXES` and `HIGH_FILES`) covers `.claude/`, `tools/`, `.github/workflows/` and named files, but not `supabase/migrations/`, `supabase/functions/`, `methods/`, `pipelines/` or `.github/CODEOWNERS` (found by W-C02-08's test designer, Open 1). C02's first migrations are the first changes under `supabase/`, so until the gate covers them a migration could reach `devos` with no fresh-context verdict, the barrier the working order relies on until the audit environment exists (section 10). This item makes the gate treat the missing paths as class high, with its tests, before the first migration merges. The change is class high (`tools/**`). Owner: the executor. Deadline: before W-C02-03's first migration merges.

1. **Each listed path is class high, shown by its own cases.** For each of the eight paths `CLAUDE.md`, `.claude/`, `methods/`, `supabase/migrations/`, `supabase/functions/`, `pipelines/`, `.github/workflows/` and `.github/CODEOWNERS`, the test file has cases whose labels name the path, written in Appendix C's form C0 (claim, failure class, examples, both controls and the break, in the case's comment or label):
   - (a) ✘ Negative: a pull request that touches the path and adds no verdict gives `GATE FAIL`, exit 1, and a "class high:" line naming the touched path. At least two examples per path, from these forms: a new file in it (for a directory, at least one level down, for example `supabase/functions/<name>/index.ts`); a change to a file in it; a file deleted from it; a file renamed into or out of it (the gate reads diffs with `--no-renames`); a file whose name has a space or a non-ASCII character; and a file or symbolic link standing at a listed directory's own path or at a parent's path (`supabase`, `supabase/migrations`, `supabase/functions`, `methods`, `pipelines`, `.github`, `.github/workflows`; for `.claude` also nested, as the gate already treats a nested `.claude/` component, case (18)), since a link there redirects everything the list names below it while no listed path appears in the diff. Across the eight paths every form appears at least once, and the link form appears for every directory path. A pull request touching a listed path together with a class-normal one is class high.
   - (b) ✔ Positive: the same pull request, with a verdict file it adds that covers its head (PASS, `reviewed_head` the head, the `independence` and `checker_run` fields, as the fixture's verdicts have them), gives `GATE PASS`, exit 0, and "covered by".
   - (c) Break: in a copy of the gate at the head, every rule that classes the path is removed (for `CLAUDE.md` and `.claude/` more than one rule does: the list entry, and the file-name or component rule; a removal that leaves another rule classing the path is recorded as that, not as a failed break). Each path's break is run on its own; that path's negative cases then print `BAD` and the run prints `MERGE_GATE_TEST FAIL`.
   - (d) For `supabase/migrations/`, the route M7 takes: the fixture's guard, given a `merge_pull_request` call for (a)'s pull request, denies it under rule M7, and allows it once (b)'s verdict is added (as cases (1g) and (2g) do).
2. **The gate follows plan 6.7's list, not a copy of it.** A case reads the "High-impact path list" bullet of plan 6.7 from `plan/DevOS_Kurulum_Plani.md` at the head, prints the backticked paths it found and the phrase it skipped ("the code of the decision channel once C06 writes it", which names no path), and fails if a path found is not class high in the gate (a fixture pull request touching it, as in point 1 (a)) or if the set found differs from point 1's eight. A missing or unreadable plan file, and a bullet not found, are "could not check": printed as such and failing the run, never passing it (plan Section 8 item 14). Break, in a scratch copy: a ninth synthetic path added to the bullet makes the case fail; the bullet removed gives "could not check" and a failing run. So a later change of 6.7's list turns this case red until the gate and the case follow it.
3. **No other path's class changes, and the gate still fails closed.**

   - (b) ✔ Near misses stay class normal and pass without a verdict (`GATE PASS`, "class normal"), at least: `supabase/config.toml` and `supabase/seed.sql`; names that only begin like a listed path (`supabase/migrations-notes.md`, `methods.md`, `pipelines-old/x.py`, `.github/CODEOWNERS.md`); a listed directory's name below another directory (`docs/methods/x.md`, `tests/supabase/migrations/x.sql`, `tests/pipelines/x.py`); and another file under `.github/` (`.github/ISSUE_TEMPLATE/x.md`).
