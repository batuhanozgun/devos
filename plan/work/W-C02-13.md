# W-C02-13 · C02's tests run in full, each with its break (task 6)

Every test W-C02-07 wrote is run on real PostgreSQL in the environment it names, and passes; and for each, the rule it tests is deliberately removed and the test is shown to fail (the Acceptance's first line: "when each rule is deliberately broken, the related test fails"), by the break path W-C02-04 decides for `devos-test`; the concurrency test runs with many connections, repeatedly (Appendix C, "Concurrency"). A test that does not fail when its rule is removed proves nothing (Appendix C, C0). The results are recorded with the common evidence envelope (plan Section 8 item 9). Owner: the executor; the test run by a prober. Deadline: before W-C02-17.

## Acceptance

<!-- acceptance -->
Marks as in plan Section 9, "Marks in the acceptance conditions": ✔ a right attempt is observed to succeed; ✘ a wrong attempt, input or state is made, planted or looked for, and the point states what must then be observed. A point without a mark is judged from the records.

This item shows the first line of C02's Acceptance: "✔ The Appendix C tests whose stage is C02 pass (F02's rule is tested in C04 with the subagent task definition; PC-08); when each rule is deliberately broken, the related test fails." A test that does not fail when its rule is removed proves nothing (Appendix C, C0; plan Section 8 item 3). It runs every test W-C02-07 wrote, including those that show other lines of that block (W-C02-07 point 5).

A prober that wrote none of the tests and produced none of the builds they judge runs them, and the record names its run (agent ID). A fresh-context checker that did not write, build or run any of it (same session, fresh-context subagent; declared, Ek A 5.3; PC-06) judges, from the run's raw outputs rather than the prober's summary, at the head that adds the run's record, and states its independence level and what it shared with the prober and the producers (plan Section 8 item 7), that:

1. **The tests are those written before the build.** ✘ The test files the run used are identical to those W-C02-07 merged (no change under their paths between W-C02-07's accepted merge and the run's commit), or each change is recorded with the earlier result voided and the test repeated (ledger rule 3; Appendix G, G8 item 3). Every test W-C02-07's record lists was run, and the run's count of tests equals that list's.

2. ✔ **Each passes, on real PostgreSQL, where it says.** Each test ran in the environment its C0 field names and passed, with both its negative and its positive control observed (plan Section 8 item 2). The envelope names the Supabase project (name and ref) and the server version the database reports; a run on anything else does not count. A real-token test ran with that environment's real token by the route W-C02-05 designs ("Batu's steps" row 5); W-C02-12's run of a test counts here only if its envelope shows the same deployed migrations and function versions as this run's.

3. ✘ **Each fails when its rule is broken.** For every test, the rule it tests is removed by the break its C0 field states, through the break path W-C02-04 decides for `devos-test`, and the test, run against the broken rule, fails at the example or assertion that break names (for example, F01: the example whose intent field was dropped from the comparison starts to pass; F04: the row count in (a) explodes; F07: with updates allowed on the observation table, example (a)'s past evidence is lost). A failure from anything else (a missing object, a syntax error, a lost connection) is not a break shown. Where that path cannot reach the environment a test names (for example a real-token test against the live project), the record says on which target and with which tokens the break was shown, and why that target carries the same rule version. After each break the rule is restored and the test passes again; the run ends with the databases matching `main` by the comparison of 6.2 (`deployment_drift`), or the record says what could not be checked. A test that does not fail on its break fails this point; it is rewritten through W-C02-07's route, and its run and its break are repeated.

4. **Concurrency** (Appendix C, "Concurrency": "Many concurrent connections on real PostgreSQL; repeated runs"). ✔ With the numbers of connections and of runs that W-C02-07's test fixed in advance, in every run exactly one connection claims the work item, the system neither deadlocks nor rejects everyone, and two opposing hard dependencies added at the same time form no cycle; the record shows that the connections' transactions overlapped in time, not only that the connections were opened. ✘ With the rule broken, at least one of the same number of runs shows a second claim or a cycle.

5. **Format gates and the sample.** ✘ Every "filled but meaningless" example passes the database and lands in sample review, as a `Review` of kind `sample` in the audit environment's queue; ✘ N-074 T-31's planted records are caught at the rate W-C02-07 wrote in advance, within its tolerance, and N01's sampled share matches the set rate within its written tolerance; ✔ every complete record is accepted.

6. **"Could not check" kept apart** (plan Section 8 item 14). ✘ The missing, unreadable and partial inputs give "could not check", and a write or merge the check guards is blocked. The run's totals count pass, fail and "could not check" apart; a test that could not run is "could not check", never a pass, and while any C02 test stands there the Acceptance line is not met.

7. **The evidence envelope** (plan Section 8 item 9; Appendix B line 80, a form in git). Each result carries the source commit, the deployment configuration (the project, and the migrations and function versions deployed), the criterion version (the test file's commit), the input (synthetic and labelled, plan Section 8 item 13), the actual observation, the raw evidence ID (the runner's unedited output, filed), the independence level, and the evidence layer (plan Section 8 item 10). The later parts of F07, N04, N09, N25 and N29 are named as not run here, with their stages; F02 is C04's (PC-08).

The verdict is PASS, or PASS-WITH-CONDITIONS with every condition met.

Not covered, so that silence is not read as a pass (plan Section 8 item 14): the content of records, which the sample review judges in the audit environment (plan Section 8 item 12); the C03-stage tests of what C02 builds for C03; whether these results still hold after a later C02 migration that touches a rule a test covers (W-C02-14's, for example), which the stage close judges (W-C02-18 point 1); and the design of the break path, which W-C02-04 decides and this item only uses and records.
