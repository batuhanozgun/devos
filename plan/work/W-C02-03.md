# W-C02-03 · Migration path (task 0)

Plan C02 task 0, which the plan puts first: the CI job in `devos` that applies `supabase/migrations/` to `devos-test` and `devos` on merge to `main` (6.2), its migration credential, and the comparison function of 6.2 (`deployment_drift`, B:387 and B:390) with the database's record of the migrations it applied and the version of each deployed function. The credential's exact form, and how GitHub limits it to that job on `main`, are "[Awaiting verification: read from the current GitHub and Supabase documentation, with its date, and probed here]" (plan C02 task 0); R5 is the documentation reading to start from, with its dates. Batu enters the credential ("Batu's steps" row 1; Section 12 item 1). It serves the Acceptance's lines "✔ A migration merged into `main` is applied by the CI job, and its effect is seen in the database", "✘ A migration merged into `main` but not applied is detected by the comparison of 6.2", "✘ The migration credential cannot be read by an agent session, nor by a workflow run for a branch other than `main`" and "✔ The C01 probe schema and its tokens no longer exist". The probe schema and the probe tokens were never built (PC-21 item 1; `plan/key_inventory.md` rows 16 and 17), so the last line is shown by observing their absence, and the plan text that still says the first migration removes them (plan lines 938, 997 and 1239; R3 G1) is corrected by this item's plan change, which also carries N-209's corrections. Questions this item settles: the migration credential's database role and its place in Appendix B section 2 (R1 section 5 item 6); how `deployment_drift` authenticates when the migration job calls it, since every `devos_api` function first verifies an environment token (B:45; R3 G6); when the pull-request checks can run it, since `devos_ci`'s key comes with the identity chain (R3 G5; W-C02-05); the database record of applied migrations, which no Appendix B family describes (R1 section 5 item 6); and the migration ✘ against a workflow run for another branch while the rule of `main` is not yet a layer against sessions (R3 G8; N-175 on `plan/work/C03.md`). R5's documentation reading of 2026-10-12 bears on the design: a repository secret is readable by every workflow a write user can push, so it cannot meet the ✘ line (R5 G1); an environment secret with a deployment-branch rule of `main` and administrator bypass disallowed reaches only jobs on `main` that reference it (G2, G3, G7), and the documentation contradicts itself on whether a collaborator can write it (G8); no role limited to applying migrations is documented, and every documented credential that applies them can do more (S4 to S6); Supabase's own GitHub integration is a credential-free route (S8); GitHub Actions reaches a Free project only through the session pooler (S7); a Free project idle for seven days is paused (S10); and a custom schema is exposed in the dashboard (S11). N-099 T-65 (`plan/work/C09.md`) is met by this item's build. Any cost the documentation shows (a paid plan for an environment's secrets, for example) goes to Batu as his decision before it is relied on. It also settles how task 1's "first in the test project" is met when 6.2's job applies a merged migration to both projects, and how a high-impact migration's verdict comes before it reaches `devos` (W-C02-08's test designer, Open 2). The workflow under `.github/workflows/` is class high. Its own tests, in form C0, are written by the test designer before its build, as W-C02-07's are for the rest. Its first migration merges only after W-C02-19 is accepted, so that the merge gate treats it as high impact; its design, its workflow and Batu's step 1 do not wait for W-C02-19 (its test designer's Open 2: a `depends_on` would put W-C02-19's whole duration on the critical path). Batu reported on 2026-10-12 at 13:36Z, in the working session, that both Supabase projects are paused after a week without activity, so resuming them is his step before the first probe ("Batu's steps" row 0); since a Free project idle for seven days is paused again (R5 S10), the design says how C02's work keeps them active or how a pause is met, and a paid plan to avoid pausing goes to him as his decision only if neither works. Owner: the executor. Deadline: first, before any other C02 build.
