<!-- note N-036 status=open origin=OI-011#21 -->
**OI-011 item 21** (moved verbatim from `plan/ledger.md` section 5). Disposition: `plan/builder/w-c00-12/08_oi011_dispositions.md` section 1, row 21.

(21) the structure that makes knowledge visible, for context activation (principle 12). The library's own structure is a pyramid, proposed by Batu; observed on the gstack study: library routers (`research/INDEX.md`, `research/studies/INDEX.md`, `CATALOG.md`) → per-study `INDEX.md` routing by need → `CORE.md` compact model → `syntheses/` → `SOURCE-LEDGER.md` → pinned upstream source, plus META, STATE, METHOD and an adversarial CLOSURE-AUDIT, and a concept layer (`concepts/studies/<study>/TERMS*.md`) with numbered concept IDs. First assessment: it combines known patterns (progressive disclosure, hierarchical summary trees such as RAPTOR, provenance chains), and it suits agentic navigation by file reading. Weaknesses: weak cross-study routing (no visible problem → mechanism → studies index; to be confirmed); routes cover only anticipated needs; hand-written summaries can drift. Compare with vector RAG (finds the unanticipated but loses structure and provenance), CAG (infeasible at this size), GraphRAG (closest to "this also exists", heavy to build). Working hypothesis, to be tested against outside best practice and the library's memory studies: keep the pyramid as backbone, add a cross-study problem-and-mechanism index and semantic search for unanticipated queries. This also bears on the C04 library search design.
