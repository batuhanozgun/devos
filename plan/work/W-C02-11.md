# W-C02-11 · The guard and settings before the environments (task 7's prerequisites)

What must be in place before any session runs in the three environments (N-136; N-181; N-174; PC-21 item 5): the S9 bridge in `.claude/settings.json` (class high, with a checker verdict), confirmed by a session's own tool list, with N-181's answer on when that list is taken and whether S9's deny covers the desktop session tools; the decision whether the owned-ID recorder hook (`.claude/hooks/record_owned_id.py`) is kept, and, if it makes a checked change of the guard or the recorder hook, N-194's change (it records `send_later`'s trigger ID, with a test; N-200 on `plan/work/C06.md`); the installation's uses of session tools listed (N-136); and the guard's tests run again at the commit that will be live (N-174; its trigger is already met). Owner: the executor. Deadline: before W-C02-12.

This item serves no line of C02's Acceptance directly. It carries what N-136, N-181, N-174 and PC-21 item 5 require before task 7 creates the three environments and before any session runs in them, so W-C02-12 does not ask Batu's step 2 before this item is accepted. Marks as in plan Section 9: ✔ a right attempt is observed to succeed; ✘ a wrong attempt, input or state is made, planted or looked for, and what must then be observed is stated. Unmarked points are records the item must make.

1. **Uses listed** (N-136). A record lists every tool of the platform's session-tools server, `RemoteTrigger`, `SendMessage` and `ListAgents`, and any other session, messaging or routine tool a session of the installation has (from a session's own list, taken as point 4 sets). With each tool it lists every use the installation has made of it, from the logs, the guard's decision logs, the working order and the evidence files, each source named with how it was searched. Each tool is marked kept, with the use that needs it, or denied. The session's own reading for the opening check and the usage readings is kept (working order section 3; N-111); the check-ins armed with `send_later` (L-250) are kept or denied, with a reason.
2. **The bridge** (N-136; EV-C01-004 S9). `.claude/settings.json` gets: a deny of `RemoteTrigger`, `SendMessage` and `ListAgents`; a deny, under each of the session-tools server's three documented names, of every tool of that server that point 1 does not keep; and `crossSessionInbound` set to `refuse`. The names and the entries' form are quoted from the current documentation with its URL and reading date. For N-181, the record states, with its evidence, whether `ccd_session` (EV-C01-020) is one of the three names, and if it is not, whether the bridge also denies its tools, and why. The change adds no guard rule family (FR-05 B; EV-C01-004 S10).
3. **Rule-change route.** The settings change is class high: it merges only with a fresh-context checker's verdict at the head that adds it. The plan text EV-C01-004 section 8 names for S9 (its item 7, the 6.7 row "The Claude account's control surface"), and any working-order text the change makes untrue (for example the session tools named in sections 3 and 10), change through plan Section 14: a `plan/decisions/PC-<nn>.md` record with the old text, the new text, the reason and the affected stages, and a fresh-context checker's verdict on that change before its merge (class high where it touches the working order). They are merged before W-C02-12 relies on the bridge.
4. **Confirmed by a session's own tool list** (N-136; N-181; D-017 item 2 (a)). N-181's answer states when the confirming list is taken, so that a server that arrives after a session's first call (EV-C01-020) is in it, with its reason and evidence. Each list is recorded raw, and what the confirmation rests on in the documentation carries PC-21 item 9's claim (source, reading date, "not independently tested", the qualifiers).
   - ✔ Control: a list taken the same way before the change shows the tools the bridge will deny, so the listing would show them if the deny did not hold.
   - ✘ After the merge and the live tree's sync, a session's own list, taken at the time N-181's answer names, lacks every tool the bridge denies, under every name.
   - ✔ The kept tools are listed and do their use (the opening check's own-session reading); a subagent call still returns its result; and the guard is live after the sync (`tools/guard_report.py` shows decisions made after it), so a settings file the platform rejected or ignored would show.
5. **The recorder hook** (N-136). The record decides, with its reason, whether `.claude/hooks/record_owned_id.py` and its `PostToolUse` entry are kept, changed or removed under the bridge, which may deny the tools it watches. If this item changes the guard or the recorder hook, N-194's change (N-200 on `plan/work/C06.md`) is made with it: the recorder records `send_later`'s returned trigger ID, with a test that fails without that change; or the record shows, with its reason, that the bridge removes the need (for example because `send_later` is denied). If neither changes, N-194 and N-200 keep their deadline, and the record says so.
6. **The guard's tests at the commit that will be live** (N-174; PC-21 item 5). After this item's last change to `.claude/hooks/tool_allowlist.py`, `.claude/settings.json` or `tools/test_tool_allowlist.sh`, `tools/test_tool_allowlist.sh` runs at that commit on a pushed branch (for example `main` in a scratch clone). It judges only the three properties (the guard denies a tool not on its list, never answers "ask", and denies when it fails or runs past its time limit) and carries no rule detail (D-017).
   - ✘ No `BAD` line and no skipped control. If a property does not hold, the guard is corrected through the merge gate and the run is repeated before W-C02-12 (plan C01 row 9's fail path).
   - The run counts only while its three blobs are the live tree's: if any of them differs when the first session runs in one of the three environments, the run is repeated before that session.
