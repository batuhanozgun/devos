# W-C02-17 · C02's combined scenario, read cumulatively (plan Section 8 item 5)

N-207: at C02's end, one scenario tests together what has been built up to that point, read cumulatively: C02's builds with the working system from C00 and C01 that C02 relies on, including at least one guard deny path, a merge through the merge gate, a records-tool check, and a subagent call that loads a role file; its record names each component as used, not used, or could not check (as `evidence/C01/EV-C01-028_W-C01-47_combined_scenario.md` section 3 does), and names what C01 never observed live with where it is next observed (T4's deny path and the platform side of `onFailure: block`, C03 test 3 and N-137; T4 allowing a repository skill, C05 and N-077). Owner: the executor. Deadline: before W-C02-18.

## Acceptance

Marks as in plan Section 9, "Marks in the acceptance conditions": ✔ a right attempt is observed to succeed; ✘ a wrong attempt, input or state is made, planted or looked for, and the point states what must then be observed. A point without a mark is judged from the records.

This item serves plan Section 8 item 5 ("The whole system can fail while the parts pass one by one. At the end of each stage, what has been built up to that point is tested together in one scenario") and carries N-207's elements word for word: "At this stage's end the scenario tests together this stage's builds with the working system from C00 and C01 that it relies on: at least one guard deny path, a merge through the merge gate, a records-tool check, and a subagent call that loads a role file; its record names each component as used, not used, or could not check (as `evidence/C01/EV-C01-028_W-C01-47_combined_scenario.md` section 3 does). What C01 never observed live is named with where it is next observed: T4's deny path and the platform side of `onFailure: block` (C03 test 3; N-137), and T4 allowing a repository skill (C05, N-077)." C01's scenario tested its stage only in part (CHK-C01-112 finding 7); this condition is written so that the same narrowing fails it.

A fresh-context checker that neither designed nor ran the scenario and produced none of C02's builds (same session, fresh-context subagent; declared, Ek A 5.3; PC-06) judges, at the head that adds the scenario's record, and states its independence level and what it shared with the producer (plan Section 8 item 7), that:

1. **Fixed before it ran.** The scenario's steps, the component each step uses and each step's expected observation are committed before the run (git order shows it), and the record names who wrote them. The run's record follows them; a departure is recorded as a departure, never as the expected result.

2. **When, and on what.** It ran after W-C02-13 and W-C02-14 were accepted and before W-C02-18 started, on the `main` commit and deployment its envelope names. The record lists every C02 item whose build was merged at that commit, and names any C02 build merged after the run as not part of it.

3. ✔ **Tested together, in one run.** The steps hand their results to one another (for example, the record a subagent loaded with its role file writes goes through the rule gate; the merge through the merge gate carries a migration that the CI job applies), so that the run would fail if the parts did not fit; the record names each hand-off. The run uses at least:
   - (a) the builds the plan gives as the reason for C02 (plan Section 9, the table under the ordering principle: "Recording the work: without the rule gate, the identity chain and the format gates, C07's needs and decisions (measures 2 and 7) would rest on the agent's word, and its effects would need no claim"): a state transition through a `devos_api` function with a real environment token and a claim token, and its event in the same transaction; a record through a format gate; and the migration path, a migration merged into `main` and applied by the CI job, with `deployment_drift` run after it;
   - (b) a record written or read where W-C02-06's design keeps it after the ledger transfer (W-C02-14);
   - (c) the working system from C00 and C01 that C02 relies on, as N-207 names it: at least one guard deny path, a merge through the merge gate, a records-tool check, and a subagent call that loads a role file (the call's type is a file in `.claude/agents/`, and the evidence shows that it loaded: the guard's decision record and the role's output form in the report).

4. ✘ **Wrong attempts inside the run** (plan Section 8 item 2). The run makes at least: a call the guard must deny, recorded with the denial's rule ID and decision-log record number, after which the denied effect is absent; and an effect without a valid claim token (none, or another session's), which the rule gate rejects with its recorded reason, with no state change and no event. Every right attempt of the run succeeds.

5. **Each component named** as used, not used, or could not check, as EV-C01-028 section 3 does: every lasting build of C02 (the products of W-C02-03, W-C02-08 to W-C02-12 and W-C02-14 to W-C02-16) and every component of the working system from C00 and C01 that C02 relies on, each with the item and merge that built it, the run's evidence for it, and, for "not used" or "could not check", why. The record states which C02 builds the run did not test together.

6. **What C01 never observed live** is named with where it is next observed: T4's deny path and the platform side of `onFailure: block` (C03 test 3; N-137), and T4 allowing a repository skill (C05, N-077). If this run observes one of them live, the record says so, with its evidence.

7. **The record** carries the common evidence envelope (plan Section 8 item 9; Appendix B line 80), labels its inputs synthetic (plan Section 8 item 13), and has a section "What the record cannot show" (plan Section 8 item 14) that names what rests only on the session's own records.

The verdict is PASS, or PASS-WITH-CONDITIONS with every condition met. ✘ A run that uses only point 3 (c)'s four elements and none of C02's builds, or whose parts each run on their own prepared inputs with no hand-off between them, does not meet point 3, whatever its record says.
