### 2. Working order section 10, "What it does", the "Token formats" bullet (line 143), its last sentence (W-C02-20 point 10). Labelled: no.
Old:
```text
The client path's exception (W-C02-20's second change) is not built: a string of either format is denied there too.
```
New:
```text
The client path's exception (L5; W-C02-20 point 3, its second change; EV-C02-015): a string of the claim token's format, and of that format only, may stand in the arguments of the client script's own call to the live project's host, and nowhere else. That call is a `Bash` call whose whole command matches in full the one form the guard holds: `python3 -I tools/devos_rpc.py <function>`, the function's name in the client's own form (a lower-case letter or an underscore, then at most 62 lower-case letters, digits or underscores), then its arguments in a single-quoted here-string or in a here-document whose delimiter is in single or double quotes, and at most one final newline. Nothing else may stand in the command (no pipe, no second command, no other path or interpreter, no call without `-I`), and a here-document whose body holds a line equal to its delimiter is not that form. The hook input's `cwd` must be the guard's own checkout, by its real path, and `tools/devos_rpc.py` there must be byte for byte the script merged into `main` (added by `9af14f1`, merged by `7a6f3ea`, PR #352): the guard pins its SHA-256, and the script names its one host in its own text, so the pin fixes the host too. In that call L4 still reads the command outside the arguments (the function's name included) and every other field of the call (its `description` too) with both finders, and the arguments with the environment token's finder, so the environment token's format is denied there as everywhere; while the shared files cannot be checked, the call is denied as "could not check". The exception does not apply to another form, to another directory, or while the script is missing, unreadable or changed: the call is then L4's like any other, and a claim-format string in it is denied as a match. So every change of the script turns the exception off until a guard change of its own follows it. Every other rule still reads the call; when none denies it, it is allowed as `L5`, and every L5 decision, the allow included, is logged with the call's text withheld; an L4 denial of it keeps its rule, and another rule's denial of it is returned as `L5`, naming only that rule's ID and title. Residuals of the exception: the guard takes the hook input's `cwd` for the shell's directory, and does not resolve `python3` (an interpreter earlier on the process's `PATH` is outside the call's text); the script's content is read at the decision, not at the run; and the claim string stays in the session's own transcript, by design (EV-C02-003 section 1.7).
```
Reason: the old sentence is untrue at the head. Each clause of the new text is the guard's at `e82e84b`, as EV-C02-015 section 1 records it:
- **The form excepted:** `CLIENT_CALL`, matched with `fullmatch` against the command; the function's name is the client's own `FUNCTION` pattern; the delimiter may be single- or double-quoted (EV-C02-015 section 2, R8's addition), and `<<-` is not accepted; `client_args()` gives no span when a body line equals the delimiter. The absolute path, `./` and the call without `-I` are denied (`P3c2-info-abs`, `-dot`, `-no-I`, observed `deny`).
- **Only the claim format:** `token_stop(..., claim_ok=...)` reads the arguments with every finder but the claim token's, and the rest of the input (the command with the arguments cut out, and every other field, object keys included) with both; `token_finders()` runs first, so "could not check" holds on this path too.
- **The pin:** `CLIENT_SHA256` over `ROOT/tools/devos_rpc.py`; `cwd` must be absolute and equal `ROOT` by `realpath`. The script's host is a constant in its text (P4), which is why a content pin fixes the host (README 12.1, R9).
- **What turns it off:** `client_args()` returns `None` for another form, another `cwd`, or a script that cannot be read (missing, a directory, a link loop) or whose hash differs; L4 then runs as before, so the claim string is denied as a match, not as "could not check" (EV-C02-015 section 2, R13).
- **Logging:** `LEAK_WITHHELD` holds L5, so every L5 decision's summary is withheld; `decide()` returns the allow as `L5`, keeps an L4 (or L1, L2) denial's rule, and returns any other rule's denial as `L5` with that rule's ID and title only (EV-C02-015 section 2, R12).
- **Residuals:** EV-C02-015 section 9, its four items, each stated. The bullet's "Not caught" list above still holds for this path: arguments read from a file the call names are not in the call (`P3c2-info-file-arg`, allowed).
The last two sentences of the bullet before this one (the shared files and their class) are unchanged. Stages: C02 (N-221 step 5 and the first claim-carrying calls), C03.
