# FR-07

**Why it opened.** W-C02-03 (the migration path) had its second FAIL: CHK-C02-029 on the build (GitHub expressions inside `run:` bodies, which every offline check ran past) and CHK-C02-045 on revision H1 of its live campaign (with lenses CHK-C02-043 and CHK-C02-044). Working order section 6 item 2 and plan 6.12 item 2: a second FAIL on the same item opens a frame review before a third attempt. Between the two, a third defect of the first one's class was found on GitHub: the pull-request check could never read the migration job's run report, because every run skips two of its four jobs and GitHub answers 404 for a skipped job's log, while the offline stub listed two jobs, both run (L-304). Three fresh-context researchers worked in parallel: a premise inventory from the records, the failure class across the item's FAILs and defects, and an independent counter-assessment that read only W-C02-03's acceptance block, the plan's text and stated platform facts; a fourth weighed them (the inputs, verbatim, under `evidence/C02/raw/FR-07_*.md`). The executor decides here.

**What was found.** The premises are in the front matter (P-A to P-E). Their common frame: the campaign kept class-high merges and scheduled waits few by bundling parts made in parallel and by modelling GitHub offline, so consistency and the truth about the platform were checked only by a reader at the end. The checkers caught eight of nine defects before a merge, and the one that reached `main` failed closed: the failures were costly, not unguarded. The class is still open for the search, the next GitHub-facing code, which has never run on GitHub: its archive layout is "could not check", and no scheduled run of `migrate.yml` has yet been created (none by 2026-10-13T01:15Z, for the 00:41Z slot).

**The decision.**

1. **Before any verdict, code that needs no secret runs on GitHub.** The pull request's own check shows the workflows load and their secret-free steps behave; the search is run before its verdict by a never-merged rehearsal workflow with no environment (`issues: read`, `actions: read`, the search's own code, the plant only in base64, the unbroken copy only), on a branch based on the revision; its log is read against the expected counts. The rehearsal is exploratory: it is never T-W03-09's result. Repeatable tests replay only shapes observed on GitHub, each labelled observed or derived. Before H2, H2 to H5's sequence is rehearsed with the pinned CLI on a throwaway PostgreSQL of the projects' major version where reachable (for example a service container in a never-merged workflow with no environment), the gap stated where not.
2. **A revision is built in sequence from facts its tasks fix.** The executor writes the shared facts into every task (for H1-prime: the plant step stays in `check-devos-test`, whose reason in EV-C02-007 14.2 holds; S1, the first scheduled run after the merge, prints; S2, the second, searches; the expected count is one per job, read from S1's archive by the search's rule; S1's own logs place reads "could not check" by design; CHK-C02-045 C1's windows; T-W03-08 (e) after S2's search). The producer builds first; the test designer revises the test after reading the build, before any result (the role may read the product and never writes it). Once a revision's tasks are out its scope is frozen; a finding made meanwhile becomes its own change. The checker compares the facts in the tests with the facts in the build.
3. **The plant is made last and never held as text.** For each round the executor makes a new tag and the plants from it at the point of use, last, after the revision's other parts are judged ready; the value is never written to any file (scratch files included), commit message, pull-request text, verdict or record; records name the tag only. Before each push the search's own counting code runs over the local clone and prints counts only; on GitHub the rehearsal counts it before the verdict, against CHK-C02-045 C2's numbers. Tag `20261012T2338Z` is retired. A separate tag per place, a repository variable, or object IDs instead of totals come in only if a second tag is spoiled.
4. **A class guard rides on the change that can repeat the class.** When a verdict finds a class that the next change can repeat, the guard is a condition of the verdict on that next change, not a note. N-265 is met, not re-dated, by H0 below.
5. **The schedule stays** (M04). S1 and S2 are planned explicitly, and the fixture track runs beside them. If by the 06:41Z slot of 2026-10-13 no scheduled run of `migrate.yml` has been created, or later ones are hours late, `workflow_dispatch` for the compare-only jobs is reopened as a design change with its own record and verdict before H1-prime merges; taking p4 out of the binding control is the fallback only.

**The order that follows.**
- **H0** (class high): N-265's guards (pull request #310, with CHK-C02-049's conditions met) and the `pr_inputs` fix (`f266f84` on the H1 branch, with EV-C02-007 14.14) on one head off `main`. One fresh verdict at that head; its pull request's own check must show `W03_PR_INPUTS_TEST PASS`, `W03_RUN_EXPR_TEST PASS` and both projects read. It removes CHK-C02-045 F-3 (N-265 met), the red window #310 alone would open, and the block on M16's allowed removal.
- **H1-prime**, by item 2's sequence: the executor's tasks with the facts; the producer's build (H1's content without the plant, EV-C02-007 14.13 naming the tag only, `W03_PLANT_B64` empty, the rehearsal workflow on its own branch); the test designer's revision of T-W03-09 as CHK-C02-045 C1 asks; the executor's new tag and plants, last, with the local count; the pull request's check and the rehearsal's log; a fresh checker, limited as CHK-C02-045 allows, reading the rehearsal log and comparing the facts. No merge while a scheduled run is queued or in progress.
- **Then two tracks.** Point 9: S1, S2, then the break copies, then T-W03-08 (e); the plant's unsetting rides on the next class-high merge; merges stay free except from about 35 minutes before S2's slot until its search ends. The fixtures: A3's rehearsal, then H2 to H5, each built, revised, checked on GitHub and judged. T-W03-08's probes (a) to (d) and (f) need no merge and can run at any time; their negative results stay "could not check" until the positive control (H1-prime's push run) has run.
- **Last:** the records, then point 13's checker.

**CHK-C02-045's conditions under this frame.** C1 unchanged, met by item 2's sequence. C2 unchanged, counted twice before the merge (locally before each push; on GitHub by the rehearsal). C3 met by H0, not re-dated. C4: "not while a scheduled run is queued or in progress" stays; the baseline is any completed scheduled run at a pre-H1-prime head; if none exists when H1-prime is ready, the revised T-W03-09 drops the baseline under C4's own exception, with its reason (the rehearsal shows the code on GitHub, S1 shows P7).

**What this decision does not do.** It does not change W-C02-03's acceptance block, or T-W03-09 after S1 has run; it adds no standing mechanism, no further lens of the same kind, and no offline model of GitHub written from belief as evidence (the executor's own harnesses `c2_cases.py`, `c2b_cases.py` and the producers' simulators are hints, never a verdict's evidence); it does not patch `workflow_dispatch` into H1-prime; it does not count the rehearsal as T-W03-09's result. It asks nothing of Batu: no money, no account action, no change of scope. The old fixture branch holds only the retired tag and can be left for one of his batched steps.

**Corrections it makes.** EV-C02-001's PC-23 row for the schedule ("None: it applies nothing") is incomplete: the schedule gates T-W03-09, so it adds about 6 to 12 hours per search round to W-C02-03's acceptance (annotated there with this decision).
