### 1. Appendix B 3.15, the rules, their last sentence (line 286). Labelled: no (Appendix B is a [Proposal], its line 3).

New: "Exam tasks are opened in the working environment as ordinary `Work`. The fact that a task is an exam is kept in no field of the `Work` record: `EvalRun`'s link holds it (above), and so does the `role_class` of every event that happens in a `devos_sinav` call, the task's creation event among them (3.13); the exam records stay hidden, no function returns the link or that `role_class` to the working environment, and no function answers the working environment differently for an exam task than for ordinary work (`evidence/C02/EV-C02-002_data_model_choices.md` DM-24 and DM-35; `evidence/C02/EV-C02-008_design_addendum_roles_and_samples.md` section 5.1)."
Revised 2026-10-12 (CHK-C02-028 C4). The first New text said "The fact that a task is an exam is kept only in `EvalRun`'s link (above), never in a field of the `Work` record; the exam records stay hidden, and no function answers …". Its "kept only" was untrue: the task's creation event carries `role_class` `devos_sinav` (B:266), and `devos_sinav` opens only exam tasks (B:38).
Reason: EV-C02-008 sections 5.1 and 5.3 place 1. The old sentence's "field" has disagreed with B:284 ("the link lives only here, so only `devos_sinav` can read it") since PC-42, and with EV-C02-002 DM-24 (no exam field on Work). The Work an exam task was opened as is ordinary for every class. The new text says so, and states property P where B states the exam's rules. It names the working environment only. The audit class has two reads that stay open until C05 opens an exam task for an audit role (section 5.1 (d); P:814; CHK-C02-027 A): RejectedAttempt, whose rows keep `role_class` and `target_ref` (B:270), and a sample's creation event, which it reads at once (place 2). ### 2. Appendix B 3.11, the rules, the bullet on `sample` reviews (line 247). Labelled: no (Appendix B is a [Proposal], its line 3).

New: "- A review of kind `sample` is created by the database, never by an agent, for a set share of the records a format gate accepts (principle 12) and of the work items and decisions labelled `routine` (3.3, 3.17); it is queued for the audit environment, which judges the content and the label (PC-08).
