# PC-20

**Authority.** Note N-110 on `plan/work/C01.md` and item W-C01-28, whose acceptance block is binding: CHK-C01-001's condition and its findings 6 and 7, and CHK-C01-002's findings 7 to 9, the follow-ups of PC-19. Plan Section 14 and the working order section 6 apply.

**Labelled text.** No passage labelled as Batu's decision is edited; D-016 is cited, not changed. **Acceptance conditions.** None is touched: no stage's Acceptance line, no acceptance block of a `plan/work/*.md` file, no Appendix C test. The task check gets stricter. The log check now accepts a later correction for an entry: without it, an entry on `main` without the line could never be repaired in an append-only log, and every later `render --check` and stop check would fail. The correction gives the nine answers, checked in the same form as an entry's own line.

**Class high.** `plan/Installation_Working_Order.md` and `tools/`; checked before the merge.

## Changed places

1. **Working order section 4, step 4.** *Old text:* "a helper's report is taken the same way (D-016). On PASS, …" *New text:* "a helper's report is taken the same way (D-016). After `DISCIPLINES MISSING`, the helper's output is not taken as a result. If the task lacked the block, the task is given again, with the block, to a fresh helper: the guard denies resuming a helper (`SendMessage`), so a fresh one is the only route. If the report or verdict lacks the nine answers, it is not filed or used, and a fresh helper is given the task. The earlier output may be read as a hint, never as evidence or a verdict. The log records the result and the re-run (N-110). On PASS, …" *Reason:* CHK-C01-002 finding 7; D-016 item 2 ("the executor does not accept a report without it").
2. **Working order section 4, "Stage close".** *Old text:* "a "no" where the discipline was needed is a finding (D-016). Until C03 …" *New text:* "a "no" where the discipline was needed is a finding (D-016). Helpers' reports live only in the container's transcripts, so the stage close samples them while the container lasts. The executor keeps the reports it relies on by filing them, or their essential content, in the records: verdicts verbatim, as now; a research report as evidence when a result rests on it (N-110). Until C03 …" *Reason:* CHK-C01-002 finding 9.
3. **Working order section 9, log entry format.** *Old text:* "From L-159 every entry carries the Disciplines line, nine answers in order (D-016); `tools/records.py render --check` fails without it." *New text:* the same, then: "The merge gate does not run that check; `tools/stop_check.sh` does, so such an entry is caught before a stop at the latest. The log is append-only, so the remedy for an entry without the line that reaches `main` is a new correction entry. It names the entry and gives the nine answers as they stood, in a line `- **Disciplines of L-nnn (D1–D9):** …`, beside its own Disciplines line; `render --check` then counts the entry as answered (N-110)." *Reason:* CHK-C01-002 finding 8.
4. **`tools/records.py`.** An entry from L-159 on whose own line is missing or malformed passes when a later entry (a higher number, in any log) carries a line starting "- **Disciplines of L-<n> (D1–D9):**" whose answers pass the same check. Tests: `tools/test_records_disciplines.py` L-172 to L-178.

It has no test file. Scratch copies of the repository showed the new line: PASS on the log as it is, FAIL with an entry without the line, PASS with that entry and a correction entry.
