**F2. The exemption keeps N28's purpose, and I could not build a Review that takes it (does not block).**
- **Evidence:** EV-C02-008:189-213; B:247 and B:266 at HEAD; P:1010 ("✘ No role can write directly to the tables"); README 8.1:350-352.
- **Client-made Review:**
  - Through `open_review` or `transfer_review` with kind `sample`, it is refused (condition 2).
  - By a direct insert, there is no table privilege (P:1010), and the table check needs the marker.
- **Verifier-made Review:**
  - Kind `review` fails condition 1, and filled reviewer fields fail condition 4.
  - A Verdict always counts (2.2, "every Verdict").
  - A verifier that takes a sample inside the drawing transaction is refused, because the drawn revision is in that same transaction ("either order").
  - A verifier that writes a gated record only draws a sample of its own new revision, and nothing in that transaction is judged.
- **Forged sample:** even if condition 2 were bypassed, the row would carry no reviewer and no verdict. It records no judgement, and taking it falls under DM-41.
- So condition 4 together with the taking rule is what protects N28. Condition 2 protects N01 (no agent-written samples).
- Case 6 (a further revision before any verifier acts) adds nothing a later transaction does not already allow.
