## 2. Where I disagree
- **The shared reading ("the role file is the one root").** It is not the only root. Three carriers are always present: the role body (owned by the role), `CLAUDE.md` (common to all) and the task text (chosen by the executor). The common floor belongs in `CLAUDE.md` (Ek A 3.5, last bullet). The task text is the one route already observed working (O6), but it depends on the executor's selection, which is exactly the D-039 failure. So the role body has to carry what the task might leave out.
- **Test designer ("under about 4 pages it gets read in full") and producer ("read in full at the start").** Both are untested. Whether the file is opened can be observed (O4); whether it is read in full cannot, from the log alone; whether it is used needs the planted case. Treat both as hypotheses.
- **Researcher (agent teams as "a candidate to weigh").** Plan 7.2 already decides this, and the brief says the plan does not change. Reopening runs through the condition CHK-C00-048 recorded, not through a fresh weighing.
- **My own round-1 note.** I wrote that a `skills` preload "would put the package into context every time". That is documented, not observed. It also has a side effect I did not mention: a skill can be preloaded only if the model is allowed to invoke it (doc line 627). So any agent, the executor included, could also invoke it, and its description would appear in skill listings.
