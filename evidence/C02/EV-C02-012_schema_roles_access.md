## 4. Point 4: no role can write directly to the tables

**What the build does** (M5:77 to M5:106; M6:68 to M6:78; M8). `revoke all` on the schema `devos_private`, on all its tables, sequences and functions, from PUBLIC and from `anon`, `authenticated`, `authenticator` and `service_role` where each exists; `revoke all on schema devos_api` from the same, then `grant usage on schema devos_api to anon` only (README 8.1). M8 revokes all (for a type, USAGE) on every type in `devos_private` whose privileges can be set, from the same (below). Nothing is granted on any `devos_private` object. M6 drops and makes again the view `finding_current` (section 9) and applies the same revokes to it; M7 replaces it in place (`create or replace view`, three columns added at its end), which keeps the relation and its privileges (O, C: `06_catalog_types_finding.txt`: `finding_current` `relacl` `{postgres=arwdDxt/postgres}`). Reads granted by name: none (EV3 §4.1 grants every read through a function), so no read reaches EvalRun directly, `devos_sinav`'s included.

The identity columns of `event`, `rejected_attempt` and `leak_fingerprint` are `generated by default`, so that a direct write is refused by the privilege check, not first by the identity rule (SQLSTATE 428C9), which is what T-W07-5A measures (the first producer's finding under B-5A-1).

**Types (M8; CHK-C02-068 C2).** PostgreSQL gives PUBLIC USAGE on a new type: its `typacl` is null, and `acldefault('T', owner)` reads `=U/owner`. Before M8 that held on every type in `devos_private` (CHK-C02-068 counted the 30 enum types; O, C: `07_probe_types_before_after.txt`, database `probe` after M1 to M6: 30 own types, 32 row types and 62 array types, each with a PUBLIC grantee in the verdict's query, all 124 usable by PUBLIC and by each application role). M8 runs `revoke all on type <t> from public`, and from `anon`, `authenticated`, `authenticator` and `service_role` where each exists, for every type in `devos_private` that is not an array type (nor a multirange type, of which there is none): the 32 enum types (30 of M1 to M6, 2 of M7) and the 32 row types of the 27 tables and 5 views.

What PostgreSQL lets a migration set (O, C: `07_probe_types_before_after.txt`, probes in one transaction, rolled back, as the non-superuser `postgres`):
- **An array type:** `revoke` and `grant` on `devos_private._finding_status` are refused, `SQLSTATE 0LP01: cannot set privileges of array types` (P1). An array type has no privileges of its own: `has_type_privilege` checks its element type. After a revoke on `finding_status`, `_finding_status` keeps `typacl` null, PUBLIC may use neither type, and `anon` may not use `_finding_status` (P3; before the revoke all three were true).
- **A table's or a view's row type:** `revoke all on type devos_private.finding from public` and the same on `finding_current` are accepted; `typacl` becomes `{postgres=U/postgres}` (P2).

**The condition's query at the new tree** (O, C: `06_catalog_types_finding.txt`, sections C2 (1) to (3); C: `06b_chk68_type_query.txt`; the same after M7 and M8 in `probe`, C: `07_probe_types_before_after.txt`):
- `aclexplode(coalesce(typacl, acldefault('T', typowner)))` over every type in `devos_private` gives a PUBLIC or application-role grantee for **no enum type and no row type**: each of the 64 has `typacl` `{postgres=U/postgres}`. CHK-C02-068's own query (enum types only, its `run/catalog.sql` section 10, run verbatim) returns 0 rows over the 32 enum types.
- **It still lists PUBLIC USAGE for the 64 array types**, because their `typacl` stays null and `acldefault` then reads `=U/postgres`. No revoke can remove it: PostgreSQL refuses GRANT and REVOKE on an array type (P1). It grants no use: `has_type_privilege` for `public`, `anon`, `authenticated`, `authenticator` and `service_role` is false on all 128 types in `devos_private`, the 64 array types included (0 of 128 usable for each). Read literally, the condition's query is therefore not empty, and this is the PostgreSQL behaviour that leaves it so; restricted to the types whose privileges can be set, it is empty.

**Explicit revokes, not `ALTER DEFAULT PRIVILEGES`** (D1). Alternatives weighed with the probes:
- `alter default privileges in schema devos_private revoke usage on types from public` does nothing: it writes no `pg_default_acl` row, and a type made afterwards still has `typacl` null and PUBLIC's USAGE (P4). Inf, consistent with P4: a schema's default privileges add to the role's and cannot take one away (PostgreSQL's documentation of `ALTER DEFAULT PRIVILEGES` says so; not re-read for this record).
- `alter default privileges revoke usage on types from public`, for the migration role in every schema, writes the row (`postgres`, all schemas, `T`, `{postgres=U/postgres}`). A new enum type then gets `{postgres=U/postgres}`, but its array type keeps `typacl` null (the verdict's query would still list it), a new **table's row type keeps `typacl` null and PUBLIC's USAGE**, and a type `postgres` makes in `public` loses PUBLIC's USAGE too (P5). So it would not spare a later migration its revokes (tables and views still need theirs), it could not reach the 64 types that already exist, and it would change how `postgres`, the migration role, makes types in every schema, outside `devos_private` too, which this item does not need.
- Chosen: explicit revokes in M8, as M5 does for functions, and **each later migration revokes USAGE on the types it adds, a new table's or view's row type included**, as each later function revokes its own EXECUTE (M5:81-82). An array type needs nothing: it follows its element type.
- `pg_default_acl` has 0 rows (O, C: `06_catalog_types_finding.txt`); the merged 5A test's `5A-cat-default` reads it for tables and sequences and passes (C: `05_dbtests.txt`). No merged test reads types' privileges (`5A-cat-priv` covers the schema, relations and columns); a test over `typacl` would catch a later migration that forgets its revoke (section 11).

**Offline (PostgreSQL 16 supporting evidence, not counted).** Set C (O, C: `05_dbtests.txt`) gives the same results as set B: `W07_5A_NO_DIRECT_WRITES PASS (168/168)` with M7 and M8 applied, the non-superuser `postgres` running it; C: `06_catalog_types_finding.txt`: no relation of `devos_private` with a PUBLIC or application-role grantee, `devos_private` `nspacl` `{postgres=UC/postgres}`, `devos_api` `{postgres=UC/postgres,anon=U/postgres}`, functions `deployment_drift` and `refuse_change` only, each `{postgres=X/postgres}`.
