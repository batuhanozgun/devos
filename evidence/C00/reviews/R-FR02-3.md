## Criterion 3: attempts to show a route around a refusal or to Batu

1. **Equivalence by effect (L-066).** The refused change was an edit that would let the brief gate accept a bare hash line. The row now counts "the same effect on the check or property the denial protected, for example a gate that passes what it was built to stop" as the denied outcome, and the fixed question asks it. R-FR02-2's C2 scenario (a generator that shrinks the "whole generated brief" to a pointer) is now caught by the row's text.
2. **Reaching it by presenting the same change again (L-070).** Two routes stay closed. "A change of tool, interpreter, wording, split, file indirection, generation or session is never a different design" stays. "One attempt per denied outcome, whatever the change or the need is called" closes restating the need.
3. **Through Batu, via Precedence.** "No option may contain a denied outcome or a way to it, and his answer never authorises an action a check refused" closes the L-066 "let the user decide" route by content, not only by form.
4. **Through Batu, via C5 (access).** Could the builder frame a request for a more permissive permission mode (FR-02 alternative A) as "access to or a change of his accounts"? Then it would reach him. But a mode chosen to stop a check refusing is "a way to" the denied outcome, so C3 bars it as an option. A real access need, such as an app install only the account owner can do, reaches him as a decision with options, which is the intent.
5. **Through Batu, via C4.** A builder could argue that dropping the brief from the `/goal` message "alters what PC-01 decided", so the change goes to Batu by bullet 3. C4's text sends him the question of changing his decision, which is legitimately his. The refused action still cannot follow from his answer, because C3's second clause is general ("his answer never authorises an action a check refused"). C3's first clause is placed in Precedence, though, so it does not textually bind the options of a bullet-3 question (n2).
6. **The new exit sentence ("except through this exit, the ban above holds").** It makes the ban the default and the exit the only exception. It does not widen the exit: the exit is still defined by result, with one attempt, and `reopen_if` still says "never widened".
