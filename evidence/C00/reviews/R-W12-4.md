## Blocking findings

### B-1 · The N-049 disposition leaves the C00 hold liftable at class normal

**Location:** `tools/check_records.py:367-377` (`impact()`, the W-R7 (ii) exemption); `plan/builder/w-c00-12/03_work_model.md` W-R7 (the "unless" clause); `plan/work/W-C00-12.3.md` note N-049 disposition (ii); `plan/builder/w-c00-12/15_tranche_1b-ii_intent.md` section 2 ("Together, lifting the C00 hold needs a session verdict that names W-C00-12, reviewed at or after its work"); `plan/ledger.md` `summary_tr` item 4.

**Problem.** The exemption asks only that `accepted_by` match `evidence/*/reviews/*.md`, that the file hold a PASS line naming **any** resolvable commit, that the item be `finished`, that the file be used by no other item, and that it name the item's ID. It does not ask what W-R1 asks and what N-049 (ii) promises ("a session verdict … that the work check accepts"): it never checks the M-R16 (b) binding (review branch, owned non-producer trailer) and never checks that the named commit lies at or after the item's own work. Both omissions are reachable by the producer alone.

**Failure scenario 1, reproduced** (scratch clone of `242d195`, my own fixture): the producer adds `evidence/C00/reviews/<fixture>.md` containing `## Verdict: PASS`, the item ID and the SHA of `89acd48`, writes `execution: finished`, `acceptance: accepted`, `accepted_by: <that file>`, `acceptance_label: session` into `plan/work/W-C00-12.md`, re-renders and adds the Record changes line. Result: `kinds` PASS, `stamps` PASS, `claims` on the range FAIL (as designed) but `impact` prints **`class normal`**. By W-R7 a normal PR needs no session verdict, so this PR merges unreviewed, and the render then shows `W-C00-06` to `W-C00-09` as **Ready (startable now)**: the C00 hold is lifted by a file the producer wrote.

**Failure scenario 2, reproduced**: the same without writing any new file, using the existing `evidence/C00/reviews/R-W12-2.md` (a real verdict that names W-C00-12, accepts no other item, and was written long before this work) as both `accepted_by` and `composition_by`. `impact` prints `class normal`; `kinds` and `stamps` pass; the frontier lifts. The pre-registered planted case T-W9 (t) does not catch either variant, because it reuses one verdict across **five** items and so trips the "used by no other item" leg.

**Why this is blocking, not minor.** It is one of the failure classes the brief names ("a class-high change that the impact check computes as normal, or a route to lift the C00 hold without a bound session verdict"), and it is the exact threat N-049 states ("a session could also create a file"). The later stop check does catch both scenarios (`work` by the W-R1 binding, `claims` (b) on the merged commit, which the exception line cannot waive), so the defence is not absent — but it is *after the merge*, and three texts, one of them Batu-facing, state the stronger property as already true. `summary_tr` item 4 tells Batu that the hold now needs "a verdict naming the work, given after the work, accepting no other work", and names as the only residual that the builder could forge a reviewer's signature; scenario 1 needs no forged signature and no review branch at all.

**Severity:** blocking. **Suggested fix:** C-1 above.
