## Findings

**B10-1 (blocking; regression introduced by `53b89d3`): the attached `-o<path>` parse is greedy.**
- **Location:** `.claude/hooks/tool_allowlist.py`, `git_checks`, `re.sub(r"^-[A-Za-z]*o", "", a2)`.
- **Problem:** The greedy `[A-Za-z]*` strips up to the *last* letter `o` before a non-letter. For `-otools/x.tar` the parsed path becomes `ls/x.tar`, which is not guarded. git takes the text after the *first* `o` as the value; I confirmed this writes into `tools/`. At `f121e3a` the old `a2[2:]` parse denied `git archive -otools/<f>` and `git format-patch -otools/<d>`. Both are now allowed, and so is `-kotools/<d>`. With `archive` the file name is chosen, so a tracked `tools/` script can be overwritten with archive bytes. That content is not executable, but it corrupts the gate.
- **Example:** `git archive -otools/x.tar HEAD` is allowed.
- **Fix:** Use the first `o` (`^-[A-Za-z]*?o`), or iterate over the cluster letters. Add planted cases for `-otools/…` and `-kotools/…`.

**B10-2 (blocking; B9-2 incomplete): named-tree destinations outside the expected positional slot.**
- **Location:** `git_checks`, the B9-2 block (`dests`).
- **Problem:** Three spellings pass with a live `tools/` destination (and the first one also with `.claude/`):
  - **Implicit destination.** `git -C <guarded dir> clone <src>`, or `cd tools && git clone <src>`, has no destination argument, so `dests` is empty. git creates `<guarded dir>/<basename of src>`, which I confirmed. A scratch repository named like an imported module re-opens B7-1's import shadow. The same works with `-C .claude/skills`. `git -C <guarded> init` with no argument is similar.
  - **Value-taking options.** `git worktree add -b <branch> <dest> <rev>` and `-B` are allowed: the branch name takes the destination's slot, which I confirmed. This includes the `-C <scratch>` absolute form, which gives a worktree with chosen content.
  - **`git worktree move <wt> <dest>`** is not handled.
- **Example:** `git -C tools clone <scratch>/yaml` is allowed.
- **Fix:** For `clone`, `init` and `worktree`, also deny when the effective directory (`-C`/`cd`) is itself in a guarded zone. Skip the values of `-b`, `-B` and `--reason` when finding the `worktree add` path. Treat the last positional argument of `worktree move` as a destination. Add planted cases.

**B10-3 (blocking, small; B9-1 narrowing has a spelling gap for `tools/`): attached `-m<mod>`.**
- **Location:** `command_checks`, the `exempt` loop. Only the exact words `-m`, `-c` and `-e` stop the scan.
- **Problem:** `python3 -mzipfile …` (or a cluster such as `-Bm…`) is skipped as an ordinary option. The module's first positional argument under `tools/` is then exempted as a "script". The standard-library zip and tar module CLIs write that argument, so a named `tools/` file can be created or overwritten. The separate-word `-m zipfile` form is denied. The content is archive bytes, not code (low impact), but the target is named on the command line in a module CLI. That puts it in the class B9-1 excluded from the residual, not the interpreter's own language. `.claude/`/`.git/` are unaffected, because only `tools/` paths are exempt.
- **Example:** `python3 -mzipfile --create tools/<existing script> <file>` is allowed.
- **Fix:** Exempt only when every option before the script is on a small allow list (for example `-B`, `-u`, `-O`, `-S`, `-I`, `-E`, `-s`). Alternatively, stop at any option word that begins with `-m`, `-c` or `-e`, or contains `m`/`c` in a short cluster. Add planted cases.

**Not blocking (accepted residual / minor):**
- Attached program spellings with a `tools/` positional argument (`node -e1 tools/x`, `python3 -c'…' tools/x`, `ruby -pi -e'…' tools/x`) are an interpreter acting in its own language. `perl -pi -e … tools/<f>` and `… .claude/<f>` were allowed before and were noted in R-D008-9. These are fresh instances of the accepted residual.
- Over-denial: an interpreter option that takes a value (for example `python3 -W ignore tools/x.py`) loses the exemption and is denied. This is a usability nit, not a daily command.
