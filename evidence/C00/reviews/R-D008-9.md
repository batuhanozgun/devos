## Findings

**B9-1 (blocking, regression): the interpreter exemption covers all guarded zones.**
- **Location:** `.claude/hooks/tool_allowlist.py`, `command_checks`, the catch-all condition `prog not in INTERPRETERS`.
- **Problem:** The exemption was meant to keep `tools/` scripts runnable. But it skips the catch-all for every zone. An interpreter's module command line that names a live `.claude/` or `.git/` path as its **output file** was denied at `HEAD~1` and is now allowed. I compared both revisions: the standard-library JSON, zip and tar module CLIs with a live destination all moved from deny to allow. I confirmed in a disposable directory that the JSON module CLI writes its second argument.
- **Example:** `python3 -m json.tool <file> .claude/settings.json` replaces the hook configuration.
- **Why this is not the accepted residual:** the target is named on the command line. The write is not done in the interpreter's own language, and the guard denied it before this change.
- **Fix:** Exempt an interpreter only when the guarded path it names is its script argument (the first non-option argument) and that path is under `tools/`, as R-D008-8 fix (a) said. Keep the catch-all for every other argument and for `.claude/`/`.git/`. Add planted cases (`-m <module> … .claude/…` denied; `python3 tools/x.py` allowed).

**B9-2 (blocking, pre-existing, not reported before): git positional destinations write into live guarded locations.**
- **Location:** `git_checks`. `git` is in `already`, so the catch-all never sees git's arguments. B4 bans only some subcommands, and only in the live tree.
- **Problem:** These commands are allowed with a live `tools/`, `.claude/` or `.git/` destination, including through `-C <scratch>` with an absolute live path:
  - `git clone <src> <dest>`
  - `git worktree add <dest> <rev>`
  - `git init <dest>`

  A named destination under `tools/` brings back B7-1's import-shadow route: `check_records.py` imports `yaml`, and the script's own directory comes first on the import path. I reproduced the shadowing in a disposable repository with a cloned package directory. Under `.claude/`, a clone or worktree at a config subdirectory (for example `agents/`, `commands/` or `skills/`) adds session configuration. The cp-style equivalent of both is denied.
- **Example:** `git clone <scratch-repo> tools/yaml` is allowed.
- **Fix:** Treat the destination argument of `clone`, `worktree add` and `init` (and `init`'s `-C`/`--separate-git-dir` targets) as write destinations, checked with `write_guarded`. Add planted cases, including the `-C <scratch>` absolute form.

**B9-3 (blocking as a record inaccuracy, low impact): the B8-2 parser misses two format-patch spellings.**
- **Location:** `git_checks`, the B8-2 loop.
- **Problem:** `--output-directory=<dir>` (with `=`) is not matched, because only `--output=` and the separate-word form are. Bundled short options such as `-ko <dir>` and `-ko<dir>` are not matched either. I confirmed with git 2.43 that both write into the named directory. git picks the file names (`NNNN-<subject>.patch` or numbers), so this cannot replace a guard file or shadow a `.py` import. But L-105 and §9 say `--output-directory` and `-o` are caught.
- **Fix:** Match the `--output-directory=` prefix. For `archive`/`format-patch`, read a short-option cluster containing `o` as `-o` (the rest of the cluster, or else the next word, is the path). Add planted cases.

**Not blocking:** `perl -pi` on `.claude/` was already allowed at `HEAD~1`; it is the stated interpreter residual. Writes into a live `.git/hooks/<dir>` by clone or init create a directory, not a hook file; they are covered by the B9-2 fix anyway.
