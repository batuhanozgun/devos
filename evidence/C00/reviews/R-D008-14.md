## Criterion 4 — focused sweep

### B14-1 (BLOCKING, PLAIN): a bundled or attached `-t` on `cp`/`install`/`ln` hides the destination

- **Location:** `.claude/hooks/tool_allowlist.py`, `command_checks`, the `DEST_COMMANDS` branch (about line 965). `tdir` takes only the exact words `-t`/`--target-directory` and `--target-directory=`. When `tdir` is empty, `written = plain[-1:]`, which here is the source.
- **Allowed on this head, each a direct copy to a live guarded location:**
  - `cp -rt tools /tmp/a`
  - `cp -Rt tools /tmp/d`
  - `cp -vt tools /tmp/a`
  - `cp -at tools /tmp/a`
  - `cp -ttools /tmp/a`
  - `cp -rt tools/ /tmp/check_records.py` (overwrites the merge-gate checker)
  - `install -Dt tools /tmp/a`
  - `install -vt tools /tmp/a`
  - `ln -st tools /tmp/a`
  - `ln -sft tools /tmp/a`
  - `cp -vt /etc /tmp/gitconfig` (writes `/etc/gitconfig`)
  - `install -Dt /etc /tmp/gitconfig`
  - `cp -vt /tmp/devos-guard /tmp/x` (into the decision log)
- The separate-word forms are denied: `cp -t tools /tmp/a`, `install -D -t tools /tmp/a`, `install -Dm644 -t tools /tmp/a`.
- For `.claude` and `~/.config/git` the separate `COPY_LIKE` component check still denies (`cp -ft .claude …`, `cp -rt ~/.config/git …`). The hole is therefore `tools/`, `/etc/gitconfig` and the log dir.
- **Why it is plain:** `cp -rt DIR …`, `cp -vt DIR …` and `install -Dt DIR …` are ordinary GNU idioms (the last is a packaging staple). An injected "copy these into tools/" instruction is naturally written this way. It is the B13-2 defect (an option bundled into a cluster) on a listed destination writer. That makes it a "direct cp/install/ln to a literal guarded path", which the brief names as blocking.
- **Suggested fix:**
  1. For `DEST_COMMANDS`, collect the `-t` value from any single-dash cluster containing `t`: the rest of the cluster after `t` if non-empty (`-ttools`, `-vttools`), otherwise the next word (`-rt tools`).
  2. Check that value **in addition to** `plain[-1:]` (union), not instead of it. Otherwise a value-taking option whose value contains a `t` (for example `install -gstaff /tmp/a tools/x`, `-g` = group `staff`) would replace the real destination and open a new hole. The union can only over-deny.
  3. Plant tests: the cases above denied, and `cp -vt /tmp/out /tmp/a` allowed.
- **Known over-deny of the union:** `cp -rt /tmp/d tools/x` (a `tools/` source copied out) is denied, because the last plain word is still checked. It is denied today as well, so this is not a regression; use the separate `-t` form or `cat` to copy out.

### B14-2 (BLOCKING, PLAIN, lower severity): `sort -o` bundled in a cluster is missed

- **Location:** the `sort` reader exception in `command_checks` (about line 994): `a == "-o" or a.startswith(("-o", "--output"))`.
- **Allowed on this head:**
  - `sort -uo tools/x tools/x`
  - `sort -uo .claude/x .claude/x`
  - `sort -uo ~/.config/git/ignore /tmp/a`
  - `sort -no tools/x /tmp/a`
  - `sort -ro tools/x /tmp/a`
- Denied: `sort -u -o tools/x tools/x` and `sort -otools/x …`.
- **Why it is plain:** `sort -uo FILE FILE` is the well-known in-place de-duplicate idiom. The guard already treats `sort -o` as a write flag (B5 reader rule), and this is the same bundled-cluster miss as B13-2, so the guard's own stated rule is incomplete in its common form. The severity is lower than B14-1 because `sort` rewrites rather than plants content. It still writes a live guarded file (`.claude/`, `tools/`, `~/.config/git`).
- **Suggested fix:** treat `sort` as a writer when any single-dash cluster contains `o` (the same helper as B14-1 can return the value). Plant `sort -uo tools/x tools/x` (deny) and `sort -u tools/x` (allow).

Both fixes are the same helper ("does a short cluster contain option letter X, and what is its value"). If it is applied once to the destination writers and the output flags the guard already lists (`cp/install/ln -t`, `sort -o`, and optionally `yq -i`), the B13-2/B14 class is closed for listed options.

## Accepted residual seen (information, not blocking)

These are exotic under the brief, or in the stated §9 residual:

- `sed --in s/a/b/ tools/x`: an abbreviated GNU long option (`--in` for `--in-place`). This is a value-option quirk.
- `yq -Pi '.a=1' tools/x.yml`: a bundled cluster on a less common tool. It falls under "a writer or in-place flag not yet listed". The B14 helper would close it at no cost.
- `xxd /tmp/a tools/x` and `xxd -i /tmp/a .claude/x`: xxd's second positional argument is an output file. This is an obscure tool's positional write mode. Cheap to close by checking xxd's second positional as a write.
- `cd tools && cp /tmp/a 1 >/dev/null`: a destination file literally named `1`, followed by a spaced redirection. The tokenizer cannot tell `1 >` from `1>`, so the B13-1 pop removes the real destination. This is exotic (a digit-named file, inside a cwd change), and it is the price of the B13-1 fix. It is noted so the trade-off is on record.
- `cd /tmp && cd - && …`: `cd -` sets an unknown cwd, after which relative writes are unchecked. This is stateful and multi-step.
- Data-derived writes and interpreter-language writes (`perl -e`, `sed 'w file'`, `awk` redirection) are unchanged and already stated in §9.
