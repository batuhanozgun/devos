## Findings

### B-1 (blocking): writes into guarded zones through unlisted redirections and unlisted writer programs

- **Location:** `.claude/hooks/tool_allowlist.py`. `REDIRECT_OTHER` (line 417) treats `>&` and `<>` as non-writing redirections. The writer checks in `command_checks` (lines 845 to 861) only cover the fixed sets `DEST_COMMANDS`, `WRITE_COMMANDS` and `IN_PLACE_COMMANDS`, plus `dd`.
- **Problem:**
  - **Redirections.** `>& file` writes stdout and stderr to the file, and `n<> file` opens it for writing. Both are skipped by the output-target check. Only a digit or `-` after `>&` is a descriptor duplication.
  - **Writer programs.** A program that writes a named file through its own option is not checked at all: for example `sort -o`, extracting an archive with a target directory, or `patch`. Each of these was allowed with a target in the live `.claude/`.
  - **Proof.** With the clone's guard deciding, `echo probe >& .claude/r5probe` was allowed (B0). Running it in the clone created the file. The same holds for every guarded zone (`.git/`, `~/.claude`, the protected configuration files, the decision log), because they share one zone check.
  - **Impact.** Every route above changes the enforced guard or git's internals without review. The redirection form is also common, unremarkable syntax, so it fits the §9 threat model: an accident or an injected instruction, not deliberate guard editing.
- **Severity:** blocking. It is a plain-command bypass of an explicit ban in (d), and §9 states B5 as covering shell writes without listing this as a residual.
- **Suggested direction (a design matter, per L-100):**
  - **Narrow fix.** Treat `>&`, `<>` and fd-prefixed forms as writes unless the target is a descriptor. Then invert B5 into a path-based rule: deny any command whose arguments, redirection targets or option values resolve into a guarded zone, unless the program is on a short read-only allow list. That is the same shape as the git allow-list move of L-098.
  - **Stronger fix.** Accept the environment as the primary boundary for the live `.claude/`: make it read-only for the session's user, or detect the change with a hash check at every hook call and deny all calls on a mismatch. Either way, B5 stops depending on enumerating writers.

### m-1 (minor): acceptance (g) wording and the PermissionRequest hook

- **Problem:** the `PermissionRequest` command has no wrapper. If the interpreter is missing or crashes, the prompt is left open, which is not a denial. §9 states this honestly, but acceptance (g) says such a prompt is "denied, not left open".
- **Severity:** minor. Leaving the prompt open is not fail-open.
- **Fix:** align the text of (g), or add the same `|| exit 2` wrapper to the `PermissionRequest` command.
