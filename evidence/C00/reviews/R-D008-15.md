## Findings

### C15-1 (condition; regression, fail-closed, low-medium): the `-t` union denies a `tools/` source copied out

- **Location:** `.claude/hooks/tool_allowlist.py`, `command_checks`, the `DEST_COMMANDS` branch: `written = list(tdir) + plain[-1:]`.
- **Problem:** when `-t` is present, `plain[-1]` is a source, not the destination. It is now checked as a write, so any `-t` copy whose last source is under `tools/` (or another guarded zone) is denied. This applies even with the explicit `-t DIR` / `--target-directory=DIR`, which were unambiguous and allowed before.
- **Impact:** an honest "copy the gate scripts to a scratch dir" (`cp -t /tmp/w tools/*.py`, `install -Dt /tmp/bin tools/x`) is refused. The plain no-`-t` form still works, so the cost is friction, not lost capability.
- **Suggested fix:** parse the short cluster properly for the destination writers instead of unioning.
  1. Walk the cluster's letters left to right and stop at the first value-taking letter. For `cp`, that is `S`. For `install`, `m o g S t`. For `ln`, `S t`.
  2. If that letter is `t`, the value is the rest of the cluster, or else the next word. If it is another letter, the cluster has no `-t`.
  3. With a `-t` value found this way, or from an explicit `-t`/`--target-directory[=]` word, the written paths are the `-t` dir(s) plus `dir/basename(src)`, and `plain[-1:]` is **not** added.
  4. Keep the union only as a fallback if you want to stay conservative for unparsable clusters.
  5. Plant `cp -t /tmp/d tools/x`, `cp -rt /tmp/d tools/x` and `install -Dt /tmp/bin tools/x` as allow. `install -gstaff /tmp/a tools/x` must stay deny: `g` takes the value, so no `-t` is found and `plain[-1]` is the destination.

### C15-2 (condition; honesty, low): L-111 overclaims a planted allow case

- **Problem:** see criterion 3.
- **Suggested fix:** after C15-1, plant the allow cases so the sentence becomes true. Otherwise reword it to say that only the no-`-t` copy-out stays allowed.

### n-1 (minor): `cluster_opt_value` computes the write path but nothing checks it

- **Location:** the `sort` reader exception, and the catch-all candidate extraction (`[a[2:]] if len(a) > 2 and a[1] != "-"`).
- **Problem:** for `sort`, the helper is used only to decide "not a reader". The path then comes from the catch-all, which takes `a[2:]` of a cluster. For `-uotools/x` that yields `otools/x`, so `sort -uotools/x /tmp/a` is **allowed**. The separate-word forms work because the next word is checked as an ordinary argument.
- **Severity:** exotic (a bundled *and* attached value). It is listed under accepted residual below.
- **Suggested fix:** in the catch-all, also check every value returned by `cluster_opt_value` for the program's known output letters. At minimum, check `sort`'s `o` values as written paths. This is a one-line change.

## Accepted residual seen (information, not blocking)

- `sort -uotools/x /tmp/a`: a bundled and attached `-o` value (n-1).
- `curl -sLotools/x URL`, `wget -qOtools/x URL`, `unzip -qdtools a.zip`: a bundled and attached value on a program the catch-all handles. The spaced forms (`curl -sLo tools/x`, `wget -qO tools/x`, `unzip -qd tools`) are denied. The same catch-all fix as n-1 (letters `o`/`O`/`d`) would close these.
- `xxd -rp /tmp/a tools/x` and `xxd -pr …`: a bundled `-r`. These fall under the already-accepted "xxd second positional is an output" residual: `xxd /tmp/a tools/x` without `-r` is also allowed. `xxd -r -p` is denied. The cheap fix is to treat `xxd`'s second positional as written, or any single-dash cluster containing `r`.
