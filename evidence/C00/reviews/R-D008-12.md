Where a case is "allowed", I also ran the shell command in a throw-away directory to confirm it really writes there (marked *executed*).

## Verdict: **FAIL**

B11-1, B11-2 and B11-3 are fixed as specified, and the suites pass. But the adversarial sweep (criterion 4) found six further ways to write the live `tools/`, `.claude/` or `.git/` through commands the guard allows, with the guarded path visible on the command line. Four of them need no variable at all. All are outside the accepted residual. Because of them, the §9 and L-108 wording ("blocks every write that names a guarded location"; a guarded path that appears literally as a command-line token "is denied") claims more than the code checks.

## Blocking findings

### B12-1: an unresolvable `cd`/`pushd` target that literally shows a guarded component lets every following relative write through (criteria 1, 2 and 4)

- **Location:** `.claude/hooks/tool_allowlist.py`, `shell_checks` (the `cd`/`pushd` branch sets `d = resolve_dir(...)`, which is `None`), then `guarded_write(None, "rel")`: `target_path` returns `None`, and `literal_guarded("check_records.py")` sees nothing guarded.
- **Allowed (each writes the guarded file):**
  - `cd $PWD/tools && echo x > check_records.py` (*executed*: the file is created in `tools/`)
  - `cd $(pwd)/tools && cp /tmp/a check_records.py`
  - `cd $(pwd)/tools && rm check_records.py`, `… && mv /tmp/a .`, `… && tee x`
  - `cd $PWD/.claude && echo x > hooks/tool_allowlist.py`
  - `cd $PWD/.claude/hooks && cp /tmp/a tool_allowlist.py`
  - `` cd `pwd`/.claude; sed -i s/a/b/ settings.json ``
  - `cd $PWD/.git/hooks && echo x > pre-commit`
  - `cd ${HOME}/.claude && echo x > settings.json`
  - `cd $HOME/.config/git && echo x > config`
  - `pushd $PWD/tools && touch x`
- **Why this is not residual:** the guarded component (`tools`, `.claude`, `.git`, `.config/git`) is literally visible in the `cd` token. This is exactly the B11-2 rule, applied to the working directory instead of to the target. The git tree-writers are already denied in this state (`cd $PWD/tools && git init` is denied), so only the ordinary writers are open.
- **Suggested fix:** when `resolve_dir` returns `None`, run `literal_guarded` on the `cd`/`pushd` argument. If it matches, either deny the `cd` outright when a write follows in the same command, or set the cwd to a sentinel "unresolved but guarded" state in which every relative write target (redirection, writer, catch-all) is denied. Keep the plain unresolvable state (`cd $(mktemp -d)`, `cd $DEST`) as it is, so the common scratch-directory pattern stays allowed. Plant both the deny cases and `cd $(mktemp -d) && touch x` (allow).

### B12-2: `cd` options are read as the target directory: a literal hole with no variable (criterion 4)

- **Location:** `shell_checks`: `d = resolve_dir(d, args[1] ...)` takes `args[1]` even when it is an option.
- **Allowed:** `cd -P tools && touch x` (*executed*: creates `tools/x`), `cd -L tools && echo x > check_records.py`, `cd -- .claude && echo x > settings.json`, `cd -P .git/hooks && cp /tmp/a pre-commit`. The guard resolves the cwd to `<root>/-P` (or `<root>/--`), so the write looks safe.
- **Suggested fix:** skip `-L`, `-P`, `-e`, `-@` and `--` before taking the operand, and return `None` (unresolvable) for any other leading `-` word. Do the same for `pushd` (`-n`, `+N`, `-N`).

### B12-3: `env -C DIR` / `env --chdir=DIR` changes the working directory without the guard noticing (criterion 4)

- **Location:** `strip_wrappers()` drops `env` and its options but ignores `-C`/`--chdir`.
- **Allowed:** `env -C tools touch x` (*executed*: creates `tools/x`; GNU coreutils 9.4 is installed here), `env --chdir=$PWD/tools touch x`, `env -C $PWD/tools sh -c 'echo x > check_records.py'`.
- **Suggested fix:** in `strip_wrappers`, treat `env -C X`, `-CX` and `--chdir[=]X` as a `cd X`: return the new directory so the caller resolves it like `cd`, with the B12-1 rule applied. The simpler alternative is to deny `env -C`/`--chdir`, which has no daily use here.

### B12-4: tilde forms other than `~` and `~/` are resolved as a literal relative directory (criterion 4; the same defect class as B11-1)

- **Location:** `target_path()`. An argument that starts with `~` but not `~/` falls through to `os.path.join(d, arg)`, so `~+/tools/x` "resolves" to `<root>/~+/tools/x` (not guarded) and `literal_guarded` is never consulted. `resolve_dir` already returns `None` here; `target_path` does not.
- **Allowed:** `echo x > ~+/tools/x` (*executed*: bash expands `~+` to `$PWD`, so it writes `tools/x`), `echo x > ~+/.claude/settings.json`, `cp /tmp/a ~+/tools/check_records.py`, `git clone /tmp/r ~+/tools/x`, and `echo x > ~root/.claude/settings.json` (here `HOME=/root`, so this is `~/.claude`). `~root/.gitconfig` is denied only because the protected-name check looks at the basename.
- **Suggested fix:** in `target_path`, return `None` for every other `~…` form (`~+`, `~-`, `~user`), so `guarded_write` falls back to `literal_guarded`. Alternatively, expand `~+` to `d` and `~-` to unknown.

### B12-5: brace expansion and `$'…'` quoting hide a literally visible guarded component (criterion 4)

- **Location:** `target_path` treats `{a,b}` as part of a literal name. `literal_guarded` splits only on `/` and drops any component that contains a `$`.
- **Allowed:** `touch {tools,tmp}/x` (*executed*: creates `tools/x`), `cp /tmp/a {tools,/tmp}/`, `touch .clau{de,}/x`, `echo x > $'tools'/x`, `echo x > $PWD/$'tools'/x`.
- **Suggested fix:** treat a token with an unquoted `{…,…}` or `{a..b}` as unresolvable, and in `literal_guarded` split components on `/`, `{`, `}` and `,` as well. Unwrap a `$'…'` that contains no escape before the component test, or treat any `$'…'` component as a match on its inner text. `tool{s,}/x` spells no guarded component literally and can stay residual.

### B12-6: writers that the guard treats as readers, or whose in-place flag it does not know (criterion 4)

- **Location:** `PURE_READERS` contains `xxd`. `IN_PLACE_COMMANDS` is only `sed`/`perl`.
- **Allowed:** `xxd -r /tmp/a tools/x` and `xxd -r /tmp/a $PWD/tools/x` (`xxd -r infile outfile` writes `outfile`); `yq -i '.a=1' .claude/settings.json` and `yq -i '.a=1' tools/x.yml` (`yq` is installed at `/usr/bin/yq`); `gawk -i inplace '{print}' tools/check_records.py` and `awk -i inplace … .claude/settings.json` (gawk's in-place extension; this container's `awk` is mawk, so it would fail here, but the guard allows it).
- **Why this is not the awk residual:** the accepted residual is a path produced *inside* the program text (an `awk` `print > "f"`). Here the guarded path is a command-line operand and the write is selected by a command-line option.
- **Suggested fix:** remove `xxd` from `PURE_READERS`, or check its second operand as written when `-r` is present. Treat `yq -i`/`--inplace` and `awk`/`gawk -i inplace` like `sed -i`, so the file operands are checked as written. Also check the remaining `PURE_READERS` for output options: `sort -o` is already caught, because `sort` is not listed.

### B12-7: §9 and L-108 claim more than the code checks (criterion 5)

- **Location:** `plan/Builder_Operating_Model.md` §9 ("The guard blocks every write that names a guarded location (by redirection or by a non-reader naming it) … a write to any guarded location is denied whether it comes from a program outside the readers …"); `plan/ledger/C00-log.md` L-107 as corrected in L-108 ("a guarded path that appears **literally** as a command-line token … is denied").
- **Problem:** B12-2, B12-3, B12-5 and B12-6 are literal command-line tokens that are not denied. B12-1 and B12-4 contradict "caught … when a guarded component … is still literally visible". L-108 also says the fix covers "every write site", but the cwd set by `cd`/`pushd`/`env -C` is a write site it does not cover.
- **Suggested fix:** after fixing B12-1 to B12-6, keep the claim limited to the forms the suite plants: redirection, the listed writers, the non-reader catch-all, git output and tree-writers, and the working directory set by `cd`/`pushd`/`env -C`. Name explicitly what stays residual: brace forms that spell no guarded word, own-language writes such as `sed 'w file'`, and bare variables.

## Minor findings

- **m-1 (`literal_guarded` does not cover two guarded locations).** The decision-log directory and `/etc/gitconfig` have no literal component in `literal_guarded`. `echo x >> ${TMPDIR:-/tmp}/devos-guard/log.jsonl` and `echo x > $(echo /tmp)/devos-guard/x` are allowed. The literal `/tmp/devos-guard/…` form and the `DEVOS_GUARD_LOG_DIR` path are denied. Suggested fix: add `basename(LOG_DIR)` (`devos-guard`) and the `etc`/`gitconfig` pair to the literal set.
- **m-2 (removal of a guarded zone's ancestor behind a variable).** `rm -rf $HOME/.config` is allowed and removes `~/.config/git`. `literal_guarded` ignores the `remove=True` ancestor rule that `guarded_zone` applies. Suggested fix: for `remove=True`, also match when the visible tail is a proper prefix of a guarded zone (`.config`, the tree root by name). `rm -rf $PWD` with nothing visible stays residual.
- **m-3 (information).** The new over-denial also covers `cd $(mktemp -d) && git init`. This is consistent with the planted `git -C $(mktemp -d) init`, but it is not planted or mentioned in L-108.
