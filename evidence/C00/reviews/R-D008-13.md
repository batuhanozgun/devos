## Blocking findings

### B13-1 — a trailing fd-numbered redirection hides the destination of `cp`/`install`/`ln` (PLAIN/COMMON)

- Location: `.claude/hooks/tool_allowlist.py`, redirection split in `shell_checks` (around lines 776–791) together with the destination pick `written = tdir or plain[-1:]` (around line 952).
- Problem: the tokenizer leaves the descriptor number of `2>…`, `1>…`, `2>>…`, `2>&1` as an ordinary argument. For the destination-only commands the "destination" then becomes the word `2` (or `1`), so the real target is never checked. The `.claude`/`.git` copy-like component check still catches `.claude` targets, but `tools/`, `~/.config/git/config`, `/etc/gitconfig` and the decision-log dir are not caught.
- Concrete scenarios, all **allowed** on this head (each really writes the guarded file in bash):
  - `cp /tmp/a tools/check_records.py 2>/dev/null`
  - `cp /tmp/a tools/check_records.py > /dev/null 2>&1`
  - `cp /tmp/a tools/x 2>&1`; `cp /tmp/a tools/x 1>/dev/null`; `cp /tmp/a tools/x 2>>/tmp/err`
  - `cp /tmp/a tools/x 2>/dev/null && echo done`; `… || true`
  - `install /tmp/a tools/x 2>/dev/null`; `ln -sf /tmp/a tools/x 2>&1`
  - `cp /tmp/a ~/.config/git/config 2>&1`; `cp /tmp/a /etc/gitconfig 2>&1`; `cp /tmp/a /tmp/devos-guard/x.jsonl 2>&1`
  - (Denied correctly for comparison: the same without the redirection; `… >/dev/null`; `… &>/dev/null`; `cp 2>/dev/null /tmp/a tools/x`.)
- Why it blocks: silencing stderr with `2>/dev/null` or `2>&1` is one of the most common things written after a `cp`; an honest builder or an injected "copy this into tools/" instruction would plausibly carry it. It is not an exotic spelling.
- Severity: blocking.
- Suggested fix: in the redirection loop, when `t` is a redirection operator and the previous token appended to `args` is all digits and was written adjacent to the operator (no whitespace; check against the raw text or make `tokens()` emit `N>` as one operator), pop it from `args` (it is an IO number, not an argument). A cruder safe alternative: drop an all-digit word that immediately precedes a redirection operator token (over-reads `cp a 2 > f` as having no `2` operand, which only matters for a file literally named `2`). Add regression tests for `2>/dev/null`, `2>&1`, `1>`, `2>>` after `cp`, `install` and `ln` into `tools/` and `~/.config/git/config`, with allowed near misses (`cp tools/x /tmp/y 2>/dev/null`, `cp /tmp/a /tmp/b 2>&1`).

### B13-2 — `-i` bundled with other short options is not seen for `sed`/`perl` (PLAIN/COMMON)

- Location: `.claude/hooks/tool_allowlist.py` around line 955: `prog in IN_PLACE_COMMANDS and any(a.startswith(("-i", "--in-place")) …)`. Because `sed`/`perl` are in `IN_PLACE_COMMANDS`, they are also excluded from the catch-all (`already`), so nothing else checks them.
- Problem: only an argument that *starts* with `-i` counts. A bundle where `i` is not the first letter is missed.
- Concrete scenarios, all **allowed** on this head:
  - `perl -pi -e 's/a/b/' tools/check_records.py` — the canonical perl in-place idiom
  - `perl -pi -e 's/a/b/' .claude/settings.json`; `perl -pi.bak -e … .claude/settings.json`; `perl -0pi -e …`; `perl -lpi -e …`
  - `sed -ri 's/a/b/' tools/check_records.py`; `sed -Ei 's/a/b/' .claude/settings.json`; `sed -ni 's/a/b/p' tools/…`; `sed -si …`
  - (Denied correctly: `perl -i -pe`, `perl -i.bak -pe`, `sed -i`, `sed -i -e`, `sed -e … -i`, `sed --in-place`, `sed -iE`, `ruby -pi -e`.)
- Why it blocks: `perl -pi -e` and `sed -Ei`/`sed -ri` are the everyday spellings of an in-place edit, the very class B5 names; they are not exotic.
- Severity: blocking.
- Suggested fix: for `sed` and `perl`, treat as in-place any single-dash short-option word whose letters before any attached value contain `i` — e.g. `re.match(r"-[A-Za-z0-9]*i", a)` for words not starting with `--`, plus `--in-place`. For perl, stop scanning a bundle at `e`/`E`/`M`/`I`/`x` where the rest is a value if you want precision; over-matching only over-denies when a guarded path is also named. Add the probes above as planted denials and `sed -E 's/a/b/' tools/x` / `perl -ne 'print' tools/x` as allowed near misses.
