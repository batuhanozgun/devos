## 1. Verdict: **FAIL**

The frame is right. The design derives needs from stage outcomes. It replaces instructed restatements with generated views and checks. It names a DevOS successor and a hand-over trigger for every builder mechanism. It makes the C02 transfer a field mapping. None of that should be reopened.

The design still fails acceptance (d) as merged, for four reasons:

1. **Its own log contradicts the evidence behind its central continuity decision** (B1).
2. **The mechanism that is supposed to make L-033 impossible does not cover the place the design moves that failure to** (B2).
3. **Several design-level defects would break the system on day one** (B3, B4, B5).
4. **As specified, it is too heavy for its purpose, and it is not yet a single consistent text** (B6, B7).

Criterion (3) states that a design too heavy for its purpose fails criterion (1). I judge that it does, *as specified*: about twenty rules, three hooks, five scripts and about fifty tests are delivered in one migration PR before any C00 work resumes. A staged version of the same design would pass (§3).

**Re-review scope.** The failures are specific, not a frame failure. A narrow re-check of the revised pieces 02–05, the test register and the staging plan is enough. Another full round is not needed. Patching finding by finding is the squeeze pattern this design itself warns about, so the fixes below are grouped by cause.

## 2. Findings

Severity: **B** = blocking, **M** = major (must be fixed before implementation, but does not on its own fail the design), **m** = minor.

### Blocking

**B1 · The dispatcher's retirement rests on "no run has died", and the log shows a run that stopped mid-work and was restarted only by a human.**
- **Location:** `05_continuity.md` §1 ("A run dies mid-work … never observed") and §3 ("no run has died"); `06` D-28 and K1.
- **Evidence:** L-039. The run's turn ended at 17:46:47Z with `error_during_execution`, caused by an account subscription problem. Work resumed only because Batu typed "Sorun çözüldü devam et" and the parent session relayed a message.
- **Why this matters:**
  - This is exactly the "stall" that D-28's re-admission trigger K1 names ("if T-C2 fails, or a stall is observed once, a keeper or the Actions watchdog is admitted"). By the design's own rule, K1 has already fired.
  - Neither 05 nor 06 cites L-039 for this. 07 does not locate the incident.
  - The T-C1 PASS ("nobody typing") is also framed more strongly than the chain supports. The `create_session` call was untyped, but the predecessor had been restarted by a human five minutes earlier.
- **Failure scenario:**
  - A turn aborts on a platform or account error while the run holds the lease.
  - If no `send_later` is armed past that moment, nothing wakes the session. If one is armed but the account-level problem also suppresses scheduled delivery, the same holds.
  - Batu sees only an old "Son güncelleme" in `DURUM.md`, and acceptance criterion 7 of plan §1.4 (no message-carrying by Batu) fails.
- **Related gaps, from the comparison audit:**
  - D-28 ties the GitHub Actions watchdog to D-08. The counter-design's watchdog is a scheduled workflow that reads `main` hourly (CD line 503). It needs no `pull_request_target`, no required checks and no credential probe, so the tie is unsupported.
  - D-44 adopts T-21 ("ended abruptly (archived) … resumes"). As merged, no layer can restart an archived session, so T-21 fails by design.
- **Fix:**
  - Record L-039 as an observed stall and locate it on the map.
  - Admit an independent detection layer now. The CD scheduled watchdog is cheap and is the only candidate that does not depend on the stalled session. Alternatively, state the stall as a Batu-visible residual risk and put it to Batu as his decision (it concerns criterion 7 of plan §1.4).
  - Make T-21 consistent with whichever is chosen.

**B2 · The path-computed impact class cannot see the two high-impact changes the design relocates.**
- **Location:** `02` M-R2 and §3; `03` §2; `06` D-06; `07` B8, H1 ("acceptance-condition change … M (route computed)") and X-16 ("M").
- **Problem:** the design moves both triggers of L-033-class failures into files that change in every routine record PR:
  - Governing-document status moves into a row of `plan/ledger.md`, which every lease and record PR edits.
  - Acceptance conditions move into `plan/work/<ID>.md`, which every execution, claim or triage update edits.
  
  Either the path class marks those files high, so every lease PR needs a session verifier (unworkable), or it does not, so the exact L-033 act escapes. L-033 promoted a governing document's status to "binding" as a "status-only" edit. Under M-R2 that act becomes a state-file row change. Ledger rule 3 ("acceptance conditions are never loosened") then rests on nothing mechanical. No piece specifies how "acceptance-condition change" is computed. The "M" in H1 and X-16 is a claim without a mechanism.
- **Fix:**
  - Classify by record field as well as by path. A diff that touches the Governing-documents rows, or the acceptance block of any work item, is class high.
  - Add tests: a status promotion in the state file must route to a session verifier, and so must a one-word change to an acceptance block.
  - Add a migration test showing that every acceptance text moved from `ledger.md` §2 into `plan/work/` is byte-identical. The migration itself is a moment where ledger rule 3 could be broken unseen.

**B3 · The single timestamp rule (D-25) rejects legitimate, required records.**
- **Location:** `06` D-25 ("a time in a changed record line must not be later than its commit time and not earlier than 15 minutes before it, unless marked `observed_at_source`"); M-R9 (superseded).
- **Failure scenario:**
  - The very next lease renewal fails, because the Run lock row carries the expiry, a future time by definition (today: "Expires 2026-10-03T21:08Z").
  - The same happens to every scheduled wake time (D-03, D-28), reminder time and due date.
  - Every new log entry that quotes a past time also fails, unless the time is marked. Examples: "Batu answered 2026-10-02T06:27Z"; L-040 quotes times hours old.
  - The result is either constant marker noise (the rule erodes) or hand-edited exemptions.
- **Fix:** type the times. Scheduled or expiry fields must be in the future and bounded (for example, a lease expiry at most 3h15m ahead). Observation stamps follow the 15-minute rule. Quoted historical times must reference their source record, not merely be marked. Then test all three types.

**B4 · The design removes the mechanical floor delivery to subagents, and the boot would show no failure patterns after migration. Both are acceptance clauses.**
- **Location:** `06` D-12 and §7; `04` §4; `08` migration table (failure patterns "candidates until qualified"); `07` B1 and H14.

**(a) D-12 regresses (k):**
- P-W12-2 showed that the `@path` import reaches custom and built-in subagents (the draft's mechanical delivery). D-12 replaces it with a reading gate keyed on read receipts.
- Hooks fire inside subagents in the parent's session (L-037). So the Producer's own `Read` almost certainly satisfies the gate for every Triager, Researcher and Verifier subagent. These are the roles (k) names, and none of them would read the floor.
- The stated reason (79,327 bytes, which I re-measured, see §5) does not hold either. Satisfying the gate requires a `Read` of the same two files, so it costs the same context. A partial read cannot be shown to cover §2.

**(b) The boot hides failure patterns:**
- Boot prints only *qualified* failure patterns. The migration lands all of them as *candidates*. H14 qualifies a candidate only when it is "older than one stage, or used three times".
- So for the rest of C00, sessions would see **no** known failure patterns at boot. That breaks (j) ("sessions see the known failure patterns at boot").

**Fix:**
- Keep the whole-file import until W-C00-06 re-cuts Ek A and Ek D, and measure its token cost instead of estimating it. If the cost is unacceptable, use an instructed read tested by T-R5 *per subagent role*.
- Have RUN_BRIEF §5's ten patterns qualified by a verifier inside the migration PR, or print candidates at boot, labelled as candidates.

**B7 · Proportionality, as specified: one big-bang migration of everything before C00 resumes.**
- **Location:** `08` §2 ("in one change PR reviewed with the whole design"); `06` §4.

- **Fix:** stage the migration in tranches, each with its tests and review. Resume C00 heavy work after tranche 1. Admit later tranches only on their stated triggers, which is the design's own admission rule applied to timing. §3 gives the cut.

### Major

**M1 · A fail-closed boot gate with no break-glass.**
- **Location:** D-01 and 07 A-01.
- **Failure scenario:**
  - A bug in `tools/boot` or `receipts.py` reaches `main`, for example an exception on an unexpected issue-API response. The hook maps errors to block (X-04).
  - Every session, including the one sent to fix it, is then denied `Edit`, `Write`, `git push` and `create_session`.
  - Shell writes stay open (stated), so the gate is bypassable in one direction yet bricks the normal path.
- **Fix:** document the recovery path. Batu or a GitHub web edit can merge a one-line revert, since ruleset 24194116 requires a PR with 0 approvals. Add a test: a `tools/boot` crash yields a clear message naming that path. Consider making a crash in `tools/boot` leave the gate in a narrowly scoped "repair mode" that allows edits only under `tools/` and `.claude/`, with a session verifier still required.

**M2 · Read receipts (D-09) will produce false failures for the builder's actual working method.**
- **Problem:** receipts log `Read` and session-event reads only. Files read with `cat`, `sed`, `grep` or `git show` in Bash leave no receipt. Every session in this log does that, and the comparison's own instruction is to copy verdicts with `git show`. A citation of such a file is then refused. Producers either re-`Read` files ritually (the check then proves a call, not attention) or learn to avoid citing.
- **The real failure class is narrower:** all three FP 7 incidents (L-030, L-033, L-039) were claims about *another session's* actions.
- **Fix:** scope the citation check to session-event claims and to evidence paths that must exist at the cited commit. Drop the file-`Read` requirement.

**M3 · Basis-hash staleness (D-18) will mark nearly every item stale at once at W-C00-06.**
- **Problem:** the translation rewrites every plan file, and the D-12 re-cut changes Ek A and Ek D. If bases are hashed per file, every item that names a plan section goes `stale: recheck` together. That is a mass hand-recheck exactly when the binding plan text changes language.
- **Fix:** hash at section-anchor level. Define how a basis moves from the Turkish to the English plan (a supersession mapping recorded once, not N rechecks). Test with a one-section edit that leaves unrelated items current.

**M4 · F-2 is mislabelled, so D-04's dependency is not what the design says.**
- **Problem:** F-2 says the issue was read with an "unauthenticated `curl`". Re-run from this session through the environment's proxy: `X-Ratelimit-Limit: 15000`, used 52. The unauthenticated limit is 60. So the request is authenticated somewhere on the path, most likely by the agent proxy. D-04's mechanical read therefore depends on the proxy's credential, its scope and its availability (OI-003-like), not on the public API.
- **Fix:** relabel F-2, and state the real dependency and its failure mode. If the read fails at stop, the stop must fail, or be logged as a named S3-class reason. A "warning" lets F-036-1 recur silently.

**M5 · No proposed check catches a log entry that cites evidence that does not exist, and two such entries exist today.**
- **Evidence:** L-019 and L-021 say the R-C00-BOM-3 and R-C00-BOM-4 verdicts are at `evidence/C00/reviews/R-C00-BOM-3.md` and `-4.md`. Neither file has ever existed in any commit (`git log --all` on both paths is empty). The verdicts exist only on branches `claude/review-R-C00-BOM-3` (`5973c7d`) and `-4` (`8cfee7b`).
- **Why it matters:** this is an FP 1 / FND-001-class failure inside L-016–L-034 that 07 §5 does not locate. That contradicts (m)'s "each failure recorded from L-016 to L-034 located" as a completeness claim. The proposed checks miss it: M-R4 checks only paths named in `CLAUDE.md`, and B7 checks only references at item finish.
- **Fix:** add an evidence-resolution rule to the record checks: every `evidence/…` path named in a log entry or record must exist on the tree. Copy the two verdicts. Locate the failure on the map.

**M6 · The role-and-goal map omits a demonstrated builder actor: Batu's conversation session acting as builder.**
- **Evidence:** this session wrote L-031, L-034 and L-035, created W-C00-12 and OI-011, and started the W-C00-12 run. Its not booting caused F-036-1.
- **Problem:** 04 §2 and 07 do not list it. D-01 decides what boot prints by the brief's role line, and this session has no brief, so its boot behaviour and write authority are undefined.
- **Fix:** give it a row: terminal goal, what it may write, which boot it runs. Or rule that it never writes records and that only runs do.

**M7 · The migration omits plan files that name the old model as authoritative.**
- **Problem:** plan §9 says, under its "Kurucunun çalışma düzeni" heading, that `plan/Builder_Operating_Model.md` prevails in a conflict, and summarises the dispatcher and `/goal` runs in its item 1. Ek F lines 7 and 52 name the same path and model.
- **Failure scenario:** the migration moves and supersedes that file. The binding Turkish plan then points to a missing file and describes a retired dispatcher. That recreates the OI-011 item 22 class (two homes that disagree) in DevOS scope.
- **Fix:** add plan §9 and Ek F to the migration table as plan-change candidates under plan §14, with their owner.

**M8 · Several "keep, reject or defer" dispositions rest on "no incident" for mechanisms whose purpose is to prevent a severe failure.**
- **Location:** D-08 (no fixed evaluator), D-13 (role profiles), D-15 (hook integrity at boot).
- **Problem:** with CI deferred, D-06, D-07 and every record check run from the producer's own working tree, which the producer can edit (`check_records.py` included). D-15's rejection says D-06 plus D-07 cover the property "at stop", but they too run from that working tree. CD §12 aims at a local self-edit that governs the session, not at a merge. D-15 therefore describes the counter-design's purpose wrongly.
- **Weighing:** an outside evaluator is cheap on a public repository (one workflow, no credentials beyond the default token for read-only checks). Without one, every M arrow in 07 is "M unless the producer edits the checker".
- **Fix:**
  - Either admit a minimal scheduled or `pull_request` workflow that runs the record checks from `main`'s definition (not merge-blocking until P-05), or state plainly in 07 that every M arrow is conditional on an unmodified checker, and label it that way in R-R2.
  - Correct D-15's description of the counter-design.

## 3. Proportionality (criterion 3), explicitly

About twenty rules in three carriers would be proportionate *if* each rule addressed a recurring failure and the rules arrived when needed. Measured against the log, they do not all qualify. My recommendation follows.

**Tranche 1: build now (recurring failures, cheap, enables C02).**
- One home, plus generated views and frontier (W-R2, M-R6), and `docstatus` with markers. Basis: L-027, OI-011 item 22, F-036-1.
- Producer cannot accept (W-R1), with the field-level impact class of B2. Basis: W-C00-05, L-033.
- Typed timestamps (B3 fix). Basis: L-016 M6, L-028, F-037-2, four times in one hour.
- Union merge and `send_later` recorder. Basis: F-037-1, three times; OI-011 item 24.
- Stop reasons with the wake requirement, and the issue read failing the stop (M4). Basis: F-036-1, L-033.
- Brief gate on `create_session`. Basis: FP 5; (a2) and (k) require the purpose chain; it is an existing hook rule.
- Dispatcher retirement, with B1's independent detection layer.
- Composition check. Basis: (a2).
- Record-change kinds as a presence-and-format check. Basis: (l).
- Evidence-resolution check (M5).

- Map check. Basis: (m).

**Merge:**
- Receipts, verdict binding and evidence binding become one "claims resolve" check, scoped as in M2.
- The usage-row check becomes one line of the stop check, not a separate rule.

**Defer, each with a trigger:**
- Boot gate (D-01). One incident (F-036-1), which the issue read at stop already covers. Admit it when an unbooted session writes a wrong record again.
- Reading gate (D-12). Superseded by B4's fix.

- Card length (D-36). No incident.

- Transcript-size warning (D-05). One incident (L-022); cheap. It can ride tranche 1 only if its carrier is observed.
- The Triager as a per-item call. Keep (i)'s requirement, but triage only items the path or field class does not already mark high. The floor is then computed, and the Triager answers only "which expertise".

**Tests.** Keep T-07 (three trials plus a control) and T-23 (seven days) out of the critical path to resuming C00. Each belongs with the mechanism it tests.
