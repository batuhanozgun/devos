## Criterion 1 — C15-1 fixed: MET

**Allowed, as required.** In each, a `tools/` source is copied out. All of these were **deny** on `abe37ea`, which I re-confirmed on the old-head clone for `cp -t /tmp/d tools/x`.
- `cp -t /tmp/d tools/x`, `cp -rt /tmp/d tools/x`, `cp --target-directory=/tmp/d tools/x`
- `install -Dt /tmp/bin tools/x`, `install -t /tmp/bin tools/x`, `install -m755 -t /tmp/bin tools/x`, `install -g staff -t /tmp/bin tools/x`
- `cp -vt /tmp/d tools/x tools/y`, `cp -t /tmp/d tools/*.py`, `cp -r -t /tmp/d tools`
- `ln -st ~/bin tools/x`, and `ln -st /tmp/d <abs>/tools/x`
- Also `cp -t /tmp/d -- tools/x`. GNU treats everything after `--` as a source, so allowing it is correct.

**Denied, as required:**
- `-t` into `tools`:
  - `cp -rt tools /tmp/a`, `cp -vt tools /tmp/a`, `cp -ttools /tmp/a`, `cp "-ttools" /tmp/a`, `cp -t "tools" /tmp/a`
  - `cp -at ./tools /tmp/a`, `cp -t tools/ /tmp/a`, `cp -t <abs>/tools /tmp/a`, `cd tools && cp -t . /tmp/a`
  - `cp --target-directory tools /tmp/a`, `cp --target-directory=tools /tmp/a`
  - `install -Dt tools /tmp/a`, `ln -st tools /tmp/a`, `cp -rt tools/ /tmp/check_records.py`
- `-t` into other guarded locations:
  - `cp -vt /etc /tmp/gitconfig` (writes `/etc/gitconfig`), `cp -t /etc /tmp/gitconfig`, `install -Dt /etc /tmp/gitconfig`
  - `cp -t .claude /tmp/settings.json`, `cp -t .git/hooks /tmp/pre-commit`, `cp -t ~/.claude /tmp/settings.json`
  - `cp -t ~/.config/git /tmp/config`, `ln -t ~/.config/git /tmp/config`
  - `cp -vt /tmp/devos-guard /tmp/x` and `cp -rt /tmp/devos-guard /tmp/x`, which go into the default decision-log dir. Note: these are allowed only when `DEVOS_GUARD_LOG_DIR` points somewhere else. That is correct, because the guard then protects that other directory.
- The crucial case, `install -gstaff /tmp/a tools/x`, is denied. So are its siblings: `install -ostaff …`, `install -m0755 …`, `install -Sbak …`, `install -vgstaff …`, `install -gstaff -m755 …`, `cp -Sbak /tmp/a tools/x`, `ln -Sbak -s /tmp/a tools/x`.
- With a separate-word value before `-t`: `install -S .bak -t tools /tmp/a`, `install -m 644 -o root -g root -t tools /tmp/a`, `cp -S .bak -t tools /tmp/a`, `ln -S .bak -st tools /tmp/a`.
- With two `-t` options in either order: `cp -t tools -t /tmp/d /tmp/a` and `cp -t /tmp/d -t tools /tmp/a`. Both directories are collected.
- In a compound command: `cp -t /tmp/d tools/x; cp -t tools /tmp/x` and `cp -t /tmp/d /tmp/a && cp /tmp/a tools/x`.

**The cluster parse.** I read `target_dirs` (`.claude/hooks/tool_allowlist.py`, after `cluster_opt_value`):
- It walks a single-dash cluster letter by letter. On `t`, it takes the rest of the cluster, or else the next word. On any other value-taking letter, it stops.
- `DEST_VALUE_OPTS` is `cp: t S`, `install: t m o g S`, `ln: t S`. I checked these sets against `cp`, `ln` and `install --help` on GNU coreutils 9.4. They list exactly the short options that take a value: cp `-S -t`, ln `-S -t`, install `-g -m -o -S -t`. Nothing is missing, and no flag letter is wrongly included.
- When a `-t` directory is found, every plain argument other than that directory is a source. The written set is then the directory(ies) plus each `dir/basename(src)`. Without `-t`, the written set is `plain[-1]`, and each source is joined under it. Both match GNU semantics.

## Criterion 4 — light sweep of the destination writers: no new PLAIN hole

The C15-1 change has one structural risk. With `-t` found, `plain[-1]` is no longer checked, so a **false** `-t` detection could hide a real destination. A false detection needs one of these:
- **A value-taking short option missing from `DEST_VALUE_OPTS`.** There is none: the sets match coreutils exactly (criterion 1).
- **A word starting with `-t` that is really an operand.** Two ways give one:
  - A filename after `--`. On `cp -- -ttools tools/x` the guard still denies, because the other checks catch it.
  - A separate-word option value that itself starts with `-t`, such as `cp -S -tx /tmp/a tools/x`. This is exotic.
- **A long option whose separate value word starts with `-t`,** such as `install --group -tx …`. This is exotic.

I found no plain form in which a real destination goes unchecked.
