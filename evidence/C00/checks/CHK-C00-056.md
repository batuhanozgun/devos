**F1. The embedding binding is incomplete, and the card option breaks the "reproducible" class** (plan 5.4, 5.7 item 1, K-6 item 3b, 6.7 leak check; Appendix G G1 item 1 and G6 item 2; Appendix B 3.8 and section 7)
- **Sources:** S:hands-on-large-language-models/SOUL-DEVELOPMENT-OS-ASSESSMENT §4.1, §4.2, §4.3, §4.5, §7.3, §7.5.
- **What the source shows:**
  - What a vector means depends on more than the model name: tokenizer, configuration, preprocessing and revision also matter.
  - A mismatch between two components can run without any error and still produce wrong representations.
  - A generator chosen by an unstated default can change silently.
  - Derived representations of one source are not interchangeable.
- **What it means for the plan:**
  - Document vectors are made in the Actions job, while query vectors are made on the session machine (Appendix B section 7). The semantic leak threshold is tuned in C04 and then used in the session.
  - On restore, vectors are regenerated from "the source commit and the model version" only. Nothing requires both encoders to be the same exact revision with the same preprocessing, or requires regenerated vectors to give the measured search quality again. The likely failure is silent degradation, not a crash.
  - Under the English-card option, the vectors come from cards written by Claude. These cannot be reproduced from the source commit and model version, and rewriting them costs Claude usage. 5.7 item 1 would then classify them wrongly.
- **Type:** factual or technical defect. Condition 1.

**F2. The search benchmark does not cover multi-source or no-answer questions** (plan 1.3 phase B, K-6 Testing, C04 task 2; Appendix C C4; Appendix B 3.19; C10 dead-end acceptance)
- **Sources:**
  - S:ai-knowledge-strategies/05-LONG-CONTEXT §11, §24
  - S:ai-knowledge-strategies/02-KNOWLEDGE-GRAPH §14, F-KG-06
  - S:context-memory-harness-engineering/02 §18 (abstention item)
  - S:context-memory-harness-engineering/01-CONTEXT-ENGINEERING §7, §17
  - S:hands-on-large-language-models/SOUL-DEVELOPMENT-OS-ASSESSMENT §4.4
- **What the sources show:**
  - Retrieval quality has several independent dimensions. A top-10 hit rate measures only single-source lookup.
  - When an index lacks something, that does not mean the corpus lacks it.
  - The ability to say "not found" has to be measured on its own.
- **What it means for the plan:**
  - In phase B the repositories are not opened, so negative search results become the evidence for "no earlier attempt" and "no matching dead end".
  - The C4 protocol (high and low word overlap, cross-language, status error) measures neither of these.
- **Type:** insufficient sources (the measurement does not cover the claim). Condition 2.

**F3. Criterion 5's relation search is not built or tested for library content** (criterion 5, K-6 item 3c, C04 tasks and acceptance, Appendix B 3.4)
- **Sources:** S:ai-knowledge-strategies/02-KNOWLEDGE-GRAPH §10, §25.1, §25.4, §28 (evidence-before-decision list), F-KG-07.
- **What the source shows:**
  - Every extracted edge is a claim, so it needs a source pointer, an extraction method and an epistemic status.
  - Whether relations add value depends on the real query mix, measured against simpler baselines.
- **What it means for the plan:**
  - No C04 task says how relations between ingested library sources come into being.
  - Relation (Appendix B 3.4) has no field for method or epistemic status.
  - The C04 acceptance has no relation question over library content.
  - Criterion 5 therefore promises more for library content than any stage shows.
- **Type:** scope conflict between criterion 5 and C04. Condition 3.

**F5. The object that is merged is not the object that was checked** (5.6, 6.8, Appendix G G3, C08; Appendix C N23 and K07)
- **Sources:**
  - S:gstack/syntheses/review-qa-ship-delivery-qualification §3, §8, D5
  - S:gstack/syntheses/deploy-canary-production-retrospective-feedback §5.1, §15, failure classes F2 and F6
  - S:superpowers/syntheses/S04-execution-verification-and-delivery §6
  - S:gastown/FINDINGS §15
  - S:superpowers/syntheses/S02-availability-runtime-and-distribution §3
- **What the sources show:**
  - Evidence must be about the thing actually merged. Two branches that pass separately can fail together.
  - The sources' release steps bring in the latest base before testing and redo review after the content changes.
  - Review validity is tied to the reviewed content, not to a commit identity.
  - Source revision, version label and artifact digest are separate identities.
- **What it means for the plan:**
  - The plan re-reads authority at merge, but never requires the checks to have run on the PR combined with the current `main`. Independent products are written in parallel, so this matters.
  - If branches are forced up to date instead, every update creates a new head commit and voids an audit verdict bound to "the head commit". High-impact PRs would then need a new audit after each move of `main`, and there are only 3 audit runs a day (6.4).
  - The release into `soul-system` does not bind its identity back to the `devos` commit.
  - Confirmed as sound: G3 window 3 and K07 already read the real merge state instead of trusting the command result, as deploy-canary §8–§9 support.
- **Type:** technical defect. Condition 5.

**F6. "Merged" is not "applied", and a timestamp is not freshness** (6.2 migration path, C02 acceptance, Appendix B section 6 independent monitoring, Appendix G G7, C09, C11 task 2)
- **Sources:**
  - S:gstack/syntheses/repository-self-development-… §7.1, §8, §9.1, §18, §22
  - S:ecc/notes/32 §4
  - S:ecc/notes/20 §5, §8
- **What the sources show:**
  - The source repository moving forward does not mean the runtime was updated.
  - A migration runner can skip a step permanently while its version marker moves on.
  - A check that could not reach its target can be stored as "current".
  - A missing measurement can turn into zero instead of "unknown".
  - "Last run" times record when a job was dispatched, not what it produced.
- **What it means for the plan:**
  - C02 shows once that a merged migration is applied. After that, nothing compares the applied migrations or deployed functions with `main`.
  - The monitoring path judges ingestion and backup by the time of the last run only. An ingestion job that runs but cannot reach the library would look fresh.
- **Type:** technical defect. Condition 6.
