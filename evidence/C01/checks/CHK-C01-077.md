2. **The documentation claims (item 1) hold. Not blocking.** I read hooks.md, settings.md and changelog.md under code.claude.com/docs/en/ by plain GET today.
   - **The `onFailure` field:** it is in the command-hook fields table (hooks.md:461). The values are `"continue"` (the default) and `"block"`. The table says "Requires Claude Code v2.1.295 or later".
   - **Which hooks it applies to:** only Stop, SubagentStop, TaskCompleted, TeammateIdle and async/asyncRewake hooks are excluded (hooks.md:926-929). PreToolUse and PermissionRequest are not.
   - **What counts as a failure** (hooks.md:916-922): the hook cannot start, exits with a code other than 0 or 2, hits an HTTP error, times out, or gives invalid output. Plain-text stdout from a command hook is not a failure.
   - **PermissionRequest:** "With `"block"` set, a failure does what exit code 2 does on that event, except on `PermissionRequest`, where it denies the request" (hooks.md:924, matching L-222 word for word). Exit 2 is not honoured on that event (hooks.md:938), and "A hook that exits 2 without a `decision` object leaves the permission flow unchanged".
   - **Decision form:** a deny is `hookSpecificOutput.decision.behavior` set to deny, with `message`. `hookSpecificOutput` "requires a `hookEventName` field set to the event name" (hooks.md:1006). The guard's outputs (tool_allowlist.py:2088-2092) and the wrapper's fixed deny both match.
   - **Changelog:** 2.1.295 (October 8, 2026) "Added `onFailure: "block"` for command and HTTP hooks". 2.1.296 (October 9, 2026) is the latest entry, and none of its hook entries changes this.
   - **Version:** all 47,388 version fields in this session's transcripts read "version":"2.1.296". `claude --version` was denied (B7, #7273) and I did not use it.
   - **Default shell:** the page contradicts itself. The `shell` field "Defaults to `"bash"`" (hooks.md:459), but the shell-form text says "`sh -c` on macOS and Linux". The test injects the faults under both /bin/sh and bash (test:997), so the result holds either way.
